# 낙상 데이터 구분 · 평가 기준 · 평가 지표

2026-09-17 정리. 낙상 후보의 영상 확인에는 **Gemma4 31B Cloud**를 사용하기로 한다.
모델 선택을 기록한 것이며, 운영 코드 연결이나 실물 검증이 끝났다는 뜻은 아니다.
Cloud 응답 형식 처리는 운영 연결 전에 정리해야 한다.

## 1. 데이터 구분

총 **84개 합성 RGB 영상**을 사용한다. 모델 학습이나 파인튜닝이 아니라 비교 평가용이다.
사람이 영상을 보고 라벨과 판단 이유를 작성했으며, 생성 프롬프트를 정답으로 사용하지 않는다.

| 구분 | 수량 | 판단 기준 |
|---|---:|---|
| 낙상 | 25개 | 넘어지는 과정을 봤고, 균형 상실이나 의도치 않은 떨어짐이 뚜렷하다. |
| 낙상 의심 | 25개 | 넘어지는 동작이 애매하거나, 처음부터 쓰러진 듯한 상태여서 사고인지 휴식인지 구분하기 어렵다. |
| 정상 행동 | 34개 | 스스로 앉거나 눕기, 휴식, 일상 활동 등 정상적인 행동이 명확하다. 사람이 없는 영상도 포함한다. |

‘이미 쓰러짐’은 별도 라벨로 두지 않는다. 쓰러지는 과정을 못 봤고 사고 여부가
불분명한 208·414는 낙상 의심이다. 반대로 처음부터 이불을 덮고 자는 모습처럼
정상적인 휴식이 명확하다면, 눕는 과정을 못 봤어도 정상 행동으로 분류할 수 있다.

공통 원칙은 다음과 같다.

- 넘어지는 과정을 못 봤다는 이유만으로 모두 낙상 의심으로 분류하지 않는다.
- 속도, 침구 유무, 미동 중 하나를 자동 판정 규칙으로 쓰지 않는다. 보이는 동작과 맥락을 본다.
- 반드시 단서가 두 개 이상 있어야 하는 것은 아니다. 근거가 제한적이면 판단 이유에 적는다.
- 넘어진 뒤 움직이거나 일어나도, 영상에서 확인한 낙상은 낙상으로 남긴다.
- 영상만으로 부상·의식 소실·질문에 대한 무응답을 추측하지 않는다.
- 판단을 방해하는 손·발 중복이나 비정상적인 움직임은 평가 전에 품질 제외로 기록한다.
  어려운 영상이나 모델이 틀린 영상이라는 이유로 빼지 않는다.
- 모델 결과에 맞춰 라벨을 고치지 않는다. 사람이 재검토해 변경할 때는 이유와 버전을 남긴다.

## 2. 평가 기준 — 어떻게 채점하는가

기본 단위는 **영상 1개**다. 사람 검토로 확정한 라벨과 유효한 모델 라벨이 같으면
1점, 다르거나 응답에 실패하면 0점이다.

- 낙상·낙상 의심·정상 행동, 세 분류를 그대로 비교한다.
- 낙상 의심 영상도 정확도 계산에 포함한다. 애매하다는 이유로 분모에서 빼지 않는다.
- 정답이 낙상인데 모델이 낙상 의심이라고 답하면 분류 오답이다. 반대도 마찬가지다.
  추가 확인 대상으로 남겼다는 사실은 별도 메모이지, 분류 정답이나 부분 점수가 아니다.
- 설명이 그럴듯하거나 사람의 판단 근거가 제한적이어도 점수를 더 주지 않는다.
- 호출 대상으로 선정된 영상은 시간 초과·형식 오류·분석 불가가 생겨도 분모에 남긴다.
  유효한 ‘낙상 의심’은 오류나 분석 불가가 아니라 정식 라벨이다.
- YOLO 후보가 없어 호출하지 않은 영상은 ‘미호출’이다. 정상이라고 답한 것으로 세지 않는다.
- VLM 단독 결과를 골라서 YOLO-Pose 후 VLM의 결과처럼 사용하지 않는다. 각각 실제 호출한다.
- 같은 영상에서 여러 후보가 나와도 영상 수를 중복해서 세지 않는다. 사용할 요청·응답은
  실행 전에 정하며, 결과를 본 뒤 정답에 맞는 응답을 고르지 않는다.
- 미완료 평가는 일부 결과만으로 전체 점수를 발표하지 않는다.

정답·판단 이유·생성 프롬프트·라벨을 드러내는 파일명은 모델에 보내지 않는다.
이번 비교는 동일한 RGB 프레임과 프롬프트를 사용했으며, YOLO 결과나 센서 요약도 보내지 않았다.

## 3. 평가 지표 — 무엇을 비교하는가

**주 평가지표는 아래 세 가지다. 가중치를 주거나 하나의 종합 점수로 합치지 않는다.**

| 순서 | 평가 지표 | 계산 방법 | 현재 평가 범위 |
|---|---|---|---|
| 1 | YOLO-Pose로 찾은 비율 | 각 라벨에서 낙상 확인 후보가 나온 영상 수 ÷ 해당 라벨의 전체 영상 수 | 전체 84개에서 후보 발생 여부 확인 |
| 2 | VLM 단독 정확도 | YOLO 결과와 무관하게 VLM이 세 라벨 중 정답을 맞힌 영상 수 ÷ 전체 평가 영상 수 | 84개 전부 호출, 분모 84 |
| 3 | YOLO-Pose 후 VLM 정확도 | 후보가 나온 영상에 VLM을 실제 호출해 정답을 맞힌 수 ÷ 호출 대상으로 선정된 영상 수 | 후보 40개 별도 호출, 분모 40 |

### 3.1 YOLO-Pose로 찾은 비율

| 정답 구분 | 후보가 나온 영상 / 전체 | 비율 | 의미 |
|---|---:|---:|---|
| 낙상 | 15/25 | 60.0% | 낙상 영상에서 확인 후보가 생김 |
| 낙상 의심 | 15/25 | 60.0% | 의심 영상에서 확인 후보가 생김 |
| 정상 행동 | 10/34 | 29.4% | 정상에서도 후보가 생김. 정답이 아니라 불필요한 확인 요청 |

낙상·낙상 의심을 합치면 **30/50(60.0%)**이며, 정상에서 생긴 후보10개까지 합쳐
VLM 호출 대상은40개다. 정상 후보를 낙상 검출 성공에 더하지 않는다.

이 수치는 **영상에 확인 후보가 하나라도 생긴 비율**이다. 사람 박스·관절 검출률이나
정확한 대상자를 찾은 비율이 아니다. 다른 사람이나 배경에서 후보가 나왔다면
해당 대상자의 낙상을 검출했다고 단정할 수 없다. 대상자 연결 검토는 별도로 남긴다.

### 3.2 VLM 단독 정확도

전체84개를 YOLO 결과와 관계없이 확인한다. 세 라벨을 그대로 채점하므로
낙상25개뿐 아니라 낙상 의심25개와 정상34개도 모두 분모에 들어간다.

### 3.3 YOLO-Pose 후 VLM 정확도

낙상15개·의심15개·정상10개, 총40개에 별도로 호출한 결과를 채점한다.
이번 입력은 후보가 나온 시점까지이며, 이후 장면을 미리 넣지 않았다.

**이 지표는 후보로 선정된 영상에서의 VLM 정확도이지, 전체 낙상 감지율이 아니다.**
후보가 없어 호출하지 못한 낙상·의심20개는 이40개 분모 밖에 있다.
그러므로 첫 번째 지표와 세 번째 지표를 반드시 함께 읽는다.
VLM 단독과 후보 후 평가는 영상 구성과 제공 구간도 달라, 두 정확도를 단순히 비교해
YOLO가 VLM 자체의 판단 능력을 높였다고 해석하지 않는다.

응답 시간·형식 오류·정상으로 놓친 사례·정상 오탐·혼동행렬은 결과 해석과
운영 검증을 위한 **참고 정보**다. 주 평가지표를 늘리거나 기존 안전 점검을 없애는 것은 아니다.

원문 그대로의 엄격한 채점은 단독0/84·후보 후0/40이며, 위 점수와 별도로 보존했다.
모든 비교 모델에 같은 형식 진단 규칙을 적용했고, 라벨·설명 내용은 수정하지 않았다.

Cloud를 사용하기로 한 결정과 별개로, 운영 연결 전에 응답 형식 처리를 명세하고 검증한다.
이번 보조 결과를 근거로 기존 채점기나 정답을 소급 변경하지 않는다.

이번 자료는 이미 검토·개선에 사용한 합성 개발 데이터다. 실제 가정이나 Jetson에서의
성능을 입증하지 않으며, 과거41개·77개 평가와 데이터 수나 점수를 섞지 않는다.
