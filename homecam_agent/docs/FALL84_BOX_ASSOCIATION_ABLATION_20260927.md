# 사람 박스 연결과 낙상 자세 조건을 분리한 시험

2026-09-27 / SWM25-186

**관절 정보가 충분해야 한다는 조건만 사람 연결에서 빼도, 이번 4개 장면의 사건 연결 결과는
개선되지 않았다.** 사용 가능한 Cloud 응답 7개 중 연결은 기존과 같은 1개였다.
따라서 운영 코드는 변경하지 않았다. 이 실험만으로 모델 교체나 연결 기준 완화를 결정하지 않는다.

## 바꾼 것과 유지한 것

기존 코드에서는 현재 박스가 있고 추적이 이어져도, 낙상 자세를 판단할 만큼 관절 정보가
충분하지 않으면 `associationUsable=False`가 된다. 사람의 위치를 연결할 때도
이 자세 조건이 필요한지 확인하기 위해 두 조건을 비교했다.

| 조건 | 기존 | 분리 실험 |
|---|---|---|
| 현재 프레임에서 실제 박스 관측 | 필요 | 유지 |
| 추적 상태 `tracked` | 필요 | 유지 |
| 박스 검출 점수 0.45 이상 | 필요 | 유지 |
| 연결하지 못한 애매한 검출이 남아 있지 않음 | 필요 | 유지 |
| 낙상 자세 분석용 관절 정보가 충분함 | 필요 | **사람 위치 연결에는 요구하지 않음** |
| Cloud 박스와 IoU 0.60 이상·다른 추적과 차이 0.15 이상 | 필요 | 유지 |
| Cloud가 반환한 모든 위치가 같은 추적·연결 구간에 대응 | 필요 | 유지 |
| 최신 대상 관측과 기존 사건의 연결 구간 확인 | 필요 | 유지 |

박스만 연결되는 경우는 자세가 정상이라는 뜻이 아니다. 실험의 위치 관측은 모두 `unknown`으로
입력해, 자세 정상·회복 확인이나 사건 종료의 근거로 쓰이지 않게 했다.
낙상 후보, 기존 자세 특징, 점수, 원본 박스는 변경하지 않았다.

## 시험 방법

- [앞선 실제 Pose 재현 시험](FALL84_ALIGNED_POSE_MERGE_REPLAY_20260927.md)의
  4개 장면·86프레임 추론 결과와 원래 Cloud 입력·응답을 그대로 재사용했다.
- 프레임이나 응답을 새로 고르지 않았다. 실패한 초기 프레임을 빼거나,
  뒤에서 안정된 추적을 과거의 불확실한 구간까지 이어 붙이지 않았다.
- 기존 조건을 다시 실행해 앞선 결과와 같은지 확인한 뒤 분리 조건과 비교했다.
- 실제 후보 JSON은 기존 입력 검사를 거쳤다. 분리한 위치 관측만 별도 실험 입력부에서
  `SubjectFrame`으로 전달했다. 이후에는 현재 대상 연결·사건 병합·SQLite 코드를 사용했다.
- **운영 ROS 입력 형식은 바꾸지 않았다.** 기존 `FallDetectorInput`은 여전히
  `features.usable=False`인데 `associationUsable=True`인 입력을 거절한다.
  실험을 통과시키려고 자세 정보가 충분한 것처럼 바꾸지 않았다.
- 검수 정답은 두 조건의 연결·병합 실행이 모두 끝난 뒤 사람을 대조할 때만 읽었다.
- 새 Pose 추론·Cloud 호출·비용은 모두 0이다.

이것은 분리 방식의 효과를 살펴보는 **오프라인 실험**이다. 실제 호출 우선순위,
60초 주기, ROS 통신, Cloud 응답 대기 중 움직임, 주행·음성·보호자 알림은 검증 범위가 아니다.
이 4개는 이미 문제를 확인하고 고른 개발용 장면이며, 독립적인 전체 성능 평가가 아니다.

| 영상 | 기존 연결 가능 관측 | 분리 후 연결 가능 관측 |
|---|---:|---:|
| SYN012 | 30 | 30 |
| SYN045 | 46 | 46 |
| SYN063 | 20 | 20 |
| SYN067 | 11 | 50 |
| 합계 | 107 | 146 |

관측 수는 **프레임마다 추적별로 센 수**다. 같은 사람이 여러 번 포함되므로
서로 다른 사람 수나 사건 수가 아니다. 두 Cloud 모델에 공유된 Pose 자료는 한 번만 셌다.

SYN067에서 추가된 39건 중 38건은 추적 1·2, 나머지 1건은 프레임 8의 추적 3이었다.
정확히 같은 프레임의 승인 박스로 대조할 수 있던 10건은 주변 인물이었다.
나머지 29건은 해당 프레임의 대조 결과가 없어 사람별 정답으로 세지 않았다.
추적 번호가 같다는 이유만으로 미검수 프레임의 실제 신원을 확정하지 않았다.

### 왜 개선되지 않았나

- **SYN012:** 첫 Cloud 프레임에서 대상 검출 점수가 약 0.275로 낮고,
  애매한 추가 검출도 남았다. 관절 조건을 빼도 점수·추적 조건을 통과하지 못했다.
- **SYN063:** 앞부분에서 누운 대상의 박스 자체가 없었다. 곁에 있는 사람의
  박스가 더 안정적이라는 이유로 그 사람에게 연결하지 않았다.
- **SYN067:** 첫 Cloud 프레임의 주요 대상 점수는 약 0.182였고 추적도 아직 불확실했다.
  일부 주변 인물의 박스를 더 사용할 수 있게 돼도, 누운 대상의 처음부터 끝까지 연결은 성립하지 않았다.

따라서 이번 실패를 **관절 정보 조건 하나의 문제로 설명할 수 없었다.**

## 확인한 보호 조건

새 시험 36개를 포함해 관련 회귀 시험 **528개 통과**.
새 시험의 사람·박스 입력은 테스트 값이며 실제 영상 정확도와 합산하지 않았다.

- 강한 검출인데 관절만 부족한 테스트 입력은 분리 조건에서 연결 가능.
- 낮은 점수, 아직 확인되지 않은 추적, 애매한 미연결 검출은 계속 차단.
- 중간에 관측이 끊겼다가 같은 ID로 나타나도 이전 연결 구간에 붙이지 않음.
- 두 프레임에서 서로 다른 사람을 가리키면 연결하지 않음.
- 겹치는 사람 박스가 구분되지 않으면 연결하지 않음.
- 박스 위치만 확인됐다고 정상 자세나 회복으로 바꾸지 않음.
- 장면 전체의 정상 응답만으로 진행 중인 사람별 사건을 종료하지 않음.
- 원본 박스·점수·시각·추적 상태를 바꾼 입력은 거절.
- 같은 결과를 반복해도 사건·질문 ID·재확인 횟수가 달라지지 않음.
- DB를 다시 열었을 때 사건·미연결 발견 기록이 유지됨.

기존 조건 8개 조합과 분리 조건 8개 조합, 총 16회 오프라인 재현을 수행했다.
보존 대상 161개 파일의 해시가 실행 전후 같았다. 실제 카메라나 Cloud를 16번 호출한 것이 아니다.

## 판단과 다음 확인

후속 시험 완료: [회전·고정 구역 확대 비교와 전체 진행 정리](FALL84_POSE_LINKING_SUMMARY_20260927.md).
일부 누운 대상의 검출은 좋아졌지만 사건 연결은 늘지 않았고, 중복 검출과 추론 시간이 늘어
운영 코드는 유지했다.

사람 연결과 자세 판단을 분리하는 구조는 테스트 입력에서 동작했지만,
이번 실제 장면의 대상 연결 실패를 해결하지는 못했다. 실험 코드는 운영 경로에 연결하지 않았다.

다음에는 **쓰러진 대상의 약한 검출과 미검출을 먼저 개선할 수 있는지** 확인해야 한다.
주변 사람이나 이불을 대상으로 잘못 잡는 사례도 함께 봐야 한다.
점수 기준을 낮추거나 일부 Cloud 프레임을 버리는 것은 이번에 적용하지 않았다.

안정된 뒤쪽 프레임만 이용하는 방식은 추적 단절·사람 바뀜을 숨길 수 있어 별도 검증이 필요하다.
새 영상으로 재확인한다면 기존 Cloud 응답을 다른 프레임에 재사용할 수 없으며,
실제 입력 선택·응답 도착 시점까지 연결한 시험도 남아 있다.
