# 후속 사건 연결 — 새 추론과 실제 ROS 검증

2026-09-27. 운영 코드나 설정은 변경하지 않았다. 테스트 코드와 결과 문서만 추가했다.

## 결과 요약

앞서 사용한 개발 영상 9개의 YOLO-Pose와 SAM을 다시 추론한 뒤, 새 관측으로 사건 연결을 재생했다. 기존 Pose 사건에 연결된 것은 움직임 장면 6개 중 5개로 이전과 같았다. 다인 장면 2개는 여전히 연결하지 못했다. 성능이 더 좋아졌다는 결과가 아니라, 새 추론에서도 연결 결과를 재현한 것이다.

별도로 로컬 전용 실제 ROS 통신에서 후속 연결 테스트 4개가 통과했다. 그러나 SAM CPU는 영상 하나의 15~20프레임을 처리하는 데 33.75~47.06초가 걸렸다. 현재 방식 그대로 실시간 연결이 가능하다고 판단할 수 없다.

## 1. 새 영상 추론

- 동일한 합성 개발 영상 9개. 새로운 독립 검증 영상은 아니다.
- 실제 YOLO26s-Pose ONNX: 182프레임 재추론.
- 실제 SAM 2.1 Hiera Tiny: Cloud 시드가 있는 8개 영상, 155프레임 재추론. CPU, float32, 4스레드.
- 정상 대조 영상 1개는 기존 Cloud 응답에 발견이 없어 SAM을 실행하지 않았다.
- Cloud 응답만 기존 Gemma 기록을 사용했다. 새 API 호출·영상 업로드·비용은 0.
- 원래 Cloud RGB 12장과 중립 4Hz 추적 일정 유지. 사람 박스 정답은 추론/연결 입력으로 사용하지 않고, 완료 후 정확히 검토된 프레임에서만 비교했다.
- 입력·모델·코드 해시를 새 실행 계획에 기록했고, 기존 결과는 덮어쓰지 않았다.

| 구분 | 영상 수 | 기존 Pose 사건에 연결 | 별도 유지 |
| --- | ---: | ---: | ---: |
| 움직임·부분 가림·카메라 움직임 | 6 | 5 | 1 |
| 다인 대조 장면 | 2 | 0 | 2 |
| 정상 대조 장면 | 1 | 0 | 발견 없음 |

연결: SYN059, SYN075, SYN078, SYN083, SYN084.

보류: SYN050은 마지막에 Pose 박스가 없었고, SYN063은 일치하는 Pose 대상을 찾지 못했다. SYN067은 중간에 일치한 구간이 있어도 마지막 관측이 연결에 사용할 수 없는 상태여서 붙이지 않았다.

5건 모두 기존 사건 ID에 Cloud 근거가 추가됐고, 별도의 사람 사건을 새로 만들지 않았다. 확정 시점 f120의 검토 박스와 비교한 5건 모두 같은 사람이었으며, 그 5개 시점에서 잘못된 사람 연결은 없었다. 영상 전체의 ID 전환이나 완전 가림 후 재등장을 검증했다는 뜻은 아니다.

SQLite 재개방과 중복 입력 무변경 검사도 9개 모두 통과했다. 원본 장면 사건은 보존하고, 개별 발견만 사람 사건에 연결했다.

## 2. 처리 시간

| 측정 | 결과 |
| --- | ---: |
| SAM 8개 영상 중 최소 | 33.75초 |
| SAM 중앙값 | 46.85초 |
| SAM 최대 | 47.06초 |
| Pose 182프레임 추론 시간 합계 | 13.05초 |

SAM 시간은 각 영상의 프레임 로딩·초기화·추적 처리 시간이며 최초 모델 로딩, Cloud 응답 대기, 보호자 알림 시간은 포함하지 않는다. 같은 PC에서 ROS 테스트도 병행했으므로 단독 실행 성능을 정밀 비교한 수치는 아니다.

사건 연결 재생에서는 새 추론 결과를 영상 촬영 시각에 맞춰 제공했다. 실제 SAM 소요 시간까지 실시간 카메라와 묶어 재현한 것은 아니다. 따라서 위 5/6을 실시간 감지 성공률로 사용할 수 없다. 영상 신선도 제한을 늘리거나 촬영 시각을 새 시각으로 바꿔 통과시키지 않았다.

## 3. 실제 ROS에서 확인한 후속 연결

`malbut_agent_server/test/test_fall_deferred_ros_flow.py`를 추가했다.

| 시험 | 확인한 동작 |
| --- | --- |
| 같은 대상 | 이후 Pose 관측으로 기존 사건 ID에 연결, ROS 연결 이벤트 수신, 기존 질문 ID 유지, 추가 Cloud 호출 없음, DB 연결 이력 보존 |
| 다른 위치의 대상 | 기존 사람에게 붙이지 않음. 장면 질문과 미연결 발견 유지 |
| 카메라 OFF | Manager 설정 Service 적용 뒤 기존 추적 세션의 결과 거절 |
| 늦게 도착한 추적 결과 | 카메라·heartbeat를 계속 보내면서 실제 2.2초 기다린 뒤 이전 결과 전달. `current_target_unavailable`로 연결 거절 |

같은 대상 시험에서는 장면 전체에 대한 “괜찮다” 결과를 ROS로 보낸 뒤에도 해당 사람의 사건이 정상 종료되지 않는지 확인했다. Manager 확인 요청 조정기에 실제 수신 이벤트를 넣었을 때 장면 질문과 사람 질문의 ID도 각각 유지됐다.

원본 코드 4개 통과(22.30초), `malbut_test` 미러 4개 통과(22.36초). 시간은 시험 전체 실행 시간이다.

실제로 사용한 것은 설정 Service, RGB/Pose Topic, 운영 후보 처리·VLM 노드·이벤트 전송·SQLite다. RGB 픽셀·Pose 추정·Cloud 발견·추적 박스는 테스트 값이다. 새 추적 ROS API를 만든 것이 아니라 모니터의 로컬 추적 입력 함수를 시험 코드에서 호출했다. 따라서 위의 새 모델 추론 시험과 이 ROS 시험은 별도이며, 실제 SAM→실시간 ROS의 전체 연결 시험은 아니다. Agent 음성·로봇 이동·웹 알림은 실행하지 않았다.

## 4. 기존 동작 회귀 확인

- ROS 인터페이스를 현재 소스로 별도 경로에 빌드: 성공(14.7초).
- 기존 PC 흐름 11개 + Manager 확인 연동 7개 + 설정 연결 3개 + 런타임 23개: 44개 통과, 157.35초. 20초 Cloud 시간 초과와 60초 주기적 확인을 줄이지 않고 검사했다.
- 일반 낙상 회귀 묶음은 ROS 의존성을 불러온 환경에서 416개 통과, 15개 건너뜀(2.67초). 건너뛴 opt-in ROS 테스트 15개는 위 PC 흐름 11개와 후속 연결 4개로 별도 실행해 통과했다. 여러 묶음의 시험이 겹치므로 개수를 단순 합산하지 않는다.
- 추가 테스트 파일 flake8(최대 100자) 및 `git diff --check`: 통과.
- ROS는 `ROS_LOCALHOST_ONLY=1`, 분리된 domain 193~196, 테스트별 UUID Topic/Service로 실행했다. 운영 로봇의 Topic에 명령을 보내지 않았다.
