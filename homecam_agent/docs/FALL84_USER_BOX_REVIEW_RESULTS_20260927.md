# 사용자 박스 검수 반영과 대상 대조 결과

2026-09-27 / SWM25-186

사용자가 맥북에서 검수한 JSON을 전달받았다. **15프레임 모두 확인 표시가 있었고,
34개 박스 중 초안과 달라진 좌표는 10개**였다. 원본 프레임·JPEG 해시·사람 ID·역할·좌표를
검사한 뒤, 기존 정답을 보존하고 별도 검수 자료로 반영했다.

추가 Cloud 호출·비용은 없다. 운영 코드와 84개 영상의 판단 라벨·모델 응답도 변경하지 않았다.

## 검수 자료 반영

- SYN012: 보호자 박스 3개 수정.
- SYN045: 이미지 8의 누운 대상자 박스 1개 수정.
- SYN063: 초안의 박스 8개를 그대로 확인.
- SYN067: 누운 대상자 박스 2개와 회색 바지 사람 박스 4개 수정.
- 기존 승인 자료의 533개 박스는 모두 유지했다. 실제 Cloud 입력의 15프레임에
  승인한 박스 34개를 추가해 새 자료는 총 567개다.
- 640×400 Cloud 캔버스 좌표를 원본 영상 좌표로 역변환했다. 1280×720 영상의
  위아래 여백 20픽셀을 빼고 원본 크기로 돌린 뒤, 다시 변환해 같은 좌표인지 확인했다.
  박스를 임의로 자르거나 가까운 프레임으로 옮기지 않았다.
- 초기 41개 영상과 추가 영상의 기존 자료 형식이 달라, 각각의 영상 해시 보관 위치와
  `reviewed_frames` 형식을 구분해 읽도록 처리했다. 시간 정답·분류 라벨은 그대로다.

원본 JSON의 `approval_status=pending_human_review`는 그대로 보관했다. 검수 화면이
스스로 정답을 승인하지 않도록 만든 필드이기 때문이다. 별도 `approval.json`에 사용자의
“다 확인했어.” 및 전송 완료 확인, 15프레임 확인 표시, 전달 파일 해시를 함께 기록했다.
초안에 적힌 메모는 과거 작성 내용을 보존하며, 수정된 박스의 최종 승인 여부는 이 별도 기록을 따른다.

## 검수한 박스로 저장 응답 대조

Gemma·Gemini의 기존 84개 응답을 각각 다시 읽어, 새 검수 자료와 정확히 같은 프레임에서만
박스를 비교했다. 모델을 다시 호출한 것이 아니다.

| 검수 장면 | Gemma | Gemini |
|---|---|---|
| 414 / SYN012 | 2개 출력 박스 모두 누운 대상과 대응 | 4개 모두 누운 대상과 대응 |
| SYN045 | 기존 JSON 오류로 대조 불가 | 4개 모두 누운 대상과 대응 |
| SYN063 | 2개 모두 누운 대상과 대응 | 4개 모두 누운 대상과 대응 |
| SYN067 | 2개 모두 누운 대상과 대응 | 4개 모두 누운 대상과 대응 |

SYN012의 Gemini 4개에는 이전에 승인된 이미지 4도 포함된다. 앞선 초안 보고서의
3개는 새 초안 프레임만 센 값이었고, 이번 표는 이 장면에서 반환한 4개 전체를 센다.

이 4개 선택 장면에서 대조 가능한 Gemma 3개·Gemini 4개 응답은 각각 두 프레임 이상에서
같은 누운 사람에 대응했다. 다른 사람으로 바뀐 대응은 나타나지 않았다. **이는 선택된
표본 프레임의 박스 대조이며, 실제 YOLO 추적 ID 연결·사건 병합 성공률이 아니다.**

몸 일부를 빠뜨리는 문제도 남았다. SYN063의 Gemma 박스는 대상과 대응하지만 무늬 바지
쪽을 충분히 포함하지 않아 검수 사각형의 약 70.3~70.7%만 덮었다. 이 비율은 신체 픽셀
비율이 아니라 사각형 면적 비율이다. SYN045의 중복 JSON 오류는 정상으로 바꾸거나
일부분만 꺼내 사용하지 않았다.

전체 84개 저장 응답에서 같은 프레임 정답과 대조할 수 있는 박스는 Gemma 8→14개,
Gemini 14→29개로 늘었다. 나머지 Gemma 171개·Gemini 177개는 같은 프레임의 정답이
없어 여전히 수치 평가하지 못한다. 대조 가능한 박스만으로 전체 위치 정확도를 만들지 않았다.
기존 영상 라벨 정답 수·호출 비용·응답 시간은 바뀌지 않는다.

## 사건 병합 관련 코드 시험

검수 파일 처리와 기존 유료 평가·좌표 변환·Cloud 어댑터·대상 연결·사건 처리 테스트를
합쳐 **365개 통과**했다. 이 중 기존 사건 관련 회귀 시험은 다음을 확인한다.

- 같은 사람으로 확인된 Cloud 발견을 기존 YOLO 사건에 연결하고 사건·질문을 중복 생성하지 않음.
- 기존 재확인 횟수를 초기화하거나, 이미 받은 결과 때문에 Cloud를 추가 호출하지 않음.
- 사람이 사라졌다 다시 나타나거나 추적 연결이 끊기면 예전 사건에 억지로 붙이지 않음.
- 보호자 등 다른 사람의 정상 행동으로 대상 사건을 종료하지 않음.
- 화면 전체가 정상이라는 응답만으로 기존 사람별 의심 사건을 종료하지 않음.
- 도움 요청이 들어온 사건을 새 영상 응답으로 지우지 않음.

이것은 **테스트 입력을 넣은 코드 회귀 시험**이다. 검수한 4개 영상을 실제 Pose·Cloud로
동시에 실행해 보호자 알림까지 확인했다는 뜻이 아니다.

## 실제 Pose 연결 시험 전 확인한 문제

이전 개선판 `YOLO26s-Pose / s-partial r4 / partial_brief`의 보존된 기록을 확인했다.
Cloud가 박스를 반환한 프레임 중 일부가 이 Pose 기록에 없다.

| 영상 | Cloud가 박스를 반환한 원본 프레임의 합집합 | 기존 Pose 기록에 있는 같은 프레임 |
|---|---|---|
| SYN012 | 3, 24, 46, 62 | 24, 46, 62 |
| SYN045 | 2, 46, 89, 122 | 없음 |
| SYN063 | 2, 46, 78, 122 | 없음 |
| SYN067 | 2, 46, 78, 122 | 없음 |

이는 서로 다른 평가에서 이미지를 고른 시점이 다르기 때문이다. Pose가 해당 사람을
검출하지 못했다는 결과가 아니라, **필요한 같은 프레임의 추론 기록이 없는 상태**다.
유효한 Cloud 응답 7개 중 필요한 모든 프레임의 Pose 기록이 갖춰진 경우는 0개였다.
이번에는 가까운 프레임의 Pose를 복사하거나 정답 박스를 Pose 출력으로 대신하지 않았다.

다음 시험에서는 동일 영상·동일 촬영 시각으로 RGB와 Pose 기록을 준비해야 한다.
정답·대상 ID를 추적기에 넣지 않고 실제 Pose 추론과 추적 결과를 만든 뒤, 이번 검수
박스는 채점에만 사용한다. 저장된 Cloud 응답의 정확한 입력 프레임을 재사용하는
오프라인 연결 시험과 실제 최대 5fps·버퍼 선택 조건의 통합 시험도 구분해야 한다.
촬영 시각 사이의 추적 연속성이 필요하므로 검수한 15장만 따로 추론해서는 충분하지 않다.

후속 시험 완료: [같은 입력 프레임으로 Pose 연결·사건 병합 재현](FALL84_ALIGNED_POSE_MERGE_REPLAY_20260927.md).
4개 장면을 새로 Pose 추론한 결과, Gemini의 SYN045는 기존 사건에 연결됐고
나머지는 추적 불확실성·대상 미검출 또는 기존 JSON 오류 때문에 연결되지 않았다.
이전의 정답 박스 대조 결과를 실제 사건 연결 성공으로 해석하면 안 된다.
