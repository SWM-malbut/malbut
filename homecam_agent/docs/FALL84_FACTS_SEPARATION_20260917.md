# Gemma 관찰·추측 분리 비교

## 결론

**이번 출력 형식은 기본값으로 채택하지 않는다.** 후보 40개에서는 확인 대상으로 남긴 수가
2개 늘었으나, 전체 영상에서는 기존에 잡던 낙상 2개를 새로 정상으로 판정했다.
두 평가의 3분류 정확도는 그대로이고 응답 시간은 늘었다. V034의 정상 오판도 해결하지 못했다.
로컬 실제 호출 124회(40 + 84)를 완료했으며 모두 유효한 JSON 응답을 받았다.

## 비교한 것

바닥에 있는 사람을 보고 '넘어지는 과정이 없으므로 휴식'으로 단정하는 문제를 대상으로,
출력을 `observations`(보이는 내용/알 수 없는 내용)와 `assessment`(기존 3분류)로 나눴다.
원래 A 판단 기준은 유지하고 추가 출력 지시·JSON 스키마 안내·전송 스키마를 변경했다.
앞선 프롬프트 B는 사용하지 않았다. 모델 판정을 코드에서 의심으로 바꾸는 규칙도 넣지 않았다.

- 공통 데이터: 낙상 25 / 낙상 의심 25 / 정상 34, 합계 84개 합성 개발 영상.
- 모델: 맥의 로컬 Gemma4:12b, 기존 digest·Ollama 0.31.2·옵션 유지.
- 입력: 기존 A의 JPEG 12장과 시각·구간·해상도 동일. 원본 요청 재구성 해시로 대조.
- YOLO 이후: 기존 39개 + 추가 V034 후보의 40개에 호출. 나머지 44개는 미호출 유지.
- VLM 단독: 전체 영상 84개에 호출. 모델에 라벨·이유·YOLO·depth·음성은 전달하지 않음.
- 평가: 모델의 `assessment`를 그대로 기존 3분류 채점기에 전달.
  잘못된 관찰 필드/응답은 실패로 남기고 분모에서 빼지 않음.

관찰 필드도 모델이 생성한 주장이지 검증된 사실이 아니다. 이 실험은 출력 항목의 분리이며,
관찰을 먼저 생성하고 다음 호출에서 판단하는 2단계 방식은 아니다. JSON 직렬화에서 키를
정렬하므로 응답에 assessment가 먼저 나타날 수 있다. 내부 추론 순서를 입증하지 않는다.

## YOLO 후보 후 VLM: 완료

후보 40건은 새로 실제 호출했다. 대조군은 이전 A의 39건 + 앞서 실제 호출한 V034 1건을
재사용했다. 새 출력 형식 40건 모두 유효했다.

| 지표 | 기존 A | 출력 분리 |
|---|---:|---:|
| 호출된 영상 3분류 정확도 | 25/40 (62.5%) | 25/40 (62.5%) |
| 낙상·의심 50개 중 확인 대상으로 남김 | 17/50 (34.0%) | 19/50 (38.0%) |
| 낙상·의심을 정상으로 판정 | 13 | 11 |
| 후보가 없어 호출하지 못한 낙상·의심 | 20 | 20 |
| 호출된 정상 10개 중 불필요한 확인 | 0/10 | 0/10 |
| 요청 시간 중앙값 / p95 | 11.07초 / 12.71초 | 14.36초 / 15.57초 |

정상 34개 중 24개는 호출하지 않았다. 10/10 정상 판정을 34/34 모델 정확도로 해석하지 않는다.
확인 대상은 GT가 낙상 또는 의심이고 모델도 낙상 또는 의심으로 답한 영상이다.
확실한 낙상을 의심으로 답하면 확인 대상에는 남지만 3분류 정답은 아니다.

V034는 새 형식에서도 정상으로 답했다. 모델은 '휴식인지 사고인지 알 수 없다'고 적으면서도,
넘어지는 과정·자세 변화가 보이지 않는다는 이유로 정상 판정을 유지했다.

## VLM 단독: 완료

| 지표 | 기존 A | 출력 분리 |
|---|---:|---:|
| 전체 영상 3분류 정확도 | 59/84 (70.2%) | 59/84 (70.2%) |
| 낙상·의심 50개 중 확인 대상으로 남김 | 33/50 (66.0%) | 31/50 (62.0%) |
| 낙상·의심을 정상으로 판정 | 17 | 19 |
| 정상 34개 중 불필요한 확인 | 2/34 | 2/34 |
| 정상 영상에서 분석 불가 응답 | 1 | 0 |
| 요청 시간 중앙값 / p95 | 10.28초 / 12.08초 | 14.37초 / 16.44초 |

정확도만 보면 같지만, 낙상을 더 놓쳤다. 세부 정답 수는 낙상 22→20, 의심 6→7,
정상 31→32다. 정상 오탐 수가 같아도 해당 영상은 달라졌으므로 동일한 오류라고 볼 수 없다.

### 중요한 변화

- **413, V002**: 전체 영상에서 기존 낙상 판정이 정상으로 바뀌었다.
  413은 누워 있는 마지막 상태를 휴식으로 해석하며 넘어지는 과정을 놓쳤다.
  V002는 바닥으로 내려가는 모습을 정상적인 주저앉기로 해석했다.
  이는 모델 설명과 사용자 라벨의 대조이며, 새 영상 재라벨링은 하지 않았다.
- **208, V035**: 후보 이후 평가에서 기존 정상 판정이 의심으로 바뀌었다.
- **V017, V037**: 전체 영상에서 기존 의심 판정이 정상으로 바뀌었다.
- **V034**: 후보 구간과 전체 영상 모두 여전히 정상. '휴식인지 사고인지 알 수 없다'는
  설명과 정상 판단이 함께 나오는 문제는 출력 항목만 분리해도 남았다.

모델이 관찰 항목을 채우는 것과 실제로 장면을 정확히 읽는 것은 다르다.
이번 결과만으로 관찰을 먼저 추출하는 별도 2단계 방식까지 효과가 없다고 결론내리지는 않는다.
다만 이 단일 호출/출력 분리 방식의 효과는 제한적이며 낙상 미탐 개선안으로 채택하지 않는다.

## 검증·제한

- 관련 테스트 381개 통과. 실패 보존·누락/중복 키·길이 제한·원본 요청 변조 차단 포함.
- 모든 124개 비교 입력을 첫 호출 전에 원래 A 요청으로 재구성해 검증했다.
- 프로토콜과 소스 사본을 실행 전에 저장했으며 실행 도중 변경하지 않았다.
- 실행 후 124개 요청을 다시 재구성해 이미지·시각·요청 해시를 확인하고, 원문 응답의
  파싱 결과와 저장된 판정, ID별 원본 대조 및 전체 재집계가 일치하는지 검증했다.
  보고서의 첫 비교는 기존 결과의 파일 열거 순서 차이로 멈췄다. 영상 ID별 정렬 비교로
  보완했으며 원문 결과·지표·모델 호출은 수정하거나 재실행하지 않았다.
- 요청 시간은 Mac/SSH의 단일 실행 측정이다. 출력 길이·로딩 등이 포함된다.
  Jetson 성능이나 낙상 발생부터 조치까지 걸린 시간이 아니다.
- 이미 보고 조정한 합성 개발 데이터다. 실환경 또는 독립 평가 성능을 주장하지 않는다.
- 유료 호출·모델 다운로드·운영 코드 수정·배포·커밋 없음.

## 다음 비교

같은 Gemma에 문구만 더 강하게 추가하는 방식은 우선 멈춘다. 현재 입력을 고정한 채 다른
로컬 VLM과 비교하거나, 관찰 추출과 판정을 별도 단계로 분리한 새 실험을 검토한다.
어느 경우든 낙상·의심뿐 아니라 정상 영상도 함께 평가하고, 추가 지연과 새로운 미탐을
같이 확인해야 한다. 현재 검증된 결과를 운영 경로의 안전성 입증으로 사용하지 않는다.
