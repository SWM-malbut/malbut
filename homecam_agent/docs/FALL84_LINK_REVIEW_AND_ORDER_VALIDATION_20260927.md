## 결과 요약

이전 시험에서 정답 박스가 없어 미검수로 남긴 4건을 원본 JPEG 위의 SAM·Pose 박스로 확인했다.
**assistant가 확인한 연결 순간과 직전·직후 12프레임에서는 다른 사람으로 연결된 모습이 보이지 않았다.**
이는 추가 사람 검수나 정답 박스 작성이 아니라 이미지에 대한 assistant의 정성 검토다.
기존 정량 결과의 ‘검수 시점 일치 3건·정답 박스 없는 4건’을 7/7 정확도로 바꾸지 않았다.

별도 제어 입력 시험에서는 두 발견 순서 모두 같은 사람의 사건 ID를 유지했고,
반복 입력 30회로 사건·분석 요청·Manager 질문 요청이 추가되지 않았다.
다른 사람·겹치는 후보·ID 교체·늦은 추적·카메라 OFF는 연결하지 않았다.

다만 **뒤늦게 사람을 연결한 경우, 장면 질문 1개와 사람 질문 1개가 함께 남았다.**
사람 대상의 사건 중복 방지와, 장면 질문까지 하나로 정리하는 기능은 구분해야 한다.

## 2. 발견 순서·중복·지연 시험

10개 시나리오에 명시적인 가짜 RGB·Pose·Cloud 답변을 주고,
실제 `CloudFallMonitor`·SQLite·Manager의 `FallConfirmationCoordinator`를 실행했다.
실제 ROS나 음성 재생은 아니다. 질문 수는 Manager에 남은 요청 수이지 실제 발화 횟수가 아니다.

| 조건 | 확인한 결과 |
| --- | --- |
| Pose 먼저 → Cloud에서 바로 대상 확인 | 기존 사람 사건 ID 유지. 사람 사건 1개·질문 요청 1개 |
| Pose 먼저 → Cloud 위치 한 장만 받아 추적 후 연결 | 기존 사람 사건 ID 유지. 사람 사건 1개와 대상 미확인 장면 기록 1개. 질문 요청은 2개 |
| Cloud 먼저 → 추적 후 Pose ID 확보 → Pose 후보 도착 | Cloud 발견에서 만든 사람 사건을 후속 Pose 후보도 사용. 사람 사건 1개와 장면 기록 1개. 질문 요청은 2개 |
| Cloud 박스와 다른 위치의 사람만 Pose에 존재 | `no_matching_track`, 연결 안 함 |
| 같은 위치에 경쟁하는 Pose 후보 2개 | `ambiguous_tracks`, 연결 안 함 |
| 연속 확인 마지막 관측에서 Pose ID 교체 | 새 ID로 확인 횟수를 다시 쌓는 `confirming_track`, 즉시 연결 안 함 |
| 마지막 촬영 시각보다 2초 이상 늦은 추적 결과 | `current_target_unavailable`, 연결 안 함 |
| 추적 결과 전달 전 카메라 OFF | `unknown_tracking_session`, 연결 안 함 |
| 새 근거로 사건 revision 변경 뒤 예전 질문 답변 도착 | 예전 답변 거절. 새 사건 ID를 만들지는 않음 |
| Cloud 응답을 기다리는 동안 새 Pose 사건 발생 | `incident_changed_during_scan`으로 기존 응답의 자동 연결 거절. 새 Pose 분석은 계속 진행하고 질문 요청 생성 |

Pose 선행 시험은 Pose 사건의 첫 분석을 가짜 응답으로 끝낸 후 주기적 확인을 실행했다.
따라서 해당 시험의 공급자 함수 호출 2회는 사건 분석 1회와 주기적 확인 1회다.
Cloud 선행 시험은 주기적 확인 1회 결과를 재사용했다. 두 경우 모두 실제 API 호출은 0회다.
이를 운영 비용 비교로 쓰지 않는다.

연결 이후 같은 추적 결과·Pose 후보·Manager 이벤트를 30회 반복 전달하고 스케줄러도 확인했다.
같은 사람의 추가 사건, 추가 공급자 호출, 추가 질문 요청은 생기지 않았다.
단, 처음부터 장면 질문과 사람 질문이 각각 있던 경우에는 **2개를 유지한 것**이며 1개로 줄인 것은 아니다.

Cloud 분석 중 새 Pose 사건이 생긴 경우에는 이전 영상만으로 새 사건을 덮어쓰지 않았다.
이미 대기 중인 새 Pose 분석을 처리해 질문까지 이어지는지도 확인했다.
이때의 추가 분석은 중복 입력 때문이 아니라 새 근거를 확인하기 위한 호출이다.

10개 시나리오 모두 DB를 닫았다 다시 열어 사건·발견 기록이 유지되는 것을 확인했다.
신규 순서 테스트 12개를 포함해 관련 회귀 시험 **314개 통과, 1개 모듈 건너뜀**.
GPU 전용 Python에 `rclpy`가 없어 Manager ROS 통합 모듈은 수집하지 못했다.
실제 DDS/Action 통과로 기록하지 않는다.

## 3. 남은 개선점

현재는 사람을 잘못 연결하지 않기 위해 장면 사건과 질문을 보존한다. 나중에 한 발견이 사람에게
연결돼도 장면 전체가 해결됐다고 보지는 않는다. 다른 발견이나 도움 요청이 있을 수 있기 때문이다.
하지만 이번 단일 발견 시험에서도 장면 질문과 사람 질문이 함께 남으므로 사용자에게 비슷한
질문을 반복할 가능성이 있다. 연결 성공과 질문 정리 완료를 같은 것으로 설명하면 안 된다.

다음 구현 후보는 **장면 확인에서 특정 사람 확인으로 넘어갈 때 질문을 이어받거나 정리하는 처리**다.
장면에 다른 미해결 발견이 남았는지, 질문이 아직 대기 중인지 이미 발화 중인지,
도움 요청이 들어왔는지 확인해야 한다. 장면의 ‘괜찮다’는 답을 특정 사람의 정상 근거로
옮기거나, 도움 요청을 자동으로 없애는 방식은 사용하지 않는다.
이번 요청은 추가 검증이므로 해당 운영 동작은 수정하지 않았다.

실제 Cloud 지연 이후까지 계속 이어지는 긴 영상은 없어 해당 검증은 여전히 미완료다.
