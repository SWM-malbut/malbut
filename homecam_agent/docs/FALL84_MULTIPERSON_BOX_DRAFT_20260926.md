# 다인 장면의 실제 Cloud 입력 프레임 추가 검수 초안

SWM25-186 / 2026-09-26

후속: 9월 27일 사용자의 검수 파일을 받아 [별도 승인 자료와 재대조 결과](FALL84_USER_BOX_REVIEW_RESULTS_20260927.md)를
작성했다. 아래 내용과 초안 파일은 당시 미승인 상태의 기록으로 보존한다.

다인 장면 4개에서 **기존 정답 박스가 없는 15프레임·34개 사람 박스**를 검수 초안으로
작성했다. 누운 대상자뿐 아니라 보호자·서 있는 사람도 함께 표시했다. 저장된 Gemma·Gemini
응답만 재사용했으며 새 API 호출·비용, 운영 코드 변경, 기존 정답 자료 변경은 없다.

**아직 사용자 승인 전이다. 아래 수치는 초안과 대조한 참고 결과이며 공식 평가 점수가 아니다.**
이 작업은 실제 YOLO 추적 ID 연결이나 사건 병합 시험도 아니다.

## 원본 프레임에서 작성한 내용

[앞선 위치 점검](FALL84_NATIVE_BOX_LOCALIZATION_AUDIT_20260926.md)에서 모델 출력과
정답 박스의 프레임이 달라 연속 대상 확인이 어려웠다. 우선 같은 장면에 다른 사람이 함께
보이는 SYN012·SYN045·SYN063·SYN067을 선택했다. 전체 84개를 무작위로 뽑은 표본이 아니다.

| 영상 | 새로 작성한 전송 이미지 번호 | 원본 프레임 | 사람 수 | 새 박스 수 |
|---|---|---|---:|---:|
| 414 / SYN012 | 0, 8, 11 | 3, 46, 62 | 2 | 6 |
| SYN045 | 0, 4, 8, 11 | 2, 46, 89, 122 | 2 | 8 |
| SYN063 | 0, 4, 7, 11 | 2, 46, 78, 122 | 2 | 8 |
| SYN067 | 0, 4, 7, 11 | 2, 46, 78, 122 | 3 | 12 |

- 두 모델에 보낸 JPEG 바이트와 해시가 같은지 확인했다. 전송 이미지 번호는 0부터 시작한다.
- 원본 JPEG 15장을 각각 열어 확인하고, 640×400 캔버스의 픽셀 좌표로 박스를 작성했다.
  좌표는 `(left, top, right, bottom)`이다. 720p 원본의 입력에는 위아래 20픽셀 여백이 있다.
- 이전에 승인된 사람 ID·역할·설명은 유지했다. 기존 정답이 있는 프레임은 새로 그리지 않았다.
- 모델이 반환한 박스를 정답으로 복사하거나 다른 프레임의 박스를 보간하지 않았다.
  몸이 거의 움직이지 않은 프레임도 각각 확인했으며, 그 결과 일부 좌표는 같다.
- 보이는 머리·손·발은 포함하고 가려진 몸의 크기는 추측하지 않았다. 사각형 특성상
  신체 사이의 가구·배경이나 겹친 다른 사람 일부가 박스 안에 포함될 수 있다.
- 이전 모델 출력과 기존 검수 프레임을 이미 본 상태에서 작성했다. **블라인드 검수가 아니다.**
  특히 SYN012·SYN063에서 두 사람의 손과 옷이 겹치는 경계는 사용자의 추가 확인이 필요하다.

## 저장 응답을 초안과 대조한 참고 결과

기존 동결 자료의 연결 기준을 유지했다. 사각형 겹침·중심점·서로 가장 잘 맞는 대상인지를
확인했고, 후보가 겹치거나 불분명하면 연결을 보류한다. 같은 프레임의 모든 모델 박스를
함께 대조하여 한 사람을 중복 할당하지 않는다. 미확인 사람이 있으면 연결 성공으로 세지 않는다.

| 영상 | Gemma: 새 초안과 대상이 대응한 박스 | Gemini: 새 초안과 대상이 대응한 박스 |
|---|---:|---:|
| SYN012 | 2 / 2 | 3 / 3 |
| SYN045 | JSON 오류로 대조 불가 | 4 / 4 |
| SYN063 | 2 / 2 | 4 / 4 |
| SYN067 | 2 / 2 | 4 / 4 |

이 표의 분모는 **새 초안 프레임에 모델이 실제 반환한 박스**다. 기존 승인 프레임의 박스는
이번 표에 더하지 않았다. 모델에 12장 전부의 박스를 요구한 것이 아니므로 나머지 프레임에
박스를 반환하지 않은 것을 검출 실패로 세지 않았다.

초안 기준으로 대조 가능한 Gemma 3개·Gemini 4개 응답은 각각 두 프레임 이상에서 누운
대상자와 대응했고, 이 표본에서 다른 사람으로 바뀐 대응은 나타나지 않았다. 그러나
**미승인 초안을 사용한 4개 선택 장면의 관찰이지, 전체 대상 연결 정확도나 연속 추적 성공률이 아니다.**

대상 대응과 몸 전체 포함은 다르다. SYN063의 Gemma 박스는 대상과 대응했지만 오른쪽
무늬 바지 쪽을 충분히 포함하지 않았다. 두 출력 프레임에서 대상 초안 사각형의 약
70.3~70.7%를 덮었다. 이는 신체 픽셀 비율이 아니라 **두 사각형의 면적 비율**이다.
SYN067에서는 누운 사람의 손이 왼쪽으로 뻗어 박스 범위가 변하는 것도 별도로 표시했다.

Gemma SYN045의 기존 중복 JSON 오류는 그대로 유지했다. 일부 JSON만 꺼내 박스를 그리거나
정상으로 바꾸지 않았고 다시 호출하지도 않았다.

## 사용자가 확인하는 방법

로컬 산출물:

`~/.local/share/malbut-evaluations/native-v4-multiperson-review-20260926/`

1. `review.html`을 브라우저에서 연다. 이미지를 포함한 단일 파일이라 별도 서버가 필요 없다.
2. 프레임·사람 버튼을 누르고 보이는 머리·손·발이 박스에 포함되는지 확인한다.
3. 필요하면 드래그하거나 숫자를 입력해 박스를 수정한다. **Alt 키 없이 사용 가능하다.**
4. 사람을 구분하기 어렵다면 `사람 구분 어려움`, 실제로 안 보이면 `보이지 않음`을 선택한다.
   이 경우 박스를 비우며 추정 좌표로 채우지 않는다.
5. 각 프레임에서 `이 프레임 확인했음`을 누르고 `수정 JSON 내려받기`로 저장한다.
   좌표나 관측 여부를 다시 바꾸면 해당 프레임의 확인 표시를 해제한다.
6. 내려받은 파일을 전달받아 원본 연결·검수 여부를 확인한 후, 명시적인 사용자 승인에 따라
   별도 정답 자료로 반영한다. 화면에서 확인 표시를 눌렀다는 이유로 자동 승인하지 않는다.

탭을 닫기 전에 JSON을 내려받아야 한다. 브라우저 내부 저장이나 서버 업로드는 하지 않으며,
저장한 JSON을 다시 불러올 수 있다. 기존 정답 자료와 평가 점수는 바뀌지 않는다.

주요 파일:

- `packet.json`, `source_hashes.json`: 선택 범위와 원본 해시, 기존 승인 프레임 참고 자료.
- `assistant-coordinates.json`, `manual.json`, `draft.json`: 직접 작성한 좌표와 프레임 연결.
- `frames/`, `source_sheets/`, `draft_sheets/`: 원본 JPEG·좌표 격자·초안 박스 모음.
- `draft-probe.json`: 미승인 초안과 모델 응답의 탐색적 대조. 공식 점수와 구분하는 플래그 포함.
- `review.html`, `review-completed.json`: 편집 가능한 검수 화면과 산출물 해시.
- `browser-smoke-r2/`: 실제 Chromium에서 확인한 결과와 화면. 이 폴더의 다운로드 JSON은
  **자동 테스트용이며 사람이 검수한 파일이 아니다.**

## 구현과 확인 범위

추가한 코드는 `review_cloud_box_frames.py`, `cloud_box_review.html`,
`test_cloud_box_review.py`다. 준비·초안 연결·결과 생성 순서로 실행한다.

```bash
python homecam_agent/scripts/review_cloud_box_frames.py prepare \
  --audit /path/to/native-v4-localization-audit \
  --spatial /path/to/spatial-final --output /path/to/new-review \
  --cases SYN012 SYN045 SYN063 SYN067
python homecam_agent/scripts/review_cloud_box_frames.py seed \
  --coordinates /path/to/independently-reviewed-coordinates.json --folder /path/to/new-review
python homecam_agent/scripts/review_cloud_box_frames.py compile \
  --manual /path/to/new-review/manual.json --folder /path/to/new-review
```

새 파일만 생성하며 기존 결과는 덮어쓰지 않는다. 잘못된 좌표, 원본 해시·프레임·사람 ID 변경,
초안의 임의 승인, 겹친 예측의 중복 할당, 오류 응답을 억지로 사용하는 경우를 검사한다.
기존 유료 평가·좌표 변환·위치 검사·Cloud 어댑터 테스트와 합쳐 **236개 통과**했다.
`test-results.xml`에 최종 실행 결과를 남겼다.

Chromium에서 프레임 이동, 사람 선택, 좌표 수정, 잘못된 값 거절, 드래그, 관측 불가 처리,
확인 표시 해제, 실제 JSON 다운로드·불러오기 등 13개 확인을 통과했다. 페이지의 외부 HTTP
요청과 JavaScript 예외는 없었다. 첫 브라우저 시험은 기능 확인 후 임시 프로필 정리에서
오류가 나서, 브라우저 종료 절차를 수정하고 새 출력 폴더에서 다시 실행해 정상 종료했다.

다음은 **사용자 박스 검수 → 별도 승인 자료 반영 → 실제 Pose 대상 연결·사건 병합 시험**이다.
이 초안 대조만으로 모델을 교체하거나 기존 84개 점수를 바꾸지 않는다.
