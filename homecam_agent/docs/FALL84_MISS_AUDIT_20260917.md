# YOLO-Pose가 놓친 20개: 원인 대조와 개선 순서

2026-09-17. 새 모델 추론이나 기준 변경 없이 기존 실제 Pose 출력과 원본 RGB를 대조했다.
**결론: 모델이 사람을 못 찾는 문제와, 관절을 찾고도 확인 요청을 만들지 않는 문제가 섞여 있다.**
모델 크기나 신뢰도 하나만 바꿔 해결할 수 있다고 보기는 어렵다.

## 범위와 현재 점수

- 합성 개발 영상 84개: 낙상 25, 낙상 의심 25, 정상 34.
- 현재 후보: 낙상 15, 의심 15, 정상 10. 총 40개. 확인 대상 50개 중 20개 미호출.
- 현재 기준은 V034의 관절 불일치 보조 요청까지 포함한 실험 경로다. 운영 적용 상태와 다르다.
- 전체 84개의 실제 Pose 2,224표본에서 baseline 판단 결과를 재생해 동일함을 확인했다.
- 놓친 20개는 모든 평가 표본 **528프레임**의 RGB·예측 박스·관절을 검토했다.
- 모든 원본 프레임을 연속 재생한 검토나 사용자 재승인은 아니다. 중간 프레임을 보간하지 않았다.
- 기존 라벨·박스·시간 경계·모델·기준·후보·VLM 응답은 바꾸지 않았다. 감지율 개선 실험도 아니다.

## 1. 우선 확인할 부분별 분류

아래는 RGB와 로그를 함께 본 **개발 우선순위 분류**다. 한 영상에도 가림·부분 검출·추적·
조건 탈락이 겹친다. 숫자를 각 원인의 독립적인 영향 비율로 해석하지 않는다.

| 먼저 살펴볼 부분 | 영상 수 | 영상 |
|---|---:|---|
| 쓰러진 대상의 Pose 검출이 끊김 | 3 | 404, 431, 442 |
| 몸 일부만 잡히거나 필요한 관절이 부족함 | 5 | 413, 422, V031, V033, V037 |
| 낮은 자세가 잠깐 잡혀도 연결·누적되지 않음 | 4 | 411, V022, V040, V045 |
| 관절은 있어도 현재 자세 조건에 맞지 않음 | 8 | 207, 441, V001, V002, V009, V010, V011, V044 |

### 검출 성공을 과대평가하기 쉬운 사례

- **442:** f43부터 쓰러진 대상이 검출되지 않는다. f60의 유효 Pose는 오른쪽 배경에
  붙었다. 따라서 `any usable pose = 1`을 대상 검출 성공이라고 읽으면 안 된다.
- **413:** 침대 위의 약한 큰 박스에 관절이 생기지만 침구도 포함한다. 이런 출력까지
  짧은 관측만으로 확인 요청하게 하면 배경 오탐이 늘 수 있다.
- **V031·V037:** 대상의 상체·얼굴 일부가 높은 점수로 검출되어도 전신 자세는 부족하다.
  `usable`은 현재의 수치 조건을 통과했다는 뜻이지, 관절 위치가 정확하다는 판정이 아니다.

낮은 자세가 나온 프레임 수다. 사람 수·정답 대상 재현율이 아니며 배경과 중복 예측도 포함한다.

## 3. 코드에서 확인한 공통 제한

### 넘어지는 변화도 사실상 수평 자세에 의존한다

이번 RGB 평가에서 로봇 이동 상태는 모두 `unknown`이다. 따라서 `_transition()`의
영상 아래쪽 이동량 기반 `descent` 분기는 꺼져 있다. 남은 `collapsed`와 `shape_change`는
모두 `horizontal`이 참이어야 한다. 즉, 몸이 낮아져도 상체가 세워져 있거나 잘못 추정되면
빠른 자세 변화 경로와 지속 low 경로를 함께 놓칠 수 있다.

그렇다고 합성 영상이 고정 시점처럼 보인다는 이유로 이동 상태를 `stationary`로 바꾸면 안 된다.
실제 odometry 또는 검증된 영상 기반 카메라 움직임 정보가 필요하다.

### 실제 관측은 있어도 누적되지 않을 수 있다

- baseline low는 3표본 이상·0.6초 이상, 자세 변화는 2회 연속 조건이다.
- 실제 미검출·관절 부족·다른 자세에서는 누적을 끊는다.
- pose-loss는 사라지기 전의 낮은 자세를 3표본·0.4초 이상 요구한다.
- V045처럼 매번 한 표본씩만 잡히거나 V022처럼 유효 관측이 미할당이면 이 경로도 시작 못 한다.
- ID를 억지로 붙이거나 관측하지 않은 시간까지 낮은 자세로 더해서는 안 된다.

### Depth도 현재 연결 방식만으로는 독립적인 보완 경로가 아니다

`extract_pose_features()`의 `near_floor`는 usable Pose를 전제로 한다. `_floor_height()`도
측정된 몸통 깊이와 품질을 요구한다. 센서를 켜는 것만으로 431 같은 Pose 미검출을
복구하는 구조가 아니다. Pose 없이도 확인을 시작할 경로가 필요하다면 별도 설계·검증해야 한다.

## 4. 다음 개선 비교 순서

아직 아래 개선을 구현하거나 점수를 측정한 것은 아니다.

1. **수평 자세가 아니어도 큰 자세 변화가 확인되면 확인 요청할 수 있는지 비교.**
   몸 크기·골반/어깨 위치·다리 굽힘 등의 시간 변화를 조합하는 별도 실험으로 둔다.
   정상 앉기·무릎 꿇기·물건 줍기 요청이 얼마나 늘어나는지 반드시 함께 비교한다.
   화면 이동만으로 낙상을 확정하거나 `unknown` 이동 상태를 가정으로 채우지 않는다.
2. **관측 누락과 부분/전체 박스 연결을 분리해서 비교.**
   V045의 짧고 반복되는 실제 low 관측, V022의 부분/전체 중복 관측을 구분해 실험한다.
   관측하지 못한 시간을 더하지 않고, 약한 근거는 ‘확인 필요’로만 전달한다.
   예전에 실패한 단순 missing 보존을 그대로 재적용하는 것은 개선이 아니다.
3. **가려진 사람·부분 신체에 대한 다른 입력 처리나 Pose 모델을 비교.**
   같은 모델의 단순 입력 확대와 기존 ROI 재검출은 이미 실패한 비교가 있다.
   재실행한다면 이전과 다른 가설과 조건을 먼저 기록한다. GT 박스로 잘라 성능을 올리지 않는다.
   실제 Jetson 지연과 메모리를 측정하기 전에는 큰 모델을 운영에 채택하지 않는다.
4. **RGB로 복구되지 않는 경우는 실제 보조 센서로 별도 검증.**
   RGB+정렬된 Depth+로봇 이동을 먼저 기록하고, 음성·질문 응답도 실제 입력과 연결한다.
   정상 앉기·안전한 눕기·이미 누워 있음·주행·생활 소음으로 센서 동작과 오탐부터 확인할 수 있다.
   이것을 실제 낙상 감지율 검증으로 부르지는 않는다. 합성 RGB에서 생성한 Depth·효과음은
   흐름 시험에는 쓸 수 있어도 센서 미탐 개선을 입증하는 독립 증거가 아니다.

모든 개선 비교는 기존 84개 전체와 같은 라벨·표본을 사용하고, 기존 40개 요청의 손실 여부,
추가 요청의 실제 대상, 정상 34개의 불필요한 요청, 감지 지연·연산량을 함께 남긴다.
이미 본 개발 영상에 맞춘 결과이므로 일반화는 새 영상·실물 기록으로 별도 확인한다.
사용자가 정한 세 주요 평가 지표는 그대로 유지하며 위 항목은 원인 분석용 보조 자료다.
