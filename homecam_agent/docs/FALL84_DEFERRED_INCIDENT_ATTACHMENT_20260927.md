# Cloud 발견의 후속 Pose 사건 연결 — 2026-09-27

## 바뀐 것

미연결 이유를 분류하는 데서 끝내지 않고, 연속 영상 추적과 Pose가 일치하면 Cloud의 개별 발견을 실제 기존 사람 사건에 붙이는 코드를 추가했다. 원래 장면 확인 사건은 사람 사건과 구분해서 유지한다. 장면에 여러 사람이 있을 수 있으므로 질문·답변·도움 요청을 통째로 옮기거나 정상 종료하지 않는다.

구현 계약: `malbut_agent_server/docs/fall/fall_deferred_association.md`.

## 시험 방법

이전에 저장한 Gemma 응답·SAM 마스크·Pose 관측을 다시 사용했다. 새 모델 추론/API 호출은 0회다. 원본 입력·결과·영상/마스크 해시를 확인하고, 새 연결 코드의 해시는 별도로 기록했다. 옛 실행 계획의 코드 해시를 고쳐서 재사용하지 않았다.

Cloud는 원래 12장 전체를 보고 답한 결과다. 따라서 그 응답을 첫 시드 시각에 알았다고 가정하지 않았다. 영상 끝까지의 Pose를 입력한 뒤 저장된 Cloud 응답을 넣고, 그 후 과거 추적 결과를 순서대로 재생했다. 최종 최신 관측에서도 Pose가 확인되는 경우에만 붙였다.

영상 추적에는 기존 중립 4Hz 일정의 프레임을 사용했고, Cloud에는 원래 평가의 12장을 그대로 사용했다. 두 일정이 모두 일치하지 않으므로 직접 박스 비교에서는 정확히 같은 시각에 Pose가 있는 경우만 사용했다. 근처 시각의 Pose로 빈칸을 채우지 않았다. 이는 과거 7건 평가와 다른 입력·조건이며, 1/7에서 아래 수치로 개선됐다고 비교할 수 없다.

## 결과

| 구분 | 영상 수 | 기존 Pose 사건에 실제 연결 | 보류/미발견 |
| --- | ---: | ---: | --- |
| 움직임·부분 가림·카메라 움직임 | 6 | 5 | 1 |
| 여러 사람이 나오는 대조 장면 | 2 | 0 | 2 |

연결된 영상은 SYN059, SYN075, SYN078, SYN083, SYN084다. 5건 모두 새로운 사람 사건으로 분리하지 않고 이미 만들어진 Pose 사건 ID에 `cloud_crosscheck` 근거를 붙였다. 완료된 영상이 포함하는 대기 첫 분석은 재사용하여 불필요한 추가 호출을 예약하지 않았다.

SYN050과 SYN063은 마지막 시점에서 일치하는 Pose 대상을 확인하지 못했다. SYN067은 중간에 대응되는 관측이 있었지만 마지막 시점의 Pose를 연결 근거로 사용할 수 없어 보류했다. 여러 사람이 나오는 두 장면의 연결 문제는 해결되지 않았다.

연결 5건의 확정 프레임(f120)은 기존에 검토한 정확한 프레임과 대조했다. 5건 모두 그 프레임에서 올바른 사람과 일치했고, 다른 사람에게 연결한 사례는 없었다. 이 검토는 5개 시점에 대한 결과이며 영상 전 구간의 신원 유지 정확도나 별도 검증 데이터 성능을 뜻하지 않는다. 검토 정보는 모든 사건 연결을 끝낸 뒤 대조했으며 연결 코드의 입력으로 쓰지 않았다.

9개 모두 SQLite를 닫았다 다시 열어 이력 유지 여부를 확인했다. 연결된 세션의 반복 입력은 사건·질문·재확인 횟수를 바꾸지 않았다. RGB·음성·모델의 자유 서술은 연결 이력에 저장하지 않는다.

## 검증과 한계

- 신규 후속 연결 테스트: 30개. 기존 사건 연결/새 사건 생성, 중복 입력, 질문·도움 보존, 잘못된 장면 답변, 약한/경쟁 Pose, 추적 단절, 토큰 재사용, 오래된 관측, 설정 변경, 종료된 사건, 저장 실패 롤백, DB 재개방, Manager 질문 전달을 포함한다.
- 소스와 `malbut_test` 미러의 낙상 관련 회귀 테스트 각각 405개 통과, 16개 제외. 위 신규 30개도 이 수에 포함된다. 제외된 것은 opt-in 실제 ROS PC 시험 11개와 현재 Python에서 ROS 모듈을 불러오지 못한 5개다. 결과는 `verified-fall-regression.xml`, `verified-mirror-regression.xml`에 보관했다.
- 기존 오프라인 평가/추적/유료 모델 파서 관련 테스트 447개 통과.
- 전체 Manager 테스트를 한 번 시도했으나 이 Python 환경에서 `action_msgs`, `nav2_msgs`, `ament_*` 등의 ROS 의존성이 없어 수집 단계에서 실패했다. 관련 낙상 테스트로 범위를 명시해 다시 검증했으며, 전체 저장소 테스트 통과라고 주장하지 않는다.
- 실시간 카메라·ROS·Cloud 지연·SAM 처리 시간·실제 질문/알림 전달은 이번 재생 시험에 포함하지 않았다. 실제 추적 어댑터를 운영 경로에 켜지 않았다.
- 기존 CPU SAM 처리 시간은 약 34~47초/15~20프레임으로, 이를 그대로 켜면 입력/추적 결과가 오래돼 연결을 거절할 수 있다. 캐시 재생 결과를 실시간 성능으로 해석하면 안 된다.
- 장면 확인 사건의 자동 정리나 질문 취소는 추가 설계 대상이다. 현재는 잘못된 사람에게 답변을 옮기지 않도록 원래 이력을 유지한다.
