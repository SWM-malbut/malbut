# 번호로 대상 지정 / Cloud 박스로 시작한 영상 추적 시험

2026-09-27 / SWM25-186 후속 개발 시험

## 결과 요약

**후보 번호를 주면 Gemma가 4개 장면 중 3개에서 확인할 사람을 골랐다. 다만 번호를
이미지에 그린 조건과 좌표표만 준 조건의 결과는 같았다.** 나머지 SYN063에서는
누운 사람의 유효한 Pose 대상이 없어 두 조건 모두 연결을 보류했다. 돕는 사람에게
대신 연결하지 않았다.

Cloud 박스 하나로 시작한 SAM 2.1은 검수한 표본 프레임에서 누운 대상에 대응했다.
하지만 사람이 거의 움직이지 않아 **시작 박스를 그대로 반복한 진단용 대조군도 같은
점수**였다. 이번 결과로 움직임·가림을 견디는 추적 성능이 좋아졌다고 결론 내리지 않는다.

**사건 병합은 아직 개선됐다고 계산하지 않는다.** 이번 시험은 대상 번호 선택과
영상 추적을 분리해 확인했다. 운영 연결 조건을 바꾸거나 새로운 ID로 사건을 합치지 않았다.

## 시험 조건

- 기존 다인 장면 SYN012(414), SYN045, SYN063, SYN067. 문제를 살펴보려고 고른
  개발 자료이며 무작위 표본·독립 검증 자료가 아니다.
- 앞서 실제 Cloud에 보냈던 원본 JPEG 12장, 프레임 번호·시각·해시를 그대로 사용.
  이전 YOLO26s-Pose의 실제 관측·추적 결과도 그대로 사용했다.
- 번호 선택에는 기존 후보 ID를 `T1`, `T2` 등으로 바꿔 전달. 같은 실제 추적 ID에는
  같은 표시를 사용하고, 관측이 없는 프레임에 이전 박스를 복사하지 않았다.
- 정상 여부나 검수한 사람 ID·정답 박스는 요청에 넣지 않았다. 검수 자료는 모든
  추론이 끝난 뒤 별도 `score` 명령으로 읽었다.
- 정상 여부는 Gemma가 직접 판단하고, 의심되는 사람을 후보에 연결할 수 없으면
  JSON `null`을 허용했다. 없는 ID나 그 프레임에 나타나지 않은 ID를 답하면 검사 실패.
- 번호 선택은 실제 Gemma4 31B Cloud 호출 8회. 4개 × 2조건을 장면별로 번갈아 실행.
  동일 프롬프트·좌표표를 사용하고 시각적 표시 유무만 비교했다. 표시 영상은 JPEG 재인코딩도
  거치므로 엄밀하게는 표시와 재인코딩이 함께 바뀐 조건이다.
- 요청당 20초 제한, 자동 재시도 없음, 요청 수 8회·예상 비용 한도 $0.10.
  시간 초과·형식 오류는 발생하지 않았다.
- SAM은 공식 SAM 2.1 Hiera Tiny 체크포인트, CPU/float32/4스레드.
  새 API 호출 없이 Gemma·Gemini의 기존 응답 중 사용할 수 있는 7개를 시작점으로 사용.
  기존 Gemma SYN045의 JSON 오류는 고치거나 일부를 꺼내 쓰지 않고 제외했다.
- 각 발견이 반환한 가장 이른 박스 하나만 SAM에 제공. 이후 Cloud 박스·정답·Pose 박스로
  수정하지 않고 12장 입력을 순방향으로 추적했다. 7개 모두 시작점은 입력 0번이었다.
  이 방식은 과거 영상 구간에 대한 오프라인 추적이며 실제 Cloud 응답 지연까지 재현하지 않는다.

## 1. 후보 번호를 선택하게 한 결과

| 장면 | 원본 영상 + 후보 번호·좌표표 | 번호 표시 영상 + 같은 표 | 현재 Pose 쪽의 제한 |
|---|---|---|---|
| SYN012 | 대상 T2 선택 | 대상 T2 선택 | 초기에 약한 추적; 검수 프레임 4개 중 연결용 관측은 3개 |
| SYN045 | 대상 T2 선택 | 대상 T2 선택 | 검수 프레임 5개 모두 연결용 관측 있음 |
| SYN063 | 연결 보류(null) | 연결 보류(null) | 검수 프레임 5개 모두 누운 사람의 대응 후보 없음 |
| SYN067 | 대상 T3 선택 | 대상 T3 선택 | 검수 프레임 5개 중 대상 후보 4개, 연결용 관측은 2개 |

| 항목 | 원본 + 좌표표 | 번호 표시 + 좌표표 |
|---|---:|---:|
| 검수 프레임에서 대상에 대응하는 ID 선택 | 3/4 | 3/4 |
| 다른 사람의 ID 선택 | 0 | 0 |
| 연결 보류 | 1 | 1 |
| 응답 형식 오류 | 0 | 0 |
| 응답 시간 중앙값 | 2.91초 | 2.97초 |

선택한 ID가 나타나는 **모든 검수 프레임**을 확인했다. 모델이 근거로 골라준 프레임만
채점하지 않았다. 검수하지 않은 중간 프레임까지 ID가 정확했다고 간주하지 않는다.

SYN063에서 Gemma는 누운 사람과 돕는 사람을 구분했다. 좌표표 조건에서는 후보 T1의 박스가
두 사람 일부를 포함해 누운 사람의 ID로 쓰기 어렵다고 설명했고, 표시 조건에서도 T1을
돕는 사람으로 설명하며 `null`을 반환했다.

이는 **VLM이 기존 후보 번호를 선택할 수 있는지**의 결과다. 앞선 Cloud bbox → Pose →
사건 병합 1/7과는 모델·출력 형식·채점 단계·분모가 다르므로 1/7 → 3/4 개선이라고 쓰면 안 된다.
약한 추적, 연결 구간 단절, 사건의 시간·상태 확인을 통과한 결과도 아니다.

## 2. Cloud 박스 하나로 시작한 SAM 추적

SAM 출력 마스크의 바깥 박스를 검수한 사람 박스와 대조했다. 기존 고정 기준인
대상 박스 포함 비율 0.50, 출력 박스 포함 비율 0.25, 중심 포함, 매칭 차이 0.10을 사용했다.
이 기준은 신체 전체를 정확히 분할했다는 뜻이 아니다. 마스크 정답은 없어 분할 정확도는 미측정이다.

| 장면 | Gemma 박스로 시작: 대상 대응 | Gemini 박스로 시작: 대상 대응 | 이후 유효한 Pose 관측과 겹친 프레임 |
|---|---:|---:|---:|
| SYN012 | 4/4 | 4/4 | 각각 10/12, 같은 Pose ID |
| SYN045 | 기존 응답 오류로 미실행 | 5/5 | 12/12, 같은 Pose ID |
| SYN063 | 5/5 | 5/5 | 각각 0/12 |
| SYN067 | 5/5 | 5/5 | 각각 6/12, 같은 Pose ID |

분모는 **해당 12장 중 정확히 검수 박스가 있는 프레임 수**다. 네 장면의 고유 검수 시점은
19개이며, 두 모델의 시작 박스가 같은 시점을 반복 사용했다. 총 33개 대조를 33개 독립 장면으로
계산하지 않는다. 시작 프레임을 뺀 26개 대조도 모두 대상에 대응했지만, 고정 박스 대조군도 26/26이었다.

마지막 열은 기존 IoU 0.60·다른 후보와의 차이 0.15·`associationUsable` 조건을 유지한
**프레임별 기하 비교**다. 시간 연결 토큰이나 사건 병합 조건을 통과했다는 뜻이 아니다.
표의 같은 Pose ID는 비교에 성공한 프레임들에서 같았다는 의미이며, 중간 공백의 신원을 보장하지 않는다.

특히 SYN063에서는 Pose가 못 찾은 누운 대상의 영역을 SAM이 유지했다. 다만 비교할 유효한
Pose 대상이 계속 없어 두 경로의 ID를 합치지는 못했다. Gemma 시작 박스에서는 몸 일부가
덜 포함되는 차이도 남았다. 검수 기준 통과를 완벽한 신체 박스로 해석하지 않는다.

### 처리 시간과 제한

- 12장 처리에 25.93~26.20초. 입력 로드·크기 변환·SAM 추론·마스크 저장 포함,
  모델 로드·Cloud 응답 대기·Pose 처리는 제외한 PC CPU 시간이다.
- GPU·Jetson 시간이나 실시간 처리율을 측정하지 않았다. 현재 측정 조건 그대로는
  로봇의 5fps 처리 경로에 넣을 근거가 없다.
- 첫 실행에서는 공식 빌더가 요청한 `fill_hole_area=0`을 기본값 8로 덮어썼지만,
  CUDA 확장이 없어 해당 구멍 채우기는 공식 오류 처리 경로에서 생략됐다.
  원래 기록은 유지하고 `execution-notes.json`에 실제 동작을 명시했다.
  후속 코드에서는 이 선택적 후처리만 명시적으로 끄고 나머지 기본 옵션은 유지하도록 수정했다.
  SYN063의 Gemma 시작 박스로 재실행해 12장 마스크가 최초 실행과 모두 완전히 같은 것을 확인했다.
- YesTrack의 학습된 동일 대상 검증기는 이번에 실행하지 않았다. 이번 시험을 YesTrack 재현으로 부르지 않는다.

## 다음 시험

1. 사람이 실제로 움직이고 서로 가리거나 교차하는 별도 영상에서 추적 ID가 바뀌는지 확인.
   같은 개발 영상만 반복해서 통과하는지 보는 것으로 채택하지 않는다.
2. Cloud에서 만든 영상 추적과 이후 Pose 관측을 **언제 같은 공통 대상 ID로 확정할지** 검증.
   애매한 경우 연결 보류를 유지하고, 다른 사람과 잘못 합쳐지는 수를 별도로 센다.
3. 그 다음 공통 대상 ID와 사건 시간·진행 상태를 함께 확인해 실제 병합까지 재현.
   기존에 받은 정상 답변이나 다른 사람의 답변으로 미확인 사건을 닫지 않는지도 확인.
4. 채택 후보가 되면 GPU/Jetson 처리 시간과 실제 Cloud 응답 지연을 포함한 경로를 시험.

연구 참고: [SoM](https://arxiv.org/abs/2310.11441)의 시각적 표식을 후보 ID 선택에 응용했다.
원 논문의 평가를 재현한 것은 아니다. [SAM 2 공식 코드](https://github.com/facebookresearch/sam2)는
박스를 입력한 영상 추적에 사용했고, 실행한 커밋·체크포인트 해시는 결과에 남겼다.
