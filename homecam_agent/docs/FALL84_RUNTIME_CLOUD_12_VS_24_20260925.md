## 비교 조건

- 낙상 25 / 낙상 의심 25 / 정상 34, 총 84개. 라벨과 판단 이유는 그대로 유지.

- 매 호출 전 Free 계정 확인. 인증·결제·한도 오류 없음.
- 영상 전체를 보는 VLM 단독 평가. YOLO-Pose·박스·정답·소리·센서·Agent 답변은 전달하지 않음.
- 640×400, 원본 비율 유지, JPEG, 시간순 입력. 처음과 끝을 포함해 균등 추출.
- 실제 영상 길이는 약 5.1초. 12장에 12장을 붙인 것이 아니라 24장으로 다시 균등 추출.
- 기존과 같은 프롬프트·출력 형식·temperature=0·num_predict=512·thinking=false·응답 제한 20초.
- 현재 운영 어댑터는 이후 변경됐으므로 당시 저장한 코드로 평가용 작업 공간을 따로 구성.
- 기존 요청의 최대 구간 10초와 앞부분 부족 표시도 그대로 유지. 실제 없는 영상을 복제하지 않음.
  이번 결과는 약 5초 영상의 12장/24장 비교이지, 실제 10초 영상이나 로봇의 5 Hz 버퍼 검증이 아님.

### 433

- 12장: 중심을 잃고 요 위로 빠르게 쓰러진다고 설명하며 낙상으로 판단.
- 24장: 스스로 요 위에 눕는 통제된 행동이라고 설명하며 정상으로 판단.
- 사용자 정답은 낙상 의심. 정답에서 오답으로 바뀐 사례는 아니지만,
  낙상 가능성을 남기던 판단이 정상으로 바뀐 점을 따로 기록함.

### 441

- 12장: 소파에서 미끄러져 내려오는 동작을 제어되지 않은 하강으로 설명하며 낙상으로 판단.
- 24장: 바닥에 기대어 누워 있는 모습이 우려된다고 설명하며 낙상 의심으로 판단.
- 최종 분류는 정답이지만, 24장 답변은 내려오는 과정을 보지 못했다고 설명함.
  따라서 정답 1개 증가를 동작을 더 정확히 이해했다는 증거로 단정하지 않음.

## 해석

24장은 기술적으로 사용할 수 있었다. 이번 결과만으로 24장이 불가능하거나 항상 나쁘다고 볼 수는 없다.
다만 정답 1개 증가와 함께 의심 영상을 정상으로 넘긴 사례가 생겼으며 입력량과 측정 응답 시간이 늘었다.
현재 운영 설정은 12장 그대로 유지했고, 자동으로 24장으로 바꾸지 않았다.

두 실험은 실행 날짜가 다르다. 공개된 모델 메타데이터가 일치하는 것은 확인했지만
Cloud 내부 모델 버전·서버 부하·응답 변동까지 같다고 보장할 수 없다.
같은 날 번갈아 여러 번 비교하지 않았으므로 차이가 모두 이미지 장수 때문이라고 단정하지 않는다.

응답 시간은 SSH 왕복을 포함한 요청 시간이며, 낙상 발생부터 감지·질문·알림까지의 지연이 아니다.
이미 검토와 개선에 사용한 합성 개발 영상 결과로, 실생활 성능이나 통계적인 우월성을 입증하지 않는다.
