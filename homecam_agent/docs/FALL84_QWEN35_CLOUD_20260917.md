# Qwen3.5 · Gemma Cloud 비교 결과

2026-09-17 완료. Qwen3.5 4B·9B와 Gemma4 31B Cloud에 각각 124회,
총 **372회 새로 호출**했다. 모두 응답을 받았으며 재시도하지 않았다.
Gemma4 12B와 Qwen2.5-VL 7B는 같은 입력으로 완료했던 결과를 재사용했다.

## 공통 데이터와 방법

- 합성 영상84개: 낙상25 / 낙상 의심25 / 정상34. 의심 영상도 정확도에 포함한다.
- YOLO-Pose 후보: 낙상15/25(60%), 의심15/25(60%), 정상10/34(29.4%).
- VLM 단독은84개 모두 호출, YOLO 후 VLM은 후보40개에 별도로 호출했다.
- 기존39개 후보에 V034 f077을 더한 조건이다. YOLO를 다시 돌리거나 후보/라벨을 바꾸지 않았다.
- 원래 Gemma A의 RGB JPEG12장·시각·영상 구간·프롬프트·채점 기준을 유지했다.
  후보 후 입력은 후보가 나온 시점까지의 영상이며 미래 장면을 추가하지 않았다.
- 정답·판단 이유·영상 ID·YOLO 결과·depth·음성은 모델에 전달하지 않았다.
- temperature=0, seed=0, num_ctx=16384, num_predict=1200, thinking 비활성,
  요청 제한300초. Qwen 두 모델은 Mac의 로컬 GGUF Q4_K_M으로 순차 추론했다.
- Cloud는 이전에 확인한 유료 크레딧/자동 충전 없음 조건하에서 호출 전마다 Free 계정을
  확인했다. 충전/구독/결제 설정을 변경하지 않았고 한도·인증 오류도 발생하지 않았다.

## 먼저 구분해야 하는 출력 형식 문제

Gemma Cloud는 **124개 응답 모두 JSON을 Markdown 코드 블록으로 감쌌다.**
따라서 원래의 엄격한 검증기로는 유효 응답0/124, 정확도는 단독0/84·후보 후0/40이다.
이것은 124개 영상 판단이 모두 틀렸다는 뜻이 아니라 현재 연동 형식을 지키지 못했다는 뜻이다.

아래 표는 이를 구분하기 위해 **모든 모델에 동일하게 바깥 코드 블록만 제거한 뒤**
같은 스키마로 재검증한 사후 보조 결과다. 라벨이나 설명 내용은 수정하지 않았고,
영상도 분모에서 빼지 않았다. 로컬 네 모델은 보정 전후 점수가 같다.
원래 응답과 엄격한 채점 결과는 그대로 보존했다.

Cloud 요청에서는 지원되지 않는 `format`과 로컬 상주 설정 `keep_alive`를 생략했다.
원래 JSON 스키마 전문은 프롬프트에 그대로 남겼다.

## 결과 해석

- **Gemma Cloud:** 형식을 정리했을 때 이번 데이터의 판단 성능이 가장 높았다.
  단독에서 낙상25개 중24개, 의심25개 중24개를 확인 대상으로 남겼다.
  다만 의심6개를 확실한 낙상으로 단정했다. 운영에 연결하려면 출력 형식 처리를 먼저 정리해야 한다.
- **Qwen3.5 4B:** 단독에서 낙상25개 중24개는 낙상으로 맞혔다.
  의심25개는 의심3 / 낙상10 / 정상12로 나뉘었다. 정상 영상도6개를 낙상으로 오탐했다.
- **Qwen3.5 9B:** 단독에서 낙상7개와 의심16개를 정상으로 놓쳤다.
  후보 후에도 명확한 낙상15개 중6개를 정상으로 놓쳤다. 이번 조건에서는 4B보다
  크다고 해서 미탐이 줄지 않았으며, Qwen2.5-VL을 대체할 근거도 부족하다.
- **후보 단계 문제는 그대로다.** 낙상·의심50개 중20개에는 후보가 없으므로 Cloud를
  연결해도 그20개를 확인하지 못한다. 단독48/50과 후보 후28/50의 차이를 함께 봐야 한다.

Cloud가 정상으로 놓친 영상은423(낙상),433(의심)이다. 두 방식 모두에서
의도적으로 요/방석에 눕는 동작으로 해석했다. 정상 V020·V021은 오탐했다.
이 결과로 정답 라벨이나 프롬프트를 바꾸지 않았다.

## 검증과 제한

- 새 요청372개의 원래 A 입력 재구성·JPEG/시각/구간 해시·실제 요청 해시를 확인했다.
- 원응답을 같은 검증기로 다시 읽어 저장된 결과·점수와 일치함을 확인했다.
- 입력/원응답/결과/코드 스냅샷/완료 마커를 보존했다. 관련 테스트419개 통과,
  `git diff --check`와 flake8의 E9/F63/F7/F82 검사도 통과했다.
- Cloud에는 모델별 토큰화·하드웨어·양자화 차이와 서버 설정 적용 불확실성이 있다.
  동일한 영상/프롬프트 비교이지, 파라미터 수만 바꾼 완전한 통제 실험은 아니다.
- 로컬 추론은 순차였지만 `keep_alive=10m`으로 4B/9B 가중치 상주가 잠시 겹쳤다.
  Cloud와4B 큐의 네트워크/영상 추출 작업도 일부 겹쳤다. 메모리·네트워크까지 완전히
  분리한 지연 실험이 아니며, 표시한 시간은 **실제 로봇의 낙상 감지 지연이 아니다.**
- Cloud 설정에 대조군의 `wire_schema_sha256` 참고값이 남아 있다. 실제 Cloud 요청에는
  `format`이 없음을 검증했다. 완료된 기록은 수정하지 않고 별도 감사 메모를 남겼다.
- 이미 라벨링·검토·개선에 사용한 합성 개발 데이터다. 실제 가정/Jetson/임상 성능은 미검증이다.
- 운영 코드·DB·로봇은 변경하지 않았다. 커밋/배포하지 않았다.
  평가를 위해 켠 임시 절전 방지는 해제했고, 새로 받은 모델은 맥에 남겨뒀다.
