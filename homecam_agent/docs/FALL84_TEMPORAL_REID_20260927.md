# 프레임 간 Pose 추적에 ReID를 추가한 결과

2026-09-27 / SWM25-186

**연결하지 못한 검출은 일부 줄었지만, 최종 사건 연결은 늘지 않았다.** 새 추적 ID가
더 많이 생겼고 일부 정상 영상에서는 낙상 확인 요청도 늘었다. 이번 조건은 운영에 반영하지 않는다.

앞선 [같은 프레임의 외형 비교](FALL84_REID_ASSOCIATION_20260927.md)는 Cloud 박스와
Pose 박스를 비교했다. 이번에는 **이전 프레임에서 관측한 사람과 현재 검출을 연결하는
Pose 추적 단계**에 외형을 추가했다. 두 실험의 변경 위치는 다르다.

## 비교 방법

기존 OSNet-AIN x1.0 MSMT17 모델로 실제 검출 박스의 RGB를 잘라 외형 특징을 구했다.
현재 검출과 각 추적 ID의 마지막 실제 관측을 비교했다. 미검출 프레임에 과거 박스를
복사하거나, Cloud·정답 박스를 Pose 입력에 추가하지 않았다.

| 조건 | 이전 관측과 현재 검출을 연결하는 방법 |
|---|---|
| 기존 추적 | 기존 박스 겹침·이동 거리·관절 거리 비용 그대로 사용 |
| 시간축 ReID | 기존 기하학적 후보 안에서 외형 유사도 0.80 미만은 제외. 나머지는 `기존 비용 + (1 - 유사도)`로 비교 |

수치는 실행 전에 고정했다. 결과를 보고 임계값을 바꿔 좋은 결과만 고르지 않았다.
이는 시험용 값이며 유사도 0.80이 같은 사람일 확률 80%라는 뜻은 아니다.

다음 조건은 유지했다.

- 실제 Pose 좌표·점수·관절, 약한 후보 0.10 / 강한 검출 0.45 기준.
- 기존 크기·이동 거리 범위 밖인 대상은 외형이 비슷해도 연결하지 않음.
- 양쪽에서 서로 최선인 일대일 대응만 허용. 경쟁 비용 차이 0.10 미만이면 보류.
- 추적 관측·확정·최대 1초 공백·만료·초기화 규칙. 약한 점수를 ReID로 올리지 않음.
- 특징을 구할 수 없는 경쟁 후보가 있으면 그 프레임 전체를 기존 기하학적 비교로 처리.
  특징이 없는 사람을 후보에서 빼거나 일부 후보만 다른 비용 기준으로 비교하지 않음.
- 대상마다 마지막 실제 관측 특징 하나만 유지. 미연결 검출로 기존 특징을 갱신하지 않음.
  만료·초기화 후 옛 ID를 복구하는 장기 갤러리는 이번 범위가 아님.
- 기존 낙상 후보 생성 코드와 Cloud→Pose 연결 기준(IoU 0.60 / 차이 0.15).
- Cloud가 반환한 모든 위치의 대상·연결 구간, 최신 관측·사건의 연결 구간 확인.

실험 추적기는 기존 `PersonPoseTracker`를 상속해 비용 계산만 바꾸었다. 기존 추적 조건에서는
저장된 추적 결과와 후보 JSON이 필드별로 같은지 먼저 확인했다. 이름만 정하는 무작위 ID
접두사는 이전 실행의 값을 재사용했으며, 정답 신원이나 영상 라벨은 전달하지 않았다.

## 입력과 실행 범위

- 이전 9개 개발용 장면을 사용했다. 다인 장면 SYN012(414), SYN045, SYN063, SYN067과
  SYN011(413), SYN023(308), SYN028(410), SYN033(425), SYN036(435)이다.
- 각 영상의 기존 **전체 화면 / 전체+양방향 회전 / 전체+구역 확대** Pose 결과를 재사용했다.
  검출기를 새로 실행하거나 앞선 추가 중복 제거를 섞지는 않았다.
- 각 입력 조건에 같은 171개 시점이 있다. 세 입력 조건 각각 기존 추적과 ReID 추적을 실행했다.
- ReID는 원래 RGB 위에 복원된 실제 검출 박스에서 외형을 구했다. 같은 시점·같은 박스는
  조건 간 특징을 재사용했다. 별도 학습이나 이미지 합성은 하지 않았다.
- 추적과 후보를 다시 생성한 뒤 저장된 Gemma·Gemini 응답으로 실제 사건 병합 로직을 재현했다.
  3개 입력 × 2개 추적 × 2개 Cloud 모델 × 9개 영상으로 총 108회다.
- Cloud 입력은 기존의 12장 그대로다. 로컬 추적용 중간 프레임을 Cloud에 보냈다고 가정하지 않았다.
- 정답 라벨·사람별 박스는 모든 추적·사건 병합이 끝난 뒤에만 읽어 대조했다.

새 Cloud 호출·Pose 추론·추가 API 비용은 0이다. 새로운 로컬 OSNet 추론은 crop 810개와
별도 워밍업 1회였다. 입력 crop이 작아 특징을 얻지 못한 경우는 이번 자료에서는 없었다.

## 결과

아래의 화살표는 **기존 추적 → 시간축 ReID**를 뜻한다.

| 항목 | 전체 화면 | 회전 추가 | 구역 확대 추가 |
|---|---:|---:|---:|
| 다인 장면의 기존 사건 연결 | 1/7 → 1/7 | 0/7 → 0/7 | 1/7 → 1/7 |
| 미연결·불확실한 검출이 남은 시점 / 171 | 10 → 8 | 75 → 67 | 59 → 36 |
| 새로 만들어진 추적 ID 수 | 19 → 27 | 39 → 62 | 31 → 45 |
| 정상 4개 영상에서 생성한 확인 후보 수 | 3 → 3 | 3 → 4 | 4 → 5 |
| 정상 영상 중 확인 후보가 생긴 영상 수 | 3/4 → 3/4 | 3/4 → 3/4 | 3/4 → 3/4 |

7개는 다인 영상 4개에서 나온 유효 응답 수(Gemma 3개·Gemini 4개)다. 독립적인 영상
7개가 아니며, Gemma SYN045의 기존 중복 JSON 오류는 그대로 별도 처리했다.
연결된 사례는 기존과 같이 Gemini SYN045였다. 추가 5개 장면에도 새 Cloud 사건 연결은 없었다.

새 ID 수는 사람 수나 정식 ID-switch 지표가 아니다. 검출 변화·추적 분할·오검출·새 대상을
모두 포함한다. 하지만 미연결 수가 줄어도 새 ID와 확인 후보가 늘 수 있어, 미연결 수만으로
추적이 좋아졌다고 판단할 수 없다. 정상 영상의 확인 후보도 보호자에게 보낸 낙상 오알림 수는 아니다.

### SYN023(308): 같은 사람의 이력이 갈라지는 사례

전체 화면에서는 기존 추적 ID가 1개였지만 ReID 조건에서는 5개가 생겼다.
검수한 같은 사람 P01이 원본 0번 프레임에서는 ID 1, 24번 프레임에서는 ID 3에 연결됐다.
기존 조건에서는 이 두 검수 시점에 같은 ID가 유지됐다.

실행 기록에서 새 ID가 생성된 일부 지점은 기하학적으로는 후보였지만 외형 유사도가
0.755, 0.764, 0.699 등으로 0.80을 넘지 못했다. 이번 방식은 이런 비교를 제외하기 때문에
기존 이력을 잇지 않고 새 ID를 만들 수 있다. 다만 모든 중간 프레임의 사람을 검수한 것은
아니므로, 모든 거부가 같은 사람을 잘못 나눈 결과라고 단정하지 않는다.

회전·확대 조건에서는 이 정상 영상의 확인 후보가 각각 1개에서 2개로 늘었고,
로컬 사건 기록도 1개에서 2개가 됐다. 추적 방식만 바꿔도 후속 확인 부담이 늘 수 있다는 사례다.

### SYN067: ID가 같아도 사건 연결을 통과한 것은 아님

확대 조건에서는 미연결 검출이 남은 시점이 14개에서 5개로 줄었고,
연결에 사용할 수 있는 Pose 관측도 9개에서 27개로 늘었다.

그러나 Cloud가 가리킨 대상의 ID는 같아도, 중간에 관측 사용 조건이 끊겨 **연결 구간
토큰이 달라졌다.** Gemma가 반환한 처음과 마지막 위치는 같은 ID 4였지만 토큰은 달랐다.
Gemini가 반환한 위치들도 같은 ID에 대해 서로 다른 구간이었다.

따라서 실제 사건 연결은 `track_changed`로 거부했다. 이 코드는 반드시 숫자 ID가 바뀌었다는
뜻은 아니며, 같은 ID 안에서 관측의 연속성이 끊긴 경우도 포함한다. ReID가 비슷하다는 이유로
이 구간들을 소급해서 합치지는 않았다.

## 다른 사람을 잘못 붙이지 않았는가

프레임 간 연결의 양 끝에 정확한 시각의 검수 박스가 있는 경우만 대조했다.
없는 정답을 주변 프레임에서 복사하거나 보간하지 않았다.

| ReID 조건 | 같은 검수 인물로 대응한 연결 | 서로 다른 인물로 대응한 연결 | 양 끝의 대응 확인 불가 |
|---|---:|---:|---:|
| 전체 화면 | 2 | 0 | 220 |
| 회전 추가 | 3 | 0 | 313 |
| 구역 확대 추가 | 1 | 0 | 355 |

총 894개 연결 중 대조 가능한 것은 6개뿐이고 888개는 미확인이다. 세 입력 조건은 같은
영상을 공유하므로 6개도 독립적인 사례 수가 아니다. 드문 검수 시점에서 하나의 ID가 서로
다른 검수 인물에게 붙은 사례는 발견하지 못했지만, **전체 오연결이 0이라고 확인한 것은 아니다.**

다음에 추적 품질을 평가한다면 사람이 겹치고 가려지는 구간을 연속 프레임으로 검수해야 한다.
현재 자료로는 상세한 IDF1·MOTA나 전체 오연결률을 산출하지 않는다.

- crop 1개 처리 중앙값 약 **49.01ms**, 810개 합계 **38.545초**.

  특징을 조건 간 재사용했으므로 이것을 조건별 전체 처리 시간이나 로봇 FPS로 해석하지 않는다.

  이를 JSON 표현으로 비교하도록 고친 뒤 새 `r1` 경로에 실행했다. 임계값·영상·모델을
  바꾸지 않았고 중단된 결과도 덮어쓰지 않았다.

## 판단

이번 **마지막 관측과의 유사도 0.80 차단 + 외형 비용 추가** 방식은 운영에 반영하지 않는다.
최종 사건 연결은 늘지 않았고 새 ID·정상 영상의 확인 요청 증가가 있었다.
ReID 전체가 효과 없다는 결론은 아니며, 이번에 고정한 연결 방식의 결과다.

다음 설계에서는 외형 점수가 떨어졌다는 이유만으로 이력을 바로 끊어 새 ID를 만드는
부분을 검토할 수 있다. 단, 다른 사람의 이력을 이어 붙이는 위험을 함께 검증해야 한다.
임계값을 낮춰 같은 9개 점수만 올리기보다, 먼저 연속 구간의 인물 정답과 별도 검증 장면을
확보해야 한다. 대상 자체를 검출하지 못하는 문제는 추적 외형 비교만으로 해결되지 않는다.

이번은 저장된 Cloud 응답을 즉시 병합하는 오프라인 실험이다. 84개 전체, 장기 재식별,
새 장면, 실제 RGB-D, Jetson, Cloud 지연 중 사람 이동, ROS·주행·음성·알림 연동을
검증한 결과가 아니다.
