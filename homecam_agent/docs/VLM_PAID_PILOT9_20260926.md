## 무엇을 확인했나

84개 전체를 돌리기 전에, 같은 영상 9개로 각 회사의 API 연결·답변 형식·판단·응답 시간을

Google Gemini와 Ollama Gemma는 결제 계정이 달라 별도 예산이다.

13개 모델에 각각 9개씩, 총 117회가 계획이었다. 실제로는 **87회 요청**했고,
8개 모델이 9개를 모두 완료했다. Meta·GLM·Kimi·Qwen은 아래 이유로 중단했다.
이미 보낸 요청을 다시 보내거나, 실패한 영상을 다른 모델로 대신 채점하지 않았다.

이번 결과는 **VLM 단독 시험**이다. YOLO-Pose 감지율이나 YOLO-Pose 후 VLM 정확도,
낙상 발생부터 보호자 알림까지의 시간은 측정하지 않았다. 운영 모델도 바꾸지 않았다.

## 발견한 문제: 프롬프트의 답변 형식 설명

이번 공통 프롬프트에는 `assessment, explanation, findings`와 박스 좌표 순서가 있지만,
**JSON 객체로 답해야 한다는 문장과 박스 배열 예시가 빠져 있다.**
박스는 `normalized left,top,right,bottom`으로만 설명하고 0~1 범위를 숫자로 적지 않았다.
검사 코드는 JSON 객체와 `[left, top, right, bottom]` 배열을 요구하므로 설명과 검사 사이에
부족한 부분이 있었다. 실제 응답에서도 다음 문제가 나왔다.

| 사례 | 답변에서 확인한 것 | 검사 결과 |
|---|---|---|
| Sonnet 5 / SYN050 | 낙상이라고 답했지만 박스를 `{left: ..., top: ...}` 형태의 객체로 반환 | 배열이 아니어서 오류 |
| Gemini 3.8 Flash / SYN050 | 낙상이라고 답했지만 일부 박스 값이 `502.0`, `514.0` 등으로 반환 | 0~1 범위를 벗어나 오류 |
| Gemma4 / SYN050 | 낙상이라고 답했지만 `assessment, observed_fall`처럼 쉼표로 항목을 나열 | JSON 객체가 아니어서 오류 |
| Grok 4.7 / SYN019 | `assessment: observed_fall`처럼 항목을 나열 | JSON 객체가 아니어서 오류 |

따라서 위 점수는 **현재 요청 형식으로 바로 사용할 수 있었던 답변의 정답률**이다.
낮은 점수를 전부 영상 인식 능력 부족으로 해석하거나 최종 모델 순위를 정하면 안 된다.
특히 Gemma의 이번 1/9를 과거 84개 평가 점수와 그대로 비교하면 안 된다.

시험 도중 프롬프트를 바꾸거나 답변을 고쳐 점수를 다시 만들지 않았다.
다음 비교에서는 먼저 JSON 객체와 박스 배열·범위를 명확히 적고, 모든 모델에 같은 새 조건을
적용해야 한다. 이것은 별도 실험으로 기록하며 이번 결과를 덮어쓰지 않는다.

### 형식 검사를 통과했지만 판단이 다른 사례

- SYN018(433): 정답은 낙상 의심. Astra·Sol·Opus·Sonnet·Gemini 3.8·Muse·Grok은 낙상,
  Kimi는 정상으로 답했다. 나머지 답변은 형식 오류 또는 미호출이다.
- SYN019(441): 정답은 낙상 의심. Sol은 정상으로 답했다.
- SYN060(V020): 정답은 정상. Astra는 정상, Sol·Opus·Kimi는 낙상 의심,
  Sonnet·Grok은 낙상으로 답했다. 다른 결과는 형식 오류·시간 초과·미호출로 구분했다.

판단을 정상으로 잘못 넘긴 사례와 형식 오류 때문에 판단을 읽지 못한 사례를 합쳐 숨기지 않는다.

### 답변 거부·안전 차단

87회 요청에서 공급자의 명시적인 답변 거부·안전 차단 표시는 확인되지 않았다.

## 실행 중 비용 처리 보완

- OpenAI의 캐시 쓰기 토큰을 일반 입력과 중복 계산하지 않도록 했다.
- Kimi의 캐시 쓰기는 응답의 5분·1시간 사용량과 대조한다. 맞지 않으면 비용 미확인으로 남긴다.
- xAI Chat 응답은 답변 토큰과 추론 토큰을 나눠 보고한다. 첫 요청에서 이 차이로 비용 계산이
  멈췄다. 원래 응답의 사용량과 `cost_in_usd_ticks`를 대조해 비용만 바로잡았으며,
  영상 판단·응답 시간은 수정하지 않았다. 같은 요청을 다시 보내지 않고 미호출 8개만 진행했다.
- OpenAI도 최초 13회 뒤 요청당 예비 금액 때문에 일시 중단했다. 공식 단가와 입력 크기·
  출력 한도를 대조해 예비 금액을 조정하고, 남은 5개만 호출했다. 두 모델 합계 예산은 그대로 $1이다.
