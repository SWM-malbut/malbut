# Cloud 좌표 수정부터 Pose 대상 연결까지 확인한 결과

2026-09-27 / SWM25-186

좌표 출력 방식을 바꿔 **좌표 범위·크기 오류는 줄였지만, Cloud가 찾은 사람을
YOLO-Pose의 추적 대상과 연결하는 문제는 남았다.** 이번에 영상 회전과 고정 구역 확대도
비교했으나 사건 연결은 늘지 않았다. 실험 결과만 보존하고 운영 코드는 유지했다.

## 목표

Cloud 응답을 읽을 수 있는지뿐 아니라, 실제로 의심되는 사람을 가리키는지,
그 사람을 기존 Pose 추적·사건에 연결할 수 있는지 단계별로 확인한다.
누운 사람을 더 잘 검출하려고 바꾼 방법이 주변 사람·이불·고양이의 오검출을
늘리거나 처리 시간을 지나치게 늘리는지도 함께 본다.

## 지금까지 진행한 내용

| 단계 | 방법 | 확인한 결과 |
|---|---|---|
| Cloud 좌표 출력 변경 | Gemma·Gemini에 0~1000 정수 `box_2d`를 요청하고 검사 후 내부 0~1 좌표로 고정 변환 | 84개 재평가에서 라벨 정답과 응답 검사를 모두 통과한 수: Gemma 52→71, Gemini 55→73 |
| 사람이 박스 검수 | 다인 장면 4개에서 사용자가 15프레임·34개 박스를 확인하고 10개 좌표 수정 | 대조 가능한 Cloud 응답 7개는 반환한 표본 프레임에서 같은 누운 사람에 대응 |
| 실제 Pose·사건 연결 | Cloud에 보낸 것과 같은 프레임을 포함해 실제 YOLO26s-Pose 실행, 저장 응답으로 병합 재현 | 사용 가능한 응답 7개 중 Gemini SYN045 1개만 기존 사건에 연결 |
| 사람 연결에서 관절 조건만 분리 | 낮은 점수·추적 단절·다른 사람과의 혼동은 계속 차단하고 관절 정보 충분성 조건만 제외 | 연결 가능한 관측은 107→146개로 늘었지만 사건 연결은 1/7로 같음 |
| 이번 추가 비교 | 원본 전체 화면 / 전체+양방향 90도 회전 / 전체+고정 구역 2개 확대 | 연결은 각각 1/7, 0/7, 1/7. 일부 대상 검출은 좋아졌지만 중복·불확실한 추적과 연산량이 늘어남 |
| 후속 중복 처리 | 서로 다른 입력의 박스 겹침과 동일 이름의 관절 위치를 함께 비교해 일부 중복 관측 제외 | 회전 18개·확대 59개 박스를 제외했지만 사건 연결은 그대로. 일부 장면에서는 추적이 더 불안정해 운영 반영하지 않음 |
| 후속 외형 비교(ReID) | 기존 OSNet으로 같은 프레임의 Cloud 박스·Pose 박스 외형 비교. bbox 기준만 완화한 비교군도 별도 실행 | 세 조건 모두 사건 연결 1/7. 느슨한 bbox 기준이 주변 사람을 고르는 일부 선택은 거부했지만 검출 누락·초기 추적 문제는 남음 |
| 시간축 ReID 추적 | 마지막 실제 관측과 현재 Pose 박스의 외형을 추가해 추적 연결을 비교 | 미연결 검출은 일부 줄었지만 사건 연결은 그대로. 새 ID와 일부 정상 영상의 확인 요청이 늘어 운영 반영하지 않음 |

첫 행의 증가는 **좌표 때문에 사용하지 못하던 응답이 줄어든 결과**다. 영상 라벨 정답은
Gemma 72→71, Gemini 73→73이었다. Gemma의 좌표 오류 0건은 JSON을 읽을 수 있었던
83개 응답 기준이며, SYN045의 중복 JSON 오류 1건은 남아 있다. 따라서 모든 형식 오류가
해결됐다고 쓰지는 않는다.

검수한 Cloud 박스가 실제 사람과 대응한 것과, 운영 연결 조건을 만족한 것은 서로 다른
시험이다. 7개 응답은 4개 영상에서 나온 Gemma 3개·Gemini 4개이며 독립적인 영상 7개가 아니다.
4개 영상 모두 문제를 살펴보기 위해 고른 개발용 자료다. 전체 대상 연결 정확도로 환산하지 않는다.

## 이번에는 어떻게 비교했나

- 기존 다인 장면 SYN012(414)·SYN045·SYN063·SYN067과, 추가 점검용
  SYN011(413)·SYN023(308)·SYN028(410)·SYN033(425)·SYN036(435)을 사용했다.
  추가 장면에는 낙상 영상 1개와 이불·고양이·일상 행동의 정상 영상 4개가 있다.
- 같은 YOLO26s-Pose ONNX, CPU 실행, 모델 입력 640×640 비율 유지 조건이다.
  검출 후보 점수 0.10, 강한 검출 점수 0.45, 기존 추적·낙상 후보 조건을 유지했다.
- 총 171개 시점을 사용했다. 저장된 Cloud 입력 12장을 모두 포함하고 그 사이 실제 프레임을
  추가했으며, 입력 시각 간격은 0.2초 이상이다. 같은 프레임의 JPEG를 세 조건이 공유한다.
- 회전 조건은 전체 화면에 시계·반시계 방향 90도 입력을 추가했다.
  확대 조건은 640×400 화면의 `(0,0,400,400)`과 `(240,0,640,400)`을 추가로 봤다.
  대상 정답이나 Cloud 박스로 구역을 고르지 않았다.
- 추가 입력의 박스·관절을 원래 화면 좌표로 돌린 뒤 추적했다. 관절 이름과 실제 검출 점수는
  유지했다. 구역 안쪽 경계에 정확히 닿아 잘린 박스는 제외하고 원시 기록을 남겼다.
- 서로 다른 입력에서 겹침 IoU가 0.85 이상인 박스는 실제 점수가 높은 결과 하나를 남겼다.
  점수가 같으면 전체 화면 결과를 우선했다. 좌표 평균이나 점수 보정은 하지 않았다.
  그보다 덜 겹치는 결과는 기존 추적기가 처리하도록 남겼다.
- 기존 연결 조건과 앞선 관절 조건 분리 실험을 각각 실행했다. Cloud 박스와 IoU 0.60,
  다른 추적과의 차이 0.15, 반환한 모든 위치의 동일 추적·연결 구간 조건은 바꾸지 않았다.
- 정답 박스는 추론·추적·사건 병합이 끝난 뒤 같은 원본 프레임에서만 대조했다.
  검수하지 않은 프레임의 신원을 보간하거나, 기존 Cloud 응답을 다른 영상 구간에 쓰지 않았다.

전체 화면 추론은 세 조건이 공유했다. 실제 추론 호출은 워밍업 1회를 포함해 856회다.
저장된 Gemma·Gemini 응답을 재사용했으므로 **추가 API 호출과 비용은 0**이다.

## 이번 비교 결과

| 항목 | 전체 화면 | 전체 + 양방향 회전 | 전체 + 구역 2개 확대 |
|---|---:|---:|---:|
| 다인 4개 장면의 사용 가능한 Cloud 응답 중 기존 사건 연결 | 1/7 | 0/7 | 1/7 |
| 171개 시점 중 미연결·불확실한 검출이 남은 시점 | 10 | 75 | 59 |
| 정상 4개 영상 중 낙상 확인 후보가 생긴 영상 | 3/4 | 3/4 | 3/4 |
| 정상 4개 영상에서 생성한 후보 수 | 3 | 3 | 4 |
| 한 시점의 Pose 추론 시간 중앙값 | 88.23ms | 264.19ms | 264.16ms |
| 추론에 200ms를 넘긴 시점 | 0/171 | 118/171 | 118/171 |

사건 연결 수는 기존 연결 조건과 관절 조건 분리 조건에서 같았다.
Gemma SYN045의 기존 JSON 오류는 7개 분모에서 제외해 따로 보존했다.
추가한 5개 장면에서도 기존 사건에 새로 연결된 Cloud 발견은 없었다. 정상 응답으로
박스가 없는 경우까지 연결 실패율로 합치지는 않았다.

정상 영상의 후보 수는 Pose가 추가 확인을 요청한 수이지 최종 낙상 오판이나 보호자 알림 수가 아니다.
이 4개는 오검출을 살펴보려고 고른 장면이므로 전체 정상 영상의 오검출률로 해석하지 않는다.

시간은 이 PC에서 각 조건을 한 번 실행한 값이다. 각 `estimate_all` 호출 시간의 합으로,
외부 영상 디코딩·회전·자르기·좌표 복원·추적·Cloud 대기는 제외했다. 순차 실행과 PC 부하의
영향도 있다. 회전·확대는 추론만으로도 여러 시점에서 5fps의 200ms 간격을 넘겼다.
이것은 Jetson 성능 측정이 아니며 실제 최대 처리율을 측정한 결과도 아니다.

### 일부 검출이 좋아져도 사건 연결은 좋아지지 않음

SYN063은 책상 아래 누운 사람 옆에 다른 사람이 있는 장면이다. 전체 화면에서는 검수한
대상 프레임 5개 모두 강한 대상 박스와의 단독 대응을 만들지 못했다. 회전 결과를 추가하자
점수 0.45 이상 박스만 대조했을 때는 5개 모두 대상과 대응했다.

그러나 약한 박스까지 포함하면 마지막 프레임에서 대응이 애매했고, 여러 입력에서 나온
주변 사람의 겹치는 박스도 남았다. 실제 사건 연결은 Gemma `ambiguous_tracks`,
Gemini `track_unusable`로 실패했다. **5개 프레임에 강한 대상 박스가 있었다는 것이
안정된 대상 추적이나 병합 성공을 뜻하지는 않았다.**

SYN067은 확대 후 강한 대상 박스와 대응하는 검수 프레임이 2/5에서 5/5로 늘었다.
그래도 초기 추적을 포함한 연결 조건은 통과하지 못해 두 Cloud 모델 모두 미연결로 남았다.
반대로 기존에 연결됐던 Gemini SYN045는 회전 조건에서 추적을 사용할 수 없게 돼 연결이 끊겼다.

### 기존 오검출도 남음

- SYN028(410)은 이불을 덮고 쉬는 정상 장면이다. 확대 조건에서는 같은 프레임에 서로 다른
  추적 ID의 후보가 2개 생겼다. 기존 조건의 후보 1개보다 늘었다.
- SYN033(425)의 고양이 장면은 세 조건 모두 사람 Pose에서 낙상 확인 후보를 만들었다.
- SYN011(413)의 초기 후보도 사라지지 않았다. 영상 일부의 검출이나 후보 수가 늘었다는
  이유로 실제 넘어지는 사람과 시점을 올바르게 찾았다고 계산하지 않았다.

## 현재 판단과 다음 작업

이번 회전·확대 방법은 **운영에 반영하지 않는다.** 누운 사람의 일부 박스를 더 잘 잡는
효과는 있었지만, 사건 연결은 늘지 않고 추론 시간이 약 3배가 됐다.
다른 병합 방법까지 모두 실패한다는 결론은 아니다. 이번에 고정한 구역·회전·중복 제거
방식으로는 운영 반영할 근거를 얻지 못했다는 뜻이다.

후속 [중복 처리 비교](FALL84_POSE_DUPLICATE_COMPARISON_20260927.md)도 완료했다.
박스와 관절 위치를 함께 확인해 일부 관측을 제외했지만 사건 연결은 늘지 않았고,
한 프레임에서만 중복이 제거돼 뒤쪽 추적이 더 불안정해지는 사례가 있었다.
관련 테스트는 후속 신규 36개를 포함해 586개 통과했다. 추가 API 비용은 없다.

이어 [같은 프레임의 ReID 비교](FALL84_REID_ASSOCIATION_20260927.md)를 진행했다.
기존 사람 따라가기의 OSNet 인코더를 재사용해 원본 전체 화면 Pose·저장 Cloud 응답을
비교했지만 사건 연결은 세 조건 모두 1/7이었다. 이 단계의 신규 시험과 인코더 시험을
포함해 652개 통과했고 추가 API 비용은 없다.

다음으로 [프레임 간 추적의 ReID 비교](FALL84_TEMPORAL_REID_20260927.md)도 진행했다.
원본·회전·확대 각각에서 기존 추적과 외형을 추가한 추적을 비교했지만 사건 연결은
1/7·0/7·1/7로 변하지 않았다. 새 추적 ID는 각각 19→27, 39→62, 31→45개로 늘었고,
회전·확대 조건의 정상 영상 확인 후보도 1개씩 늘었다. 최신 관련 시험은 686개 통과했다.
실험값을 운영에 반영하지 않았고 새 Cloud 호출은 없다.

검출 점수나 연결 기준을 낮추기보다, 프레임별 중복 처리와 시간에 따른 추적이 일관되게
이어지는지 함께 검토해야 한다. 가까이 있는 다른 사람을 합치지 않는 조건과 누운 사람을
처음부터 놓치는 문제도 남아 있다. 현재 9개로 방법을 고쳤다면 채택 판단은 새 장면에서도 확인해야 한다.

별도로 실제 RGB/Pose 입력 주기·버퍼 선택·후보 우선순위·Cloud 응답 지연을 연결한 시험이
남아 있다. 이번 재현은 저장 응답을 병합 단계에 즉시 전달한 오프라인 시험이다. 실제 지연 중
대상 이동·추적 소실, ROS, 주행 정지, 음성 질문, 보호자 알림까지 검증한 것이 아니다.
새 영상 구간을 선택하는 시험에는 그 구간을 실제로 분석한 새 Cloud 응답이 필요하다.

## 검증 및 보존

- 신규 시험 22개를 포함한 관련 테스트 **550개 통과**. 좌표 역변환, 구역 경계,
  중복 처리, 정확히 같은 프레임에서의 정답 대조와 기존 연결·사건 보호 조건을 확인했다.
  코드 테스트 수는 영상 정확도와 별개다.
- 기존 4개 장면의 전체 화면 JPEG·원시 Pose 결과가 앞선 보존 결과와 정확히 같았다.
- 입력·모델·코드 등 187개 보존 파일과 완료 시점의 결과 파일 469개의 해시를 다시 확인했다.
  변경된 파일은 없었다. 완료 후 생성한 `test-results.xml`은 이 469개와 별도다.
- 3개 입력 조건 × 2개 연결 조건 × 2개 Cloud 모델 × 9개 영상으로 108회 로컬 병합 재현.
