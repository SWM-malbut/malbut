# 여러 입력에서 나온 사람 박스를 중복 처리한 결과

2026-09-27 / SWM25-186

**중복으로 판단해 제외한 박스는 늘었지만, Cloud 발견을 기존 사건에 연결한 수는 늘지 않았다.**
한 프레임에서만 중복을 지우고 다음 프레임에서는 두 박스가 다시 남으면 추적이 더
불안정해지는 사례도 있었다. 이번 방식은 운영에 반영하지 않았다.

## 목표

[앞선 회전·부분 확대 비교](FALL84_POSE_LINKING_SUMMARY_20260927.md)에서 같은 사람 주변에
여러 박스가 생기면서 추적 연결이 애매해졌다. 겹치는 박스를 줄일 수 있는지 확인하되,
누운 사람과 곁에 있는 다른 사람을 잘못 합치지 않는 것을 함께 확인한다.

## 진행 방법

앞선 9개 영상·171개 시점의 Pose 결과를 그대로 사용했다. 새 추론과 Cloud 호출은 없었다.
전체 화면, 양방향 회전 추가, 고정 구역 2개 확대의 세 조건마다 중복 처리 전후를 비교했다.
점수를 높이거나 박스·관절을 새로 만들지 않고, 실제로 나온 결과 중 하나만 남기는 방식이다.

기존 IoU 0.85 중복 제거를 거친 박스들에 다음 조건을 추가했다.

1. 서로 다른 입력에서 나온 박스이고, 두 박스의 IoU가 0.45 이상이어야 한다.
2. 두 출력 모두 점수 0.5 이상인 **이름이 같은 신체 관절**이 4개 이상 있어야 한다.
   이 중 어깨·골반의 네 관절 중 최소 3개가 포함돼야 한다.
3. 실제 640×400 픽셀 거리로 비교한다. 두 박스 중 작은 박스의 대각선 길이 대비
   공통 관절의 최대 거리는 10%, 평균 거리는 6% 이하여야 한다.
   얼굴을 포함해 두 출력에서 신뢰할 수 있는 공통 관절이 크게 어긋나면 제외하지 않는다.
4. A와 B, B와 C가 비슷해도 A와 C가 다르면 세 박스를 그대로 남긴다.
   한 입력의 두 사람 박스가 다른 입력의 하나에 대응하는 경우도 그대로 남긴다.
5. 조건을 모두 통과한 묶음에서 실제 박스 검출 점수가 가장 높은 결과 하나를 남긴다.
   점수가 같으면 전체 화면 결과를 우선한다. 좌표·관절·점수를 평균내지 않는다.

이 수치는 이번 개발용 비교의 고정 조건이지 검증된 운영 기준이 아니다.
결과를 보고 수치를 반복해서 바꾸는 탐색은 하지 않았다.

낙상 후보·추적·Cloud 연결 기준은 그대로 유지했다. 낮은 검출 점수, 추적 단절,
다른 사람과의 혼동을 허용하지 않았다. Cloud가 반환한 초기 위치를 버리고 뒤쪽 위치만
연결하지도 않았다. 기존 조건과 앞선 관절 조건 분리 실험을 각각 실행했다.

정답 박스와 라벨은 중복 처리·추적·사건 병합이 끝난 뒤에만 읽었다. 두 조건을 비교하려고
같은 영상 프레임·Cloud JPEG·응답을 사용했고, 정답으로 박스를 고르지는 않았다.

## 결과

| 항목 | 전체 화면 | 전체 + 양방향 회전 | 전체 + 구역 2개 확대 |
|---|---:|---:|---:|
| 이번 조건에서 중복으로 판단해 제외한 박스 | 0 | 18 | 59 |
| 미연결·불확실한 검출이 남은 시점, 처리 전→후 | 10→10 | 75→70 | 59→56 |
| 다인 4개 장면의 사용 가능한 Cloud 응답 중 사건 연결, 처리 전→후 | 1/7→1/7 | 0/7→0/7 | 1/7→1/7 |
| 정상 4개 영상의 낙상 확인 후보 수, 처리 전→후 | 3→3 | 3→3 | 4→3 |

시점 수의 분모는 각 조건 171개다. 박스 수에는 같은 사람이 여러 프레임에서 반복 포함된다.
사건 연결의 7개 응답은 다인 영상 4개에서 나온 Gemma 3개·Gemini 4개이며,
Gemma SYN045의 기존 JSON 오류 1개는 따로 유지했다.

두 연결 조건 모두 표의 사건 연결 수가 같았다. 전체 화면·확대 조건의 Gemini SYN045만
기존 사건에 연결됐으며, 반환한 프레임 2·46·89·122에서 검수한 누운 대상과 대응했다.
추가한 5개 영상에서도 기존 사건에 새로 연결된 Cloud 발견은 없었다.
정상 응답에 위치 발견이 없는 경우까지 연결 실패로 세지는 않았다.

### 박스를 덜 남기는 것만으로 추적이 좋아지지 않음

SYN028(410)은 이불을 덮고 쉬는 정상 장면이다. 확대 조건에서는 첫 프레임의 두 박스가
중복 조건을 통과해 하나만 남았다. 다음 프레임들에서는 관절 조건을 만족하지 못해
두 박스가 다시 남았고, 기존 추적 하나에 여러 검출이 겹치면서 연결하지 못한 관측이 생겼다.

- 중복 처리 전: 17개 시점 중 불확실한 검출이 남은 시점 2개, 후보 2개.
- 중복 처리 후: 같은 17개 중 불확실한 검출이 남은 시점 15개, 후보 1개.

따라서 이 장면의 후보 2→1을 그대로 감지 품질 개선으로 해석하면 안 된다.
프레임별 박스 정리와 시간에 따른 추적의 일관성을 같이 봐야 한다.
고양이 장면 SYN033(425)의 불필요한 후보도 사라지지 않았다.

SYN063은 회전 결과의 일부 중복 박스를 줄여도 실제 연결은 여전히 애매했다.
SYN067에서는 이번 조건으로 제외할 수 있는 박스가 없었고, 대상 연결도 개선되지 않았다.
관절 정보가 불충분하거나 서로 어긋나는 관측을 억지로 같은 사람으로 취급하지 않았다.

### 서로 다른 사람을 지우지는 않았나

이번 조건에서 중복으로 처리한 묶음은 회전 18개·확대 59개로 총 77개이며,
각 묶음에서 박스 하나씩을 제외했다.

- **7개 묶음:** 정확히 같은 프레임의 승인 박스가 있어 대조할 수 있었고,
  두 예측 박스가 같은 검수 인물과 대응했다.
- **70개 묶음:** 같은 프레임의 정답이 없거나 인물을 단독으로 대응시키기 어려워 미확인으로 남겼다.
- 대조할 수 있었던 7개에서 서로 다른 사람의 박스를 하나로 줄인 사례는 없었다.
  그렇다고 나머지 70개까지 안전하다고 확인한 것은 아니다.

위 대조는 승인된 사각형과의 수치 비교다. 모든 장면의 픽셀·신원·검출 누락을 새로
육안 검수한 결과가 아니다. 같은 검수 인물과 대응해도 신체 일부가 빠질 수 있다.
이 9개는 이미 문제를 알고 고른 개발용 자료이므로 독립적인 성능 검증도 아니다.

## 판단

이번 방식은 중복 관측을 일부 줄였지만 사건 연결 개선이 없고, 특정 장면에서는 추적이
더 불안정해졌다. **운영 중복 제거·추적·Cloud 연결 기준은 바꾸지 않는다.**

이 결과만으로 중복 처리 자체가 불필요하다고 결론 내리지는 않는다. 다음 설계를 검토한다면
한 프레임에서 중복으로 본 두 관측이 다음 프레임에서 다시 갈라질 때 어떻게 처리할지,
실제로 다른 사람이 가까워진 경우는 어떻게 구분할지를 함께 다뤄야 한다.
과거 박스를 현재 관측처럼 복사하거나 서로 다른 사람의 이력을 이어 붙이는 방식은 쓰지 않는다.
처음부터 누운 대상을 놓치는 문제도 별도로 남는다.

이번에는 저장된 Pose로 처리부만 다시 실행했으므로 새 추론 시간은 측정하지 않았다.
중복 처리 함수의 중앙값은 회전 약 0.065ms, 확대 약 0.062ms였지만,
앞선 세 번의 영상 추론 비용을 없애는 방식은 아니다.
실제 RGB 버퍼 선택·Cloud 대기·대상 이동·ROS·음성·주행·알림을 연결한 시험도 아니다.
