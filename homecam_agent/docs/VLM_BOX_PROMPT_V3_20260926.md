# 좌표 출력 규칙 수정 — 평가용 v3

SWM25-186 / 2026-09-26

[기존 응답 점검](FALL84_BOX_ERRORS_AUDIT_20260926.md)에서 확인한 혼합 좌표와
뒤집힌 박스를 줄이기 위해 `normalized_boxes_v3` 평가 조건을 추가했다.
작성 시점에는 코드와 로컬 테스트까지만 완료했다. 이후 사용자 요청으로
[Gemma 9개 실제 호출](VLM_BOX_V3_GEMMA9_RESULTS_20260926.md)을 진행했으나,
응답 검사까지 통과한 정답 수가 5/9개로 같아 운영에 반영하지 않았다.
Gemini에는 아직 호출하지 않았다. 아래 전송 0회 표기는 최초 준비 단계의 기록이다.

## 바꾼 부분

- 기존 `explicit_json_v2` 뒤에 좌표 확인 지시만 추가했다. 낙상 판단 기준은 유지했다.
- 네 좌표의 의미를 각각 명시했다. left/right는 가로 위치를 이미지 너비로,
  top/bottom은 세로 위치를 이미지 높이로 나눈 값이다.
- 네 값 모두 같은 0~1 범위를 사용하며, 가로만 정규화하거나 프레임마다 다른
  단위를 쓰지 않도록 명시했다. 전달한 이미지 전체를 기준으로 한다.
- 반환 전 각 박스의 범위·순서와 해당 프레임의 대상자를 다시 확인하게 했다.
  잘못된 숫자를 범위 안으로 잘라 넣거나 좌우를 바꾸는 것으로 대신하지 않게 했다.
- 위치를 확실히 못 정하면 의심 판단과 발견 항목은 유지하고 `regions: []`를
  반환하도록 했다. 검사를 통과하려고 무조건 빈 배열을 쓰게 한 것은 아니다.

새 응답에는 `localization_counts`도 기록한다. 발견 항목 수, 위치가 있는 항목 수,
빈 `regions` 항목 수, 제안한 박스 수를 센다. 요약에는 위치를 하나도 주지 않은
낙상·의심 응답 수를 별도로 남긴다.

이 숫자는 실제 사람 위치를 맞힌 수가 아니다. 잘못된 박스를 반환해도 ‘제안한
박스 수’에는 포함되며, 기존 오류 검사와 정답 계산은 그대로 적용한다.
형식이 깨져 셀 수 없거나 과거 응답에 이 진단값이 없으면 확인 불가로 구분한다.

## 바꾸지 않은 부분

- 운영 프롬프트와 로봇 실행 코드.
- 기존 `explicit_json_v2` 내용, 원본 응답과 평가 점수.
- 좌표 배열 순서·0~1 범위·응답 검사 기준. 자동 나누기·반올림·클램핑·순서 교환 없음.
- 이미지 바이트, 영상 구간, 정답 라벨, 모델 옵션, 20초 제한과 자동 재시도 없음.
- API의 구조화 출력 옵션. 이번에는 프롬프트만 바꾼 조건을 먼저 분리해 확인한다.
  구조화 출력 추가는 지원 여부 확인 후 별도 조건으로 비교할 수 있다.

## 준비한 9개 영상

두 모델 모두 같은 9개를 사용한다. 실패 유형을 확인하는 진단용 선택이며,
새 정확도 비교용 표본이나 독립적인 검증 데이터는 아니다.

| ID | 선택 이유 |
|---|---|
| SYN001 | Gemini 혼합 좌표 |
| SYN011 | Gemma 네 좌표 모두 범위 밖 |
| SYN014 | Gemma 가로 소수·세로 큰 숫자 혼합 |
| SYN063 | Gemini 오른쪽 좌표 범위 오류 및 Gemma 혼합 좌표 |
| SYN079 | Gemma 좌우 뒤집힘 및 Gemini 소수 자릿수·범위 오류 |
| SYN083 | Gemini 위아래 뒤집힘 |
| SYN004 | 기존 두 모델 모두 라벨과 응답 검사를 통과한 낙상 영상 |
| SYN003 | 기존 두 모델 모두 라벨과 응답 검사를 통과한 낙상 의심 영상 |
| SYN022 | 기존 두 모델 모두 라벨과 응답 검사를 통과한 정상 영상 |

평가 입력은 아래 위치에 준비했다. 기존 입력 파일은 덮어쓰지 않았다.

`~/.local/share/malbut-evaluations/paid-vlm-box-v3-diagnostic9-20260926/`

Gemma·Gemini × 9개 = **18회 호출 계획만 점검했다. 실제 전송은 0회다.**
이후 실행할 때는 새 비용 한도를 정하고 승인된 범위만 호출한다.
이번 수정 요청을 새 API 지출 승인으로 해석하지 않았다.

## 실행 방법

새 `derive` 명령은 기존 입력의 해시를 확인하고 JPEG를 재추출하지 않은 채
새 실험 묶음을 만든다. 새 디렉터리만 허용하며, 일부 영상만 고르면 `pilot`으로
기록한다. 정답은 채점용 메타데이터에만 남고 모델 요청에는 들어가지 않는다.

```bash
python3 homecam_agent/scripts/evaluate_paid_vlm.py derive \
  --inputs /path/to/previous/inputs \
  --output /path/outside/git/new-v3-inputs \
  --prompt normalized_boxes_v3 \
  --cases SYN001 SYN011 SYN014 SYN063 SYN079 SYN083 SYN004 SYN003 SYN022

# 실행 계획만 확인. --execute가 없으므로 키를 읽거나 전송하지 않음.
python3 homecam_agent/scripts/evaluate_paid_vlm.py run \
  --inputs /path/outside/git/new-v3-inputs \
  --models gemma4:31b gemini-3.8-flash \
  --model-profile low_reasoning
```

기존 실행의 소스 해시는 수정 전 상태로 보존된다. 코드가 바뀐 상태에서 예전
실행을 이어 가는 것은 기존 검사대로 거부하며, `derive`로 새 실험을 만든다.

## 검증 결과

- 새 회귀 테스트 22개를 포함한 관련 로컬 테스트 **214개 통과**.
- 기존 두 프롬프트의 SHA-256 유지 확인.
- 기존 응답 168개를 다시 검사해 라벨·검사 통과 여부·오류 코드가 이전과 같음 확인.
- 기존 84개 입력 파일 해시 유지 확인.
- 새 9개 입력의 JPEG 108장, 영상 메타데이터, 라벨이 원본과 같음 확인.
- 두 모델의 실제 요청 본문 생성 코드에서 시스템 지시문 외 항목이 같음 확인.
- 명령행 dry-run에서 9개·2모델·18회 계획, 20초 제한, `low_reasoning`, 전송 0회 확인.

다음 실제 시험에서는 좌표 오류뿐 아니라 빈 위치 목록, 라벨 오답과 정상 오판,
응답 시간·비용을 함께 확인한다. 실제 사람 위치와 맞는지도 별도 검토해야 한다.
숫자 규칙 통과만으로 대상자 연결 정확도가 개선됐다고 판단하지 않는다.
