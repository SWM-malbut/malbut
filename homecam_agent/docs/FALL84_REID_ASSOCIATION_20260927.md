# Cloud 박스와 Pose 박스를 ReID로 비교한 결과

2026-09-27 / SWM25-186

**같은 사람으로 보이는 박스를 구분하는 데 참고할 수 있었지만, 기존 사건에 연결된
Cloud 응답은 1/7로 늘지 않았다.** 이번에는 같은 프레임의 두 박스에서 외형을 비교했다.
여러 프레임의 ReID 이력으로 추적을 복구하는 시험은 아니다. 운영 연결 기준은 유지한다.

## 무엇을 확인했나

기존 연결은 Cloud가 반환한 사람 박스와 같은 시각의 Pose 박스가 얼마나 겹치는지 보고,
반환한 모든 위치가 같은 추적 대상·같은 연결 구간에 속하는지 확인한다.

이번에는 `malbut_reid`에 이미 있는 OSNet-AIN x1.0 MSMT17 인코더를 재사용했다.
VLM 박스와 Pose 박스에서 각각 원본 RGB를 잘라 512차원 외형 특징을 구하고,
코사인 유사도를 비교했다. 같은 프레임을 썼으므로 카메라 이동이나 시간 차이는 없다.
정답 박스를 잘라 넣거나 영상 정답으로 임계값을 맞추지는 않았다.

| 조건 | 박스 겹침·외형 비교 방법 |
|---|---|
| 기존 bbox 연결 | IoU 0.60 이상, 1·2순위 IoU 차이 0.15 이상 |
| bbox 범위만 확대 | IoU 0.20 이상, 1·2순위 IoU 차이 0.15 이상 |
| 확대된 범위 + ReID | IoU 0.20 이상인 후보 중 외형 유사도 0.80 이상, 1·2순위 유사도 차이 0.10 이상 |

ReID 조건은 겹침 차이 대신 외형 차이로 후보를 고른다. 중간 조건은 결과가 좋아졌을 때
단순히 겹침 기준을 낮춘 효과인지 구분하기 위한 비교군이다. 이 수치는 실행 전에 고정한
실험값이며 실제 로봇의 안전 기준이나 신원 확률로 검증한 값이 아니다.

세 조건에서 다음은 바꾸지 않았다.

- Pose의 관절·검출 신뢰도 조건, 추적기, 낙상 후보, 시각, 연결 구간 토큰.
- 약한 박스도 경쟁 후보에 포함. 약한 대상 박스를 빼고 주변의 강한 검출을 선택하지 않음.
- Cloud가 반환한 **모든** 위치에서 같은 대상·연결 구간 확인. 유리한 프레임만 선택하지 않음.
- 최신 관측·진행 중 사건의 연결 구간을 확인하는 실제 VLM 모듈의 사건 병합 로직.
- 정보가 없거나 연결하지 못하면 미확인 발견으로 기록. 다른 사람 사건에 넣거나 정상 처리하지 않음.

ReID 점수가 높아도 사용할 수 없는 추적을 살리거나 새 토큰을 만들지 않았다.
특징을 구할 수 없는 경쟁 후보가 있으면 외형을 모르는 것으로 처리했다.

## 입력과 실행 범위

- 이전 비교의 9개 장면, **전체 화면 Pose 결과**를 사용했다. 회전·구역 확대·중복 제거를 섞지 않았다.
- 다인 장면: SYN012(414), SYN045, SYN063, SYN067.
- 추가 점검: SYN011(413), SYN023(308), SYN028(410), SYN033(425), SYN036(435).
- 기존 Gemma·Gemini 응답과 Cloud에 보냈던 JPEG를 재사용했다. 영상·좌표·응답을 고치지 않았다.
- 171개 시점의 Pose 이력은 그대로 유지했다. 외형은 Cloud가 위치를 반환한 시각의 RGB에서만 구했다.
- 같은 프레임·같은 박스의 특징은 재사용했다. 외형 특징 68개를 계산했고, 별도 워밍업은 1회다.
- 각 장면에 3개 조건 × 2개 Cloud 모델을 적용해 총 54회 로컬 사건 병합을 재현했다.
- 정답 박스는 모든 연결·병합이 끝난 뒤 정확히 같은 프레임에서만 대조했다. 없는 정답은 보간하지 않았다.

Cloud에 새로 요청하지 않았고, Pose 모델도 다시 실행하지 않았다. 추가 API 비용은 0이다.
ReID 노드나 ROS 주행·따라가기 노드를 실행한 것도 아니다.

| 기존 사건에 연결 | 1 | 1 | 1 |

7개는 독립적인 영상 7개가 아니라 4개 영상에서 나온 Gemma 3개·Gemini 4개 응답이다.
Gemma SYN045는 이전 중복 JSON 오류 그대로 사용 불가이며, 연결률 분모에 넣지 않았다.
연결된 SYN045는 반환한 4개 위치 모두 검수한 낙상 의심 대상과 대응했다.
추가 5개 장면에도 새로 연결된 발견은 없었다. 정상 응답처럼 발견 박스가 없는 경우는
연결 실패 건수에 넣지 않았다. 정상 장면의 Pose 후보와 기존 사건은 그대로 유지됐다.

### 외형이 비슷한지는 비교할 수 있었음

정확히 같은 프레임의 검수 박스와 대조할 수 있었던 crop 쌍은 다음과 같다.

| 정답 박스와의 대응 | 비교 쌍 | 코사인 유사도 범위 | 중앙값 |
|---|---:|---:|---:|
| 같은 검수 인물에 대응 | 20 | 0.791~0.982 | 0.938 |
| 서로 다른 검수 인물에 대응 | 28 | 0.416~0.676 | 0.503 |
| 대응 확인 불가 | 9 | 0.517~0.948 | 0.603 |

같은 인물에 대응한 20쌍 중 19쌍은 유사도 0.80 이상이었다. 다른 인물의 28쌍에는
0.80 이상인 쌍이 없었다. 그러나 이 표는 여러 모델이 같은 프레임을 공유한 작은 개발용
표본이다. 같은 인물의 두 crop은 서로 겹쳐 같은 픽셀을 많이 포함하므로 높은 유사도가
나올 수 있다. **이 결과를 시간에 따른 사람 재식별 정확도나 일반적인 임계값 근거로 쓰지 않는다.**
겹침 기준 밖의 박스도 외형 진단용으로 계산했지만 연결 후보에 추가하지 않았다.

### 겹침 기준만 낮췄을 때 생기는 잘못된 선택은 막았음

SYN063의 Gemini 응답을 보자. 누운 사람을 가리키는 Cloud 박스 옆에 다른 사람이 있었고,
초기 세 반환 시각에는 Pose가 주변 사람의 박스만 제공했다.

- 기존 IoU 0.60 기준은 해당 박스와 연결하지 않았다.
- IoU만 0.20으로 낮추면 초기 세 위치에서 주변 사람을 골랐다. IoU는 약 0.296~0.338이었다.
- ReID를 추가하면 이 세 쌍의 유사도가 약 0.594~0.676으로 낮아 외형 불일치로 거부했다.

겹침 기준을 낮춘 비교군도 마지막 위치에서 추적 조건을 통과하지 못해 **최종적으로 잘못된
사건 병합을 하지는 않았다.** 따라서 이번 결과는 ReID가 느슨한 위치 비교를 보완한 사례이지,
기존 운영 방식보다 실제 사건 오연결을 줄였다는 증거는 아니다.

### 최종 연결이 늘지 않은 이유

- SYN012·SYN067: 누운 사람과 외형이 비슷한 박스를 골라도 초기 관측이 안정된 추적으로
  인정되지 않아 연결 구간 토큰이 없었다. 뒤쪽 프레임의 좋은 결과로 앞부분을 대신하지 않았다.
- SYN063: 초기 반환 시각에는 대상 Pose 박스가 없었다. ReID는 주변 사람을 거부할 수는
  있어도 검출되지 않은 사람의 박스나 추적 이력을 만들 수 없다. 마지막 대상 관측도 사용 불가였다.
- SYN011(413): 높은 외형 유사도가 나온 일부 위치도 정확한 사람 대응을 검수하지 못했으며,
  기존 불안정한 추적과 뒤쪽 대상 박스 부족 때문에 미연결로 남았다.

## 판단과 다음 단계

이번 비교만으로 운영 연결에 ReID를 추가하지 않는다. 외형 비교는 주변 사람으로 잘못
연결할 위험을 확인하는 보조 정보로 검토할 수 있지만, 사건 연결 개선은 없었다.

다음에 ReID를 더 검증한다면 **한 프레임의 VLM↔Pose 박스 비교가 아니라, 실제로 관측된
대상 박스들이 시간에 따라 같은 사람으로 이어지는지**를 별도 시험해야 한다.
동일한 옷, 가림, 누움·일어남, 추적 단절 후 재등장, 서로 가까운 두 사람을 포함하고,
연결 증가뿐 아니라 다른 사람 이력을 붙인 수를 함께 봐야 한다.
Pose가 처음부터 사람을 못 찾는 문제는 외형 비교와 별도로 해결해야 한다.

후속으로 [프레임 간 추적의 ReID 비교](FALL84_TEMPORAL_REID_20260927.md)를 실행했다.
이번 문서의 같은 프레임 실험과 구분하며, 그 결과도 사건 연결은 늘지 않고 일부 추적 ID와
정상 영상 확인 후보가 늘어 운영 반영하지 않았다.

이번에는 기존 9개 개발용 장면의 저장 응답을 즉시 전달했다. Cloud 지연 중 대상 이동,
전체 84개, 새 장면, Jetson, 실제 RGB-D, 음성 질문·주행·알림까지 검증한 결과가 아니다.
운영 코드·정답·Cloud 응답·다른 작업 중인 문서는 변경하지 않았고 커밋·푸시·Jira 수정도 하지 않았다.
