# 합성 낙상 영상 판단·채점 기준

- 버전: `fall-evaluation-v2-20260912`
- 상태: 사용자 합의로 고정. 변경이 필요하면 새 버전과 변경 이유를 남긴다.
- 범위: 합성 RGB 영상으로 YOLO-Pose 후보 생성과 VLM 판단을 비교하는 개발 평가.
- 모델 학습, 실제 부상·의식 상태의 진단, 실물 로봇 성능 검증은 아니다.
- 기준을 고정한 것이며, 평가 코드 반영·데이터셋 최종 확정·모델 재평가를 완료한 것은 아니다.

기계가 읽을 수 있는 동일 기준은 저장소의
`homecam_agent/evaluations/synthetic_fall_v1/scoring_criteria_v2.json`에 있다.
Mac 데이터셋에서는 `annotations/evaluation_criteria_v2_20260912/`에 두 파일을 함께 보관한다.

## 1. 판단 기준

| 라벨 | 저장 값 | 기준 |
|---|---|---|
| 낙상 | `observed_fall` | 넘어지는 과정을 봤고, 균형을 잃거나 의도치 않게 떨어지는 모습이 뚜렷하다. |
| 낙상 의심 | `suspected_fall` | 넘어지는 듯한 동작이 애매하거나, 처음부터 쓰러진 듯한 상태로 발견되어 사고인지 휴식인지 구분하기 어렵다. |
| 정상 행동 | `normal_activity` | 자발적인 자세 변경·휴식·일상 활동이 명확하다. 사람이 없는 영상도 포함한다. |

‘정상’은 ‘정상 행동’으로 표기만 통일한다. 사람의 판단 이유는 원문을 보존한다.

- 생성 프롬프트가 아니라 실제 영상에서 보이는 내용으로 판단한다. 생성 의도는 별도 기록이며 정답이 아니다.
- 넘어지는 과정을 못 봤다는 이유만으로 낙상 의심으로 분류하지 않는다. 처음부터 식사·청소·명확한 휴식 중인 경우도 있다.
- 침구, 동작 속도, 미동 여부 중 하나만으로 확정하지 않는다. 행동 전후의 흐름을 함께 본다.
- 넘어진 뒤 움직이거나 일어나도, 목격한 낙상은 낙상으로 남긴다.
- 미동이 없다는 것을 의식 소실이나 질문에 대한 무응답으로 바꾸지 않는다.
- ‘처음부터 누워 있음’과 ‘과정을 보지 못함’은 관측 메모다. ‘이미 쓰러짐’은 이 기준의 별도 분류가 아니다.
- 모델 응답을 보고 정답을 바꾸지 않는다. 사람의 재검토로 정답을 고치면 이유와 버전을 남긴다.
- 손·발 중복 등으로 판단에 지장이 있는 영상은 모델 비교 전에 품질 제외로 기록한다. 어려운 영상이나 모델이 틀린 영상이라는 이유로 제외하지 않는다.

## 3. 분류 채점과 확인 대상 채점을 분리한다

### 3.1 분류를 맞혔는가

유효한 모델 응답의 3분류가 정답 라벨과 같으면 1, 다르면 0이다.

`3분류 정확도 = 라벨을 맞힌 영상 수 / 평가 대상 영상 수`

VLM 단독 전체 평가의 현재 분모는 77이다. 낙상 의심 25개도 포함한다.
유형별 맞힌 수/전체 수(18, 25, 34)와 정답별 예측 분포를 함께 표시한다.
설명을 잘 썼다는 이유로 틀린 라벨에 부분 점수를 주지 않는다. 설명 내용 검수는 별도다.

### 3.2 확인이 필요한 영상을 놓쳤는가

정답과 모델 판단에서 낙상·낙상 의심은 ‘확인 필요’, 정상 행동은 ‘확인 불필요’로 묶는다.
‘확인 필요’는 질문·추가 관찰 등이 필요하다는 뜻이지 긴급 알림의 정답이 아니다.

| 정답 | 모델 판단 | 분류 점수 | 확인 대상 판단 |
|---|---|---:|---|
| 낙상 | 낙상 | 1 | 확인 대상 잡음 |
| 낙상 | 낙상 의심 | 0 | 확인 대상 잡음. 낙상 분류는 틀림 |
| 낙상 | 정상 행동 | 0 | 확인 대상 누락 |
| 낙상 의심 | 낙상 | 0 | 확인 대상 잡음. 낙상으로 과도하게 확정 |
| 낙상 의심 | 낙상 의심 | 1 | 확인 대상 잡음 |
| 낙상 의심 | 정상 행동 | 0 | 확인 대상 누락 |
| 정상 행동 | 낙상 | 0 | 불필요한 확인 |
| 정상 행동 | 낙상 의심 | 0 | 불필요한 확인 |
| 정상 행동 | 정상 행동 | 1 | 정상으로 판단 |

- 확인 대상 포착률: 확인 필요 정답 중 유효하게 낙상·낙상 의심으로 판단한 수 / 43.
- 정상으로 놓친 비율: 확인 필요 정답 중 정상으로 판단한 수 / 43.
- 확인 대상 미판정 비율: 확인 필요 정답 중 호출 누락·응답 실패·판단 불가인 수 / 43. 원인별로도 표시한다.
- 불필요한 확인 비율: 정상 정답 중 낙상·낙상 의심으로 판단한 수 / 34.
- 정상 영상의 실패·판단 불가는 정상 정답 처리하지 않는다. 따라서 불필요한 확인 비율의 나머지가 모두 정상 판단 성공인 것은 아니다.

낙상→의심을 ‘낙상 분류 미탐’과 ‘확인 대상 누락’으로 혼용하지 않는다.
두 채점 결과를 가중 합산하거나 모델 순위 하나로 합치지 않는다.

## 4. 비교할 세 경로

### YOLO-Pose

- 전체 평가 영상에서 낙상 의심 후보가 생겼는지 확인한다.
- 낙상·의심·정상 각각 후보가 생긴 영상 수/전체 수를 보고한다.
- 확인 필요 43개 중 후보가 없는 영상은 후보 생성 단계의 누락이다.
- 정상 34개에서 생긴 후보는 불필요한 확인 요청이다.
- 영상에 후보가 하나라도 생긴 비율과 올바른 사람을 잡은 비율은 다르다. 전자만 측정했다면 ‘영상 단위 후보 발생률’이라고 쓴다.
- 414에서 옆의 남성만 검출한 결과를 쓰러진 여성의 검출 성공으로 보고하지 않는다. 대상 연결을 확인할 수 없다면 확인되지 않았다고 남긴다.

### VLM 단독

- YOLO 결과와 무관하게 같은 평가 목록 전체를 입력한다.
- 전체 3분류 정확도와 확인 대상 채점을 보고한다.
- 입력 영상/프레임 추출 방식·모델 버전·프롬프트·제한 시간은 실행 전에 기록한다. 정답·판단 이유·생성 프롬프트·라벨을 드러내는 파일명은 모델에 보내지 않는다.

### YOLO-Pose → VLM

- 실제로 후보가 생긴 영상에 VLM을 호출한 결과를 사용한다. VLM 단독 결과를 골라서 실제 연동 결과처럼 쓰지 않는다.
- 전체 확인 대상 포착률의 분모는 43이다. YOLO에서 놓쳐 호출하지 못한 영상도 남겨서 단계별 누락을 보고한다.
- 호출 대상으로 선정된 모든 영상에서 VLM 3분류 정확도를 따로 계산한다. 의심 영상·호출 실패도 빼지 않는다. 분모는 선정된 영상 수이며 성공 응답 수가 아니다.
- 미호출과 정상 판단은 다른 상태로 기록한다. 미호출을 자동으로 정상 예측으로 채워 전체 3분류 정확도를 만들지 않는다.
- 전체 3분류 정확도가 별도로 필요하면 시스템의 미호출 처리 정책을 먼저 명시해야 한다. 지금 확정한 전체 경로 지표는 확인 대상 포착·누락이며, 호출 후 분류 정확도와 섞지 않는다.

한 영상에서 여러 후보·재시도가 생겨도 기본 단위는 영상 1개다. 어떤 후보와 최종 응답을 사용할지는 실행 명세에서 미리 정하며, 정답을 보고 가장 유리한 응답을 고르지 않는다.

## 5. 실패·판단 불가 처리

- 응답 실패, 시간 초과, 잘못된 형식, 판단 불가, 후보가 없어 미호출된 상태를 정상으로 바꾸지 않는다.
- 호출 대상으로 정한 영상의 실패는 분류 정확도 분모에 남고 정답 점수는 0이다. 실패 사유와 수량을 별도로 보고한다.
- 유효하게 받은 ‘낙상 의심’은 판단 불가 오류가 아니다. 세 분류 중 하나다.
- 실패를 확인 대상 포착 성공으로 세지 않는다. 모델 실패 후 질문·알림 등으로 보완하는 운영 정책은 이번 영상 평가와 별개다.
- 비교를 중간에 중단한 실행은 완료한 일부만으로 전체 성능이라고 보고하지 않는다. 완료/실패/미실행 수를 구분한다.
- 정답 파일 누락·해시 불일치 등 평가 준비 오류는 모델의 오답이 아니다. 준비를 고친 뒤 실행하며, 문제가 있는 사례만 조용히 제외하지 않는다.
- 모델별 제한 시간 수치·재시도 횟수는 아직 정하지 않았다. 실행 전에 고정해야 하며 이번 문서에 임의의 숫자를 넣지 않는다.

## 6. 아직 코드에 반영하지 않은 부분

2026-09-12 확인한 기존 코드에는 이전 기준이 남아 있다.

- `scripts/score_vlm_frames.py`: `found_down` 분리 및 의심 영상 제외 문구.
- `scripts/score_fall_baseline.py`: 의심 사례를 설명용으로만 집계하는 분기.
- `scripts/summarize_ollama_suite.py`: 이전 정답/출력 매핑과 미호출 처리에 따른 집계.
- `malbut_agent_server` 평가 스키마: 기존 `confirmed_fall`·`found_down`·`unobservable` 출력 체계.

이 기준 문서를 추가해도 위 코드가 자동으로 바뀌지 않는다. 다음 작업에서 3분류 출력, 실패 상태, 분모와 집계를 맞추고 테스트해야 한다.
기존 `found_down` 응답을 근거 없이 새 ‘낙상 의심’ 응답으로 변환해 재채점하지 않는다. 과거 응답을 재사용할 경우 별도 변환 규칙과 결과 버전을 먼저 정한다.

다음 순서: 기존 라벨 일관성 확인 → 평가 입력·출력/실행 조건 명세 → 평가 코드 반영과 테스트 → 목록 고정 → 모델 재평가.
이전 영상·라벨·평가 결과는 그대로 보존한다. 이번 작업은 기준 문서와 채점표 고정이며 모델 호출·학습·새 영상 생성·실물 시험·커밋은 포함하지 않는다.
