# 후속 사건 연결 — GPU 속도 비교와 다인 장면 재검토

2026-09-27. 운영 코드·로봇 설정은 변경하지 않았다. 평가 코드와 결과 문서만 추가했다.

## 결과

이번에 좋아진 것은 **영상 추적 속도**다. RTX 3070에서 SAM을 실행하고 BF16 혼합 정밀도를
사용하니, 추적 구간 처리 시간 중앙값이 이전 CPU의 46.85초에서 1.35초로 줄었다.
기존 사건에 연결된 영상은 움직임 장면 6개 중 5개로 같았고, 다인 장면 2개는 여전히 연결하지 못했다.

별도 실험으로 사람 위치 연결과 자세 판단 조건도 분리해 봤지만 연결 수는 늘지 않았다.
그 조건을 운영에 반영하거나, 성공 수를 늘리려고 검출 신뢰도·연속 관측 조건을 낮추지는 않았다.

## 1. 같은 입력으로 GPU에서 다시 추적

[앞선 CPU 검증](FALL84_DEFERRED_FRESH_ROS_VALIDATION_20260927.md)의 개발 영상 9개를 그대로 사용했다.
의심 대상이 있는 8개에서 SAM 155프레임을 새로 추론했고, 정상 대조 영상 1개에는 추적을 만들지 않았다.
YOLO-Pose 182개 관측과 Cloud 응답은 재사용했다. 새로운 API 호출·업로드·비용은 없다.

- 시작 박스: 기존 Gemma 응답에서 가장 이른 유효한 박스 하나.
- 모델: 동일한 SAM 2.1 Hiera Tiny 체크포인트, 전방 추적만 사용.
- 이미지: 동일한 640×400 JPEG, 촬영 시각·4Hz 표본·Pose 결과 해시 확인.
- CPU와 같은 `fill_hole_area=0`, 영상·상태 CPU offload 유지. 컴파일 최적화 미사용.
- GPU 실행은 FP32와 BF16 두 조건. TF32는 모두 끄고 4개 CPU 스레드 사용.
- CUDA 실행을 동기화한 뒤 시간을 기록해 비동기 요청 제출 시간만 재지 않도록 했다.
- 모델을 한 번 불러온 뒤 영상들을 처리했다. 별도 사전 warmup은 없으며 첫 영상에는 첫 실행 비용이 포함된다.
- 추론이 끝난 뒤 별도 채점 명령으로 승인된 사람 박스를 읽었다. 정답 박스로 추적을 수정하지 않았다.

| 실행 조건 | 구간당 최소 | 중앙값 | 최대 | 움직임 6개 중 기존 사건 연결 | 다인 2개 중 연결 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 이전 CPU FP32 | 33.75초 | 46.85초 | 47.06초 | 5 | 0 |
| RTX 3070 FP32 | 2.65초 | 3.69초 | 3.89초 | 5 | 0 |
| RTX 3070 BF16 | 1.00초 | 1.35초 | 1.60초 | 5 | 0 |

각 구간은 15~20프레임이다. 시간에는 JPEG 로딩·초기화·시작 박스 처리·추적·검토용 마스크 저장이
포함되며 최초 모델 로딩, Pose 추론, Cloud 요청, 음성 질문, 보호자 알림은 포함하지 않는다.
이전 CPU 시험에서는 ROS 테스트도 동시에 실행했으므로 정밀하게 통제한 장비 성능 비교는 아니다.
각 GPU 조건도 한 번씩 측정한 개발 시험이다.

시작 프레임을 제외한 프레임별 추적 계산 중앙값은 GPU FP32 0.188초, BF16 0.053초였다.
이 값은 전체 시스템 fps가 아니다. PyTorch 최대 할당 메모리는 각각 약 712MiB, 648MiB였으며,
CUDA 컨텍스트·캐시·화면 출력 등을 포함한 GPU 전체 사용량을 뜻하지 않는다.

### 속도만 빨라지고 연결이 달라지지는 않았나

- FP32는 CPU 결과와 155개 시점의 출력 박스가 모두 같았다.
- BF16은 155개 중 21개 시점의 박스 좌표가 달랐지만, 연결 대상과 연결/보류 이유는 모두 같았다.
- 두 GPU 조건 모두 검수 가능한 시작 이후 41개 시점에서 SAM 박스가 대상에 대응했다.
  실제 사건에 붙인 5개 연결 시점에서도 같은 사람으로 확인됐고, 잘못 붙인 사례는 없었다.
- 두 조건 모두 실제 모니터 처리와 SQLite 재생에서 기존 사건 ID에 Cloud 근거를 추가했다.
  9개씩 DB 재개방·중복 입력 검사를 통과했다.

위 결과는 **검수한 시점의 박스 비교**다. 모든 프레임의 신원, 완전 가림·교차 이후 재식별,
새로운 독립 데이터에서의 정확도를 검증한 결과는 아니다.

## 2. 다인 장면에서 막히는 지점

### SYN063: 누운 사람의 연결 가능한 Pose ID가 없음

SAM은 누운 사람을 따라갔지만 Pose에는 주로 옆 사람의 추적이 있었다. 뒤쪽 f108·114·120에는
누운 대상 근처의 약한 검출도 나왔으나 검출 점수가 약 0.12~0.14였고 추적에 배정되지 않았다.
따라서 같은 사람의 기존 Pose 사건에 붙일 근거가 없었다. 옆 사람에게 대신 연결하지 않았다.

### SYN067: 자세 조건을 분리해도 마지막에 추적 연결이 다시 끊김

기존 조건에서는 누운 대상의 박스가 있어도 자세 관절을 충분히 확인하지 못해
`associationUsable=false`인 구간이 있었다. 이를 구분하기 위해 기존 오프라인
`box_subject_frame` 실험을 후속 사건 연결에도 적용했다.

바꾼 것은 **위치 연결에도 자세 판단용 관절 품질을 요구하는 조건 하나**다.
검출 점수 0.45 이상, 실제 현재 관측, 확정된 추적 상태, 미배정 검출에 대한 보류,
IoU·경쟁 후보 차이·연속 3회/0.5초·현재 연결 토큰 조건은 유지했다.
위치 관측 상태는 항상 `unknown`으로 보내 정상·회복의 근거로 쓰지 않았다.
운영 ROS 형식을 통과한 것처럼 표시하지 않고 별도 실험 입력으로 전달했다.

| 조건 | 움직임 6개 연결 | 다인 2개 연결 |
| --- | ---: | ---: |
| 현재 연결 조건 | 5 | 0 |
| 자세 판단과 위치 연결 조건 분리 | 5 | 0 |

SYN067은 조건을 분리하면 중간 구간에서 연속 관측을 확보했지만, f114의 검출 점수가
0.4175로 0.45 미만이었다. 마지막 f120에서는 0.6214로 회복했으나 새 관측 구간의 첫 확인이어서
연속 확인 조건을 채우지 못했다. 결과는 `confirming_track`으로 남았다.

이 재생은 Cloud 응답을 영상 끝에 받은 뒤 과거 추적 결과를 제공한다. 과거에 한때 박스가
맞았다는 이유만으로 현재 확인되지 않는 사람에게 붙이지 않았다. 뒤쪽 영상이 더 있었다면
연결됐을 것이라고 계산하거나, 같은 프레임을 복사해 연속 관측 수를 채우지도 않았다.

## 3. 검증 범위

- 비교·표본·실험 연결·검수·기존 사건 연결 관련 테스트: **299개 통과**.
  이 중 새 테스트는 GPU 비교 제어 9개와 실험 연결/검수 7개다.
- 위치 실험의 대조군은 GPU BF16의 기존 사건 연결 결과 9개를 모두 재현했다.
- 위치 실험 두 조건, 9개씩 총 18개 재생에서 DB 재개방 및 중복 입력 검사가 통과했다.
- 정답 프레임이 없으면 가까운 프레임의 정답을 가져오지 않는지,
  다른 사람에게 연결한 결과를 성공으로 세지 않는지, 위치 입력이 `clear`를 주장하면 거절하는지 확인했다.
- 운영 소스·카메라 설정·Cloud 동의·연결 조건은 수정하지 않았다. 커밋·푸시·배포·Jira 수정 없음.

GPU 시험용 PyTorch 2.5.1+cu124 / torchvision 0.20.1+cu124는 별도 환경에 설치했다.
버전 조합은 [PyTorch 공식 이전 버전 설치 안내](https://pytorch.org/get-started/previous-versions/)를 확인했다.
기존 CPU 환경은 변경하지 않았다. 설치 도중 시스템 Python에 ensurepip가 없어 기존 환경의 pip로
새 환경에 설치했으며, 일반 실행·모델 로딩·CUDA 추론으로 설치 결과를 확인했다.

## 적용 판단과 다음 작업

**GPU에서 속도를 줄일 수 있다는 근거는 생겼지만, 아직 실시간 운영 적용은 하지 않는다.**
현재는 전체 구간 JPEG를 준비한 뒤 추적하는 오프라인 시험이다. 사건 연결 재생에도 측정된
SAM 지연과 실제 Cloud 지연을 더하지 않았으므로, 5/6을 실시간 연결 성공률로 사용할 수 없다.
이번 GPU도 RTX 3070이며 Jetson 성능은 미검증이다.

다음은 계속 들어오는 RGB·Pose를 받으면서 Cloud의 과거 박스부터 현재 프레임까지 추적하고,
그 결과를 기존 로컬 연결 입력에 넘기는 별도 연속 실행 시험이다. 촬영 시각·신선도 제한을
그대로 유지하고, 처리 지연·취소·카메라 OFF·다른 사람 교차를 함께 확인해야 한다.
다인 장면은 추적 점수 회복 이후까지 포함한 더 긴 영상이 필요하며, Pose 대상이 없는 경우에는
Cloud 발견과 확인 질문을 계속 별도로 유지한다.
