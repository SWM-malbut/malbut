# Gemma 공식 좌표 형식 v4 — 같은 9개 영상 재시험

SWM25-186 / 2026-09-26

후속: [Gemma·Gemini 전체 84개씩 재평가 결과](FALL84_NATIVE_BOX_REEVALUATION_20260926.md).
아래는 그 전에 진행한 9개 진단 시험 기록이다.

**Gemma Cloud에 새 요청 9회를 보냈고, 9개 모두 라벨 정답과 응답 검사를 통과했다.**
좌표 범위·크기 오류와 중복 JSON은 이번 실행에서 없었다. 다만 실제 이미지에 박스를
겹쳐보니 보이는 머리·팔다리를 빠뜨리는 장면은 남아 있다. 운영 코드는 아직 바꾸지 않았다.

## 바꾼 이유와 방식

이전 v3에서는 0~1 좌표를 강조했지만 검사까지 통과한 정답 수가 5/9개로 늘지 않았다.
[Gemma 공식 이미지 문서](https://ai.google.dev/gemma/docs/capabilities/vision/image)의
객체 검출 예제는 `box_2d: [ymin, xmin, ymax, xmax]`, 0~1000 좌표를 사용한다.
이번에는 그 출력 방식에 맞춘 평가용 조건 `native_boxes_v4`를 만들었다.

- 기존 v2의 낙상·의심·정상 판단 지시는 유지하고, 좌표 관련 지시만 교체했다.
  0~1 지시와 0~1000 지시를 동시에 넣지 않았다. v3의 추가 체크리스트는 사용하지 않았다.
- 모델에는 `box_2d: [위, 왼쪽, 아래, 오른쪽]`, 0~1000 정수 네 개를 요청했다.
- 평가 연결부에서 범위와 크기 조건을 확인한 뒤 내부 형식으로 고정 변환했다.
  `[top, left, bottom, right]` → `[left/1000, top/1000, right/1000, bottom/1000]`.
- 변환 후 기존 검사로 프레임 번호·순서, 라벨과 발견 내용의 일치 여부 등을 확인했다.
- 값을 잘라내거나 좌우·상하를 뒤집지 않는다. 숫자 크기를 보고 단위를 추측하지 않는다.
  박스 중 하나가 잘못됐다고 나머지 박스만 골라 통과시키지도 않는다.
- 원본 모델 응답과 변환한 응답을 모두 별도로 남겼다. 이전 결과는 변환하거나 재채점해
  덮어쓰지 않았다. 내부 명세의 0~1, `[left, top, right, bottom]`은 유지한다.

공식 문서와 다른 형식으로 요청했다는 사실만으로 이전 오류의 원인이 입증된 것은 아니다.
이번 변경은 단위·축 순서·필드 이름과 관련 문구를 함께 바꾼 시험이다.

## 시험 조건

- 모델: Ollama 직접 Cloud API `gemma4:31b`. 다른 모델 호출 없음.
- 이전 v3와 같은 진단용 9개: SYN001, SYN011, SYN014, SYN063, SYN079, SYN083,
  SYN004, SYN003, SYN022. 낙상 6개, 낙상 의심 2개, 정상 1개.
- 최근 5초의 RGB JPEG 12장, 입력 캔버스 640×400. 기존 이미지 바이트·메타데이터 유지.
  라벨·정답 박스·판단 이유·센서·음성·YOLO 결과는 보내지 않았다.
- `low_reasoning`: `think=false`, temperature 0, `num_predict=2048` 유지.
- 요청당 최대 20초, 자동 재시도 없음. 시간 초과 시 다음 영상으로 진행하는 조건.
- 사용자 승인: “그래그래 그렇게 하고 테스트해봐”. 이번 9회 실행부 한도 $0.10,
  요청당 예약 $0.01. 공급자 청구 상한을 보장하는 설정은 아니다.

## 결과

| 항목 | 이전 v2, 같은 9개 | 좌표 지시 강화 v3 | 공식 좌표 형식 v4 |
|---|---:|---:|---:|
| JSON에서 읽을 수 있는 라벨 정답 | 9/9 | 7/9 | 9/9 |
| 라벨 정답 + 응답 검사 통과 | 5/9 | 5/9 | 9/9 |
| 좌표 범위·크기 오류 | 4건 | 2건 | 0건 |
| JSON 형식 오류 | 0건 | 2건 | 0건 |
| 시간 초과 | 0건 | 0건 | 0건 |
| 응답 시간 중앙값 | 3.62초 | 3.63초 | 3.45초 |
| 사용량 기준 비용 | $0.00673638 | $0.00747528 | $0.00674678 |

v3의 라벨 정답 7개는 판단이 반대로 바뀌었다는 뜻이 아니다. 중복 JSON 2개를
프로그램이 하나의 응답으로 읽지 못해 정답으로 세지 않았다.

이번 v4도 9건 모두 바깥 JSON 코드 블록은 붙어 있었다. 이전부터 허용한 방식대로
**응답 전체를 감싼 코드 블록 하나만 제거**했다. JSON 일부를 추출하거나 뒤의 답변만
선택한 것은 아니다. 숫자 형식·순서 변환 외에 내용 수정은 하지 않았다.

낙상·의심 8개에는 모두 비어 있지 않은 위치 목록이 있었고, 총 28개 박스를 반환했다.
정상 영상 SYN022는 `findings: []`였다. 위치 목록을 비워 점수를 높인 결과는 아니다.

응답 시간은 HTTP 요청부터 응답 전체 수신까지이며 9건 모두 포함했다. 서로 다른
실행 시점에 한 번씩 측정했으므로 3.63초 → 3.45초를 속도 개선으로 단정하지 않는다.

비용은 응답 사용량에 [Ollama 공식 단가](https://ollama.com/pricing)를 적용한 추정치다.
2026-09-26 재확인: 100만 토큰당 입력 $0.14, 캐시 입력 $0.05, 출력 $0.40.
9건 모두 사용량을 받았으며 미확인 비용은 없다. 최종 청구서 금액과는 구분한다.

## 이전 오류가 있었던 사례

| ID | 이전에 확인한 문제 | 이번 결과 |
|---|---|---|
| SYN011 | 0~1 요청에 수백 단위 좌표 출력 | 새 0~1000 계약에 맞는 정수 출력·변환·검사 통과 |
| SYN014 | 가로는 소수, 세로는 수백 단위 | 네 값 모두 같은 정수 단위로 출력·검사 통과 |
| SYN063 | v2 좌표 오류, v3 중복 JSON | 한 JSON 객체로 반환·검사 통과 |
| SYN079 | v2 좌우 뒤집힘 | 범위·크기 조건 통과 |
| SYN003 | v3 중복 JSON | 한 JSON 객체로 반환·검사 통과 |

예를 들어 SYN014의 첫 박스는 `[143, 443, 483, 576]`으로 왔고,
내부에서는 `[0.443, 0.143, 0.576, 0.483]`으로 변환했다.
이전 `[0.44, 145, 0.58, 482]`를 추측해서 고친 것이 아니라 새로 받은 응답이다.

## 박스를 이미지에 겹쳐 확인

9개 사례의 검토 이미지를 생성해 모두 확인했다. 의심 발견 8개에서 반환한 28개 박스를
해당 입력 프레임에 그대로 그렸고, 정상 사례는 입력 3장을 확인했다.
이번 검토는 보조적인 육안 확인이며 정답 박스와의 IoU 측정이나 사람의 검수 승인이 아니다.

- SYN001, 프레임 6: 사람의 머리가 박스 위로 빠져 있다.
- SYN011, 프레임 5: 박스가 이불 쪽에 치우쳐 왼쪽으로 드러난 머리를 놓친다.
- SYN079, 프레임 6: 머리 윗부분과 팔·손 일부가 박스 밖이다.
- SYN063: 도와주는 사람의 얼굴 대신 바닥에 누운 사람 쪽을 잡았지만, 이것만으로
  여러 사람 사이의 대상 연결이 항상 정확하다고 판단하지 않는다.

따라서 **이번 9개에서는 좌표 출력 계약을 지켰지만, 사람의 보이는 몸 전체를 정확하게
감쌌다고 볼 수는 없다.** 범위 안의 정수만으로 축·단위 의미나 실제 위치까지 보증할 수도 없다.

## 적용 여부와 다음 확인

- 바뀐 부분은 평가용 프롬프트·좌표 변환·실행부 선택 연결·검증 코드다.
  운영 어댑터·낙상 도메인·서비스 명세는 변경하지 않았다.
- 같은 실패 유형을 골라 만든 9개에서 조건별 한 번씩 받은 결과다. 전체 84개의
  정확도 100%나 모든 좌표 오류 해결을 뜻하지 않는다.
- 다음에는 고정한 v4로 전체 84개를 평가하고, 기존 정답 사례에서 새 오류가 생기는지,
  빈 위치 목록이 늘어나는지, 실제 사람 위치와 사건 연결이 맞는지도 별도로 확인해야 한다.
  이번 턴에서 84개 호출이나 다른 모델 시험은 하지 않았다.
