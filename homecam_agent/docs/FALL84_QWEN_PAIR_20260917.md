# 같은 입력의 Gemma / Qwen 비교

## 결론

**현재 결과만으로 Qwen으로 일괄 교체하지 않는다.** Qwen은 후보 구간에서 의심 영상을
더 잘 남겼고 3분류 정확도도 높았다. 반면 전체 영상 정확도는 더 낮았고 명확한 낙상을
새로 정상/분석 불가로 놓쳤다. V034는 두 입력 모두 의심으로 남겨 개선됐다.

로컬 Qwen 실제 호출 124회(40 + 84)와 원본 입력·응답 재검증을 모두 완료했다.
124회 모두 JSON 형식은 유효했고 API 실패는 없었다. 그러나 전체 영상에서 4건은 모델이
분석 불가로 답했다. 형식 유효성과 정확한 판정은 별개이며, 이 4건도 정확도 분모에 남긴다.

## 비교 조건

- 84개 합성 개발 영상: 낙상 25 / 낙상 의심 25 / 정상 34.
- 기준 모델: 원래 A 설정의 로컬 `gemma4:12b`. 기존 측정 결과를 재사용한다.
- 비교 모델: 이미 설치되어 있던 로컬 `qwen2.5vl:7b`.
  digest: `5ced39dfa4bac325dc183dd1e4febaa1c46b3ea28bce48896c8e69c1e79611cc`.
- 맥의 Ollama 0.31.2, Q4_K_M. 실물 Jetson에서 실행한 결과가 아니다.
- 프롬프트·3분류 출력 스키마·12장 JPEG·시간·영상 구간·추론 옵션 동일.
  모델 값만 바꾸며, thinking 미지원 Qwen에서는 Gemma의 think=false 필드를 생략한다.
- 성능 악화로 기각한 출력 분리 형식/추가 문구 B는 사용하지 않는다.
- YOLO 후보 40개: 기존 39 + 새 V034 f077. 나머지 44개는 미호출 유지.
- VLM 단독: 84개 전체에 별도 실제 호출. 과거 41개/4분류 결과와 섞지 않는다.
- 모델 내부 이미지 처리·토큰화·템플릿은 모델마다 다르다. 같은 RGB 전송을
  같은 내부 토큰 처리라고 주장하지 않는다.

## YOLO 후 VLM: 완료

같은 40개 입력에 Qwen을 실제 호출했다. 40개 모두 유효한 JSON 응답을 받았다.

| 지표 | Gemma A | Qwen |
|---|---:|---:|
| 호출된 영상 3분류 정확도 | 25/40 (62.5%) | 30/40 (75.0%) |
| 낙상·의심 50개 중 확인 대상으로 남김 | 17/50 (34.0%) | 27/50 (54.0%) |
| 호출했으나 낙상·의심을 정상으로 판정 | 13 | 3 |
| 후보가 없어 호출하지 못한 낙상·의심 | 20 | 20 |
| 호출된 정상 영상의 불필요한 확인 | 0/10 | 2/10 |
| 요청 시간 중앙값 / p95 | 11.07초 / 12.71초 | 14.12초 / 15.64초 |

정상 34개 중 24개는 호출되지 않았다. 8/10 정상 판정을 32/34 모델 정답으로 늘려 계산하지 않는다.
낙상 또는 의심으로 남기면 확인 대상으로 세지만, GT 낙상을 의심으로 답하면 3분류 정답은 아니다.

### 확인된 장단점

- V034를 의심으로 남겼다. Gemma가 정상으로 단정하던 문제는 이 입력에서 개선됐다.
- 호출된 의심 15개: Gemma는 의심 2 / 정상 13. Qwen은 의심 13 / 낙상 1 / 정상 1.
- 호출된 낙상 15개: Gemma는 낙상 13 / 의심 2. Qwen은 낙상 9 / 의심 4 / 정상 2.
  Qwen은 확인 대상을 더 많이 남겼지만 명확한 낙상 판정까지 일괄 개선한 것은 아니다.
- Qwen이 새로 정상으로 놓친 낙상은 **107(SYN001), 307(SYN004)**이다.
- Qwen이 새로 의심으로 판정한 정상은 **410(SYN028), V029(SYN069)**이다.
  놓침 감소와 불필요한 확인 증가를 함께 봐야 한다.

## VLM 단독: 완료

| 지표 | Gemma A | Qwen |
|---|---:|---:|
| 전체 영상 3분류 정확도 | 59/84 (70.2%) | 55/84 (65.5%) |
| 낙상·의심 50개 중 확인 대상으로 남김 | 33/50 (66.0%) | 33/50 (66.0%) |
| 낙상·의심을 정상으로 판정 | 17 | 14 |
| 낙상·의심에서 분석 불가로 답함 | 0 | 3 |
| 정상 영상의 불필요한 확인 | 2/34 | 2/34 |
| 정상 영상에서 분석 불가로 답함 | 1 | 1 |
| 요청 시간 중앙값 / p95 | 10.28초 / 12.08초 | 16.40초 / 17.80초 |

정상 오판이 17→14로 줄었지만, 그만큼 분석 불가가 3개 생겨 확인 대상으로 남긴 총수는
33개로 같다. 분석 불가를 정상이나 올바른 확인으로 바꿔 계산하지 않는다.

### 어떤 분류에 차이가 있었나

| 실제 라벨 | Gemma 응답 | Qwen 응답 |
|---|---|---|
| 낙상 25개 | 낙상 22 / 의심 3 | 낙상 11 / 의심 7 / 정상 5 / 분석 불가 2 |
| 의심 25개 | 낙상 2 / 의심 6 / 정상 17 | 낙상 2 / 의심 13 / 정상 9 / 분석 불가 1 |
| 정상 34개 | 낙상 1 / 의심 1 / 정상 31 / 분석 불가 1 | 의심 2 / 정상 31 / 분석 불가 1 |

Qwen이 새로 정상으로 놓친 낙상은 **107, 413, V001, V002, V009**다.
또한 낙상 **422, 442**는 분석 불가로 답했다. 반대로 의심 영상의 확인 대상 수는
Gemma 8/25에서 Qwen 15/25로 늘었다. 즉 낙상에서 잃은 7개와 의심에서 늘어난 7개가
합계 지표에서는 상쇄된다. 합계 재현 수만 같다고 같은 약점을 가진 모델은 아니다.

분석 불가 응답의 설명은 '사람 동작/자세 변화를 확인할 수 없다'는 내용이었다.
이는 원래 정의의 '이미지 자체를 읽을 수 없음'과 다를 수 있다. 응답의 형식은 유효하더라도
판단 기준을 제대로 따른 것으로 간주하지 않았고 미해결로 남겼다.

후보 평가와 전체 평가는 같은 영상이라도 전달하는 구간과 12장 샘플링 시점이 다르다.
예를 들어 208은 Qwen이 후보 구간에서는 의심, 전체 영상에서는 정상으로 답했다.
추가 영상만 주면 항상 더 나아지는 모델이라고 볼 수 없으며, 이 차이를 영상 길이 하나의
효과로 단정하지 않는다. 모델 교체 외에 입력 샘플링의 영향도 다음 검증에서 분리해야 한다.

## 검증과 제한

- 관련 테스트 391개 통과. 원본 요청 불일치 차단, 모델만 변경되는지, 호출 수/중단/재시도 금지 확인.
- 첫 추론 전에 비교 대상 A의 실제 요청 124개를 모두 재구성해 검증했다.
- 소스·프로토콜 사본을 보존하고 각 요청/응답/결과를 즉시 저장했다. GT·사용자 이유·센서는 보내지 않았다.
- 완료 후 124개 A 요청 및 Qwen 요청을 다시 재구성해 같은 JPEG·시각·구간인지 검증했다.
  응답 원문을 다시 파싱한 결과, ID별 판정 및 모든 재집계 지표도 저장 결과와 일치했다.
- 입력 prompt_eval_count 최대 7,908 / 요청 num_ctx 16,384. 90% 이상 근접 사례는 없었다.
  이 사용량만으로 모델 내부가 모든 프레임에 주의를 기울였다고 보장하지는 않는다.
- 시간은 Mac/SSH 단일 요청 측정이며 로딩·이미지 처리 등을 포함한다.
  같은 시각에 모델을 교차 반복한 측정이나 실제 낙상 발생부터 조치까지 지연은 아니다.
- 이미 사람이 보고 개선에 사용한 합성 개발 데이터다. 독립 실환경 성능으로 해석하지 않는다.
- 모델을 운영 코드에 연결하거나 기존 기본값을 바꾸지 않았다.
- 유료 호출·새 모델 다운로드·모델 삭제·로봇 조작·배포·커밋 없음.
