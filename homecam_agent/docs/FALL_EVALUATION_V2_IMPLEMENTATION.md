# 3분류 평가 코드 반영 · 2026-09-12

이 문서는 `fall-evaluation-v2-20260912` 기준을 고정한 뒤의 구현 상태다.
고정 당시 문서·JSON의 `scorer_implemented=false` 기록과 과거 평가 결과는 덮어쓰지 않는다.
이후 [r1 합의](FALL_EVALUATION_CRITERIA_V2_R1.md)에 따라 모든 영상에 같은 채점을 적용하고,
정답의 판단 근거 메모를 점수와 별도로 보고한다. 원래 채점식·3분류 응답 형식은 유지한다.
새 실행은 r1 개정 기록 해시도 남기며, 사례별 정답 메모는 모델에 보내지 않는다.

## 반영한 내용

- `scripts/fall_evaluation_v2.py`: 3분류 응답 검증, 분류 정확도, 확인 대상 포착/정상으로 놓침/미판정, 정상의 불필요한 확인, 정답별 예측 분포.
- `scripts/replay_vlm_frames.py`: v1/v2 프롬프트·응답 검증 구분. 새 CLI 실행 기본은 v2. v1은 명시적으로 선택한 과거 방식에만 사용한다.
- `scripts/run_ollama_fall_suite.py`, `scripts/run_free_cloud_fall_suite.py`: 실제 호출 함수에 v2 연결. 새 계약에 평가 버전·프롬프트·스키마·검증 코드·기준 파일 해시를 기록한다.
- `scripts/score_vlm_frames.py`, `scripts/summarize_ollama_suite.py`: 저장된 실행 계약에 따라 올바른 평가 버전으로 읽고 보고한다. 과거 `found_down` 결과는 자동 변환하지 않는다.
- `scripts/score_fall_baseline.py`: v2 라벨 묶음에서는 의심 영상도 확인 대상 후보 포착/누락에 포함한다. 다른 사람 검출과 대상 연결 불확실성은 그대로 구분한다.

새 분류 응답 예시는 다음과 같다. 채점 결과나 정답 정보는 모델 입력에 넣지 않는다.

```json
{
  "outcome": "classified",
  "label": "suspected_fall",
  "explanation_ko": "처음부터 바닥에 누워 있어 사고인지 휴식인지 구분하기 어렵습니다."
}
```

`label`은 `observed_fall`, `suspected_fall`, `normal_activity` 중 하나다.
영상 자체를 관찰할 수 없는 출력은 `outcome=unobservable`, `label=null`로 기록한다.
낙상 의심과 관찰 불가를 같은 것으로 채점하지 않는다. 중복 JSON 키·추가 필드·잘못된 형식·불완전한 응답도 검증한다.

## 분모와 실패

- VLM 단독: 입력 목록 전체. 현재 목록을 그대로 확정하면 77개이며 의심 25개도 포함한다.
- YOLO→VLM 전체 확인 대상 포착: 확인 필요 정답 전체. 현재는 43개이며 YOLO 미호출도 미판정/누락에 남는다.
- 호출 후 분류 정확도: 호출 대상으로 선정한 영상 전체. 실패도 포함한다. 전체 경로 정확도라고 부르지 않는다.
- 미호출을 VLM 정상 예측으로 바꾸지 않는다. 전체 경로의 3분류 정확도는 임의로 만들지 않고 `null`로 둔다.
- 완료하지 않은 모델 실행은 전체 점수가 없다. 중간 실패와 저장된 결과는 보존한다.
- 새 suite의 일반 전송 실패·시간 초과는 재시도 없이 실패로 저장한다. 인증·결제·쿼터 등의 중단 보호는 유지한다.
- v2는 실행 전에 `--timeout`을 명시해야 한다. 재시도 0회, 한 영상에 여러 후보가 나오면 추가 호출 전에 중단하는 기존 제약을 계약에 남긴다. 여러 사건 처리로 자동 확대하지 않는다.

## 실행 전 검사

v2는 새 3분류 라벨 버전, 영상/라벨 ID 일치, 최종 확정 상태를 검사한 뒤 모델에 접근한다.
새 [77개 평가 묶음](FALL_EVALUATION_77_READY.md)을 만들었으며 그 묶음의 `full_dataset_finalized`는 true다.
이전 검토 원본의 false 기록은 보존했다. 새 묶음에는 원래 이유·보충 답변·근거 한계 메모를 포함했다.
모델·프레임 입력·응답 제한 시간 등 실행 조건은 아직 확정하지 않았으며 모델도 실행하지 않았다.

현재 결과는 [라벨·판단 이유 대조 결과](LABEL_CONSISTENCY_REVIEW_V2.md)를 참고한다.
모든 영상을 다시 본 것이 아니라 사람이 적은 판단 이유와 합의 기준을 대조한 기록이다.

## 검증

다음 테스트는 계산 함수, 가짜 저장 결과, 대체한 호출 함수만 사용한다. 실제 YOLO·VLM 추론이나 모델 다운로드를 실행하지 않는다.

```bash
python3 -m pytest -q homecam_agent/test homecam_agent/homecam_detector/test
```

- 3×3 채점 조합과 문서 표의 일치.
- 77=18+25+34 및 확인 대상 43이라는 예시와, 다른 크기의 입력에서도 분모가 동적으로 계산되는지.
- 실패·미호출·관찰 불가가 정상 또는 정답으로 들어가지 않는지.
- 부분 실행·중복 결과·다른 정답 버전·미확정 데이터 차단.
- 실제 보고서 로더/생성기의 v2 결과 처리와 과거 v1 테스트 유지.
- 로컬·무료 클라우드 호출 함수의 같은 v2 스키마 사용. 호출은 테스트 대역이며 실호출 호환성을 입증하지 않는다.

최종 테스트 실행 수와 코드 해시는 Mac의 `annotations/evaluation_v2_implementation_20260912/implementation.json`에 남긴다.
