# Gemma·Gemini 좌표 형식 변경 후 84개 재평가

SWM25-186 / 2026-09-26

후속: [저장 응답의 실제 박스 위치 점검](FALL84_NATIVE_BOX_LOCALIZATION_AUDIT_20260926.md).
추가 API 호출 없이 검수 박스와 정확히 같은 프레임을 대조하고 대표 장면을 확인했다.

**두 모델 모두 84개를 완료했다. 좌표 검사에서 탈락하는 응답은 줄었지만, 영상 판정 자체가
같은 폭으로 좋아진 것은 아니다.** Gemma는 라벨과 응답 검사를 모두 통과한 정답이
52개에서 71개로, Gemini는 55개에서 73개로 늘었다. Gemma에는 중복 JSON 1건이 남았고,
Gemini는 낙상 1개와 낙상 의심 1개를 정상으로 판단했다.

## 확인하려던 점

이전 84개 비교에서는 Gemma가 26개, Gemini가 20개 응답에서 박스 좌표의 범위나
크기 조건을 지키지 못했다. 낙상 판단이 맞아도 해당 사람을 연결하는 데 사용할 수 없는
응답이었으므로, 좌표 출력 방식을 바꾼 뒤 같은 영상을 다시 보냈다.

[Gemma 9개 진단 시험](VLM_NATIVE_BOX_V4_GEMMA9_RESULTS_20260926.md)에서는
9개 모두 라벨과 응답 검사를 통과했다. 이번에는 전체 84개에서도 유지되는지,
Gemini에서도 비슷한 변화가 있는지 확인했다.

## 바꾼 부분과 유지한 조건

[Gemma 이미지 문서](https://ai.google.dev/gemma/docs/capabilities/vision/image)와
[Gemini 이미지 문서](https://ai.google.dev/gemini-api/docs/image-understanding)의
좌표 방식에 맞춰 `box_2d: [ymin, xmin, ymax, xmax]`, 0~1000 정수를 요청했다.

- 기존 v2의 낙상·낙상 의심·정상 판단 지시는 유지하고 좌표 관련 지시만 교체했다.
  v3에서 추가했던 좌표 확인 체크리스트는 사용하지 않았다.
- 평가 연결부에서 네 값의 정수 여부, 범위, 상하·좌우 순서를 검사한 다음,
  `[top, left, bottom, right]`를 내부 `[left/1000, top/1000, right/1000, bottom/1000]`으로
  고정 변환했다. 내부 명세의 0~1 xyxy 좌표는 유지한다.
- 잘못된 값을 잘라내거나 뒤집지 않고, 단위를 추측해서 고치지 않는다.
  여러 JSON 중 하나를 골라 채점하거나, 잘못된 박스만 빼고 나머지를 통과시키지 않는다.
- 응답 전체를 감싼 코드 블록 하나를 제거하는 기존 처리는 유지했다.
  원본 응답과 변환한 응답은 각각 보관했다.
- 입력은 같은 합성 영상 84개(낙상 25 / 낙상 의심 25 / 정상 34), 최근 5초 RGB JPEG
  12장, 640×400이다. 기존 이미지 바이트를 유지했다. 정답·판단 이유·정답 박스·YOLO
  결과·센서·음성은 보내지 않았다.
- Gemma: Ollama 직접 Cloud API `gemma4:31b`, `think=false`, temperature 0,
  `num_predict=2048`. Gemini: Google 직접 API `gemini-3.8-flash`, thinking LOW,
  출력 한도 4096. 두 모델 모두 기존 비교의 옵션을 유지했다.
- 요청당 최대 20초, 자동 재시도 없음. 한 요청이 시간 초과돼도 다음 영상은 진행하는 조건이다.
  YOLO-Pose 이후의 대상별 확인이나 여러 모델을 나눠 쓰는 방식은 이번 평가에 포함하지 않았다.

단위·축 순서·필드 이름과 관련 문구를 함께 바꾼 시험이다. 결과가 좋아져도 어느 하나가
원인이었다고 단정할 수 없으며, 모델 내부의 오류 원인을 확인한 것은 아니다.

## 실제 사람 위치는 별도 확인 필요

Gemma 7개와 Gemini 진단용 9개의 입력 프레임에 이번 응답의 박스를 겹쳐 확인했다.
이 확인은 보조적인 육안 검토이며, 사람이 승인한 정답 박스와의 IoU 측정 결과는 아니다.
Gemma의 JSON 오류 사례는 박스를 임의로 추출하지 않고 입력 영상만 확인했다.

- Gemma SYN001 프레임 6: 보이는 머리 일부가 박스 위로 빠졌다.
- Gemma SYN011 프레임 5: 박스가 이불 쪽에 치우쳐 드러난 머리를 놓쳤다.
- Gemma SYN079 프레임 6: 머리와 팔·손 일부가 박스 밖에 있었다.
- Gemini SYN083 프레임 5에서도 머리 일부를 빠뜨리는 박스가 있었다.

숫자가 범위 안에 있고 상하·좌우 순서가 맞는 것과, 실제 사람을 정확히 감싸는 것은 다르다.
이번 점수는 여러 사람이 있는 장면에서 대상 연결까지 맞았다는 보증이 아니다.

## 이번 결과로 판단할 수 있는 범위

Gemma와 Gemini 모두 공식 예제의 좌표 방식으로 요청한 뒤 응답 검사까지 통과한 정답이
늘었다. 반면 영상 라벨 정답은 Gemma 72개 → 71개, Gemini 73개 → 73개였다.
이번 변경의 주된 효과는 좌표 때문에 응답을 사용하지 못하는 경우를 줄인 것이다.

Gemini의 이번 정답은 Gemma보다 2개 많지만, 낙상·낙상 의심을 정상으로 넘긴 2개가 있고
응답 시간과 비용도 더 들었다. 이 결과만으로 운영 모델을 교체하지 않는다.
Gemma는 중복 JSON 1건과 신체 일부를 놓치는 박스부터 추가 확인할 필요가 있다.
실제 박스 위치·대상 연결과 두 역할을 나눈 호출 흐름을 검증하기 전까지 운영 코드는 유지한다.

## 집계 기준과 남은 확인

- 라벨 정답은 JSON에서 읽은 판정을 정답과 비교한 값이다. JSON 오류나 시간 초과도
  전체 84개에 포함하며 정답으로 세지 않는다.
- 응답 검사까지 통과한 정답은 라벨이 맞으면서 필수 값·좌표·프레임 번호·내용 간
  조건도 만족한 수다. 박스의 실제 위치 정확도를 채점한 값은 아니다.
- 응답 시간은 요청부터 응답 전체 수신까지다. 형식 오류 응답도 포함한다.
  낙상 발생부터 보호자 알림까지의 시간은 아니다.
- 비용은 응답에서 확인한 사용량과 호출 당시 공식 단가로 계산한 추정치이며 청구서가 아니다.
  [Ollama 단가](https://ollama.com/pricing): 100만 토큰당 입력 $0.14 / 캐시 입력 $0.05 /
  출력 $0.40. [Gemini 단가](https://ai.google.dev/gemini-api/docs/pricing): 입력 $0.75 /
  캐시 입력 $0.075 / 출력·추론 $3.75. 추론 토큰을 중복해서 더하지 않는다.
- 각 조건을 한 번씩 실행한 비교다. 호출 시점과 응답 변동을 배제한 반복 실험이 아니며,
  실제 로봇 영상의 정확도나 전체 낙상 감지율로 일반화하지 않는다.
  프롬프트 점검에도 사용했던 영상이므로 새로운 영상에 대한 별도 검증으로 보지 않는다.
- 평가용 변경만 사용했고 운영 어댑터·낙상 도메인·서비스 명세는 바꾸지 않았다.
  운영 반영 전에 중복 JSON과 실제 박스 위치, 대상 연결을 별도로 확인해야 한다.

## 호출·비용·기록 확인

- Gemma는 전체 84개를 새로 호출했다. 이전 v4 진단 9개 응답을 재사용하지 않았다.
- Gemini는 같은 v4를 고정한 채 진단 9개, 나머지 중 45개, 미호출 30개로 나눠 실행했다.
  세 구간을 합쳐 서로 다른 84개다. 완료한 영상을 다시 호출하지 않았다.
- Gemini 54개 시점에 실행부가 멈춘 이유는 잔액이나 API 할당량이 아니다.
  SYN051의 사용량 기준 비용 $0.0256455가 요청당 예약 $0.02를 넘었기 때문이다.
  해당 응답은 HTTP 200으로 완료됐고 검사도 통과했다. 출력 3943토큰 중
  3657토큰은 내부 추론, 286토큰은 보이는 답변이었다.
- 사용자에게 확인한 뒤 Gemini 전체 실행 한도를 $1에서 $1.10으로 늘렸고,
  남은 30개는 요청당 $0.03을 예약해 진행했다. 추가 30개 비용은 $0.36082875,
  Gemini 84개 합계는 $1.00062675였다. 실행부 예약은 공급자 청구 상한 보장이 아니다.
- Gemma 84개 $0.06184748와 Gemini 84개 $1.00062675를 합쳐 **$1.06247423**이다.
  이전 v4 진단 9개 및 과거 v2/v3 비용은 이 합계에 넣지 않았다.
- 168개 모두 응답 사용량을 받았고 비용 미확인 요청·시간 초과·자동 재시도는 없다.
