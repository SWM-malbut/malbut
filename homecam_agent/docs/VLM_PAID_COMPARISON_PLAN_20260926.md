# Cloud VLM 비교 계획 · 답변 거부와 안전 차단

작성일: 2026-09-26 / 관련 티켓: SWM25-186

평가 기준과 함께 **공급자별 요청·응답 처리, 거부·차단 구분, 시간·비용 기록 코드**를
추가했다. 시험용 응답으로 검증한 뒤, 회사별 $1 예산으로 [9개 영상 시험](VLM_PAID_PILOT9_20260926.md)을
진행했다. 13개 중 8개 모델은 9개 호출을 완료했고, 나머지는 오류·시간 초과로 중단했다.
84개 전체 비교는 아직 진행하지 않았다.
API 키 없이도 입력 준비와 호출 전 점검을 할 수 있다. 실행 방법은
[유료 VLM 비교 실행 안내](VLM_PAID_RUNNER.md)에 정리했다.
SWM25-187의 운영 서버가 꺼져 있어도 평가 준비는 진행할 수 있다.
아래 비교는 운영 서버·로봇·Agent·웹 알림에 연결하지 않는다.

## 1. 비교할 모델

앞서 고른 신규 후보 12개와 기존 Gemma 1개를 비교한다. 아직 운영 모델을 교체하지 않는다.

| 회사 | 우선 후보 | 추가 후보 |
|---|---|---|
| OpenAI | GPT-6 Astra | GPT-6 Sol |
| Anthropic | Claude Opus 5.5 | Claude Sonnet 5 |
| Google | Gemini 3.8 Flash | Gemini 3.5 Flash |
| Meta | Muse Spark 1.2 | — |
| Alibaba | Qwen3.8 Max | Qwen3.8 Flash |
| Z.ai | GLM-5.3-Flash | — |
| Moonshot | Kimi K3 | — |
| xAI | Grok 4.7 | — |
| 기존 비교 기준 | Gemma4 31B Cloud / Ollama | — |

Google 신규 후보 두 개와 별도로, 기존 Gemma는 전후 비교를 위해 유지한다.
후보 선정 근거는 [Roboflow Vision Evals](https://playground.roboflow.com/evals)와
각 회사의 API 문서다. 공개 종합 점수는 낙상 정확도나 검열·거부 비율이 아니다.
정책 문서만으로 ‘검열이 적은 모델’ 순위를 만들지 않는다.
API 문서에 모델이 있다는 것과 우리 계정에서 사용할 수 있다는 것도 구분한다.

## 2. 입력과 실행 조건

| 항목 | 새 비교 기준 |
|---|---|
| 기존 자료 | 합성 영상 84개: 낙상 25 / 낙상 의심 25 / 정상 34 |
| 라벨·박스·이유 | 사용자가 검토한 최종본 유지. 정답과 생성 프롬프트는 모델에 보내지 않음 |
| 입력 | 같은 구간의 최근 5초, 시간순 RGB 최대 12장, 640×400 JPEG |
| 이미지 준비 | 한 번 추출한 같은 JPEG를 모든 모델에 사용. 원본 비율 유지, 잘라내기 없음 |
| 부족한 영상 | 실제 확보한 장수와 구간을 기록. 같은 프레임을 복제해 12장을 채우지 않음 |
| 소리·센서·Agent 답변 | 보내지 않음 |
| 요청 제한 | 응답 전체를 받을 때까지 최대 20초. 첫 토큰 도착을 완료로 세지 않음 |
| 재시도·대체 모델 | 기본 비교에서는 자동 실행하지 않음. 거부 뒤 다른 답을 얻어 첫 결과를 덮어쓰지 않음 |
| 프롬프트·출력 | 판단 지시와 결과 항목을 공통으로 사용. 회사별 API 포장만 다르게 함 |
| 모델 설정 | 실제 모델 ID·버전, 추론 설정, 출력 한도, 안전 필터 설정을 기록 |

같은 이름의 `low`나 같은 출력 토큰 수가 회사마다 같은 연산량을 뜻하지는 않는다.
지원하지 않는 설정을 억지로 넣지 말고 실제 사용한 값을 남긴다.
기본 안전 설정에서 시작하며, 허용되는 설정을 바꾸는 실험은 별도 조건으로 표시한다.
답변을 거부했다고 장면을 지우거나 프롬프트를 우회 문구로 바꿔 같은 실험으로 보고하지 않는다.

기존 `evaluate_runtime_cloud_frames.py`는 Gemma·Ollama 전용이며 `WINDOW_S=10.0`이다.
9월 19일 자료는 약 5초짜리 영상을 넣은 결과이지, 실행 설정이 정확히 5초였던 것은 아니다.
새 비교용 실행부에서 5초를 명시하고 추출 시각·이미지 해시를 확인한다.
과거 실행 코드·입력 해시·점수는 고치지 않으며, Gemma도 새 조건에서 다시 호출한다.

## 3. 답변 거부와 판단 불가를 구분

| 경우 | 기록할 결과 | 채점 |
|---|---|---|
| 영상 근거를 보고 낙상·의심·정상 중 하나로 답함 | 판정과 이유 | 정답 라벨과 비교 |
| 사람이 가려지거나 동작이 안 보여 판단할 수 없음 | `unobservable` | 0점, 분모 유지 |
| 모델이 정책 등의 이유로 답변을 거부함 | 답변 거부 | 0점, 분모 유지 |
| 공급자의 안전 필터가 입력이나 출력을 차단함 | 안전 차단 | 0점, 분모 유지 |
| JSON 또는 필요한 필드가 잘못됨 | 응답 형식 오류 | 0점, 분모 유지 |
| 20초 안에 응답을 받지 못함 | 시간 초과 | 0점, 분모 유지 |
| 인증·할당량·통신 문제로 실패함 | 해당 실패 이유 | 실패한 호출은 남기고, 미실행분을 성공으로 채우지 않음 |

안전 차단·거부를 새로운 정답 라벨로 만들거나 `normal_activity`로 바꾸지 않는다.
`unobservable`도 거부를 담는 용도로 사용하지 않는다.
같은 요청에 거부 문장과 차단 표시가 함께 있으면 한 번만 센다. 명시적인 공급자 차단 표시를
우선하고 원래 사유도 남긴다. 표시가 없고 답변 문장만 의심스러우면 검토 대상으로 남긴다.
‘확실하지 않다’는 설명이나 형식 오류만으로 검열이라고 세지 않는다.

공식 API의 다음 표시를 확인하는 코드를 추가했다. 실제 계정에서 모든 모델이 호출된다는 뜻은 아니다.

| 공급자 | 확인 항목 | 근거 |
|---|---|---|
| OpenAI | 구조화 응답과 별도로 반환되는 `refusal` | [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs#refusals) |
| Anthropic | `stop_reason=refusal`, 제공되는 경우 `stop_details` | [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback) |
| Google | `promptFeedback.blockReason`, `finishReason`, 안전 관련 사유 | [Safety settings](https://ai.google.dev/gemini-api/docs/safety-settings) |
| Alibaba | `DataInspectionFailed` 등 내용 검사 실패 코드 | [Error codes](https://www.alibabacloud.com/help/en/model-studio/error-code) |
| 나머지 공급자·Ollama | Chat 응답의 `message.refusal`, `finish_reason=content_filter` 등 명시적인 표시 확인 | 표시가 없는 거부 문장은 별도 검토. 실제 API 지원은 계정별 점검 필요 |

HTTP 성공이어도 거부일 수 있으며, HTTP 400·403만으로 안전 차단이라고 판단하지 않는다.
일반적인 인증 실패와 구분하려면 공급자가 보낸 사유를 확인해야 한다.

## 4. 결과에 함께 적을 항목

기존 주 지표는 그대로 둔다: **YOLO-Pose로 찾은 비율 / VLM 단독 정확도 /
YOLO-Pose 후 VLM 정확도**. 다음 항목은 그 옆에 따로 적는다.

- 낙상·낙상 의심을 정상으로 답한 수 / 해당 라벨 영상 수.
- 답변 거부 수, 안전 차단 수, 둘을 합친 비율. 중복 없이 실제 보낸 요청 수로 나눈다.
- 라벨별로 거부·차단 때문에 확인하지 못한 수. 정상 오판과 합쳐 숨기지 않는다.
- `unobservable`, 시간 초과, 형식 오류, 기타 요청 실패 수.
- 유효한 판정을 받은 요청의 응답 시간 중앙값·p95와 해당 건수.
  거부가 빨리 왔다고 판정 속도가 빠른 것으로 계산하지 않는다.
- 전체 요청의 종료 시간도 따로 보관하고, 20초 초과는 별도 건수로 표시한다.
  시간 초과한 요청이 실제로 몇 초 뒤 완료됐을지는 추정하지 않는다.
- 입력·출력·추론·캐시 사용량과 비용. 실패·거부에서도 청구된 비용을 포함하며,
  사용량을 받지 못한 요청은 비용 0원이 아니라 확인 불가로 적는다.

기존 84개 결과와 안전 차단을 확인하기 위해 추가한 장면의 결과는 분리한다.
기존 자료에 피·상처나 욕실 등의 조건이 없다면, 84개에서 차단이 0건이어도
그런 장면까지 차단하지 않는다고 결론 내리지 않는다.
이 자료는 이미 개선에 사용한 합성 데이터이므로 실물 성능을 보장하지 않는다.

## 5. 이제 진행할 순서

1. **호출 전 준비 — 실행부·시험 응답 검증 완료, 실제 입력 묶음 준비는 남음**
   - 최종 영상·라벨 목록과 5초·12장 입력을 고정한다.
   - 아래 소규모 점검에 쓸 영상도 새 모델의 결과를 보기 전에 정한다.
   - 회사별 호출·응답 변환과 거부·차단 집계를 추가한다.
   - 요청별 모델/설정, 입력 해시, 응답 결과, 종료 사유, 시간, 사용량을 남긴다.
     API 키는 결과 파일·로그·Git에 넣지 않는다.
   - 시험용 응답으로 거부·차단·형식 오류·시간 초과가 정상으로 바뀌지 않는지 검사한다.
     거부도 분모에 남고, 미호출은 정답으로 세지 않는지 확인한다.
2. **계정과 예산 확인**
   - 사용자가 각 회사의 계정·키와 호출 가능한 모델을 준비한다. 키는 대화나 문서에 적지 않는다.
   - 회사별 사용 한도와 전체 평가 예산을 정한 뒤 실제 호출을 시작한다.
   - 인증·잔액·할당량 오류, 예산 상한에 닿으면 멈추고 완료분을 보관한다.
     중단된 실행을 전체 평가가 끝난 것처럼 보고하지 않는다.
3. **소규모 점검**
   - 제안: 기존 자료에서 낙상·의심·정상 각 3개, 총 9개로 시작한다.
   - 13개 모델 모두 한 번씩 호출하면 최대 117회다. 정확도 순위 확정용은 아니다.
   - 이미지 12장 입력, 응답 형식, 거부 표시, 20초 제한, 비용 기록부터 확인한다.
   - 피·상처, 욕실·일부 피부가 보이는 장면 등 필요한 조건은 사용 허락이 있는
     성인 자료나 합성 자료로 별도 준비한다. 실제 사람에게 낙상을 시키지 않는다.
     먼저 품질·라벨·이유와 장면 조건을 검토하며, 기존 84개 점수에 섞지 않는다.
4. **84개 VLM 단독 비교**
   - 연결 점검을 통과하고 예산 안에 든 후보를 같은 조건으로 평가한다.
   - Gemma도 같은 시기에 다시 측정한다. 과거 측정값만 가져와 공정한 비교라고 하지 않는다.
   - 호출 순서를 번갈아 배치하고 날짜·모델 버전을 남긴다. 결과가 나온 뒤 프롬프트를
     바꾸면 새로운 실험으로 분리한다.
   - 정확도, 정상으로 놓친 수, 거부·차단, 시간, 비용을 나란히 보고 후보를 줄인다.
5. **남은 후보 재확인과 YOLO-Pose 후 비교**
   - 예산을 정해 반복 측정하고 평균과 변동을 함께 확인한다. 가장 잘 나온 회차만 고르지 않는다.
   - 최종 YOLO-Pose 코드·설정과 후보 목록을 고정한 뒤, 후보 시점까지의 영상에 실제 호출한다.
     예전 40개·52개를 그대로 최신 분모로 쓰거나 단독 결과를 가져와 대신하지 않는다.
   - 후보 밖에서 놓친 낙상은 YOLO-Pose 지표에 남긴다. VLM의 정상 정답으로 세지 않는다.
   - 선택 모델과 이유를 SWM25-186에 정리한다. 운영 연결 변경과 실물 검증은 별도 진행한다.

## 6. 선정할 때 볼 것

정확도 한 숫자로 결정하지 않는다. 낙상·낙상 의심을 정상으로 놓치는 경우와,
필요한 장면에서 반복적으로 답변을 거부하는 경우를 먼저 살펴본다.
20초 안에 답하는지와 호출 비용도 함께 비교한다.
거부율 몇 %에서 탈락시킬지 등의 수치는 아직 정하지 않았다. 수치가 확정되기 전에는
임의로 합격·불합격을 만들지 않고 사례와 건수를 보고 판단한다.

정책 때문에 분석하지 못해도 사건을 정상으로 끝내지 않고 확인하지 못한 이유를 남기는 것이
운영 연결의 기준이다. 질문·답변 및 필요 알림은 기존 사건 처리 규칙을 따른다.
‘검열 우회’나 미동의 공급자로 자동 전송하는 기능은 이번 비교 범위에 넣지 않는다.
