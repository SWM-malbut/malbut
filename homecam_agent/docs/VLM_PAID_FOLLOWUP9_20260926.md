# 유료 VLM 9개 영상 재평가

SWM25-186 / 2026-09-26

이 문서는 시간 초과로 중단했던 시점의 기록이다. 이후 사용자 요청으로 남은 23건을
완료한 결과와 비용은 [9개 평가 완료·84개 예상 비용](VLM_PAID_TIMEOUT_CONTINUATION9_20260926.md)에 정리했다.

## 진행 범위

Qwen은 사용자 요청으로 제외했다. [첫 시험](VLM_PAID_PILOT9_20260926.md)의 결과와
라벨은 그대로 두고, 오류 기록 보완 → Kimi 미호출분 → Meta·GLM 추론 강도 비교 →
답변 형식을 명확히 적은 공통 프롬프트 비교 순서로 진행했다.

처음 회사별 $1에 사용자가 추가 $1를 허용해, 회사별 누적 한도는 $2다.
예산을 회사끼리 옮기지 않았다. API 계정 전체의 강제 결제 상한은 아니다.

| 단계 | 실제 호출 | 결과 |
|---|---:|---|
| Kimi 기존 조건의 미호출분 | 1 | 20초 시간 초과로 중단 |
| Meta·GLM 추론 강도 low, 기존 프롬프트 | 18 | 각각 9개 응답 완료 |
| 답변 형식 설명을 추가한 공통 프롬프트 | 76 | 7개 모델은 각각 9개 완료. Meta·Claude는 중간에 시간 초과, Kimi는 보류 |
| 합계 | 95 | 시간 초과 3건 포함 |

새 프롬프트 비교는 Qwen을 제외한 11개 모델 × 9개, 99회 계획 중 76회를 실행했다.
아직 모든 모델의 재평가가 끝난 것은 아니다. 84개 전체 평가나 운영 모델 교체는 하지 않았다.

## 입력과 채점

- 첫 시험과 같은 합성 영상 9개: 낙상·낙상 의심·정상 각 3개.
- 각 영상의 마지막 5초, 시간순 12장, 640×400 JPEG. 소리·센서·정답 라벨은 전달하지 않음.
- 새 입력 묶음에서도 이미지 바이트, 촬영 구간 정보, 채점 라벨이 같은지 해시로 확인.
- 기존 지시문 뒤에 JSON 객체·박스 배열·0~1 좌표 범위 설명만 추가.
- 같은 모델의 추론 옵션은 단계별로 기록. Meta·GLM은 `low`, 나머지는 첫 시험 옵션 유지.
- 모델별 강제 JSON 모드는 이번에 추가하지 않음. 같은 텍스트 지시와 기존 검사로 비교.
- 요청부터 전체 응답까지 최대 20초. 자동 재시도 없음.
- 바깥 코드 블록 한 겹만 제거할 수 있으며, 답변 내용·박스를 고쳐서 정답으로 만들지 않음.

회사별 호출은 순서대로, 서로 다른 회사는 병렬로 진행했다. 모든 요청이 같은 순간에 처리된
것은 아니다. 각 조건은 한 번씩만 시험했으므로 서버 부하·캐시·응답 변동과 프롬프트 효과를
완전히 분리할 수 없다. 개선 폭을 통계적으로 확정하거나 최종 순위로 사용하지 않는다.

## 새 프롬프트로 9개를 완료한 모델

정답 수는 영상 판단을 맞히고 답변 형식 검사도 통과한 경우다. 형식 오류도 분모 9개에 포함한다.

| 모델 | 첫 시험 정답 | 새 프롬프트 정답 | 새 형식 오류 | 응답 시간 중앙값 | 시간 계산에 쓴 응답 수 |
|---|---:|---:|---:|---:|---:|
| GPT-6 Astra | 8/9 | 7/9 (77.8%) | 0 | 6.11초 | 9 |
| GPT-6 Sol | 5/9 | 7/9 (77.8%) | 0 | 6.71초 | 9 |
| Gemini 3.8 Flash | 3/9 | 6/9 (66.7%) | 0 | 3.30초 | 9 |

시간은 판정을 읽을 수 있는 응답의 요청→전체 답변 시간이다. 오답도 포함하되 형식 오류는
제외하므로 표의 응답 수가 다르다. 전체 요청 종료 시간과 p95는 별도 JSON에 보관했다.
이 시간은 낙상 발생부터 보호자 알림까지의 지연이 아니다.

GLM은 첫 시험과 추론 강도도 달라졌다. 아래 중간 시험을 따로 두어 차이를 구분했다.
Gemma는 주기적 확인의 사람 위치 반환까지 검사한 결과로, 예전 84개 영상 판정 점수와는
조건이 다르다. 이번 점수를 그대로 예전 성능 저하라고 해석하면 안 된다.

## Meta·GLM에서 확인한 것

첫 시험에서는 두 모델 모두 추론 강도를 명시하지 않았다. GLM은 공식 API 명세상 기본값이
`max`다. Meta는 생략 시 모델이 강도를 결정한다. 이 부분을 `low`로 명시해 별도 평가했다.
([GLM 공식 명세](https://docs.z.ai/api-reference/llm/chat-completion),
[Meta 공식 문서](https://dev.meta.ai/docs/reasoning))

| 조건 | Meta Muse Spark 1.2 | GLM-5.3-Flash |
|---|---|---|
| low + 기존 프롬프트 | 9개 응답, 정답 4개, 형식 오류 4개 | 9개 응답, 형식 오류 9개 |
| low + 새 프롬프트 | 6개 응답 후 7번째 시간 초과. 앞선 응답의 형식 오류 0개 | 9개 응답, 정답 5개, 형식 오류 0개 |

low + 기존 프롬프트의 전체 응답 시간 중앙값은 Meta 13.81초, GLM 9.00초였다.
새 프롬프트의 Meta 결과는 미완료이므로 9개 정확도로 계산하지 않았다.

GLM은 기존 프롬프트에서 `assessment: observed_fall`처럼 JSON 객체가 아닌 형태로
답하거나 박스를 문자열로 반환했다. 새 프롬프트에서는 이 문제가 사라졌다.
Meta도 기존 프롬프트에서는 0~1 대신 수백 단위의 좌표를 반환한 사례가 있었다.

다만 Meta는 low로 바꾼 후에도 다음 시험에서 20초를 넘겼다. 추론 강도를 낮추는 것만으로
20초 응답을 보장할 수는 없다.

## 남아 있는 판단·형식 문제

- 433 / SYN018: 정답은 낙상 의심. 새 프롬프트에서 Gemini 두 모델은 정상으로 답했다.
  형식 검사를 통과해도 의심 장면을 정상으로 넘기는 문제는 별도로 확인해야 한다.
- 441 / SYN019: 정답은 낙상 의심. Astra는 낙상, Sol은 낙상 의심으로 답했다.
- V020 / SYN060: 정답은 정상. Astra는 정상, Sol·Gemini 3.8은 낙상 의심,
  GLM·Grok·Meta는 낙상으로 답했다. 다른 응답은 형식 오류 또는 미호출로 구분했다.
- Gemma는 새 프롬프트에서도 박스에 `[0.44, 145, 0.58, 482]`처럼 서로 다른 단위의 값을
  섞어 쓴 사례가 남았다. 임의로 나눠서 좌표를 고치지는 않았다.

따라서 형식 오류가 줄어든 것과 영상 판단이 좋아진 것은 구분해야 한다.
Astra는 형식 오류가 없었지만 정답이 8개에서 7개로 줄었다. 이번 9개 결과만으로 모델을
바꾸거나 일반적인 인식 성능이 개선됐다고 단정하지 않는다.
