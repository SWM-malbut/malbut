# 검수한 다인 장면의 Pose 연결·사건 병합 시험

2026-09-27 / SWM25-186

4개 장면을 실제 YOLO26s-Pose ONNX로 다시 분석하고, 저장된 Gemma·Gemini 응답을
현재 대상 연결·사건 병합 코드에 넣었다. **Gemini의 SYN045만 기존 YOLO 사건에 연결됐다.**
Cloud가 사람 위치를 맞혔다는 것과, 그 사람을 Pose 추적·기존 사건에 연결할 수 있다는 것은 달랐다.

추가 API 호출·비용은 없다. 모델·프롬프트·운영 연결 기준·검수 정답은 바꾸지 않았다.

## 어떻게 시험했나

- 사용자 검수를 마친 SYN012(414), SYN045, SYN063, SYN067을 사용했다.
- Gemma·Gemini에 실제 보냈던 12장의 JPEG 해시, 원본 영상 해시, 원본 프레임 번호를 확인했다.
  두 모델의 입력은 같은 영상·프레임·JPEG였다.
- 이 12장을 모두 포함하도록 Pose 입력 시점을 맞추고, 그 사이 실제 영상 프레임을 추가했다.
  서로 이웃한 Pose 입력의 시간 간격은 0.2초 이상으로 유지했다. 이전 박스 복사나 좌표 보간은 하지 않았다.
- SYN012는 17장, 나머지 3개는 각각 23장, 총 **86프레임**을 새로 추론했다.
  Cloud 입력 프레임은 저장된 JPEG를 그대로 디코딩했다. 중간 프레임도 같은 640×400·JPEG 품질 90
  변환을 거쳤다. Pose 모델에는 원본 비율을 유지한 640×640 입력을 사용했다.
- 현재 `PersonPoseEstimator`, `PersonPoseTracker`, `FallCandidateDetector`를 실행하고,
  실제 후보 JSON을 `FallDetectorInput`에 전달했다. 검수한 사람 ID나 박스는 넣지 않았다.
- 로봇 움직임은 `unknown`, depth는 없음으로 두었다. 측정하지 않은 값을 정지 상태나 거리 0으로 채우지 않았다.
- 정확히 같은 촬영 시각의 Pose 기록으로 대상 연결을 시도하고, 현재
  `CloudFallMonitor._record_crosscheck`와 사건 병합 코드를 실행했다.
  검수 자료는 이 과정이 끝난 뒤 추적 대상이 누구인지 채점할 때만 읽었다.

### 이번 시험의 범위

이는 **저장된 Cloud 응답을 병합 단계에 넣는 오프라인 시험**이다.
운영 시점의 전체 호출 순서를 재현한 시험은 아니다.

- Cloud에 이미 보냈던 프레임을 보존하기 위해 RGB 버퍼에는 원래 12장만 넣었다.
  중간 프레임은 Pose 추적에만 사용했다. 운영 버퍼가 최대 5fps 입력에서 12장을 선택하는 과정은 별도 시험이 필요하다.
- 짧은 영상으로 60초 주기 확인을 재현하지 않았다. 후보 우선 스케줄러도 실행하지 않고
  병합 함수를 직접 호출했다. 아직 분석하지 않은 YOLO 사건의 `pending=True`도 임의로 지우지 않았다.
- Cloud 응답은 마지막 프레임 시점에 즉시 전달했다. 실제 응답을 기다리는 동안의 사람 이동,
  추적 소실, 최신 관측의 만료까지 통과했다는 뜻은 아니다.
- ROS 통신, 실제 음성 질문, 주행 중단, 보호자 알림은 실행하지 않았다.
- 이 4개는 문제를 살펴보기 위해 고른 장면이다. 전체 84개 대상 연결 정확도로 환산하지 않는다.

사람을 정확히 연결한 성공 사례로 세지는 않는다.

### SYN045: 기존 사건에 반영됨

Gemini가 반환한 원본 프레임 2·46·89·122에서 Cloud 박스와 대상 Pose 박스의 IoU는
각각 약 0.939·0.869·0.873·0.874였다. 같은 추적과 같은 연결 구간이 유지됐고,
검수 박스로 대조했을 때 모두 빨간 옷을 입고 누운 대상이었다. 앉아서 책을 읽는 사람과 구분됐다.

YOLO 사건 ID를 그대로 유지하면서 출처에 `cloud_crosscheck`와 영상 결과를 추가했다.
사건 수는 1개로 유지됐고, 재확인 횟수도 0에서 증가하거나 초기화되지 않았다.
동일한 저장 응답을 한 번 더 넣는 반복 처리 시험에서도 사건 상태·ID·질문 ID·횟수는 바뀌지 않았다.
추가 질문 이벤트나 제공자 호출도 없었다. 반복 입력에 대한 발견·분석 이력은 별도로 기록됐다.

반복 처리는 같은 응답을 다시 넣은 코드 시험이며, 새로운 주기적 Cloud 호출을 한 것은 아니다.

### SYN012: 박스는 겹치지만 추적 연결을 사용할 수 없음

첫 Cloud 입력인 원본 프레임 3에서 대상 박스의 검출 점수는 약 0.275로
현재 strong 기준 0.45보다 낮았다. 다른 애매한 검출도 남아 있었다.
Cloud 박스와의 IoU는 Gemma 약 0.646, Gemini 약 0.612로 현재 IoU 기준 0.60을 넘었지만,
그 프레임의 `associationUsable=False`여서 연결되지 않았다.

뒤 프레임에서 안정된 추적이 생겨도, 과거의 불확실한 프레임까지 같은 연결로 소급하지 않는다.
실패 코드는 `track_unusable`이었다. 단순히 IoU 기준을 낮춰 해결할 문제는 아니었다.

### SYN063: Cloud가 가리킨 대상의 Pose가 없음

앞부분에서는 곁에서 돕는 사람만 추적했고 누운 대상의 추적은 없었다.
대신 보호자의 박스에 연결하지 않았다. 마지막 프레임에서 누운 대상이 약하게 검출됐지만
아직 사용할 수 있는 추적은 아니었다. 두 모델 모두 `no_matching_track`으로 기록됐다.

### SYN067: 몸이 보이는 박스와 쓸 수 있는 자세 정보가 다름

초기에는 누운 대상 위치에 겹치는 약한 검출들이 있었다. 원본 프레임 2의 주요 대상 점수는
약 0.182였고, 자세 정보도 현재 사용 조건을 만족하지 못했다.
Cloud 박스와 IoU는 두 모델 모두 약 0.93으로 높았지만 연결용 추적 이력이 없어
`track_unusable`로 기록됐다. 뒤쪽 프레임 78·122에서는 사용 가능한 추적이 생겼지만
앞부분의 불확실성을 지우지는 않았다.

## 기록과 회귀 시험

- 미연결 발견은 SQLite의 `cloud_discoveries`에 사유와 함께 저장됐다.
- 최초 처리의 미연결 6건을 정상 처리나 기존 사건 종료로 바꾸지 않았다.
- 8개 모델·장면 조합 각각에서 DB를 닫고 다시 열어 사건·발견 기록이 같은지 확인했다.
- 새 재현 코드 시험 **25개**를 포함해 관련 회귀 시험 **492개 통과**.
  테스트 입력으로 만든 정상 연결, 약한 추적, 추적 단절, 겹치는 사람, 잘못된 박스,
  잘못된 JSON, 반복 병합, 동일 촬영 시각 처리 등을 확인했다.
- 영상·입력·모델·운영 코드 등 보존 대상 **152개 파일**의 해시가 실행 전후 같았다.

연결 가능 박스 관측은 늘었지만 이 4개 장면의 사건 연결은 기존과 같은 1건이었다.
낮은 검출 점수·대상 미검출이 남아 있어 운영 기준은 유지했다.

1. **사람 위치 연결에 필요한 정보와 낙상 자세 판단에 필요한 정보를 분리할 수 있는지 검토.**
   현재는 자세 관절을 충분히 확인하지 못하면 박스가 맞아도 연결을 사용하지 못한다.
   그렇다고 weak 검출을 모두 허용하거나 IoU 기준부터 낮추지는 않는다.
   다른 사람·중복 검출에 잘못 연결되는지 함께 확인해야 한다.
2. **앞부분이 불확실한 Cloud 응답을 어떻게 다룰지 검토.**
   사용할 수 있는 두 프레임만 골라 연결할 경우, 나머지 프레임의 모순이나
   추적 단절을 무시하지 않는 규칙이 필요하다. 이번 시험에서는 출력 프레임을 골라 버리지 않았다.
3. **실제 RGB/Pose 입력 주기와 버퍼 선택을 연결한 시험.**
   그때 만들어진 실제 입력으로 Cloud를 호출해야 한다. 다른 프레임에 대한 옛 응답을 재사용하면 안 된다.
   추가 API 호출은 이번에는 하지 않았다.
4. **Cloud 응답 대기 중 사람이 움직이거나 추적이 끊기는 경우 확인.**
   순간적인 대상 대조와 실제 응답 도착 시점의 사건 연결을 구분한다.
