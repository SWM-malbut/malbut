## Gemma 실행

1. `gated`: Pose를 새로 추론해 기준과 대조하고 처음 요청 시점까지의 영상으로 **39회 실제 호출**.
2. `full`: 전체 84개 영상에 **84회 별도 호출**. gated 결과를 재사용하지 않음.
3. 완료 모드만 3분류 정확도·확인 대상 포착률·미판정·오류·응답 시간을 집계.

다른 후보·시간·숫자가 나오면 VLM을 호출하기 전에 중단한다.
1배속 재생 시작부터 후보 출력·요청·응답·검증 완료까지 동일한 Linux monotonic 시계로 기록한다.
Mac과 Linux의 서로 다른 시계를 직접 빼지 않는다. 실제 로봇·ROS 동시 실행 결과는 아니다.
full은 전체 영상 수집 후 판단 준비 시간이다. 온라인 최초 감지 지연으로 부르지 않는다.
대상 연결 검토 전에는 올바른 낙상 대상의 감지 지연 중앙값/p95를 확정하지 않는다.

## 첫 실행 중단과 수정

첫 사전 대조에서 dataclass의 tuple과 저장 JSON의 list가 다르게 비교돼 중단됐다.
이때 VLM 입력·결과 파일은 0개였으며 영상 추론 API를 호출하지 않았다.
`vlm-run/`, `code-snapshot/`, `evaluation.log`는 원인과 이력을 위해 보존했다.

기존 프로세스 간 통신 때처럼 JSON 표현으로 대조하도록 수정했다.
숫자 반올림이나 허용 오차 완화는 하지 않았다. 실제 54프레임 재추론이 기준과 일치함을 확인했다.
그 후 새 폴더 `vlm-run-r2/`에서 시작했으나 첫 영상 요청이 HTTP 400으로 거절됐다.
Ollama 로그에서 설명의 `maxLength=4000`을 grammar로 변환할 때 반복 수 한도를 넘는 오류를 확인했다.
영상 판정 답변은 없었으며 이 실행과 오류 원문을 보존했다.

서버용 스키마에서 설명 maxLength만 생략하면 정상 JSON 응답이 도착함을 영상 없는 형식 검사로 확인했다.
전체 스키마는 프롬프트에 계속 넣으며 클라이언트는 여전히 4000자를 초과한 답변을 거부한다.
규칙·정답을 바꾸거나 일부 오답을 다시 호출한 것이 아니다. 형식 검사 결과는 영상 점수에 넣지 않는다.
서버용 스키마 및 해시를 명시한 새 조건으로 `vlm-run-r3/`에서 84개 평가를 다시 시작했다.
이전 중단 실행의 입력·오류·코드와 해시는 그대로 보존하며 현재 점수와 섞지 않는다.
