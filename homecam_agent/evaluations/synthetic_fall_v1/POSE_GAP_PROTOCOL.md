# 107 관측 누락 후 확인 요청 실험 — 2026-09-10

## 먼저 확인한 원인

107은 53·55·58프레임(4.417~4.833초)에 낮은 자세가 잡힌 뒤,
60·62프레임에는 Pose가 없다. 실제 낮은 자세 표본 3개의 간격은 0.417초라
기존 0.6초 지속 조건을 채우지 못한다. 끝까지 다시 잡히지 않으므로
‘재등장할 때 기록을 이어 사용’하는 수정만으로는 이 영상을 해결하지 못한다.

## 실험 조건 — 전체 결과를 보기 전에 고정

기존 모델·추적·저신뢰도 기준·낮은 자세 기하·빠른 낙상 전이 로직을 바꾸지 않는다.
원본 라벨·정답 박스·시간도 유지한다. 감지 코드가 아닌 별도 오프라인 모듈로 만든다.

1. 낮은 자세의 실제 관측을 최대 2초 동안 보관한다.
2. 같은 트랙이 `missing`이면 마지막 실제 관측 후 최대 0.5초 동안만 기록을 유지한다.
   애매한 연결, 연결되지 않은 Pose 존재, 관절 부족, 관측된 다른 자세, 시간 오류,
   해상도 변경, 트랙 만료 시에는 해당 관측 기록을 끊는다.
3. 다시 낮은 자세가 잡히면 누락 시간을 제외한 실제 인접 관측 간격만 합산한다.
   표본 3개 이상이고 이 합이 0.6초 이상이면 재확인 후보를 낼 수 있다.
4. 다시 잡히지 않아도 실제 낮은 자세 표본이 3개 이상이고, 실제 인접 관측 간격의
   합이 0.4초 이상이며 연속 2회 `missing`이면 **관측이 끊겨 확인 필요**를 요청한다.
   이때도 마지막 실제 관측으로부터 0.5초 이내여야 한다.

4번은 단순 누락 보존이 아니라 **짧게 본 낮은 자세 뒤 관측 불가를 확인 대상으로 삼는
새 정책**이다. 정상 행동·가림 때문에 요청이 늘 수 있다. 기존 0.6초 지속 조건을
충족했다고 표시하지 않는다. 낙상 확정, 회복 여부, 사람 부재를 판단하지 않는다.

출력은 기존 확인 종류 `found_down`과 함께 `low_pose_then_unobserved`라는 이유,
현재 Pose가 없다는 표시, 마지막 실제 관측 프레임·시각, 요청 시각을 별도로 기록한다.
누락 중에도 계속 누워 있었다거나 넘어지는 과정을 봤다는 뜻이 아니다.

## 평가 구분

- 낙상 동작 관찰: 대상에 확인 후보를 냈는지 평가한다. 넘어지는 동작 자체를
  인식했는지와, 이후 누운 모습을 보고 확인 요청했는지는 분리해 해석한다.
- 누운 사람 발견: 낙상 발생 확정과 별개로 발견 후 확인 후보가 나오는지 평가한다.
- 정상 동작: 불필요한 확인 후보가 나오는지 평가한다. 보호자 오알림 비율이 아니다.
- 낙상 의심·확정 불가: 출력 유무만 별도 기록한다. FN/TN이나 정확도로 해석하지 않는다.
- 관찰 불가: 주요 성능 집계에서 제외하고 건수·출력 유무를 남긴다.

원본 `expected_candidate_detection` 값은 기록을 위해 유지한다. 기존 21개 합산 수치는
비교 이력용 항목으로 옮기고, 이를 낙상 감지율로 표시하지 않는다.

## 같은 입력으로 세 가지 비교

1. 기존 기본 로직.
2. 기본 로직 + 이번 관측 누락 실험(이전 다리 배치 실험은 제외).
3. 기본 로직 + 다리 배치 실험 + 이번 관측 누락 실험.

41개 영상의 실제 ONNX 결과 1,106개와 트랙 연결을 그대로 재생한다.
실험 입력에는 영상 분류·대상자 정답·사건 시각을 넣지 않는다.
기준 알고리즘을 같은 입력으로 실행해 기존 기록과 UUID 접두사 외에 완전히 일치하는지
전 프레임 검사한다. 실험 조건을 결과에 맞춰 여러 번 변경하지 않는다.

과거 관측을 쓰는 요청은 마지막 실제 Pose 프레임을 해시로 묶인 실행 기록에서 찾는다.
요청 프레임에 옛 상자·관절을 복사하지 않는다. 과거와 요청 시각을 나란히 보여주며,
원본 RGB에서 대상자 연결을 별도로 확인한다. 마지막 관측이 사건 시작 전이면,
나중에 요청했다는 이유만으로 사건을 잡았다고 채점하지 않는다.

추가 요청 수·대상자·시각을 검토하고 정상 영상의 변화도 함께 보고한다.
이는 이미 검토한 합성 영상의 개발 실험이다. 실물 성능·VLM·질문·알림·배포는 포함하지 않는다.
