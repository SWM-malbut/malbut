# 합성 영상 VLM 비교 — RGB 프레임 입력 v1

## 이번에 확인할 것

기존 41개 합성 영상을 VLM에 직접 주었을 때 어떤 답을 하는지 확인한다.
YOLO가 놓친 영상도 제외하지 않는다. 낙상 감지기를 거친 영상만 넣지 않는다.
이 결과는 **영상을 받은 뒤의 판단**이다. YOLO가 놓쳤을 때 VLM을 자동으로
실행할 수 있다는 뜻은 아니다. 로봇 운용 코드, 알림, 실시간 감지는 바꾸지 않는다.
실제 낙상·음성 자료의 추가 수집은 이번 작업의 선행 조건으로 두지 않는다.

## 입력 고정

- 기존 `fall-baseline-20260910-frozen-v1`의 41개 RGB 영상과 해시를 사용한다.
- 첫 프레임과 마지막 프레임을 포함해 12장을 균등하게 추출한다.
  63프레임 영상은 0, 6, 11, 17, 23, 28, 34, 39, 45, 51, 56, 62번이다.
- 원본 640×400 유지, 크롭·박스·관절·문자 덧그림 없음, JPEG 품질 90.
- 모델에는 시간순 이미지와 각 이미지의 영상 내 시각만 준다.
  파일명, case ID, 정답, 낙상 시각, YOLO 결과, 추정 depth는 주지 않는다.
- 추론 코드는 `media.json`만 해석한다. 정답 파일은 해시 검증만 하고 채점 때 읽는다.
- 이미지 묶음 입력이므로 원본 동영상 입력과 구분한다. 이미지 사이의 빠른 동작은
  빠질 수 있다. 음성·실측 depth·대상자 답변도 평가하지 않는다.

## 실행 고정

- 최초 모델: 맥북에 설치된 `qwen2.5vl:7b`, GGUF Q4_K_M.
  실제 모델 digest, Ollama 버전, 호스트 설명을 실행 기록에 남긴다.
- 로컬 Ollama만 사용한다. 필요하면 SSH loopback 포트 포워딩을 이용한다.
  클라우드 모델, 자동 다운로드, API 키, 유료 호출은 사용하지 않는다.
- 공통 VLM 출력 스키마/시스템 프롬프트를 재사용한다.
  프레임용 사용자 프롬프트와 스키마까지 포함한 별도 해시를 기록한다.
- temperature=0, seed=0, num_ctx=16384, num_predict=1200.
  한 요청 제한 180초, 동시 요청 1개, 자동 재시도 0회.
  이 제한은 오프라인 실험 보호용이며 제품의 클라우드 제한 시간이 아니다.
- 첫 순번 1개로 입출력을 확인한 뒤 같은 설정으로 나머지를 진행한다.
  답을 보고 프롬프트를 고치면 새 실험으로 분리한다.
- 입력 프레임 해시, 실제 요청 해시, 원본 응답, 검증 결과를 영상마다 즉시 저장한다.
  중단된 요청은 조용히 재호출하지 않는다. 재개 시 완료된 영상은 건너뛴다.
- 파일은 0600, 결과 디렉터리는 0700. 설명에는 민감한 영상 내용이 포함될 수 있다.

## 채점

기존 사용자 확인 라벨을 유지한다. 애매한 5개를 임의로 낙상/정상으로 바꾸지 않는다.

| 정답 묶음 | 확인할 값 |
| --- | --- |
| 낙상 과정 관찰 14개 | confirmed_fall 수, found_down 수, 정상으로 판단한 수, 판단 불가 수 |
| 이미 바닥에 있는 사람 2개 | found_down 수, 보이지 않은 낙상 과정을 확정한 수 |
| 정상 행동 20개 | 정상 수, 낙상/쓰러짐 오분류 수, 판단 불가 수 |
| 애매한 장면 5개 | 답의 분포와 설명만 별도 보고. 낙상 확정 정확도에 섞지 않음 |

- 응답 실패, JSON 오류, 필드 간 모순은 별도 집계한다. 정상으로 간주하지 않는다.
- 위험 확인 필요 응답(found_down/confirmed_fall)과 낙상 과정의 정확한 분류를 구분한다.
  unobservable은 감지 성공으로 세지 않는다.
- 클립 단위 비교다. 다른 사람을 잘못 판단했는지는 설명/영상으로 추가 검토해야 한다.
- 처리 시간은 요청~응답과 프레임 추출 포함 시간을 모두 기록한다.
  최초 모델 적재 시간과 이후 실행을 구분한다. 영상 수집 시간과 제품 E2E 지연은 별개다.
- 이 41개는 이미 검토·튜닝에 사용된 합성 개발 자료다. 실제 낙상 성능, 고령자별 성능,
  야간·가림 안전성, Jetson 병행 실행 성능이나 최종 모델 우열을 입증하지 않는다.

## API 근거

[Ollama Vision](https://docs.ollama.com/capabilities/vision)의 REST `images` 배열과
[Chat API](https://docs.ollama.com/api/chat)의 JSON Schema 출력 및 실행 통계를 사용한다.
기존 `video_url` 어댑터를 Ollama에서 검증한 것처럼 취급하지 않는다.
