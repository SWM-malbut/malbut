# 주저앉음·미끄러져 내려옴 후보 실험 — 2026-09-10

## 범위

207·441은 Pose가 잡혀도 몸통이 수평으로 바뀌지 않아 기존 후보가 나오지 않았다.
기존 방식에 양쪽 다리의 상대적인 배치 변화를 보는 조건만 추가해 비교한다.
ROS 기본값·Pose 모델·입력 해상도·검출 기준·추적·누락 처리·GT는 바꾸지 않는다.
VLM 호출, 보호자 알림, 실물 로봇 실행은 하지 않는다.

## 결과 집계 전 고정한 첫 실험안

- 관절 신뢰도 0.5 이상. 양쪽 엉덩이·무릎·발목과 어깨 하나 이상 필요.
- 기존 몸통 품질 조건을 통과하고 몸통 기울기가 수직 기준 45도 이내여야 한다.
- 다리마다 `L = 엉덩이~무릎 길이 + 무릎~발목 길이`를 계산한다.
- `발목 y - 엉덩이 y`를 L로 나눈 값이 2초 이내에 0.45 이상에서 0.25 이하로
  줄고, 감소 폭도 0.25 이상이어야 한다. 양쪽 다리가 모두 만족해야 한다.
- 현재 `무릎 y - 엉덩이 y` / L이 양쪽 모두 0.05 이하이어야 한다.
- 조건이 연속 3회 만족해야 확인 후보를 낸다. 관절 부족·관측 누락 시 이어 붙이지 않는다.
- 기존과 동일하게 관측 간격이 0.5초를 넘으면 시간 기록을 끊는다.
- 같은 트랙에 이미 확인 요청을 냈다면 추가 결과는 근거 갱신으로 남긴다.
  이는 짧은 클립 비교용 중복 방지이며, 제품 사건 종료/재개 로직을 대체하지 않는다.

단순한 화면 이동이나 균일 확대·축소만으로는 이 비율이 변하지 않는다.
하지만 원근 변화·카메라 회전·관절 오인식까지 보정한 것은 아니다.
RGB 다리 배치는 실제 바닥 높이가 아니며, 앉기와 쓰러짐도 확정 구별하지 못한다.
출력은 `fall_suspected`(추가 확인 필요)이지 낙상 확정이 아니다.

## 비교 방법

- 기존 41개 영상/1,106프레임의 실제 ONNX Pose 결과와 트랙 연결을 그대로 재사용한다.
  신경망 추론을 다시 하지 않고 후보 로직만 다시 계산한다.
- 재구성한 입력으로 기존 후보 로직을 실행해 저장된 기준 결과와 전 프레임 일치하는지
  확인한 뒤 실험 결과를 집계한다. UUID만 비교에서 제외한다.
- 기존 동결 라벨과 동일한 대상자 연결·시간 기준으로 측정한다.
- 새로 나온 후보는 원본 RGB에서 대상자가 맞는지 확인한다. 코드 작성자 검토이며
  독립적인 블라인드 평가는 아니다.
- 207·441 변화, 전체 21개 확인 대상의 후보 생성, 정상 20개의 불필요한 확인 후보,
  최초 후보 시각, 기존 후보 보존, 추가 로직 처리 시간을 따로 보고한다.
- 신경망 처리 시간은 기존 실행 기록이며 이번 실험에서 측정한 시간이 아니다.
- 임계값을 여러 번 바꾸어 최적 결과만 고르지 않는다. 이번 첫 실험의 결과와 한계를
  그대로 기록한다. 개선이 있어도 실물·별도 영상 평가 없이 제품 기본값으로 반영하지 않는다.

이미 살펴본 합성 영상으로 하는 개발 실험이다. 일반화 성능이나 실물 미탐률을 뜻하지 않는다.
