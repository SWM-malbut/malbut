2026-09-10. **평가 집계를 분리했고, 107에는 마지막 실제 관측을 근거로 한 확인 요청이

## 1. 평가 집계 변경

원본 영상 분류·박스·시각은 수정하지 않았다. 평가 보고서 형식을 v2로 바꾸었다.

- 낙상 동작 관찰 14개: 대상에 확인 후보를 냈는지 평가.
- 이미 누운 사람 발견 2개: 발견 후 확인 후보를 냈는지 별도 평가.
- 정상 동작 20개: 불필요한 후보가 나온 영상 수와 요청 건수를 함께 평가.
- 낙상 의심·확정 불가 5개: 출력 유무만 기록. 명확한 낙상 미탐·정상 성공에 섞지 않음.
- 관찰 불가 0개: 주요 성능 집계에서 제외하고 건수·출력 유무만 기록.

따라서 **441은 그대로 의심 라벨이며, 명확한 낙상을 놓친 목록에는 들어가지 않는다.**
기존 21개 합산 수치는 `legacy_candidate_bookkeeping`으로 옮겨 비교 이력으로만 남겼다.

- **넘어지는 동작을 인식한 결과가 아니다.** 누운 모습 이후 관측이 끊겨 확인을 요청한 것이다.

## 4. 검증한 것

- 새 테스트 31개, 기존 관련 테스트 219개: **250개 통과**.
- 3개 최종 실험 각각에서 기존 알고리즘 재생 결과가 **1,106프레임 모두 일치**.
  비교에서는 무작위 UUID 접두사만 제외했다.
- Pose 관측·트랙 연결은 기존 기록과 값 단위로 같고, 기존 분석 결과도 모두 보존했다.
- 누락 요청만 쓴 안: 기존 요청 15건 그대로 + 107·108 각 1건 = 17건.
- 누락 전체 조건: 기존 요청 14건 유지, 410의 1건은 근거 갱신으로 보존 + 새 요청 4건 = 18건.
- 현재 관측이 없을 때의 근거 참조는 이전 실제 프레임·마지막 관측·같은 트랙·시각·
  관측 인덱스를 검사한다. 최신 관측이 아닌 오래된 프레임, 미래 프레임, 0.5초를 넘긴
  근거, 현재 Pose가 있는데 없다고 표시한 경우를 거부한다.
- 요청은 사건 시작 이후여도 실제 근거가 사건 시작 전이면 성공으로 세지 않는 테스트 통과.
- 누락 시간은 실제 관측 지속 시간으로 더하지 않는다. 현재 상자·관절을 만들어 넣지 않는다.
- 정상 영상의 요청 건수 증가가 영상 단위 비율에 가려지지 않는 테스트 통과.
- 변경 Python 파일 flake8(100자 기준), `git diff --check` 통과.
- 누락 요청만 쓴 안의 추가 처리 시간: 이 PC에서 중앙값 약 **0.011ms**, p95 **0.018ms**.
  캐시 재생의 추가 규칙 처리만 잰 값이다. YOLO·ROS·Jetson·VLM 지연이 아니다.
  보고서 `pipeline_ms`는 기존 실행에서 가져온 값이며 `timing_note`에 명시했다.
