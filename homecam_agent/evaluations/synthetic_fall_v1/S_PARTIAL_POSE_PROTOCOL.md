# s 모델의 부분 자세 확인 실험 (2026-09-18)

운영 코드는 변경하지 않는다. 아래 조건을 정한 뒤 동일한 84개 저장 출력으로 한 번 비교한다.
GT·영상 이름·라벨은 후보 생성에 전달하지 않는다. 검출·ID·기존 요청은 변경하지 않는다.
결과를 본 뒤 이 실행의 임계값을 소급 수정하지 않는다.

## 먼저 확인한 내용

- s 비율 유지의 요청 51건을 11개 JPG에서 직접 대조했다. 비블라인드 assistant 검토다.
- 낙상 21건 중 20건은 실제 대상자에게 붙었다. 413은 침대 위 이불의 큰 박스를 잡은
  found_down 요청이라 낙상 성공으로 세지 않는다. 확정된 사용자 라벨은 수정하지 않는다.
- 의심 16건은 확인 대상자에게 붙었다. 시간 라벨 없는 영상의 지연은 미측정이다.
- 정상은 13개 영상 14건. 425는 고양이, 나머지 13건은 정상 행동의 실제 사람이다.
  108의 2건은 같은 누운 사람의 전신 검출이 ID1→ID3으로 다시 생긴 경우다.
- V023은 보조자의 박스가 유지되지만 누운 사람은 f000, 106, 115, 120에만 별도 출력된다.
  f106은 자세 불충분, 마지막 정상 계산 가능 관측은 2개뿐이다. ID 연장만으로
  누락된 관절이나 사람을 만들어 내면 안 된다.
- V027은 머리·팔 관절은 보이나 골반이 약하다. V048은 높이 감소·하강이 보이는데
  최종 몸통/몸 축 조건을 동시에 충족하지 못한다.

## A: 상체만 반복해서 보이는 경우

감지 점수 ≥0.45, 관절 점수 ≥0.65, 양쪽 어깨와 한쪽 어깨·팔꿈치·손목,
머리 관절 1개 이상, 몸 관절 4개 이상을 실제로 관측해야 한다.
골반이 부족한 상황에서 박스 가로/세로 ≥1.5이고 머리와 어깨 높이 차이가
박스 높이의 0.35 이하여야 한다. 같은 추적에서 4관측·0.6초를 확인한다.
이는 누워 있음 확정이 아니라 `partial_upper_body_needs_review` 확인 요청이다.
앉은 사람·가림·잘못된 관절도 조건을 만족할 수 있으므로 정상 요청 증가를 함께 집계한다.

## B: 낮은 자세 각도가 불안정해도 실제 하강을 확인하는 경우

2초 이내 같은 추적의 실제 관측을 비교한다. 두 관측 모두 감지 점수 ≥0.45,
같은 이름의 몸 관절 4개 이상, 그중 어깨/골반 관절 2개 이상이 필요하다.
이전 박스 가로/세로 ≤1, 현재 ≥1.1, 높이 감소 ≥35%, 가로/세로 비 증가 ≥1.4배,
공통 관절 y 하강 중앙값 ≥이전 높이의 25%, 하강 속도 ≥0.35 body-height/s를 요구한다.
3관측·0.3초 동안 반복 확인한다. 미래 프레임이나 GT 시작 시각은 쓰지 않는다.
카메라 이동을 보정하지 못했다는 한계를 요청에 남긴다. 정상 착석·눕기도
통과할 수 있으므로 낙상 확정/자동 알림으로 사용하지 않는다.

## 비교와 보류 조건

- control / A / B / A+B를 고정된 s 출력 전체에 적용한다.
- 기존 요청이 있는 추적은 추가 확인을 새 호출이 아닌 근거 업데이트로 보낸다.
- 기존 n 결과 및 s 대조군을 보존한다. 입력 2,224프레임·533 GT 박스 불변을 확인한다.
- 증가한 모든 요청의 대상·실제 영상·정상 요청 비용을 검토한 뒤 채택 여부를 판단한다.
- 시간 불연속, 해상도 변화, 해당 추적의 대응 불명확, 관측 누락으로 추정 자세를 만들지 않는다.

  위치가 같다는 이유만으로 병합하면 다른 사람의 요청이 사라질 수 있다.
  근거가 없는 ID 병합은 이번 실험에 넣지 않는다.

## r3: 짧은 하강 근거 실험을 별도 추가

r1/r2의 B는 V048 f053·058에서 실제 하강 근거를 2개 모았지만 f062에서
속도 조건을 만족하지 못해 초기화됐다. 따라서 기존 B 결과는 보존하고,
**하강 후속 관측 2개·0.15초** 조건을 별도 비교군으로 추가한다.
비교 대상인 이전 관측도 별도로 필요하므로 단일 프레임의 박스 변화로 요청하지 않는다.
관절 대응·감지 점수·하강량·속도·형상 조건은 그대로 유지한다.

`brief_descent`, `partial_brief`를 추가해 6조건으로 다시 비교한다. 이는 이미 본
개발 영상의 실패를 참고한 추가 탐색이지, 미사용 평가 세트에서의 성능 입증이 아니다.
정상 요청 증가와 조기 요청의 대상·시점을 반드시 함께 확인한다.
