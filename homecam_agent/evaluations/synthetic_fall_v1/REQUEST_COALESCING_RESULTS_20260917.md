## 구현

- 원래 포함률 90%를 만족하면 기존대로 비교한다. 조금 부족한 경우에만 큰 박스의
  비교 경계를 작은 박스 폭·높이의 5%만큼 늘린다. 원래 포함률 85% 이상,
  여유 적용 후 90% 이상 조건을 함께 요구한다. 실제 박스는 수정하지 않는다.
- 같은 코·양쪽 눈과 한쪽 어깨·팔꿈치·손목의 대응 조건은 유지한다.
- 한쪽 검출이 잠깐 사라져도 실제 대응 기록을 0.5초까지 보관한다.
  양쪽이 보이는데 대응이 깨지거나 ID 연결이 모호하면 바로 취소한다.
- 실제 대응 3회 조건은 유지한다. 2회·0.2초 이상 확인되어 중복 가능성이 높은
  추가 found_down 요청만 최대 0.5초 기다린다. 최초 요청과 새 fall_suspected는
  기다리지 않는다. 시간 초과·대응 실패·입력 종료 때는 별도 요청으로 내보낸다.
- 이미 합친 요청은 직접 대응이 계속 확인되는 동안 유지한다. 새 트랙을 처음
  연결할 때의 요청 후 2초 제한은 유지하고, 관계가 끊어지면 유지 권한도 취소한다.
- 모든 ID·Pose·원래 후보·기존 갱신 원문을 보존한다. 요청 전달 시각과 근거 프레임을
  별도로 기록한다. 타이머가 처리한 요청에는 가짜 현재 프레임을 넣지 않는다.

새 파일은 `experimental_request_coalescing.py`, `replay_request_coalescing.py`,
`review_request_coalescing.py`, 테스트 2개, 프로토콜 및 이 결과 문서다.
기존 검출기·추적기·판단 조건·이전 실험 파일은 바꾸지 않았다. 운영 경로에 연결하지 않았다.
