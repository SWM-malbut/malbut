# 검출 모델·입력 방식 비교 — 2026-09-17

## 고정할 것

84개 합성 영상(낙상 25 / 의심 25 / 정상 34), 최종 사용자 승인 박스와 시각을 유지한다.
기존 영상은 이미 보고 조건을 조정한 개발 자료이며 블라인드 평가가 아니다.
5fps로 뽑은 실제 2,224프레임, 검출 하한 0.10, 추적·낙상 판단·후보 유지·중복 요청
처리는 직전 결과 그대로 둔다. 오디오·depth·실제 로봇 이동 정보는 없다.
GT 박스·분류·시각은 추론이나 설정 선택에 사용하지 않고 사후 비교에만 사용한다.

## 네 가지 조건 (결과 확인 전 고정)

| 조건 | 모델 | 전처리 |
| --- | --- | --- |
| n_stretch | 기존 YOLO26n-Pose | 기존 640×640 비율 변형 |
| n_letterbox | 동일 모델 | 비율 유지 후 회색 여백으로 640×640 |
| s_stretch | YOLO26s-Pose | 기존 640×640 비율 변형 |
| s_letterbox | 동일 s 모델 | 비율 유지 후 회색 여백으로 640×640 |

640×400 원본의 경우 stretch는 세로를 1.6배 늘린다. letterbox는 원본을 그대로 두고
위·아래에 120픽셀씩 여백을 넣는다. 큰 원본은 같은 비율로 축소한다. 없는 디테일을
생성하는 초해상화가 아니다. 모델 입력 크기를 960/1280으로 늘리는 실험도 아니다.
원본 좌표로 역변환하고 여백에 있는 관절은 유효 관절로 사용하지 않는다.
실제 영상 프레임, 모델 출력 원문, 변환 정보, 소스 해시를 기록한다.

모델·입력 방식의 영향을 분리하려고 2×2로 비교한다. n 대조군은 기존 결과와 실제
Pose·추적·판단·요청이 일치해야 한다. 새 가중치는 공식 Ultralytics v8.4.0 자산의
YOLO26s-Pose이며 배포자가 제공한 SHA256으로 확인 후 기존 환경에서 ONNX로 내보낸다.
학습/파인튜닝, 유료 API, VLM 호출, 실물·운영 변경은 하지 않는다.

공식 근거:
- https://docs.ultralytics.com/tasks/pose
- https://docs.ultralytics.com/reference/data/augment/#ultralytics.data.augment.LetterBox
- https://github.com/ultralytics/assets/releases/tag/v8.4.0

## 측정

1. 최종 검수 프레임의 사람 박스 대응 및 그중 자세 계산 가능한 대응.
   관절 GT가 없으므로 관절 위치 정확도/PCK/OKS를 측정했다고 하지 않는다.
2. 요청이 발생한 영상 수: 낙상/의심/정상 별도. 총 요청 건수·대기 시간도 별도.
   영상 내 아무 요청이나 있으면 대상자 검출 성공으로 간주하지 않는다.
3. 이전 대비 새로 잡힌/놓친 영상, 요청의 실제 대상 및 첫 요청 시각.
   후보의 원래 근거 시각과 중복 확인 후 전달 시각을 분리한다.
4. 원본 박스에 대응하지 않은 출력은 미대응 검출이라고 기록한다.
   부분 검출/중복/미검수 구간이 섞이므로 전부 배경 오탐이라고 단정하지 않는다.
   사람이 없는 408·425·436은 별도로 세고, 나머지는 실제 RGB로 확인한다.
5. 같은 PC CPU·ONNX Runtime·스레드 수로 추론 시간 평균/중앙값/p95를 측정한다.
   프레임 디코딩·모델 로딩·워밍업은 제외. 조건 순서는 프레임마다 순환시킨다.
   Jetson 동시 실행 또는 실제 실시간 지연의 측정값으로 해석하지 않는다.

기존의 단순 입력 크기 확대와 ROI 재시도는 이전 결과를 참고만 하고 이번에는 반복하지 않는다.
특정 영상만 다른 설정을 쓰거나, 결과를 본 뒤 임계값을 바꿔 최고 결과만 보고하지 않는다.
