# 누운 자세 변화와 사건 재확인 실험

범위: 기존 84개 개발용 합성 영상, 최종 검수 박스·라벨 고정. 운영 배포 아님.
413을 본 뒤 설계한 규칙이므로 독립 검증 결과로 해석하지 않는다.

## 실행 전에 정한 조건

- 누워 있던 관측에서 머리가 아래로 이동하고, 골반에 대한 상대 위치도 내려가면
  확인 후보를 만든다. 먼저 서 있었을 필요가 없다.
- 동일 추적 ID의 실제 관절만 사용한다. 박스 신뢰도 0.10, 관절 0.65 이상;
  코·양 눈·양 어깨·양 골반이 필요하다. 기준 관측 2개 이상, 기준 간 0.15초 이상.
- 최근 2초에서 머리가 기준 박스 높이의 0.25 이상 하강,
  골반 대비 0.15 이상 하강, 속도 0.20 박스 높이/초 이상.
  관측 간 0.5초 초과, 추적 모호함, 알려진 로봇 이동은 이 경로를 끊는다.
- 이 조건은 침대·바닥을 식별하거나 낙상을 확정하지 않는다. 자발적인 구르기,
  카메라 회전, 이불에 잘못 생긴 관절은 남은 오탐 원인이다.
- 첫 요청은 유지한다. 이후 새 낙상 동작, 누운 자세의 하강, 의심 자세 소실은
  같은 사건 재확인 대상으로 보관한다. 단, 매 관측에서 같은 위치의 머리가
  확인되는 기존 연속성 조건을 통과하면 자세 소실만으로 재호출하지 않는다.
- 일반 근거 추가/동일 경고 반복은 재호출하지 않는다. 새 변화 뒤 0.8초 영상 추가,
  최소 호출 간격 1초, 사건당 추가 2회. 소진은 정상 판정이 아니라 확인 필요다.
- 사건별 진행 중 호출은 1개. 호출 중 새 변화는 보관하고 응답 뒤 처리한다.
  첫 응답이 정상이거나 실패여도 새 변화는 버리지 않는다.
- 클립 종료 후에도 진행 중 요청의 완료를 기다려 이미 저장된 마지막 프레임까지
  재확인할 수 있다. 미래 프레임·GT·생성 프롬프트는 입력으로 사용하지 않는다.

## 비교

기존 호출 입력·응답은 해시가 같은 경우에만 재사용한다. 새 입력만 무료 Gemma
Cloud에 실제 호출한다. 원본 응답과 바깥 코드 블록만 제거한 보조 채점을 구분한다.
전체 84개를 재생하며 첫 호출/재확인/미호출을 분리한다. 기존 YOLO 대상자 일치
21/25를 자동으로 올리지 않는다. 재확인 성공은 YOLO 박스 정답과 별개다.

지연: 변화 감지 시각, 영상 추가 대기, 앞선 API 완료 대기, 실제 추가 API 왕복을
각각 기록한다. 저장 영상의 가상 시간 재생이며 실물 Jetson 종단 간 지연은 아니다.
기존 첫 API는 과거 실측 지연을 사용하므로 모든 API를 동시기에 재실행한 결과도 아니다.
