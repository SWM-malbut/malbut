## 입력·채점

- 묶음: `fall84-v2-r1-20260917`, 84개(낙상 25 / 낙상 의심 25 / 정상 34).
- `freeze.json` SHA256: `8cb8a2c97906cfccb84f040919951abc61bed0ee8da7864354d51c2ede0a34a2`.
- 기존 `fall-evaluation-v2-20260912-r1`의 3분류와 프롬프트를 사용한다.
- 의심 영상도 점수에 포함한다. 실패·무응답·미호출을 정상 답변으로 바꾸지 않는다.
- VLM 입력은 RGB 최대 12장, JPEG 품질 90, 원본 해상도 유지.
- 원본은 640×400/12fps 또는 1280×720/24fps다. 인코딩 해상도를 혼동하지 않는다.
- GT 박스·정답·판단 이유·파일명·생성 프롬프트·YOLO 요약·depth·음성은 VLM에 보내지 않는다.
- temperature=0, seed=0, num_predict=1200, num_ctx=16384, 지원 시 think=false.
- timeout=300초는 기존 비교의 실패 상한이다. 제품 목표 지연이 아니다. 자동 재시도 없음.
- 원본 응답과 프레임 해시를 저장한 뒤 검증한다. 실행 도중 원본 파일·기준을 바꾸지 않는다.
- Ollama의 grammar 변환이 설명 `maxLength=4000`을 처리하지 못하므로 서버용 스키마에서
  그 키 하나만 생략한다. 프롬프트의 전체 스키마와 로컬 4000자 검증은 유지한다.
  서버용 스키마와 해시도 실행 기록에 남기며 이후 모델에도 같은 조건을 적용한다.

## 실제 실행

1. Linux CPU에서 기존 YOLO26n-Pose(640 입력, 5Hz, 후보 임계값 0.10), 트래커,
   pose-loss 보조 신호와 요청 중복 억제를 같은 설정으로 평가한다. 튜닝하지 않는다.
2. `gated`: 같은 Pose를 새로 실행한다. 각 프레임의 관절·후보가 1번과 일치하는지 확인한다.
   처음 요청이 생긴 프레임까지의 RGB로 VLM을 1회 호출한다. 후속 영상 대기는 0이다.
   같은 짧은 영상에서 추가 요청이 나와도 다시 호출하지 않고 원본 로그에 모두 남긴다.
   이는 영상 단위 첫 호출 평가이며, 여러 사건/사람별 최종 대응 평가가 아니다.
3. `full`: 각 영상 전체에서 RGB 12장을 뽑아 별도로 실제 호출한다. gated 결과를 재사용하지 않는다.
4. 두 모드가 끝난 후 모드별 정확도·확인 대상 포착률·오류·미호출·요청 시간을 집계한다.
   부분 완료 영상만으로 전체 정확도를 발표하지 않는다.

## 지연 측정 범위

같은 Linux 컨트롤러의 `time.monotonic`으로 1배속 영상 시작, 프레임 예정 시각,
처리 시작, 후보 출력, 요청 시작, 응답 수신, 검증 완료를 기록한다.
CPU Pose와 Mac Ollama 사이 SSH 통신 시간을 포함한 재생 시험이다. Jetson/ROS 측정이 아니다.

- gated는 5Hz 원본 시각에 맞춰 처리하며 프레임을 버리지 않는다. 동기 VLM 호출 중 후속
  프레임 처리가 밀리면 대기 시간을 기록한다. 다음 영상은 이전 영상이 끝나야 시작한다.
- 추적기의 관측 간격 설정은 기존 재현 조건을 유지한다. 실제 카메라 큐·프레임 드롭 정책 검증과 다르다.
- full은 마지막 프레임이 도착할 때까지 기다린 뒤 호출한다. 결과는 전체 영상 수집 후
  판단 준비 시간이며 온라인 최초 낙상 감지 지연이 아니다.
- 요청·모델 적재 시간을 분리해 기록한다. 모델은 한번에 하나만 실행한다.
- 감지 지연은 낙상 시작 구간을 기준으로 계산한다. 음수를 0으로 자르거나 미탐을 지연 0초로 넣지 않는다.
- 다른 사람/배경 후보를 제외하는 대상 연결 검토가 끝나기 전에는 올바른 대상의 지연
  중앙값/p95를 확정하지 않는다. 미검토 연결은 모름으로 남긴다.

모델 호출은 무료 로컬 Ollama만 사용한다. 클라우드 호출·새 모델 전체 다운로드·요금제 변경·
로봇 제어·커밋·PR·기존 결과 덮어쓰기는 하지 않는다.
