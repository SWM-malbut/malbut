# Ollama 비교 진행 기록

2026-09-10. **전체 비교가 완료된 보고서가 아니다.**
실제 호출 결과와 실행 대기 중인 모델을 구분한다. 커밋·PR·배포·로봇 변경 없음.

## 이번에 추가한 검증

- Ollama 공식 Vision 목록의 계열·기본 크기별 태그를 조회하고 registry digest를 고정했다.
- 첫 목록 52개와 추가 목록 10개가 로컬 실행 후보다. 동일 가중치 별칭과 여러 양자화 버전은
  모두 별개 모델로 세지 않았다. 문서/OCR/번역 모델도 특수 용도 비교로 구분한다.
- 40GiB를 넘는 대형 가중치는 메모리 여유 기준으로 제외하고 사유를 남겼다.
  `qwen3.8-flash-next:latest`는 없지만 명시적 125B 태그를 추가 조회했고, 이 역시 용량 초과다.
- `gated`: 새 YOLO-Pose 추론 → 트래커 → 낙상 후보 → 실제 VLM 호출.
  후보가 나온 순간까지의 RGB만 전달했다. 기존 VLM 결과에서 해당 영상만 골라 세지 않았다.
- `full`: YOLO를 거치지 않고 영상 전체의 RGB 12장을 실제 전달.
- 프레임·원본 응답·오류·모델 digest·소스 SHA256·요청 시간을 저장하고 중간 결과를 보고서로 만든다.
- 원래 설치 모델은 보존. 사용자가 허용한 뒤, 새로 받은 모델 중 두 평가를 마친 정확한 태그만
  digest·완료 파일 해시·실행 중 여부 확인 후 삭제한다. 결과 파일은 삭제하지 않는다.
- 사용자가 유료 크레딧·자동 충전을 설정하지 않았다고 확인한 뒤 Cloud 평가를 시작했다.
  요청마다 Free 계정을 확인한다. 결제·크레딧 구매·계정 설정 변경은 하지 않았다.
  Gemma 4 31B는 두 평가를 완료했다. 나머지 후보 7개는 각각 첫 요청에서
  HTTP 402와 명시적인 '이 모델은 구독 또는 크레딧 필요' 응답을 받아 제외했다.
  제외 모델: Qwen3.5 397B, GLM 5.3 Flash, MiniMax M3, Kimi K2.6,
  Kimi K2.7 Code, Kimi K3, Mistral Large 3 675B. 해당 모델에 재시도하지 않았다.
  계정 전체 한도 소진으로 추측하지 않고, 모델별 접근 거부임을 확인한 뒤 다음 후보를 확인했다.
  7개의 거부 응답은 낙상 판별 결과나 정확도 0%로 집계하지 않는다.
  무료 플랜은 일부 모델만 제공한다([Ollama 요금 안내](https://ollama.com/pricing)).

## 실제 측정 완료분

### Qwen2.5-VL 7B · YOLO 연동

41개 영상을 처음부터 처리했고 16개에 실제 VLM 요청을 보냈다.
임의 ID 접두사만 제외한 새 관절·박스·후보·시각은 기존 고정 기준의 1,106개 표본과 일치했다.

| 항목 | 결과 |
| --- | ---: |
| 호출된 명확한 영상의 유효한 정답 | 12/15 · 80.0% |
| 전체 명확한 낙상 영상의 정답 | 10/14 · 71.4% |
| YOLO 후보가 없어 호출하지 못한 명확한 낙상 | 4/14 |
| 이미 쓰러진 사람의 유효한 정답 | 0/2 |
| 실제 호출 16건의 유효한 출력 | 13/16 |
| VLM 요청~응답 중앙값 | 16.50초 |
| 정상 영상 미호출도 정상으로 계산한 전체 경로 정답 | 29/36 · 80.6% |

애매한 5개는 정확도 분모에서 제외한다. 출력 오류는 분모에서 제외하지 않는다.
`29/36`은 정상 영상 17개가 호출되지 않은 것도 포함한 시스템 지표다.
**80%가 전체 낙상 감지율은 아니다.**
YOLO 호출 기준에서 빠진 404·413·422·442는 여전히 미탐으로 남는다.
208·414와 정상 영상 308은 최종 분류와 낙상 확률 값이 서로 모순되어 출력 검증을 통과하지 못했다.

전체 영상 직접 입력도 별도 41회 호출로 완료했다. 유효한 정답은 20/36(55.6%),
유효 출력은 29/41, 응답 중앙값은 16.64초다. 최종 분류 필드만 보면 26/36(72.2%)지만,
나머지 필드와 모순된 답변도 포함하므로 두 수치를 구분한다. 이전 실행 결과와 섞지 않았다.

### Qwen3-VL 2B 기본 태그

연동 16회 + 직접 입력 41회 = 57회 호출을 완료했다.
57회 모두 최종 `message.content`가 비어 있고 JSON처럼 보이는 내용이 `message.thinking`에
들어갔다. `think=false`를 실제 전송한 기록도 남아 있다. 이를 최종 답으로 임의 변환하지 않았다.
따라서 유효 출력은 0건이다. **모델의 시각적 낙상 판별 능력이 0%라는 뜻은 아니다.**
명시적인 Instruct 태그를 별도 비교 목록에 추가했다. 그 결과는 아직 나오지 않았다.

두 평가 종료와 모델 unload 확인 뒤 이번에 받은 `qwen3-vl:2b` 태그를 삭제했다.
필요하면 `ollama pull qwen3-vl:2b`로 다시 받을 수 있다.

### 추가 완료 모델

표는 애매한 영상을 제외하고, 출력 형식과 의미 검사를 통과한 정답만 센다.
연동 분모 15는 실제 VLM이 호출된 명확한 영상이며 전체 낙상 영상 수가 아니다.

| 모델 | 전체 영상 직접 입력 | YOLO 연동 | 응답 중앙값(직접/연동) |
| --- | ---: | ---: | ---: |
| Qwen3.5 0.8B | 15/36 · 41.7% | 9/15 · 60.0% | 2.59/2.59초 |
| MiniCPM-V 4.6 1B | 14/36 · 38.9% | 3/15 · 20.0% | 3.86/3.82초 |
| GLM-OCR | 0/36 | 0/15 | 3.73/3.61초 |

GLM-OCR는 문서 인식용 모델이다. 답변은 있었지만 사건 시각·필드 간 모순 등으로 모두
검증에서 탈락했다. 이미지 내용을 전혀 이해하지 못한다는 뜻으로 해석하지 않는다.
위 세 모델의 이번 다운로드 가중치는 두 평가 완료 후 삭제했고 결과는 보존했다.
Moondream 1.8B는 문맥 길이 조건 미달, Granite Vision 2B는 요청 오류로 평가가 중단됐다.
미완료 모델을 정확도 0%로 집계하지 않는다.

### Gemma 4 31B · 무료 Cloud

연동 16회 + 직접 입력 41회 = 57회 호출을 완료했다. 답변이 모두 JSON 코드 블록으로
감싸져 있어서 기존의 엄격한 JSON 파서는 거부했다. 원본·기존 점수는 그대로 보존했다.
모든 모델에 동일하게 **최종 답변의 코드 블록 한 겹만 제거**하는 보조 집계를 추가했다.
생각 과정(thinking)은 사용하지 않고, 누락된 필드나 판정값을 고쳐 넣지도 않는다.

| 보조 집계 | 전체 영상 직접 입력 | YOLO 연동 |
| --- | ---: | ---: |
| 최종 분류 필드 정답 | 33/36 · 91.7% | 13/15 · 86.7% |
| 코드 블록 제거 후 형식·의미도 맞는 정답 | 32/36 · 88.9% | 13/15 · 86.7% |
| 요청~응답 중앙값 | 3.59초 | 3.38초 |

서버 JSON 형식 강제가 없는 Cloud와 로컬은 요청 조건 차이가 있다.
이 결과는 별도 조건의 합성 개발 영상 결과이며 실물 성능이나 최종 모델 선정 결과가 아니다.

## 검증과 한계

- 새 추론 1,106프레임: 기존 동결 Pose 관측·후보와 일치, 확인 요청 16건.
- `homecam_agent/test`: **344 passed**.
- 새 스크립트·테스트 flake8(100자), `git diff --check` 통과.
- 미래 프레임 차단, 정답/파일명/후보의 프롬프트 미포함, 원문 우선 저장, 미호출 분모,
  무료 계정 확인, 크레딧 확인 없을 때 차단, 기존 모델/실행 중 모델 삭제 방지를 검사했다.
- 합성 개발 영상 41개: 낙상 14, 이미 쓰러짐 2, 정상 20, 애매함 5.
- 12장 RGB 이미지 입력이다. 실제 depth·음성·응답은 없다.
- Pose는 Linux CPU, 로컬 VLM은 M5 Pro Mac, Cloud VLM은 원격 서버다.
  두 평가 큐가 함께 실행 중이므로 전용 장비 성능이나 실시간 ROS·실물 동시 실행 지연이 아니다.
- Cloud는 서버 JSON 형식 강제가 없어 동일 본문 명세만 사용하는 별도 조건으로 측정했다.
- 전체 모델을 실행하려면 다운로드와 추론에 긴 시간이 필요하다. 잠자기·네트워크 단절·모델 오류는
  미완료로 남기며, 실패나 제외를 완료/0% 정확도로 바꾸지 않는다.
