# 중복 요청 경계 오차·짧은 누락 처리 실험

2026-09-17. 108의 박스·관절·요청 시각을 확인한 뒤 정한 개발 실험이다.
블라인드 평가가 아니다. 전체 결과를 보기 전에 아래 조건을 고정한다.

## 바꾸지 않는 것

- 최종 사용자 검수 박스, 84개 라벨(낙상 25 / 의심 25 / 정상 34), 시각.
- 실제 YOLO 출력, 트랙 ID, 낙상 후보 조건과 pose-retention combined 결과.
- 기존 실험 파일과 결과. 새 모듈은 오프라인 실험이며 ROS/제품에 연결하지 않는다.
- VLM·음성·알림 호출 없음. 검출·분류 정확도 개선 실험이 아니라 요청 중복 처리다.

## 비교 조건

1. control: 기존 처리. 원본 combined와 요청·갱신·ID가 같아야 한다.
2. geometry_gap: 박스 여유와 짧은 누락 보존만 적용. 요청을 기다리게 하지 않는다.
3. bounded_pending: 2번에 중복 가능성이 높은 추가 요청의 짧은 확인 대기를 더한다.

박스 면적비 0.5 이하, 코·양쪽 눈과 한쪽 어깨·팔꿈치·손목 대응은 기존 조건 그대로다.
원래 포함률 90%를 충족하지 못할 때만 큰 박스 경계에 작은 박스 폭/높이의 5% 여유를
준다. 원래 포함률은 85% 이상, 여유 적용 후 포함률은 90% 이상이어야 한다.
예측 박스·관절·GT 자체는 변경하지 않고 비교용 여유와 원래 포함률을 기록한다.

실제 동시 관측 3회, 첫/마지막 관측 시각 차이 0.3초 조건을 유지한다.
한쪽이 잠깐 missing인 경우 마지막 실제 대응부터 0.5초까지 기록을 보관한다.
양쪽이 보이는데 대응이 깨짐 / 미할당 / 모호한 연결 / 제3의 대응 / 시간·해상도 변화는
즉시 취소한다. 누락 프레임은 일치 횟수에 넣지 않는다. 전체 관측 구간과 실제 인접
일치 구간 합계를 별도로 기록하고, 누락 중 계속 같은 자세였다고 표현하지 않는다.

## 추가 요청 대기 (별도 비교 조건)

108의 추가 요청 시각에는 실제 대응이 2회뿐이어서 3회 조건을 낮추지 않는다.
이미 요청을 보낸 트랙과 유일하게 대응하고, found_down끼리이며, 현재 둘 다 보이고,
실제 대응 2회·관측 구간 0.2초 이상인 추가 후보만 최대 0.5초 기다린다.
최초 요청, 새로운 fall_suspected, 대응 근거가 없는 다른 사람은 즉시 요청한다.

- 0.5초 이전에 3회 조건까지 확인되면 기존 요청의 갱신으로 보낸다.
- 대응이 깨지거나 제한 시간이 되면 별도 요청으로 보낸다. 정상 처리/폐기하지 않는다.
- 새 프레임이 없어도 poll(now_s)로 기한을 처리하고 종료 시 남은 후보를 모두 보낸다.
- 트랙·후보 원문과 원래 프레임은 보존한다. 원래 후보 시각과 실제 처리 시각을 분리한다.
- 최대 대기는 단조 증가하는 호출자 시계 기준이다. 오프라인에서는 영상 시각을 이용해
  기한 타이머를 재현한다. 실물 스케줄러·실제 VLM 응답 지연 검증이 아니다.
- 틀린 대응이면 다른 사람의 확인이 최대 0.5초 늦어질 수 있다. 이 비용도 결과에 쓴다.

## 검사

84개 2,224프레임 재생. 후보 원문은 요청/갱신/대기 중 하나에 반드시 존재해야 한다.
모든 입력·소스 해시, 원본 대응, 영상별 요청 수, 모든 추가 병합의 근거를 기록한다.
최초 요청 지연, 대기 시간, 낙상 17/25·의심 15/25·정상 10/34 유지 여부를 확인한다.
이 수치는 영상 내 요청 발생 비율이지 대상자까지 검증한 재현율이 아니다.
108, 414 및 다인 영상은 최종 검수 박스와 실제 RGB로 추가 확인한다.
정답 박스는 사후 검사에만 사용하고 희소 프레임의 ID 대응을 다른 프레임으로 추정하지 않는다.

## 1차 재생 후 보완 (재평가 전 기록)

r1에서는 108의 f041 후보를 f046에 기존 요청으로 합쳤지만 f058의 기존 추가 근거가
첫 요청 후 2초를 넘었다는 이유로 다시 별도 요청이 됐다. 전체 요청 수는 그대로 43건이었다.
이를 숨기지 않고 다음 보완을 별도로 기록한다.

새로운 트랙을 처음 연결할 때는 기존의 요청 후 2초 제한을 유지한다.
이미 연결한 트랙은 실제 대응이 계속 확인되는 동안 같은 요청을 유지한다.
관계의 취소·만료·불일치·시간/해상도 변화가 한 번이라도 있으면 이 유지 권한도 즉시
취소한다. 이후 같은 ID로 다시 나타나도 새 연결의 2초 제한부터 적용한다.
새 낙상 동작은 이 유지 규칙으로 숨기지 않는다. 요청 시각을 갱신하거나 ID를 영구
별칭으로 만드는 방식은 사용하지 않는다. 이는 108을 본 뒤 수정한 개발 실험이다.
