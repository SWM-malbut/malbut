# 관측 누적 보완 1차 결과

## 바뀐 것

기존 YOLO-Pose와 기본 낙상 판단은 그대로 두고, 두 개의 오프라인 확인 요청 규칙을 추가했다.

- 낮은 자세 재관측: 잠깐의 명시적 검출 누락을 사이에 두고 실제 낮은 자세가 3번 이상 관측되면 확인 요청.
- 급변 뒤 재확인: 기존 규칙에서 급격한 변화가 한 번 잡힌 뒤, 후속 실제 자세 2개가 지지하면 확인 요청.

안 보인 구간을 관측한 것으로 채우지 않는다. ID 변경·모호한 연결·관절 구성 변경 등은 관측 이력을 끊는다. 로봇·서버·VLM 호출 경로에는 연결하지 않았다.

## 전체 84개 비교

최종 검수 박스와 기존 실제 Pose 출력 2,224프레임을 고정해 비교했다.

| 방식 | 낙상 영상에서 후보 | 낙상 의심 영상에서 후보 | 정상 영상에서 요청 발생 | 정상 영상의 실제 요청 건수 | 전체 요청 건수 |
| --- | --- | --- | --- | --- | --- |
| 기존 방식 | 15/25 (60%) | 15/25 (60%) | 10/34 (29.4%) | 10 | 40 |
| 낮은 자세 재관측만 | 16/25 (64%) | 15/25 (60%) | 10/34 (29.4%) | 11 | 42 |
| 급변 뒤 재확인만 | 16/25 (64%) | 15/25 (60%) | 10/34 (29.4%) | 10 | 41 |
| 두 규칙 함께 | 17/25 (68%) | 15/25 (60%) | 10/34 (29.4%) | 11 | 43 |

이는 영상 단위 확인 요청 발생률이다. VLM 정확도·낙상 확정 정확도·실제 대상자 감지율과는 다르다. 기존 요청이 있던 영상 중 후보가 사라진 영상은 없다.

위 지연은 녹화 영상의 시각 차이다. 실물 처리 지연이나 VLM 응답 시간은 아니다. 시작을 한 프레임으로 억지 확정하지 않고 사용자가 검수한 시작 구간을 유지했다.

V045의 요청 프레임 f096은 최종 정답 박스와 대상 대응이 확인된다. V040 f101에는 정답 박스가 없으므로 자동 대상 대응은 미확정으로 남겼다. 실제 f091·096·101 이미지에서는 해당 사람이 요청 대상인 것을 육안 확인했다. 이 육안 확인은 정답 박스 추가나 사용자 검수 대체가 아니다.

## 부작용과 남은 문제

정상 영상 수만 보면 10/34로 같지만, 정상 영상 요청 건수는 10건에서 11건으로 늘었다.

- 108: 자는 사람의 전체 몸에 붙은 ID 외에 얼굴 부분의 별도 ID에서도 요청이 생겼다. 실제 근거 이미지 f031·038·041에서 부분 검출을 확인했다. ID만으로 임의 병합하지 않았기 때문에 중복 요청이 남는다.
- 108·410: 기존에도 있었던 불필요한 최초 요청이 더 일찍 발생한다. 각각 약 1.667초, 0.667초 빨라진다. 정상 장면의 빠른 요청을 개선 성과로 세지 않는다.
- V005: 정상적으로 눕는 장면에서도 급변 뒤 재확인 근거가 추가됐다. 기존 요청에 근거 update로 붙어 요청 건수는 늘지 않았지만, 새 규칙이 정상 눕기를 완벽히 구분하는 것은 아니다.
- V032: 낙상 의심 영상의 최초 요청이 약 0.417초 빨라졌다. 검수된 사건 시작 시각은 없으므로 실제 감지 지연 감소로 확정하지 않는다.
- 207·V009는 이번 규칙으로 구제되지 않았다. 주저앉기·수평이 아닌 넘어짐 조건은 다음 별도 실험 대상이다.
- 404·431 등 Pose 출력 자체가 없는 문제도 그대로다. 이번에는 검출기를 바꾸지 않았다.

두 규칙을 합치면 추가 근거는 11건이다. 모두 새 호출이라는 뜻은 아니다. 기존 dedup이 근거를 원문 그대로 보존하면서 기존 요청의 update 또는 새 요청으로 연결한다. 전체 최초 요청은 40건에서 43건으로 늘었다.

추가 근거 11건의 요청 시점 이미지를 모두 확인했고, V040·V045·108의 근거 프레임은 별도 이미지로 묶었다. 전체 영상 연속 재생이나 정답 라벨 재검수는 하지 않았다.

- 새 Python 파일 3개 flake8, 최대 줄 길이 100 기준 통과.

- control의 기존 요청·근거·연결 결과가 입력과 동일한지 확인.
- 네 방식 모두 전체 84개·2,224프레임 처리. Pose 출력과 기본 판단 기록은 변경하지 않았고 기존 후보 근거도 보존했다.
- 합친 방식의 보조 처리·복사·dedup 시간: 중앙값 약 0.277ms, p95 약 0.541ms, 최대 약 55.9ms. 로컬 CPU 측정이며 모델 추론·VLM·로봇 부하는 포함하지 않는다. control에도 복사·dedup 비용이 있으므로 순수 추가 알고리즘 비용으로 해석하지 않는다.
- VLM 호출 0, 유료 호출 0, 새 모델 추론 0. 모델·정답 박스·라벨·원본 미변경.

설정은 결과를 보기 전에 [실험 계획](POSE_RETENTION_PROTOCOL.md)에 고정했다. 첫 실행 r1은 채점 코드가 한 프레임만 넘겨 전체 검수 프레임을 요구하는 함수와 충돌해 중단됐다. 이를 회귀 테스트로 보완한 뒤 r2를 실행했고, 결과 집계와 코드 정리 후 r3를 최종 기록으로 남겼다. 이 과정에서 실험 임계값은 바꾸지 않았다.
