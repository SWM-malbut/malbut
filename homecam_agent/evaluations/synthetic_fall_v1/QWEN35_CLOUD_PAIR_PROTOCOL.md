# Qwen3.5 / Gemma Cloud 비교 (2026-09-17)

## 고정 조건

- 이번 대상: Qwen3.5 4B, Qwen3.5 9B 로컬 GGUF 기본 태그와 Gemma4 31B Cloud.
- 승인된 84개 합성 개발 영상: 낙상25 / 낙상 의심25 / 정상34.
- 기존 Gemma4 12B A와 Qwen2.5-VL 7B의 같은 입력 결과도 함께 표기한다.
- 후보40개(기존39 + V034 f077), 전체84개: 모델당 새 호출124회, 총372회 예정.
- 과거 41개 평가와 섞지 않는다. 새 라벨링, YOLO 실행, 후보/임계값 변경 없음.
- 원래 A의 프롬프트, 시간순 RGB JPEG12장, 시각, 구간, 채점 기준을 그대로 쓴다.
  모든 예정 요청을 첫 추론 전에 재구성해 원래 요청 해시를 검증한다.
- GT/판단 이유/파일명/사건 ID/YOLO 관측/센서/음성을 모델에 보내지 않는다.
- temperature=0, seed=0, num_ctx=16384, num_predict=1200 요청. thinking 비활성.
  300초 제한, 자동 재시도 없음. 응답 형식 실패/분석 불가/미호출을 정상으로 처리하지 않는다.
- 정확도: 전체84개, 후보 후40개. 의심25개도 정답에 포함한다.
  확인 대상으로 남긴 낙상·의심 / 정상 오탐 / 정상으로 놓친 사건도 별도로 본다.

## 실행 및 Cloud 차이

- 로컬 두 모델은 같은 맥에서 순차 실행한다. 동시에 올려 메모리 경쟁을 만들지 않는다.
  Cloud 큐는 별도 실행할 수 있으며, 추론 동시 요청은 Cloud 한 개로 제한한다.
- Qwen 모델은 이번 요청으로 다운로드한다. 기존 설치 모델은 삭제하지 않는다.
  새 다운로드 목록과 모델 digest/show 해시를 기록한다.
- Cloud: 사용자에게 이전에 확인한 유료 크레딧/자동 충전 없음 조건을 유지한다.
  호출 전마다 계정 Free 확인. 인증/결제/할당량 오류(401/402/403/429) 시 즉시 중단.
  추가 결제·구독·충전·계정 변경 없음. 사용자 개인정보/API 키를 결과에 남기지 않는다.
- Cloud는 format(JSON Schema 강제)을 지원하지 않으므로 그 필드만 생략한다.
  원래 스키마 전문은 동일한 사용자 프롬프트에 남기고 동일 클라이언트 검증을 적용한다.
  로컬 모델 상주 설정 keep_alive도 Cloud에서 생략한다.
- Cloud의 seed/context 옵션 적용 여부 및 실제 가중치 버전은 검증할 수 없다.
  그러므로 **모델 외 실행 조건까지 완전히 같다고 주장하지 않는다**.
- 정확도와 형식 유효율을 함께 공개한다. 결과를 보고 형식 보정/프롬프트 변경/재호출하지 않는다.
- 지연은 단일 요청의 Mac/SSH 또는 Cloud 왕복 시간이다. 실제 로봇의 낙상 감지 지연이 아니다.
  큐 간 네트워크·JPEG 처리 경쟁과 최초 모델 로딩도 영향을 줄 수 있다.
- 각 입력/원응답/결과를 즉시 보존. 실패·중단 결과를 덮어쓰거나 완료로 표시하지 않는다.
- 이미 검토하고 개선에 활용한 합성 개발 데이터다. 실환경/임상 성능 입증이 아니다.
