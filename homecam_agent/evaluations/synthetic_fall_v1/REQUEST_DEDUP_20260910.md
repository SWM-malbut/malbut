# 중복 확인 요청 수정 결과

2026-09-10. **108의 확인 요청을 2건에서 1건으로 줄였다. 107의 요청은 유지했고,
414의 서로 다른 사람은 합치지 않았다.** 제품에는 적용하지 않은 오프라인 실험이다.

## 바꾼 부분

기존 `pose-loss` 실험의 확인 후보 뒤에 요청을 묶는 단계를 추가했다.
모델·검출 기준·Pose·트랙 ID·낙상 후보 조건·라벨은 바꾸지 않았다.

- 작은 박스가 큰 박스 안에 있고, 같은 얼굴과 팔 관절이 반복해서 겹칠 때만 검토한다.
- 실제 동시 관측 3회/0.3초 이상을 요구한다. 겹친 박스나 높은 관절 신뢰도만으로 합치지 않는다.
- 같은 사람으로 볼 근거가 부족하거나 세 후보가 모호하게 연결되면 별도 요청을 유지한다.
- 잠깐 검출이 끊겨도 최대 0.5초 안의 마지막 실제 동시 관측을 참조할 수 있다.
  관측이 없는 프레임에 옛 박스나 관절을 복사하지 않는다.
- 기존 요청 후 2초 안의 `found_down` 요청끼리만 묶는다.
  새 `fall_suspected` 요청은 막지 않는다.
- 두 번째 후보 원문은 기존 요청의 추가 근거로 보존한다. 두 ID도 그대로 남긴다.
  이후 새 근거에서 대응 관계가 깨지면 독립 요청으로 되돌린다.

전체 비교 전에 고정한 조건은 [REQUEST_DEDUP_PROTOCOL.md](REQUEST_DEDUP_PROTOCOL.md)에 있다.
107·108·414를 이미 확인한 개발 실험이며 독립 테스트 세트의 성능이 아니다.
전체 결과를 확인한 뒤 임계값을 다시 조정하지 않았다.

## 남은 문제

1. **108은 여전히 정상 영상에 불필요한 요청 1건이 나온다.** 정상/낙상 구분을 해결한 것이 아니다.
2. **107의 가구 오탐은 그대로다.** 사람 검출 모델이나 검출 기준을 수정하지 않았다.
3. 명확한 낙상 영상 중 **404·413·422·442**에는 여전히 확인 후보가 없다.
4. 이 방식도 2D 관절 대응일 뿐 실제 사람 신원 확인은 아니다. 같은 위치로 잘못 예측된 관절,
   사람끼리 겹침·가림에서는 잘못 묶일 위험이 있다. 다른 영상과 실물 검증이 필요하다.
5. 제품 적용 전에는 실제 확인 요청의 실행 중/완료/취소, 새 사건 시작, 합쳐진 근거 전달과
   우선순위 상승 처리를 연결해야 한다. 현재는 짧은 영상 안에서의 요청 비교만 구현했다.
