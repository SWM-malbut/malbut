# 현재 Pose 낙상 후보 로직 평가 기준

2026-09-10. 사용자가 검토한 박스와 시간 범위를 이번 개발 평가의 기준으로 쓴다.
기존 초안 파일은 이력을 보존하기 위해 수정하지 않는다. 그 파일에 남은
`pending_user_review`는 이번 측정을 다시 승인받아야 한다는 뜻이 아니다.
평가 실행 시 라벨·원본 영상·모델·코드·이 문서의 SHA-256을 함께 저장한다.

## 이번에 고정할 것

- 기존 41개 합성 영상, 낙상 동작 14 / 낙상 의심 5 / 이미 누운 사람 2 / 정상 20.
- 확인 대상 21개 중 431도 시작부터 바닥에 있다. 기존 분류는 유지하며 지연의
  시작점만 208·414와 함께 최초 발견 시각으로 계산한다.
- YOLO26n-Pose, 입력 640×640 stretch, 후보 신뢰도 0.10, 관절 신뢰도 0.50,
  초당 5회 샘플링. 추적기와 낙상 후보 로직은 현재 코드의 기본값 그대로 쓴다.
- RGB만 사용한다. 실제 depth·주행 기록이 없으므로 로봇 움직임은 `unknown`이다.
- 영상마다 추적 이력을 초기화한다. 새 추론에 정답 박스·시간·분류를 넣지 않는다.
- 이번 결과를 보고 위 기준을 바꾸지 않는다. 수정안은 별도 실행으로 비교한다.

## 1. 대상자를 찾았는가

수동 박스가 있는 프레임만 채점한다. 박스 보간·마지막 박스 재사용·추적 ID를
통한 중간 프레임 정답 복원은 하지 않는다. 가려져 위치를 모르면 제외 건수를 적는다.

수동 박스는 보이는 신체 범위이고 모델 박스는 전신을 포함할 수 있다.
따라서 IoU 하나 대신 다음 조건으로 **박스 연결 여부**를 측정한다.

1. 겹친 면적 / 수동 박스 면적 ≥ 0.50.
2. 겹친 면적 / 모델 박스 면적 ≥ 0.25. 화면 전체를 덮은 상자는 통과시키지 않는다.
3. 수동 박스의 중심이 모델 박스 안에 있어야 한다.
4. 양쪽에서 서로 가장 잘 맞는 상자여야 한다. 점수는 두 겹침 비율의 기하평균이며,
   차선 후보와 점수 차이가 0.10 미만이면 `ambiguous`로 남긴다.

위 값은 이번 개발 평가의 연결 기준이지 검증된 제품 임계값이 아니다.
연결 실패는 신체 자체의 미검출과 박스 범위 불일치를 포함한다. 이를 모두
"사람을 전혀 못 봄"이라고 부르지 않는다. 0.45 이상 상자 연결률도 참고로 함께 적는다.

연결된 상자에서 기존 코드의 `features.usable`이 참인지, 추적 ID가 붙었는지,
후보 판단까지 갔는지를 따로 센다. 관절 정답 라벨은 없으므로 자세 정확도는 아니다.
다른 사람이 잡힌 것은 대상자 성공이 아니다. 414의 누운 P01과 앉은 P02를 구분한다.

## 2. 확인 신호를 냈는가

- 영상별 후보 출력 유무는 41개 모두 집계한다. 정상 영상의 출력은 **불필요한
  확인 후보**이며 보호자 오알림이 아니다. 아직 VLM·질문·알림을 연결하지 않는다.
- 확인 대상 21개에서 신호가 전혀 없으면 `no_output`으로 센다.
- 출력이 있어도 대상자가 맞는지는 별도로 확인한다. 모든 출력 시점과 근거 구간의
  원본 RGB에 모델 상자를 표시해 `target / other_person / background / unknown`을
  기록한다. 이 작업은 결과의 대상 연결 감사이지 새 정답 상자 생성이 아니다.
- 사람이 눈으로 확인한 사건 라벨과 모델 ID는 별개다. 자동 ID 연결을 정답으로
  쓰지 않는다. 불확실하면 성공이나 미탐으로 강제 배정하지 않는다.
- 이 결과 감사는 이전 결과를 본 작성자가 수행하므로 블라인드 평가가 아니다.
- 같은 영상의 반복 출력·후보 수정은 한 사건으로 집계하고 출력 횟수도 따로 남긴다.

## 3. 언제 신호를 냈는가

판단 대상이 확인된 최초 출력의 원본 영상 시각을 사용한다. 시작 라벨이 [a,b]이면
지연은 `[출력 시각 - b/fps, 출력 시각 - a/fps]`다. 중간값을 정답으로 만들지 않는다.
시작 범위보다 이른 출력은 `early`, 범위 안은 `boundary_uncertain`, 이후는 `after`다.
`early`만 있는 영상은 시간상 성공에 넣지 않는다. 음수 지연을 0으로 잘라 숨기지 않는다.
이미 바닥에 있으면 낙상 시작 대신 `first_down_frames`로 발견 지연을 계산한다.
착지 시각이 가려졌으면 착지 기준 지연은 계산하지 않는다.

약 5.2초의 짧은 영상 끝까지 출력이 없다는 결과다. 이후에도 영원히 못 잡는다는
뜻은 아니다. 원본 시각 기준 지연과 PC의 추론 처리 시간은 따로 적는다.
Jetson에서의 동시 실행 지연·네트워크·VLM 지연은 측정 대상이 아니다.

## 해석 범위

이미 보고 기준 조정에 사용한 **개발용 합성 영상**이다. 실물·실내 전체·의료적 낙상
감지 성능으로 일반화하지 않는다. 전 프레임 미탐률, 관절 정확도, ID 전환율,
시간당 오알림은 현재 라벨과 짧은 영상으로 계산하지 않는다.
중간 프레임 부족이나 사건 대상 연결 불확실성은 따로 표시하며 정상으로 간주하지 않는다.
