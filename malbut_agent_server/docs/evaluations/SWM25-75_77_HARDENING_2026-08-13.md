# SWM25-75~77 오프라인 계약 완성도 강화 보고서

## 결론

SWM25-75 장기 기억, SWM25-76 음성 대화, SWM25-77 감정 표현의 초기
비부작용 MVP를 적대적으로 재검토하고, 안전하게 로컬에서 닫을 수 있는
strictness·동시성·멱등성·감사 무결성 결함을 수정했다.

최종 전체 회귀는 **584 passed**, Mock 고정 suite는 **90/90**, 강화된 반복
matrix는 **40,500/40,500 subcheck**로 모두 통과했다. 실제 ROS 장치, 음성,
화면 renderer, 알림, 유료 API는 호출하지 않았다.

이 결과는 세 스토리의 **오프라인 계약과 정책 경계**가 견고해졌다는 증거다.
실제 사람 인식·STT/TTS·renderer·ROS adapter까지 제품 완료했다는 뜻은 아니다.

## 주요 수정

### 장기 기억

- schema/writer protocol v3와 v1/v2 원자 migration
- record·user·global persistent revision과 cross-connection CAS
- confirmed create/update/delete의 durable idempotency와 내용 없는 audit
- evidence의 session instance·generation·completed time 영속 결속
- exact completed-turn evidence validator와 reset·recreate provenance 구분
- provider용 memory copy와 서버 snapshot 분리
- memory 관련 6개 테이블의 18개 row-DML writer gate

### 음성

- final transcript만 통과시키는 strict typed contract
- per-session in-flight reservation과 provider 호출 중 barge-in·close 비차단
- result-aware completion guard로 conversation commit과 로컬 TTS 예약 선형화
- coordinator의 terminal session-state hard cap과 안전한 capacity 거절
- blank assistant message의 durable commit 전 거절
- 외부 conversation close·expire·delete의 typed fail-closed 결과
- replay·capture epoch·TTS terminal·self-echo fence

### 감정 표현

- visual-only 5종 cue와 본문을 읽지 않는 deterministic mapper
- emergency·privacy·availability revision 우선순위
- lock 밖 bounded renderer worker와 cooperative generation/cancel fence
- pending duplicate 공유, worker-start 오류, neutral 1회 fallback
- 긴급 neutral timeout 뒤 renderer 재사용 차단

### 공통 Agent·Gateway

- 전역 orchestrator lock을 대화별 lock으로 좁혀 독립 대화 병렬화
- immutable memory snapshot과 completion guard
- 영문 후행 수식어가 붙은 명시적 고수준 Tool 금지문 fail-closed
- Gateway 정수 설정의 boolean 거절
- `max_workers` 기반 adapter admission으로 executor 대기열 제한
- runner의 실행 전·후 30파일 SHA-256 manifest 검증

## 남은 구조적 blocker

1. 기억 evidence validation과 mutation, memory snapshot 검사와 response commit은
   각각 서로 다른 transaction이다. 단일 unit-of-work 또는 confirmation-token
   CAS가 없으면 cross-process TOCTOU를 완전히 제거할 수 없다.
2. 실제 TTS publish/cancel에는 durable outbox가 없고 speech session lease도
   coordinator instance-local이다. completion guard가 `yield` 이후 실패하면
   DB turn은 이미 commit되어 rollback할 수 없다. hard session-state cap이
   소진되면 재시작 또는 신뢰된 관리 정리 전까지 새 session을 거절한다.
3. 실제 renderer가 cooperative cancellation과 receiver-side generation CAS를
   지키는지 아직 검증하지 않았다. Python은 uncooperative thread를 강제 종료할
   수 없다.
4. 실제 OpenAI 5초 post-fix gate는 과거 측정에서 실패했다. hard wall-clock
   deadline, 실제 Terra→Luna→safe-refusal 조합과 100개 이상 live fixture가
   필요하다.
5. 실제 Tool 실행·confirmation·durable exactly-once·cancel·feedback·audit loop는
   이번 non-actuating 범위가 아니다.
6. Gateway는 adapter admission과 API timeout을 제한하지만 반환하지 않는
   adapter의 non-daemon worker를 강제 종료하지 못한다. adapter 자체 deadline과
   격리 프로세스가 실제 연결 전 필요하다.
7. 현재 발화의 lexical intent 검사는 열린 자연어 금지·조건 표현을 완전하게
   판별할 수 없다. 실제 실행 동의나 authenticated confirmation으로 재사용하면
   안 되며 closed grammar 또는 1회성 confirmation token이 필요하다.
