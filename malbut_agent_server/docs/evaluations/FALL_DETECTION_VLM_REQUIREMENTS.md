# 낙상 감지·능동 재확인과 VLM 선정 기준

- 상태: 평가·구현 기준안
- 기준일: 2026-09-03
- 대상 장치: 지면 약 9~12cm 높이에 Aurora930 Pro RGB-D를 장착한 이동형 로봇

## 1. 제품 요구사항

낙상 기능은 한 프레임의 자세를 `fall=true/false`로 분류하는 기능이 아니다.
다음 두 진입 경로를 하나의 사건 확인 상태기로 합쳐야 한다.

1. **목격 낙상(`OBSERVED_FALL_CANDIDATE`)**: 추적 또는 같은 공간 관측 중
   서기·걷기에서 바닥 자세로 급격히 전이한 경우
2. **순찰 중 발견(`FOUND_DOWN_CANDIDATE`)**: 쓰러지는 순간은 보지 못했지만
   순찰 중 바닥 가까이에 누운 사람을 발견한 경우

두 경로 모두 다음 최종 결과 중 하나로 끝난다.

- `CONFIRMED_FALL`: 낙상 과정과 사후 상태를 함께 확인
- `FOUND_DOWN`: 과정은 없지만 바닥 자세 또는 무반응을 확인
- `NORMAL_ACTIVITY`: 앉기·눕기·운동·물건 줍기 등 정상 행동을 확인
- `UNOBSERVABLE`: 가림·부분 시야·센서 실패 때문에 안전하게 판정할 수 없음

`FOUND_DOWN`과 `UNOBSERVABLE`은 정상으로 축소하지 않는다. 보호자에게 각각
"바닥에 쓰러진 사람 발견"과 "낙상 의심·확인 필요"로 전달한다.

## 2. 감지와 확인 책임 분리

### 2.1 로컬 1차 감지

VLM은 최초 감지기가 아니다. 로봇에서 실행되는 사람 추적·Pose·RGB-D 로직이
낙상 후보를 빠르고 민감하게 만든다.

- 머리·어깨·골반의 급격한 하강
- 몸통의 수직→수평 변화
- 사람 3D 중심과 주요 관절의 바닥 접근
- 화면 아래로 갑자기 사라진 사람 트랙
- 순찰 중 바닥 높이에 새로 나타난 사람 또는 신체 후보

후보 단계는 Recall을 우선한다. 관절 일부가 사라지거나 전신이 보이지 않는다는
이유로 후보를 폐기하지 않는다. 후보가 만들어지는 즉시 최근 5~10초 영상과
Pose·깊이·odometry·Nav2 상태를 보존하고, 현재 주행을 안전하게 정지한다.

### 2.2 결정적 물리 증거

최종 판정은 다음 증거의 시간축 결합을 사용한다.

- 하강 속도와 자세 전이
- 카메라 외부 파라미터와 RGB-D로 계산한 신체-바닥 높이
- 바닥 자세 지속 시간과 회복 여부
- 침대·소파·의자 등 지지면의 종류
- 로봇 자체 이동으로 인한 영상 변화
- 음성 질문에 대한 응답 또는 도움 요청

2D 바운딩박스의 가로세로 비율은 저상 카메라에서 원근 왜곡이 크므로 보조
특징으로만 사용한다.

## 3. 능동 재확인

판정 전에 `body_visibility`, 유효 깊이 비율, 바닥 노출, 가림과 영상 흔들림으로
현재 관측의 품질을 검사한다.

관측이 충분하면 로봇은 움직이지 않는다. 관측이 부족할 때만 다음을 수행한다.

1. 사람 추정 영역에 임시 신체 보호 금지 구역을 만든다.
2. 정적 지도와 Nav2 costmap에서 안전한 관측 후보를 만든다.
3. 벽·가구를 통과하는 시선은 raycast로 제외한다.
4. 사람에게 접근하지 않고, 필요하면 후진하거나 열린 쪽으로 이동한다.
5. 전신 또는 유효 관절을 가장 많이 확보하는 지점 최대 2개만 방문한다.

한쪽이 벽이거나 방 모서리라면 열린 반원 안에서만 관측한다. 침대·벽 사이,
좁은 욕실 또는 가구 뒤처럼 안전한 관측 위치가 없으면 억지로 진입하거나 사람
주위를 한 바퀴 돌지 않고 `UNOBSERVABLE`로 상향한다.

## 4. VLM의 역할과 제한

VLM은 로컬 물리 증거를 대신하지 않고 다음 문맥을 판정하는 2차 확인기다.

- 바닥에 누운 사람인지 침대·소파에 정상적으로 누운 사람인지
- 앉기, 쪼그리기, 운동, 물건 줍기 또는 낙상 유사 행동인지
- 낙상 후 회복 중인지 계속 쓰러져 있는지
- 가구·반사·TV·인형 때문에 발생한 오탐인지
- 현재 영상만으로 판정 가능한지

입력은 짧은 선행 영상, 현재 확인 영상, 로컬 센서 요약을 함께 사용한다. VLM은
`CONFIRMED_FALL`, `FOUND_DOWN`, `NORMAL_ACTIVITY`, `UNOBSERVABLE` 중 하나와
관측 근거를 구조화된 JSON으로 반환한다.

물리 증거가 강한 후보를 VLM의 단일 `NORMAL_ACTIVITY` 응답만으로 해제하지
않는다. API timeout, schema 오류와 모델 불일치는 모두 `UNOBSERVABLE`이며,
보호자 알림 경로를 막지 않는다.

## 5. 알림 정책

- 후보 감지 즉시: `낙상 의심 감지—로봇이 확인 중입니다`
- 확인 후: 확정 낙상, 바닥에 쓰러진 사람 발견, 정상 행동, 확인 불가 중 하나로
  같은 incident를 갱신
- 도움 요청 또는 명백한 낙상: 시야 재배치를 기다리지 않고 즉시 긴급 알림
- 확인 지연 상한은 실기 측정으로 정하되, 전체 이벤트 클립 종료를 기다리지 않음

같은 위치·같은 사람·회복되지 않은 상태는 하나의 incident로 유지한다. 순찰 때
다시 발견해도 새 이벤트를 만들지 않고 관측과 클립을 기존 incident에 추가한다.

## 6. 프라이버시와 실행 조건

순찰 중 발견은 웹 사용자가 실시간 화면을 열지 않아도 로컬 인지가 실행돼야
가능하다. 제품 설정은 다음을 구분한다.

- 카메라 하드웨어 전원
- 실시간 P2P 시청
- 클라우드 이벤트 영상 저장
- 로컬 안전 모니터링

카메라 전원을 끄면 낙상 감지는 불가능하다. 로컬 안전 모니터링과 사건 발생 시
클라우드 전송은 최초 동의, 철회, 보존 기간과 국외 처리 여부를 별도로 고지한다.

## 7. 평가 데이터 필수 구성

목격 낙상과 순찰 중 발견은 서로 다른 Recall로 보고한다. 낙상 유사 정상 행동은
낙상 데이터 이상으로 충분히 포함한다.

- 의자·바닥에 앉기, 침대·소파·바닥에 천천히 눕기
- 물건 줍기, 쪼그리기, 무릎 꿇기, 운동과 스트레칭
- 넘어질 뻔한 뒤 회복, 벽을 타고 주저앉기, 의자에서 미끄러짐
- 순찰 시작 전부터 바닥에 누워 있기
- 한쪽이 벽, 모서리, 좁은 공간, 가구에 일부 또는 대부분 가림
- 전신, 하반신만, 신체 일부만, 결과 자세만 보이는 저상 카메라 시야
- 로봇 정지·전진·회전 중의 정상 행동과 낙상

필수 지표는 목격 낙상 Recall, `FOUND_DOWN` Recall, 정상 눕기·앉기 오탐률,
`UNOBSERVABLE`을 정상으로 잘못 종료한 비율, 후보→알림 지연, 안전한 관측 위치
도달률과 최저 사람 접근 거리다.

## 8. VLM 후보 결정

최종 운영 모델은 실제 로봇 파일럿 데이터 없이 확정하지 않는다. 첫 어댑터와
비교 후보는 다음과 같이 고정한다.

| 역할 | 모델 | 선정 이유 | 확인할 위험 |
|---|---|---|---|
| 첫 구현 | Amazon Nova 2 Lite | 현재 AWS/KVS/S3 운영 경로와 직접 통합, 네이티브 영상 입력 | 1 FPS, 672×672 왜곡, 오디오 미처리, 서울 in-region 부재 |
| 품질 비교 | Gemini 3.8 Flash | 네이티브 영상·구조화 출력, 최신 안정 Flash | 국외 처리, 공급자 추가, 비용·지연 |
| 비용 비교 | Qwen3-VL Flash | 네이티브 영상·JSON Object 출력, 낮은 토큰 단가 | 국외 처리, 평가 봉인 전 스냅샷 고정 필요 |
| 엣지 가능성 | MiniCPM-V 4.6 | Apache 2.0, 1.3B급 영상 모델 | Jetson 8GB에서 YOLO·Nav2와 동시 실행 실측 필요 |

OpenAI GPT 계열은 공식 문서 기준 영상 입력을 직접 지원하지 않으므로 첫 후보군에
넣지 않는다. 필요할 때만 동일하게 추출한 프레임을 받는 트랙의 참조 모델로
사용한다.

첫 구현 모델은 **Nova 2 Lite**로 한다. 이것은 운영 모델 확정이 아니라 평가
파이프라인의 기준 구현이다. 다음 조건 중 하나면 운영 후보에서 제외한다.

- 영상 국외 처리를 허용하지 않음
- 실제 저상 카메라 데이터에서 목격 낙상 또는 `FOUND_DOWN` gate 실패
- 정사각 리사이즈 때문에 부분 시야·가림 층에서 유의한 성능 저하
- 선행 클립 분석이 제품 알림 지연 목표를 만족하지 못함

Nova가 탈락하면 Gemini 3.8 Flash를 같은 프로토콜로 평가한다. 두 클라우드
모델이 개인정보 gate에서 탈락하면 서울 리전 GPU에 오픈웨이트 모델을 배치하며,
Jetson 온디바이스는 자원 공존 시험을 통과한 경우에만 알림 경로에 사용한다.
