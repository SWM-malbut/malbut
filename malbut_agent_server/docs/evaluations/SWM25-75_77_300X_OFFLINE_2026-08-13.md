# SWM25-75~77 기능별 300회 오프라인 반복 검증

## 결론

2026-08-13 기준 SWM25-75, SWM25-76, SWM25-77의 오프라인 MVP를
각각 300회 반복했다. 최종 실행은 **900/900 story iteration**, 대표
subcheck **24,900/24,900회**가 통과했고 실패는 0건이다.

이 결과는 합성 입력과 인메모리 또는 작업 저장소 내부 임시 SQLite,
MockProvider, Recording/Noop renderer만 사용한 결정론적 회귀 증거다. 실제
사용자 300명, 실제 음성 300회, 실제 화면 출력 또는 운영 SLA를 뜻하지 않는다.

| Story | 반복 | 반복당 검사 | 총 subcheck | 실패 | p95/iteration |
| --- | ---: | ---: | ---: | ---: | ---: |
| SWM25-75 장기 기억 core | 300/300 | 14 | 4,200 | 0 | 340.022ms |
| SWM25-76 음성 경계 | 300/300 | 28 | 8,400 | 0 | 69.266ms |
| SWM25-77 시각 표현 경계 | 300/300 | 41 | 12,300 | 0 | 12.210ms |
| **합계** | **900/900** | **83** | **24,900** | **0** | 성능 SLA 아님 |

전체 wall time은 115.380초다. SWM25-75의 최대 8.259초는 동시 SQLite
migration 검사를 포함한 한 iteration이며, 위 지연 수치는 성능 gate로
사용하지 않는다.

원본 machine-readable 증거는 mode `0600`인
[`SWM25-75_77_300X_OFFLINE_2026-08-13.json`](artifacts/SWM25-75_77_300X_OFFLINE_2026-08-13.json)에
있다.

## 기능별 검증 범위

### SWM25-75

14개 대표 검사를 iteration마다 실행했다.

- 사용자별 검색·조회·변경·audit 격리
- 확인 기반 create/update/delete와 evidence metadata
- record CAS, user/global revision과 재시작 후 멱등 replay
- 만료 뒤 exact replay와 만료 row update 차단
- 동일 DB 두 connection 사이 revision 보이기
- v1 schema migration, 8개 동시 first-open, migration 실패 rollback
- 만료 purge revision·audit
- audit/idempotency table에 기억 본문 비복제
- persistent DB `0600` permission과 scoped delete

provider가 전달받은 memory list·metadata를 바꿔도 서버 snapshot을 우회하지
못하는 회귀는 최종 237개 전체 suite에서 통과했다. 이 항목은 위 14개×300
matrix에는 포함하지 않았으므로 300회 증거로 주장하지 않는다.

실제 person identity, 완료 evidence turn과 1회성 confirmation token 검증,
공개 HTTP/ROS adapter, 보존 기간과 파생 데이터 삭제는 증명하지 않는다.

### SWM25-76

28개 대표 검사를 iteration마다 실행했다.

- raw audio·PCM·path·URI와 transcript `user_id` strict 거절
- partial·저신뢰·binding mismatch·self-echo에서 provider 호출 0
- accepted sequence와 capture epoch 기반 stale 차단
- 재생 중 거절된 높은 sequence가 다음 정상 발화를 막지 않음
- final transcript만 Mock Agent 호출
- SafetyPolicy 이후 최종 문구만 text-only interruptible TTS로 전달
- duplicate at-most-once와 payload conflict
- barge-in cancel, evicted activity replay의 epoch fence
- terminal·session close 이후 늦은 이벤트 차단
- 한 conversation에 live speech session 하나만 허용
- audit에 transcript·speaker·audio 본문 비저장

실제 STT/TTS, 한국어 WER, latency, 음향 echo cancellation, ROS QoS와
다중 프로세스 coordinator lease는 증명하지 않는다.

### SWM25-77

41개 대표 검사를 iteration마다 실행했다.

- 5종 emotion·visual-only·수치 범위 strict schema
- 로컬 final-decision mapper를 통하지 않은 cue 차단
- 사용자·반려동물 심리·의료 문구 비참조
- emergency > privacy > availability > freshness 우선순위
- 미래 cue와 exact TTL 만료 차단
- conflict 상황에서도 긴급 neutral clear 우선
- display expiry 뒤 neutral 단회 복귀
- duplicate, conflict와 동시 at-most-once(cache 안에서)
- 표현 빈도 제한과 이미 neutral인 일반 cue coalescing
- renderer 오류의 neutral 1회 fallback, neutral 실패 뒤 disable
- express_emotion 모델 Tool과 motion/audio 권한 부재

실제 renderer, frontend·ROS Action, renderer timeout/cancel과 재시작 뒤 영속
exactly-once는 증명하지 않는다.

## 첫 실행 실패와 수정 근거

최초 300회 실행은 SWM25-75에서 276/300만 통과했다. 실패 24건은 모두
`concurrent_migration` subcheck였고 SWM25-76·77은 각각 300/300이었다.

원인은 여러 `SQLiteMemoryStore` connection이 schema migration 전 동시에
`PRAGMA journal_mode=WAL` 전환을 시도해 간헐적으로 `database is locked`가
발생한 것이다. 다음과 같이 수정했다.

1. memory store가 journal mode를 임의로 전환하지 않도록 책임을 분리했다.
2. schema inspection과 ALTER를 `BEGIN IMMEDIATE` 한 transaction으로
   직렬화했다.
3. migration 오류에서 rollback하도록 했다.
4. 저장소 내부 임시 DB로 동시 first-open 100회를 별도 재현해 모두 통과했다.
5. 전체 300회 matrix를 처음부터 다시 실행해 900/900을 확인했다.

최초 실패 artifact는 최종 성공 artifact로 덮어썼다. 실패 수치와 원인·조치는
이 보고서와 야간 worklog에 남겼다.

byte SHA-256을 artifact에 기록했다.
