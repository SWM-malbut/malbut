# 기억 원문 검토 보완 후 재비교 — 2026-10-14

**소유 관계와 전체 원문 검사를 보완한 Decisions는 이번 가상 사례에서 잘못된 승인과
정상 후보 거절이 모두 0건이었다. 확률 0.9 기준을 추가하면 정상 후보를 다시 놓쳤다.**
기존 Responses에도 같은 범위 지침을 적용하자 잘못된 승인은 없어졌지만 정상 후보 거절
1건은 남았다. 규칙과 Responses의 코드 수정까지 반영했으며 서비스 재시작·배포나
운영 API의 Decisions 전환은 하지 않았다.

## 확인한 원인과 수정

1. **반려동물의 소유 주체가 검토 기준에서 불명확했다.** `pet / 강아지 / name / 두부`를
   검토하면서 원문에 동물의 이름이 있다는 사실만으로 승인할 여지가 있었다. 사용자 개인
   기억의 `pet`은 사용자가 현재 키우거나 함께 돌보는 동물이라는 범위를 명시했다.
   가족의 공동 돌봄·현재 입양은 허용하고, 타인의 동물이나 관계가 불명확한 경우는 승인하지
   않는다. 같은 문장에 이웃이 등장하더라도 사용자 동물의 사실은 독립적으로 판단한다.
2. **일부 잘못된 후보는 LLM을 호출하기 전에 규칙만으로 승인됐다.** 이전 코드에서
   `옆집 강아지 이름은 두부야`는 이름 패턴에 맞아 통과했다. 근거를 `강아지 이름은 두부야`로
   잘라도 마찬가지였다. 소유 관계가 명확한 경우만 규칙으로 처리하고, 전체 원문의 제삼자
   소유·관계 변화나 근거 밖의 정정·부정 단서는 원문 검토로 보내도록 수정했다.
3. **기존 정상 후보 거절은 확률 기준에서 발생했다.** `나는 커피는 싫어하지만 차는 좋아해`의
   차 선호는 이미 `supported`였지만 확률 0.84가 0.9 기준을 넘지 못했다. 절마다 주체·대상·
   긍정과 부정을 구분하도록 지시하고, Decisions 질문마다 검토할 후보 하나를 직접 넣었다.
   후보 배열의 번호만 가리키던 구조를 바꿨다. 지침과 후보 배치를 함께 변경했으므로 각각의
   효과를 분리해서 입증한 실험은 아니다.

이전 `personal_memory.py`와 직접 대조한 규칙 재현 결과는 다음과 같다. 기준 커밋은
`ffc5c7e290b31fceebc21c40e8ef94ed34861dc6`이다.

| 새 사례 | 이전 규칙 | 보완한 규칙 |
| --- | --- | --- |
| 이웃 강아지 이름 | 잘못 승인 | 전체 원문 검토 |
| 이웃 소유 부분을 잘라낸 근거 | 잘못 승인 | 전체 원문 검토 |
| 과거에 키웠지만 지금은 보내 준 동물 | 잘못 승인 | 전체 원문 검토 |
| 뒤에서 취소한 취향의 앞 문장만 근거로 제시 | 잘못 승인 | 전체 원문 검토 |
| 이웃에게서 입양해 지금 키우는 동물 | 정상 승인 | 전체 원문 검토 |

마지막 사례처럼 추가 검토가 필요한 정상 후보도 생긴다. 모호함을 이유로 바로 거절하는
방식은 아니다. 입양·가족·공동 돌봄 사례는 보완한 두 검토기 모두 두 번씩 승인했다.
이는 제한적인 규칙 보완이며 모든 한국어 소유·시간 표현을 완전히 판별한다는 뜻은 아니다.

## 비교 범위

- 기존 가상 원문 38개와 실행 전에 고정한 새 원문 20개를 사용했다. 검토 대상은 총 48개
  묶음, 후보 60개다. 기존 사례와 새 사례를 `regression` / `holdout`으로 나눴다.
  새 사례도 이번 작업에서 작성한 기대판정이며 외부의 독립적인 정답 검수는 아니다.
- 각 묶음을 네 경로에서 두 번씩 실행했다. 경로마다 96회, **총 384회 실제 API 호출**이다.
  각 경로의 예정 후보 판정은 120개: 정상 후보 56개, 승인하면 안 되는 후보 64개다.
- Responses 두 경로는 모두 `gpt-5.6-luna`, Decisions 두 경로는 모두 `gpt-6-luna`다.
  Responses 비교군에서 새 지침만 제거해 보완 전 기준을 재현했다.
- 네 경로 모두 **보완한 공통 규칙을 거친 같은 후보**를 받았다. 아래 수치는 검토기 비교이며
  보완 전 규칙까지 포함한 전체 저장 파이프라인의 오류율은 아니다. 후보 추출·DB 저장은
  실행하지 않았다. 규칙이 새로 검토로 보내는 후보만큼 실제 호출 수는 늘 수 있다.
- 실행 중 프롬프트·사례·정답·확률 기준은 바꾸지 않았다. 실행 후 동일 입력 비교 집계를
  추가했으며 개별 호출 결과는 변경하지 않았다. 데이터 해시는 결과 JSON에 보존했다.

## 같은 입력끼리의 품질 비교

보완 전 Responses에서 `h_two_owners`의 한 반복이 응답 계약 검증 오류로 끝났다.
해당 묶음을 네 경로 모두에서 제외한 **95개 묶음, 후보 판정 118개**가 아래 비교 대상이다.
실패를 정상 거절로 세지 않았고, 전체 결과와 비용에는 해당 호출을 그대로 남겼다.

| 검토 방식 | 잘못된 승인 / 승인하면 안 되는 후보 | 정상 후보 거절 / 정상 후보 |
| --- | ---: | ---: |
| 보완 전 Responses | 10 / 63 | 1 / 55 |
| 보완 후 Responses | 0 / 63 | 1 / 55 |
| 보완 전 Decisions, 원래 선택값 | 15 / 63 | 0 / 55 |
| 보완 후 Decisions, 원래 선택값 | **0 / 63** | **0 / 55** |
| 보완 전 Decisions + supported 확률 ≥ 0.9 | 0 / 63 | 2 / 55 |
| 보완 후 Decisions + supported 확률 ≥ 0.9 | 0 / 63 | 9 / 55 |

확률 기준 행은 같은 API 응답에 다른 승인 기준을 적용한 것이며 추가 호출은 없다.
보완 후 Decisions의 전체 96개 묶음에서도 오승인은 0 / 64, 정상 거절은 0 / 56이다.
0.9를 요구하면 전체 정상 거절은 10 / 56이다. **이번 결과로 확률 0.9를 일괄 적용할 근거는
없다.** 원래 선택값을 사용하는 보완안이 이번 표본의 두 오류를 함께 줄였지만, 이 결과만으로
운영 기준이나 실사용 오류율을 확정하지 않는다.

기존 사례와 새 사례를 나눈 동일 입력 비교도 다음과 같다. 각 셀은 오승인 / 정상 거절이다.

| --- | ---: | ---: |

## 처음 문제와 남은 오류

- **이웃 강아지:** 최초 문제였던 `옆집 강아지를 두부라고 부르더라`는 보완 후 Decisions에서
  두 번 모두 `insufficient`, supported 확률 0.01이었다. 보완 전은 두 번 모두 승인, 0.66이었다.
  새 이웃·동료·소유주 불명 사례도 보완 후에는 승인되지 않았다.
- **서로 다른 취향:** 기존 차 선호 후보는 두 번 모두 supported 확률 **0.84 → 0.98**로
  바뀌었다. 새 혼합 취향과 후보 순서를 뒤집은 사례도 보완 후 정상 승인됐다. 다만 다른 정상
  후보의 확률까지 높아진 것은 아니다. 이름 소개 0.62, 두 소유주 중 사용자 동물 0.71 등은
  원래 선택이 supported여도 0.9 기준에서 거절된다. 이 확률을 보정된 정확도로 취급하지 않는다.
- **Responses 정상 거절 1건은 남았다.** `박지훈이라고 해. 반가워!`의 사용자 이름 후보가
  한 번 승인, 한 번 거절됐다. 보완 전 Responses는 이 후보를 두 번 승인했고, 보완 후에는
  두 소유주 중 정상 반려동물 후보를 놓치던 문제는 해결됐다. 따라서 Responses의 정상 거절은
  총량이 줄지 않았고, 기존 소개 사례에 회귀가 있다. 반환값에는 판단 이유가 없어 정확한 내부
  원인은 단정할 수 없다. 이름 범위 지침의 추가 보완 여부는 별도의 미사용 사례로 확인해야 한다.
- **Decisions의 거절 이유 분류는 완벽하지 않았다.** 전체 120개 중 3분류 일치는 114개다.
  두 소유주·두 사람의 취향에서 근거 부족을 모순으로, 과거 동물에서 모순을 근거 부족으로
  분류한 차이가 각 두 번 있었다. 모두 저장 거절이어서 이진 오승인·오거절에는 포함하지 않았다.

## 시간·비용·오류

성능과 다르다. 비용은 실제 토큰 사용량과 2026-10-14 Standard 요금으로 계산한 추정치다.

## 반영 및 검증

- 변경 코드: `personal_memory.py`의 규칙, `memory_contract.py`의 범위 지침,
  `providers/openai_responses.py`의 source_review 지시문. 일반 답변·추출 프롬프트는 변경하지 않았다.
- Decisions는 비교 도구에만 있고 운영 factory에 연결하지 않았다. 서비스 배포·재시작은
  하지 않았다. 보완한 Responses에서도 이름 소개 거절이 남았으므로 품질 개선을 완결로 보지 않는다.
- 기억 흐름·근거·동의·정정·자동 저장·공급자와 동일 입력 실패 처리 관련 테스트를
  2026-10-15 PR 준비 시 최신 main의 별도 작업 폴더에서 다시 실행해 **416개 통과**했다.
  실기기 적용본 경계 테스트도 **10개 통과**했고, 코드·데이터·문서 복사본 일치를 확인했다.
- 규칙 우회 차단뿐 아니라 정상 사용자 동물의 저장, 명시적 정정·여러 동물의 기존 동작도 확인했다.
- 새 코드의 lint와 공백, 결과 파일의 비밀키 미포함을 확인했다. 병행 작업 파일은 수정하지 않았다.

운영 DB가 없어 실제 검토 호출률과 추가 검토량은 여전히 미측정이다. 동일 후보 두 번 반복은
독립적인 새 표본이 아니며, 가상 사례에서 오류 0건이 실사용 오류 0을 뜻하지 않는다.
자동 검토는 백그라운드여서 검토 시간 감소가 일반 대화 응답 시간 감소와 같지도 않다.
