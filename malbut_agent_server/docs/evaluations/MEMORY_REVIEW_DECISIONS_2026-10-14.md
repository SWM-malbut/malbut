## 잘못된 판정

세 경로 모두 같은 사례를 두 번 승인했다.

> 원문: 옆집 강아지를 두부라고 부르더라
>
> 후보: kind=pet, subject=강아지, attribute=name, value=두부

이 실험에서는 개인 사실 기억의 목적에 따라 `pet`을 사용자의 반려동물 정보로 해석하고,
이 후보의 기대판정을 `insufficient`로 정했다. 이웃의 반려견을 사용자 반려견 정보로
저장하면 안 된다. 원문에는 실제 이름이 있지만 후보의 소유 주체가 충분히 구분되지 않았다.
후보 형식과 검토 지시문에서 소유 주체를 더 명확하게 표현할 필요가 있다.

Decisions의 이 사례에 대한 supported 확률은 0.66으로, 0.9 기준에서는 승인되지 않았다.
하지만 다음 묶음에서는 타당한 차 선호 후보의 확률이 0.84여서 두 번 모두 보류됐다.

> 나는 커피는 싫어하지만 차는 좋아해

즉, 이 표본에서는 확률 기준이 잘못된 승인을 줄이는 대신 정상 기억 저장을 놓쳤다.
확률은 모델의 추정값이며 실제 정확도를 보장하지 않는다. 이 결과만으로 0.9를 운영 기준으로
확정하지 않았다.

Decisions의 3분류 일치는 56 / 60이었다. 위 소유 주체 사례 외에는 제삼자의 커피 취향
사례를 `insufficient` 대신 `contradicted`로 분류한 차이가 두 번 있었다. 둘 다 저장 거절이므로
공통 이진 판정에서는 오류로 세지 않았다. 기존 검토는 두 종류의 거절을 구분해 반환하지 않는다.

## 운영 호출 비율과 해석의 한계

이 작업공간에서 운영 대화 DB를 찾지 못했으므로 **실제 검토 호출 비율은 미측정**이다.
38개 중 28개라는 가상 사례 분기는 운영 빈도가 아니다. 기존 `automatic_memory_jobs`의
검토 시간과 토큰 메타데이터를 읽기 전용으로 집계하는 도구를 함께 추가했다.
NULL 기록·취소·삭제·동기 경로 때문에 그 집계도 전체 대화의 정확한 HTTP 호출률과 다르다.

표의 60개 판정은 독립적인 60개 새 사례가 아니라 **후보 30개를 두 번 평가한 결과**다.
실사용 오류율이나 일반적인 안전성을 입증하지 않는다. 후보 추출 오류, 실제 기억 저장 완료
시간, 일반 답변 지연도 측정하지 않았다. 자동 기억 검토는 백그라운드이므로 이 속도 차이가
일반 대화 응답 속도에 그대로 반영되지는 않는다.
