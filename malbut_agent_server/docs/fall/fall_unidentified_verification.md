## 바꾼 이유

Pose 후보는 바로 사건을 만들지만, 주기적 Cloud가 의심한 사람을 Pose에 연결하지
못하면 기존에는 발견 기록만 남았다. Manager의 확인 질문으로 이어지지 않았다.
감지 시작은 Pose 또는 Cloud 중 한 경로의 유효한 의심으로 가능해야 하며,
같은 사람·사건으로의 병합은 중복을 줄이는 별도 작업이다.

## 현재 동작

| 입력 | 처리 |
| --- | --- |
| Pose 의심 후보 | 기존 사람별 사건 생성·영상 확인 경로 유지 |
| Cloud 의심 + 확실한 Pose 연결 | 기존 사건에 반영하거나 사람별 사건 생성 |
| Cloud 의심 + 연결 불가 | 아래 연결 대기 조건에 한해 잠시 대기, 나머지는 장면 확인 시작 |
| Cloud 의심 + 위치 없음/위치 오류 | 대상 미확인 장면 사건 생성·일반 확인 질문 전달 |
| 정상·판단 불가·응답 형식 전체 오류 | 낙상 의심 신호로 꾸며 사건을 생성하지 않음 |

- 미확인 사건은 `FallIncident.subject_key=None`이다. 가짜 사람 ID를 만들지 않는다.
- Manager 이벤트에는 `confirmation_scope=scene`, `subject_key=null`을 함께 전달한다.
  기존 사람별 확인은 `confirmation_scope=subject`이며 유효한 사람 ID가 필요하다.
  scope가 없는 기존 메시지는 사람별 계약으로 처리하므로, 누락된 사람 ID를 장면 확인으로
  자동 해석하지 않는다.
- 이미 받은 Cloud 판정을 사용하며 확인 시작을 위해 추가로 Cloud를 호출하지 않는다.
- Manager는 특정인을 지목하지 말고 주변에 넘어졌거나 도움이 필요한 사람이 있는지
  묻도록 Agent에 고정된 요약을 전달한다. Cloud 설명 원문을 지시문으로 전달하지 않는다.
- 같은 장면 확인이 열려 있으면 여러 미연결 발견을 그 확인에 보관한다. 각 발견의
  위치·시각·이유·발견 ID는 별도로 남긴다. 이 묶음이 같은 사람이나 같은 낙상이라는 뜻은 아니다.
- 반복 발견은 사건·질문·재확인 횟수를 늘리지 않는다. 2026-10-05 수정부터는 열린 사건의
  Cloud 판정이 낙상 의심에서 낙상 관측으로 바뀌어도 그것만으로 새 질문을 만들지 않는다.
  강해진 영상 근거는 보존하며 진행 중·완료·실패한 확인 대화와 도움 필요 결과를 유지한다.
- 미확인 사건에 받은 도움 불필요 답변은 `unclear` 답변과 `recheck_required` 상태로 기록한다.
  응답자를 대상과 연결하지 못했으므로 실제 대상이 괜찮다고 확정하지 않는다.
- 도움 필요 답변은 해당 장면 사건을 `help_required`로 바꾸고 기존 알림 요청 경로에 전달한다.
  낙상 확정으로 바꾸거나 다른 사람의 사건에 답변을 적용하지 않는다.
- 장면 정상 판정으로 미확인 사건을 닫지 않는다. 대상 없는 사건별 `recheck`는
  `target_unidentified`로 거부하고, 주기적 Cloud 확인은 계속한다.
- 설정 철회/연결 차단 뒤의 늦은 응답, 분석 도중 이미 바뀌거나 종료된 사건의 오래된
  응답은 새 질문으로 되살리지 않는다. 용량 상한은 유지하며, 공간이 없으면 발견에
  `incident_capacity`를 기록한다.

## 계속 누워 있는 상황의 재발견 (2026-10-05)

### 연결 미확인 관측과 사건 생성을 분리한 후속 변경

사용자 선택: **제한 시간만 기다린 뒤 별도 확인한다(안전 우선).**
Pose가 없다는 이유로 기존 사건을 닫거나 도움 요청/답변을 초기화하지 않는다.
반대로 기존 사람과 같다고 추정해 다른 사람에게 답변을 적용하지도 않는다.

| 재발견 조건 | 처리 |
| --- | --- |
| 확실한 동일 대상 근거 확보 | 기존 연결 경로 유지 |
| 열린 사람 사건의 마지막 관측 위치와 겹치는 `already_down` 발견 1명, 연결 불명 | 사건 없이 `association_review.status=pending` 발견 기록 |
| 대기 중 늦은 Pose가 원본 영상 시점에서 같은 연속성 토큰으로 확인됨 | `matched` 기록, 기존 사건에 클립·박스 연결, 새 질문 없음 |
| 기한까지 연결하지 못함 | `verification_required` 기록, 대상 미확인 장면 확인으로 전달 |
| 새 넘어짐, 다른 위치, 여러 사람, 위치 오류, 카메라 이동/미확인 | 대기하지 않고 기존 확인 경로로 전달 |

- 대기 시간은 `min(20초, cloud_timeout_s)`이다. 반복 발견으로 기한을 늘리지 않는다.
  ROS 루프의 별도 로컬 처리로 만료를 확인하므로 다음 60초 정기 분석이나 진행 중인
  Cloud 요청의 완료를 기다리지 않는다. 실행 루프가 멈춘 경우까지 실시간 상한을 보장하는 것은 아니다.
- 대기 후보는 열린 사건에 한한다. 최근 정지 상태가 명시적으로 전달돼야 하고,
  마지막 유효 관측은 `scan_interval_s + cloud_timeout_s` 이내여야 한다.
  모든 Cloud 위치가 그 관측과 IoU 0.60 이상 겹치며 후보 사건이 하나여야 한다.
  이 위치 조건은 **잠시 기다릴 이유이지 동일인 증거가 아니다**. 실기 정확도로 검증된 수치도 아니다.
- 실제 연결에는 기존 원본 시점 정합 규칙을 유지한다. 늦은 Pose는 응답 후 2초 이내,
  원본 RGB 시점의 정확한 측정 또는 양옆 100ms 이내 측정, 기존 사건과 같은 유효한
  연속성 토큰이 필요하다. 관측 단절 후 같은 ID가 다시 나오는 것만으로 합치지 않는다.
- `candidate_incident_id`는 대기 판단의 참고 사건이다. 대기 중 `incident_id`,
  `subject_key`, `association_link`는 null이며 사람/사건을 병합하지 않는다.
- SQLite `cloud_discoveries`에 대기·연결·만료·설정 변경에 의한 취소를 기록한다.
  같은 `discovery_id`의 마지막 기록으로 상태를 확인한다. 대기 기록은 현재 웹 사건 목록에
  새 카드로 표시하지 않는다. 별도 확인으로 전환한 뒤에는 기존 사건 업로드 경로를 쓴다.
- 최대 256개 메타데이터만 대기하며 RGB나 모델 설명을 추가 보관하지 않는다.
  상한이면 즉시 기존 확인 경로로 넘긴다. 만료 시 이미 받은 판정을 쓰며 추가 Cloud 호출은 없다.
  기존 장면 확인이 열려 있으면 그 대기열을 재사용한다. 이 역시 동일인 병합은 아니다.
- 만료 후 장면 확인에는 기존 사람의 도움 요청/괜찮다는 답변을 복사하지 않는다.
  기존 사건이 종료되거나 증거 개정이 바뀌면 대기 관측도 별도 확인으로 넘긴다.
  동의·연결·카메라 설정 변경 시에는 대기를 취소하고 과거 질문을 재생하지 않는다.
- 클립과 사람 박스는 대기 만료 시각이 아니라 원래 분석한 영상의 시각으로 기록한다.
  프롬프트, 모델, YOLO 판정, STT 및 외부 알림 정책은 바꾸지 않는다.

**한계:** Pose가 완전히 사라지고 동일인 증거를 끝내 얻지 못하면 여전히 사건/대화가
총 2개가 될 수 있다. 변경점은 두 번째 확인을 즉시 만들지 않고 제한 시간 동안

## 남은 제한

연결 실패는 [두 가지 경우](fall_association_cases.md)로 추가 구분한다.
유효한 Pose 관측이 없는 경우와 관측은 있지만 대상 연결을 확인하지 못한 경우를 기록하며,
두 경우 모두 위의 일반 확인 경로를 유지한다. 이 분류만으로 사람을 연결하거나 사건을 병합하지 않는다.

- 미연결 장면 사건을 특정 사람의 사건으로 자동 전환/병합하지 않는다. 확실한 동일인 근거와
  질문·답변 이전 규칙을 검증해야 한다. 이후 Pose에 사람이 보인다는 이유만으로 연결하지 않는다.
- 열린 일반 확인 하나로 반복 질문을 줄이므로, 새로운 다른 사람의 의심도 그 장면 기록에
  추가될 수 있다. 다인 상황의 재질문 간격·현장 확인/명시적 종결 운영 기준은 별도 검증이 필요하다.
- 웹 업로드 JSON은 변경하지 않았다. 원시 발견은 로컬에 남고 사건 이벤트는 기존 outbox로
  전달 가능하다. 웹의 대상 미확인 표시, 운영 서버 배포, 실제 푸시 수신은 이번 검증 범위 밖이다.
- 기록은 재시작 후 남지만 이전 질문을 자동으로 재생하지 않는다. 기존 재시작 복구 정책을 유지한다.
