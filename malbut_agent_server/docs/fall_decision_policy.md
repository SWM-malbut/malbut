# 낙상 확인 결과 처리 기준

작성일: 2026-09-19. [전체 명세](fall_detection.md), [실행 연결](fall_runtime.md).

**4절의 정상 자동 종결 조건은 사용자 승인 후 코어에 반영했다.**
시험용 영상 결과·Agent 답변·대상 관측으로 흐름을 검증했다.
[대상별 관측 생성과 영상 박스 연결](fall_subject_observation.md)도 추가했다.
Agent 실제 연동과 실물 검증은 남아 있으며, 운영 환경은 켜지 않았다.

## 1. 무엇을 판단하나

YOLO 또는 Cloud가 의심하면 먼저 확인 대상으로 남긴다. 이것만으로 낙상을 확정하거나
보호자에게 알리지 않는다. 그다음 같은 사람·사건의 영상, 자세 변화, 본인 답변을 함께 본다.

- **영상 판단:** 낙상 / 낙상 의심 / 정상 / 판단 불가. Cloud의 해석이지 사고의 객관적 확정은 아니다.
- **현재 처리:** 확인 중 / 재확인 필요 / 도움 필요 / 처리 완료.
- **보호자 알림:** 일반 / 확인 필요 / 긴급. 과거 영상 판단과 현재 도움 필요 여부는 별개다.

최근 독립 경로 재생에서는 정상 영상 34개 중 16개가 확인 대상이 됐다.
이는 잘못된 보호자 알림 16건을 뜻하지 않는다. 알림까지 가기 전의 처리 기준이 필요하다.
[재생 결과](../../homecam_agent/docs/FALL84_PARALLEL_POSE_CLOUD_20260919.md)

## 2. 이미 합의했고 코드에 있는 기준

아래 알림은 발송 요청이다. 실제 보호자가 받았다는 뜻은 아니다.

| 상황 | 처리 | 보호자 알림 |
|---|---|---|
| 본인이 도움을 요청함 | 영상 결과를 기다리지 않고 도움 필요로 처리 | 긴급 |
| Agent가 실제 질문 재생·답변 대기 후 무응답을 확인함 | 영상이 정상이어도 무응답 기록 유지. 의식 소실로 단정하지 않음 | 확인 필요 |
| 영상에 낙상이 관측됐지만 본인은 괜찮다고 답함 | 낙상 관측과 답변을 모두 저장. 정상 사건으로 바꾸지 않음 | 일반 |
| 추가 재확인 2회를 소진했고 의심이 계속됨 | 확인하지 못한 이유와 남은 의심을 기록. 정상으로 끝내지 않음 | 확인 필요 |
| Agent 실행 실패 또는 아직 답변을 기다리는 중 | 통신/처리 실패와 대기 상태를 구분. 무응답으로 바꾸지 않음 | 이 사유만으로 무응답 알림을 만들지 않음 |
| Cloud 지연·연결 오류·잘못된 응답 | 실패 기록. 정상 판정으로 대체하거나 Local VLM을 호출하지 않음 | 실패만으로 낙상 확정 알림을 만들지 않음 |

도움 요청·무응답은 다른 조건보다 먼저 처리한다. 영상 또는 Agent 결과가 늦게 도착해도
이미 생긴 알림을 지우거나 등급을 낮추지 않는다. 같은 사건·같은 등급 알림은 중복 요청하지 않는다.

## 3. 결과가 다를 때 — 이번에 확정할 안

여기서 ‘정상 답변’은 질문 대상이 직접 한 유효한 `okay` 답변이다.
TV·다른 사람의 말·STT 실패·이전 질문의 답변은 정상 답변으로 쓰지 않는다.

| 상황 | 다음 처리 제안 | 알림/종결 |
|---|---|---|
| YOLO 의심, Cloud 정상, 본인은 괜찮다고 답함 | 같은 사건으로 새 영상을 한 번 재확인. 새 자세 변화도 확인 | 처음 받은 정상 판정만으로 자동 종결하지 않음 |
| YOLO 의심, Cloud 정상, 답변이 불분명함 | 새 영상 재확인. Agent 쪽에서 답변 확인 필요 여부 결정 | 도움 요청·실제 무응답이면 위 우선 규칙 적용 |
| Cloud 의심, YOLO 미검출 | YOLO가 없다는 이유로 버리지 않고 질문·재확인 진행 | 재확인 후에도 의심이 남고 횟수가 끝나면 확인 필요 알림 |
| Cloud 의심, 본인은 괜찮다고 답함 | 답변은 저장하되 의심을 자동 해제하지 않고 새 영상 확인 | 의심 지속 여부에 따라 재확인 또는 확인 필요 알림 |
| Cloud 판단 불가/실패, 본인은 괜찮다고 답함 | 영상 부족/오류 사유를 남기고 새 영상으로 확인 시도 | 영상 실패를 정상으로 해석하지 않음 |
| 나중 영상은 정상이지만 앞서 낙상 관측이 있었음 | 앞선 기록을 유지하고 회복·도움 필요 여부를 별도로 확인 | 정상 사건으로 다시 쓰지 않음. 위험 해소·대응 완료는 별도 확인 |

첫 확인 후 추가 확인은 **최대 2회**다. 재확인 때 사건 ID와 사용한 횟수를 유지한다.
같은 입력·같은 근거를 즉시 다시 보내거나 처음부터 새 사건으로 만들어 횟수를 초기화하지 않는다.
새 질문도 이미 대기 중인 질문과 중복 재생하지 않는다. 질문 횟수·대기 시간은 Agent 담당 명세가 필요하다.

## 4. 정상으로 자동 종결해도 되는 조건 — 승인·코어 구현

아래를 **모두** 만족하면 보호자에게 새 알림을 보내지 않고 정상 확인으로 종결한다.

1. 처음에는 YOLO만 의심했고, Cloud는 정상으로 판단했다.
2. 같은 대상의 현재 질문에 ‘괜찮다’는 답변을 받았다.
3. **새 영상으로 추가 확인을 실제로 한 번 완료했고**, 그 결과도 정상이다.
4. 확인 중 새 낙상 동작이나 계속되는 의심 근거가 없다.
5. 이 사건에 앞선 낙상 관측·도움 요청·알림 이력이 없다.
6. 분석·질문이 대기 중이지 않으며 대상과 근거 버전이 모두 맞는다.

단, ‘새 의심 근거 없음’을 단순한 사람 미검출이나 메시지 미수신으로 판단하면 안 된다.
카메라/감지가 정상 동작했고 같은 대상의 유효한 새 관측이 있어야 한다.
실제 관측 시간과 자세 조건은 아직 수치로 정하지 않았다. 임의의 신뢰도 점수나 대기 시간을 넣지 않는다.

자동 종결하더라도 후보·영상 판정·답변 이력은 삭제하지 않는다.
이미 낙상이 관측됐거나 도움이 요청된 사건은 이 정상 종결 규칙의 대상이 아니다.

구현은 다음과 같이 구분한다.

- 첫 정상 결과와 유효한 `okay` 답변이 모이면 새 영상 재확인을 예약한다.
  기존 호출 간격·호출 상한·사건당 추가 2회 제한을 그대로 따른다.
- 단순 호출 횟수가 아니라 **실제로 성공한 정상 결과 두 건**을 확인한다.
  두 번째 요청에는 첫 요청보다 나중에 촬영된 RGB가 포함되어야 한다.
  영상 구간 일부는 겹칠 수 있으며, 같은 마지막 프레임을 다시 보낸 것은 재확인으로 세지 않는다.
- 카메라 OFF, 새 후보·관측의 의심, 관측 불확실, Cloud 실패는 이전 정상 근거를 무효화한다.
  새 버전에는 이전 답변·정상 결과를 쓰지 않는다.
- Cloud 후보가 합쳐졌거나 Cloud가 한 번이라도 낙상·의심·판단 불가로 답한 사건은
  이 좁은 자동 종결 규칙에서 제외한다. 담당 판단부가 별도로 처리한다.
- `SubjectObservation`으로 같은 대상의 새 관측을 명시적으로 받아야 한다.
  사건·대상·버전·최근 분석 요청 ID가 일치하고, 대상 연결이 검증되어야 한다.
  최신 영상 시각 이후의 관측이며 설정된 관측 유효 시간 안에 있어야 한다.
- `clear`는 카메라·감지 입력이 정상이고 해당 사람을 실제로 관측했으며,
  새 의심이나 지속되는 의심이 없음을 확인했다는 뜻이다. 미검출·가림·메시지 누락은 이 값이 아니다.
  관측 후 감지 상태가 불명확하거나 사람이 안 보이면 해당 정상 관측도 무효화한다.
- YOLO 연결부가 안정된 기립 자세에 한해 대상별 정상 관측을 생성한다.
  두 정상 영상부터 현재까지 대상 연결이 유지되어야 한다. 실제 Agent 답변이 없으면 종결하지 않는다.

## 5. 코드와 연결할 때 빠지면 안 되는 것

- `CloudFallMonitor`에 [정상 종결 조건](../malbut_agent_server/application/fall_normal_closure.py)을
  연결했다. 나머지 판단은 `decision_required`로 넘긴다.
- 명시적 `resolve(normal_verified)` 명령에도 같은 조건을 적용한다. 첫 정상 결과만으로
  명령을 보내 검사를 우회할 수 없다. `risk_cleared`·`response_completed`는 별도 명시적 결정이다.
- 정상 종결 근거의 요청 ID·촬영 시각·대상 관측은 로컬 SQLite에 남긴다.
  기존 웹 API 형식은 바꾸지 않고 원본 영상·음성·모델 설명도 추가 저장하지 않는다.
- Cloud 장면 판정을 YOLO 사람 ID에 임의로 붙이지 않는다. 대상이 불분명하면 사람별 종결도 하지 않는다.
- 같은 사건의 지난 버전 영상·답변은 새 변화의 정상 근거로 쓰지 않는다.
  단, 늦게 도착한 이전 영상의 낙상 관측은 이력에 남기고 정상 자동 종결을 막는다.
- Cloud 대기 20초·추가 재확인 2회는 유지한다. 재확인 사이 간격, 실패 때의 횟수 차감,
  Agent 답변 대기·재질문 상한은 별도로 확정할 항목이다.
- 원래 코어는 연결/동의/영상 부족으로 실패한 확인 시도도 횟수를 센다.
  이 동작을 이번 문서에서 승인된 제품 규칙으로 바꾸거나 조용히 수정하지 않았다.

## 6. 검증 범위

영상별 실제 Agent 답변 자료가 없으므로, 가짜 답변을 붙인 테스트는 흐름 검증으로만 쓴다.
84개 영상의 새 정확도나 알림 정확도로 보고하지 않는다.

- 결과 도착 순서가 바뀌어도 도움 요청·무응답 알림이 유지되는지.
- 최초 Cloud 정상만으로 종결하지 않는지, 새 영상 재확인 조건을 만족해야 하는지.
- 재확인 중 새 변화가 생겼을 때 지난 정상 답변·영상으로 끝내지 않는지.
- 사람이 안 보이거나 Agent/Cloud가 실패했을 때 정상으로 바꾸지 않는지.
- 추가 확인 2회 이후에도 미해결을 유지하고 필요 알림이 한 번만 생기는지.
- 과거 낙상 기록과 실제 회복·대응 완료를 별도로 유지하는지.

추가 검증: 정상 추가 확인의 새 프레임, 관측 유효 시간, 잘못된 대상·요청 ID,
질문 미재생, 관측 불확실·미검출, 카메라 OFF, 과거 Cloud 의심·알림 이력,
SQLite 재시작 후 근거 유지와 기존 DB 호환을 시험했다.

2026-09-19 검증: Agent 패키지 **1068개 통과·12개 건너뜀**.
기존처럼 ROS 통신 테스트 두 파일(`test_ros_memory_communication.py`,
`test_node_communication_ros.py`)은 제외했다. 변경 Python 파일 lint와
`git diff --check`도 통과했다. 실제 DDS·대상 관측 생성·Agent 응답·보호자 수신 검증은 아니다.

이번 변경으로 실제 Cloud 호출·질문 재생·알림 발송·배포는 하지 않았다.
