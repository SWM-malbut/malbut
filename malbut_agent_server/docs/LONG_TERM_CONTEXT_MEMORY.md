# 말벗 장기기억 기능 명세

사용자가 내용을 이해하고 함께 정하기 위한 초안이다. 아래의 **요구사항**과 **제안·미정 사항**을 구분한다. 통합체험에서 쓸 수 있는 범위는 8.7절, 일반 서버 연결은 8.8절에 표시한다.

## 1. 어떤 기능인가 — 요구사항

이전 대화에서 나눈 이야기를 다음 대화에서도 이어갈 수 있게 한다.
계획이나 결정뿐 아니라 **일상의 경험과 감정의 흐름도 기억 대상에 포함한다.**
사용자가 같은 배경을 매번 다시 설명하는 부담을 줄이는 것이 목적이다.
동의한 범위에서 일상 경험·감정·논의 중 이어갈 만한 내용을 자동으로 정리해 기억한다.
사용자가 매번 “기억해줘”라고 말할 필요는 없다.
현재 이야기와 관련된 이전 기억은 자연스럽게 자동으로 연결한다.
사용자가 매번 “기억해?”라고 요청하거나 연결 여부를 확인받을 필요는 없다.

현재도 이름·취향 같은 개인 정보 저장과 한 대화 안에서 원문·요약을 활용하는 기능은 있다.
이번에는 여러 대화에 걸친 이야기를 연결하고, 필요한 내용을 찾아 쓰는 기능을 추가하려 한다.
현재 구현 설명은 확인한 OpenAI 운영 경로 기준이다.

## 2. 무엇을 기억하나 — 요구사항

| 기억할 내용 | 예시 |
| --- | --- |
| 일상의 경험과 당시 감정 | 전시를 다녀왔고, 작품은 좋았지만 사람이 많아 지쳤다고 말했다. |
| 이후의 변화 | 다시 방문했을 때는 한산해서 천천히 관람했다고 말했다. |
| 목표와 논의 과정 | 설명서를 쉽게 만들려고 한 장 요약과 영상을 비교했다. |
| 결정과 이유 | 수정하기 쉬워서 한 장 요약을 먼저 만들어 보기로 했다. |
| 아직 정하지 않은 것 | 그림 중심 구성은 말벗의 제안이며, 사용자는 아직 선택하지 않았다. |
| 시점과 근거 | 언제, 누가, 어느 대화에서 말한 내용인지 함께 남긴다. |

사용자가 직접 말한 내용, 말벗의 추측·제안, 실제 확인한 결과를 구분한다.
하루의 감정을 평소 성격으로 단정하거나, 과거 상태가 지금도 계속된다고 가정하지 않는다.
결정은 제안·확정·미정·보류·변경됨을 구분하고, 말하지 않은 이유는 만들어 넣지 않는다.
기존 이름·취향 기억도 함께 사용한다.

## 3. 어떻게 대화가 이어지나 — 예시

사용자가 해당 기억의 보관과 다음 대화 활용에 동의한 경우의 가상 예시다.

**일상 이야기**

> 사용자: “오늘 전시를 봤어. 작품은 좋았는데 사람이 많아서 좀 지쳤어.”
> 다음 대화의 사용자: “그 전시 다시 가봤어.”
> 말벗: “지난번에 작품이 좋다고 했던 전시구나. 이번에는 어땠어?”

지난 경험을 알아듣되, 이번에도 지쳤을 것이라고 단정하지 않는다.

**계획 이야기**

> 사용자: “설명서는 고치기 쉽게 한 장 요약부터 만들어 보자.”
> 말벗: “그림 중심으로 구성하는 방법도 있어.”
> 사용자: “그건 아직 정하지 말자.”
> 다음 대화의 사용자: “설명서 어디까지 정했지?”
> 말벗: “수정하기 쉬운 한 장 요약을 먼저 해보기로 했고, 그림 중심 구성은 아직 미정이야.”

말벗이 제안한 내용을 사용자의 확정 결정으로 바꾸면 안 된다.

## 4. 어떻게 정리하고 찾아 쓰나

**정한 방식:** Letta에서 참고한 주제 문서 방식처럼, 같은 이야기끼리 하나의 기억 묶음으로 관리한다.
날짜나 대화가 달라도 이어지는 이야기는 같은 묶음에 연결하고, 그 안에 시간순으로 변화를 남긴다.
예를 들어 같은 전시의 첫 방문과 재방문을 함께 묶어 그때의 경험과 감정이 어떻게 달라졌는지 이어간다.

**정한 구조:** 각 이야기 묶음에 현재 상황·이야기의 흐름·원문 근거를 함께 남기고 연결한다.

1. **현재 상황:** 그 이야기가 지금 어디까지 진행됐는지 짧게 정리한다.
2. **이야기의 흐름:** 어떤 경험과 논의를 거쳐 현재 상황에 이르렀는지 남긴다.
3. **원문 근거:** 실제로 나눈 대화를 연결하고, 정확한 표현이 필요하면 앞뒤 대화도 확인한다.

평소에는 관련 이야기의 현재 상황부터 읽고, 더 알아야 할 때 이야기의 흐름과 원문 근거를 찾아본다.
모든 원문을 매번 AI에 넣지 않는다. 요약에서 빠진 내용이 있을 수 있으므로 요약만으로 확신하지 않는다.
**정한 갱신 시점:** 대화 원문은 보관하고, 내용이 어느 정도 쌓이거나 새로운 경험·결정·정정 같은 중요한 변화가 생기면 정리된 기억을 갱신한다.
매번 말을 주고받을 때마다 전체 기억을 다시 정리하지 않고, 새로 나눈 내용을 중심으로 반영한다. 구체적인 양·시간 기준은 아직 정하지 않았다.
DB·검색 기술은 아직 확정하지 않았으며, 8절에 기존 SQLite를 활용하는 설계안을 제안한다.

## 5. 저장하고 고칠 때의 규칙 — 요구사항

- **사용자가 삭제할 때까지 보관한다.** 시간이 오래됐다는 이유로 자동 삭제하지 않는다. 오래된 기억도 현재 이야기와 관련 있을 때 찾아 쓴다.
- **“새로 시작하자”는 현재 대화 흐름만 초기화한다.** 저장된 기억은 유지하고, 새 이야기와 관련된 장기기억은 계속 활용한다.
- **대화 중에도 기억을 정리한다.** 내용이 쌓이거나 중요한 변화가 생기면 갱신하며, 종료 인사나 정상 종료에만 의존하지 않는다.
- **중단돼도 이어서 처리한다.** 어디까지 저장했는지 확인하고, 같은 내용을 중복 저장하거나 실패한 저장을 완료했다고 말하지 않는다.
- **관련된 기억은 자연스럽게 연결한다.** 사용자의 현재 말을 우선하고, 무관한 과거 이야기를 꺼내지 않는다. 정확한 말이나 이유가 필요하면 원문을 확인하고, 확인할 수 없으면 모른다고 말한다.
- **정정하면 함께 고친다.** 잘못된 기억을 고치고 관련 요약과 검색 결과에도 반영한다. 뒤늦게 끝난 작업이 예전 내용으로 되돌리면 안 된다.
- **“잊어줘”라고 하면 원문과 기억을 함께 삭제한다.** 해당 내용의 원문, 정리된 기억과 관련 검색 자료를 함께 삭제한다. 어떤 이야기를 뜻하는지 모호할 때만 대상을 확인하며, 관련 없는 대화는 유지한다. 삭제한 내용이 요약·검색·복구 과정에서 되살아나지 않게 한다.
- **연결된 기억도 확인한다.** 같은 내용이 개인 정보 기억과 대화 요약 양쪽에 있으면 정정·삭제를 함께 반영한다.

## 6. 동의와 안전 — 요구사항

- 현재 대화에서 쓰는 것과 다음 대화에도 기억해서 쓰는 것을 구분해 동의를 받는다. 기존 이름·취향 기억 동의를 새 범위로 자동 확대하지 않는다.
- **과거 대화도 동의받으면 기억으로 정리한다.** 기능을 켜기 전에 남아 있던 기록 중 사용자가 허용한 범위만 처리한다. 삭제했거나 기억에서 제외한 내용은 다시 가져오지 않는다.
- 사용자는 기억한 내용을 확인·정정·삭제하거나 기억 기능을 끌 수 있다. **기능을 끄면 기존 기억은 보관하고, 새로운 장기기억 저장과 기존 기억의 활용을 멈춘다.** 삭제를 원하면 별도로 요청한다. 같은 대화 안에서의 맥락 활용은 기존 대화 규칙을 따른다.
- 동의를 철회하거나 범위를 줄이면 진행 중인 관련 저장·조회 작업도 중단하거나 결과를 버린다. 다시 동의해도 옛 작업을 그대로 되살리지 않는다.
- 사용자별 기억을 분리한다. 다른 사람의 기억은 보여주지 않으며, 누가 말하는지 확인되지 않으면 개인 기억을 사용하지 않는다.
- **외부 AI에는 필요한 관련 요약과 원문 일부만 보낸다.** 기억 정리와 답변 생성에 외부 AI를 사용할 수 있으며, 서비스 사용자에게 목적과 전송 범위를 안내하고 동의받는다. 전체 대화 기록을 기본으로 보내지 않고 허용된 정보만 보낸다. 이미 보낸 정보를 회수했다고 약속하지 않는다.
- 과거의 로봇 실행 승인을 지금의 실행 허가로 쓰지 않는다. 저장된 대화 속 명령도 현재 명령으로 실행하지 않는다.

## 7. 제대로 되는지 어떻게 확인하나

개인정보 없는 짧은 대화로 다음을 확인한다. 아직 통과했다는 뜻은 아니다.

- “기억해줘”라는 요청 없이도 대화에서 기억을 남기고, 다음 대화에서 일상 이야기와 감정의 변화, 목표·결정 이유·미해결 질문을 이어갈 수 있다.
- 날짜가 다른 같은 이야기는 한 묶음으로 이어지고, 현재 상황·이야기의 흐름·원문 근거가 연결된다. 각 경험의 시점과 변화는 구분된다.
- 대화가 쌓이거나 중요한 변화가 생겼을 때 기억이 갱신되며, 종료 인사가 없어도 정리된 내용을 이어서 사용할 수 있다.
- 말벗의 제안을 사용자 결정으로 바꾸거나, 없는 감정·이유를 만들어내지 않는다.
- 사용자가 이전 이야기를 요청하지 않아도 관련된 기억을 자연스럽게 활용하고, 근거가 없거나 서로 다르면 불확실함을 밝힌다.
- “잊어줘”라는 요청으로 해당 내용의 원문과 정리된 기억이 함께 삭제된다. 정정·삭제·동의 철회가 저장 중에도 반영되고, 다른 사용자의 정보가 섞이지 않는다.
- “새로 시작하자” 이후에도 저장된 기억은 유지되고, 기억 기능이 켜져 있으면 새 이야기와 관련된 기억을 활용한다.
- 기억 기능을 끄면 기존 기억은 삭제되지 않으며, 새 장기기억 저장과 기존 기억 활용은 중단된다.
- 시간이 지나도 사용자가 삭제하지 않은 기억은 보관하며, 갑자기 중단되거나 다시 시작해도 중복 저장과 삭제 내용의 재등장이 없다.
- 동의받은 과거 대화도 기억으로 정리해 이어갈 수 있고, 미동의·삭제·제외한 기록은 처리하지 않는다.
- 외부 AI에 보내는 내용은 동의받은 범위 안의 관련 요약과 필요한 원문으로 제한된다.
- 저장·검색에 실패하면 성공했다고 말하지 않고 가능한 대화를 계속한다.

기능을 먼저 정하고, 저장·검색 방식을 설계한 뒤 이 예시로 검증한다.
기존 성능 평가의 통과를 설계의 선행 조건으로 삼지 않는다. 속도·비용은 작은 구현으로 측정한 뒤 기준을 정한다.

## 8. 저장·검색·화면 설계안 — 제안

앞에서 정한 기능을 구현하기 위한 검토안이다. 기술 선택과 수치는 아직 확정하지 않는다.

### 8.1 저장: 기존 SQLite에 이야기 기록 추가

현재 SQLite와 대화 원문 저장소를 활용하는 안부터 시작한다. 기존 개인 사실 기억도 유지한다.
새로 관리할 정보는 다음과 같다. 아래 이름은 설명용이며 실제 DB 이름은 별도로 정한다.

| 기록 | 담을 내용 |
| --- | --- |
| 이야기별 현재 상황 | 사용자, 이야기 제목·다른 표현, 현재 상태, 결정·이유·남은 질문, 갱신 시각과 버전 |
| 이야기의 흐름 | 어떤 경험·논의·변화가 있었는지, 발화자와 시점, 제안·확정·미정 상태 |
| 원문 연결 | 어느 사용자의 어느 대화·회차·발화에서 나온 내용인지와 해당 부분의 위치 |
| 작업과 동의 상태 | 어디까지 정리했는지, 처리할 원문 범위, 적용한 동의·변경 버전, 작업 성공·실패 여부 |

원문은 기존 저장소를 참조해 중복 복사를 줄인다. 새 대화를 시작해도 이전 출처를 찾을 수 있는 식별자를 유지한다.
현재 상황의 각 내용에서 흐름과 원문까지 따라갈 수 있게 하고, 같은 근거를 쓴 개인 사실 기억도 연결한다.
같은 단어가 나온다는 이유만으로 이야기를 합치지 않는다. 같은 사건·목표의 후속 이야기인지 확인하고, 불분명하면 따로 두었다가 근거가 생겼을 때 연결한다.

### 8.2 검색: 필요한 이야기부터 조금씩 읽기

1. 서버가 확인한 사용자, 기억 기능 상태와 동의 범위로 조회 대상을 먼저 제한한다.
2. 현재 발언과 바로 앞 대화를 이용해 이야기 제목·다른 표현·핵심 내용에서 후보를 찾는다. 처음에는 SQLite의 단어 검색부터 검토하며, 오래된 기억도 검색 대상에 남긴다.
3. 관련된 이야기의 현재 상황을 읽는다. 최근 이야기라는 이유만으로 선택하지 않으며, 서로 다른 이야기가 헷갈리고 답변에 영향을 주면 짧게 확인한다.
4. 이유·정확한 표현·변화 과정이 필요하면 해당 흐름과 원문, 필요한 앞뒤 발화만 추가로 읽는다. 이때도 동의·삭제 여부를 다시 확인한다.

정리가 아직 끝나지 않았다면 마지막 정리 이후의 허용된 원문을 제한된 범위에서 보충한다. 확인하지 못한 부분은 기억하는 척하지 않는다.
다른 표현으로 질문했을 때도 찾아지는지 작은 예시로 확인하고, 부족할 때 의미 검색을 추가 검토한다. 검색량과 AI 입력량에는 별도 한도를 두되 수치는 측정 후 정한다.
[현재 원문 조회](../malbut_agent_server/conversation_recall.py)는 같은 세션에 한정돼 있으므로, 이전 세션 조회는 새로 설계해야 한다.

### 8.3 갱신: 대화는 계속하고, 새 내용만 뒤에서 정리

- 새 대화 원문이 확정되면 아직 정리하지 않은 범위를 기록한다. 대화 응답은 기억 정리 완료를 기다리지 않는다.
- 새 경험·결정·변경을 정리할 필요가 생기면 우선 처리한다. 그 밖에는 완료된 대화의 누적 분량이나 미처리 대화가 기다린 시간을 기준으로 예약한다. 압축 직전에도 미처리 범위를 확인한다.
- 매 발화마다 중요도 판정만을 위한 별도 AI 호출을 추가하지 않는다. 대화 처리 중 얻은 신호와 누적량을 예약에 활용하고, 실제 내용은 정리 작업에서 검증한다.
- 마지막 정리 이후의 원문과 관련 이야기의 현재 상황만 읽고 필요한 앞뒤 발화를 보충한다. 완료된 결과와 처리 위치를 함께 저장해 누락·중복을 막는다. 이야기의 현재 버전도 비교해 오래 걸린 작업이 최신 정리를 덮어쓰지 않게 한다.
- 정정·삭제·기능 끄기는 분량이 쌓이기를 기다리지 않고 즉시 사용을 차단한다. 대기·실행 중 작업도 무효화하고, 늦게 온 결과로 예전 기억을 되살리지 않는다.
- 대화 응답을 우선하고 기억 작업은 작은 묶음으로 처리한다. 동의받은 과거 기록은 사용자별로 오래된 것부터 정리하되, 기록 시각을 새 결정 시각으로 취급하거나 최신 정정을 덮어쓰지 않는다.
- 재시작 시 저장된 처리 위치와 원문을 대조하고 유효한 미완료 범위만 다시 예약한다. 같은 범위를 재처리해도 결과가 중복되지 않게 한다. 재시도 횟수·작업 한도는 별도 설정으로 둔다.

[기존 개인 사실 추출 작업](../malbut_agent_server/automatic_memory_jobs.py)은 활성 세션과 만료 조건에 묶여 있다. 새 작업은 끝난 대화도 다뤄야 하므로 기존 큐의 조건을 그대로 사용하지 않는다.

### 8.4 정정·삭제: 연결된 기록도 함께 처리

정정은 잘못된 현재 상황을 사용 중단한 뒤 새 근거로 갱신한다. 과거에 실제로 한 말은 정정 사실과 연결한다.
삭제는 해당 원문 부분과 이를 반복한 응답, 정리된 기억·검색 자료·작업에 담긴 사본까지 추적해 제거한다.
한 발화에 다른 이야기도 섞여 있으면 삭제할 부분을 구분해 관련 없는 내용은 보존한다. 이를 위해 원문 연결에 발화 안의 위치도 남긴다. 일부 삭제 후에는 남은 연결 위치를 갱신하거나 다시 검증한다.
사용자·원문·동의의 변경 버전을 외부 전송 전, 결과 저장 전, 답변 전달 전에 다시 확인한다. 백업 복원 때도 삭제 상태를 먼저 적용한다.
실제 백업·저장 매체·외부 제공자에 남은 정보의 삭제 절차는 구현 전에 정하고, 처리한 범위만 완료했다고 안내한다.

### 8.5 동의 화면: 한 번 이해하고 선택할 수 있게

처음 켤 때 보여줄 설명 예시:

> 일상의 경험과 감정, 함께 나눈 이야기를 자동으로 기억하고 다음 대화에 활용해요.
> 직접 삭제할 때까지 보관해요. 기억 정리와 답변을 위해 관련 요약과 필요한 대화 일부를 외부 AI에 보낼 수 있어요.
> 언제든 기억을 확인·고치거나 기능을 끌 수 있고, “잊어줘”라고 하면 해당 원문과 기억을 함께 삭제해요.

| 화면 항목 | 제안 동작 |
| --- | --- |
| 동의하고 켜기 / 나중에 | 보관·다음 대화 활용·외부 전송의 목적과 범위를 안내하고 동의한 경우에만 켠다. 기본은 꺼짐이다. |
| 이전 대화도 기억하기 | 별도 선택이며 기본은 선택하지 않는다. 사용자가 허용한 과거 기록 범위를 보여준다. |
| 내 기억 | 이야기별 현재 상황과 관련 근거를 확인하고, 잘못된 내용 정정 또는 해당 이야기 삭제를 요청할 수 있다. |
| 기억 기능 끄기 | 기존 기억은 남고, 새로운 장기기억 저장과 기존 기억 활용이 멈춘다는 점을 안내한다. |
| 다시 켜기 | 현재 동의 범위를 확인하고 보관된 기억을 다시 활용한다. 꺼둔 동안의 대화는 그 기간을 포함해 별도로 동의받은 경우에만 정리한다. |

실제 화면에는 외부 AI 제공자와 보관·삭제 정책을 함께 표시한다. 외부 전송에 동의하지 않으면 그 전송을 하지 않으며, 로컬 대안이 없으면 이 설계의 장기기억 기능을 켤 수 없다고 안내한다.
기억 기능을 끄는 것과 현재 대화 자체의 외부 AI 사용은 구분한다. 같은 세션의 대화는 기존 대화·전송 동의 범위에서 이어간다.

### 8.6 작은 구현에서 확인할 순서

먼저 이야기 한 개의 저장·재개와 원문 연결을 확인한다. 다음으로 정정·삭제·기능 끄기와 다른 사용자 격리를 확인하고, 중단·재시작·과거 기록 정리를 검증한다.
그 뒤 호출량·입력량·처리 시간·저장량을 측정해 갱신 주기와 검색 한도를 조정한다. 구체적인 수치나 성능 보장을 미리 확정하지 않는다.

### 8.7 지금 통합체험에서 쓰는 방법 — 구현한 범위

저장소 루트에서 아래 명령으로 텍스트 체험을 실행한다. Python과 의존성 준비는 [체험기 안내](../tools/agent_console/README.md)를 따른다. 처음 표시되는 장기기억 설명에 **“네”**라고 답하면 이후 대화부터 자동으로 정리한다. 기존 대화를 포함하려면 따로 동의해야 한다.

```sh
./scripts/agent_console.sh --no-tts
```

음성 환경이 이미 준비된 Mac의 기존 `.runtime/agent-console-20260925/통합체험.command`도 계속 사용할 수 있다. 모델·음성 라이브러리·개인 DB는 Git에 포함하지 않는다.

가볍게 확인하는 순서:

1. “오늘 전시를 봤어. 작품은 좋았는데 사람이 많아 지쳤어.”처럼 이야기한다.
2. `/stories sync`로 정리를 기다리고 `/stories`에서 같은 이야기 묶음을 본다.
3. `/new`로 새 대화를 시작한 뒤 “그 전시 처음 갔을 때 어땠다고 했지?”라고 묻는다. 종료 후 같은 명령으로 다시 실행해도 DB에 저장된 기억은 유지된다.
4. “그때 지쳤다는 건 잘못 말했어. 사실 편안했어.”처럼 정정한다. 정리 중에는 낡은 장기기억으로 단정하지 않는다.
5. “전시 이야기 잊어줘”라고 말한다. 대상이 여러 개면 어느 이야기인지 확인한다.

| 명령 | 하는 일 |
| --- | --- |
| `/stories` | 이야기 목록과 정리 중·실패 상태 확인 |
| `/stories sync` | 미완료 정리를 기다리고 실패한 작업 재시도 |
| `/stories sources ID` | 이야기 ID에 연결된 원문 부분 확인 |
| `/stories delete ID` | 선택한 이야기의 원문 부분과 연결된 기억 삭제 |
| `/stories off` / `/stories on` | 장기 저장·활용 중지 / 설명을 확인하고 다시 켜기 |
| `/stories history` | 미리 보여준 과거 기록 범위에 동의한 뒤 정리 |
| `/checks` | 임시 DB와 가상 입력으로 콘솔·기억·음성 연결 검사 |

구현은 기존 SQLite에 이야기·동의·작업 기록을 추가하고 기존 개인 사실 기억과 함께 사용한다.
[저장소](../malbut_agent_server/story_runtime_store.py), [정리 작업](../malbut_agent_server/story_memory_service.py), [AI 추출](../malbut_agent_server/story_extractor.py), [대화 연결](../malbut_agent_server/story_memory_provider.py)을 공통 대화 엔진에 연결했다. 통합체험과 일반 서버가 같은 구현을 사용한다.
새로 완료된 대화를 작은 묶음으로 뒤에서 정리하고, 제목·다른 표현·내용에서 관련 이야기를 선택한다. 정상 종료 외에도 중간 저장과 재시작 복구를 지원한다.
대화에는 관련된 현재 상황을 넣고, 정확한 표현이나 이유를 물으면 필요한 원문도 제한해서 가져온다. 제안·사용자 발언·확정 상태를 구분하며 과거 감정을 현재 상태로 단정하지 않는다.
동의·삭제 상태와 선택한 원문 근거를 전송·저장·답변 전달 때 다시 확인한다. 기억은 현재 로봇 실행 권한으로 쓰이지 않는다.

**현재 제한도 알아두기**

- 일반 HTTP 서버도 공통 대화 엔진을 사용한다. ROS 경로도 같은 factory를 사용하지만 실제 로봇에서의 음성·장치 동작은 별도 검증 대상이다.
- 콘솔은 한 명의 체험 사용자로 실행된다. 저장 계층은 사용자별로 분리하지만 여러 사람이 같은 콘솔·DB를 함께 쓰면 같은 사용자로 취급된다. 다중 사용자용 인증은 별도다.
- 이야기 검색은 단어와 다른 표현을 이용한다. 의미가 같아도 표현이 크게 다르면 놓칠 수 있다. 자동 정리에서 오류가 나면 상태를 표시하고 재시도하며, 성공했다고 말하지 않는다.
- 미처리 대화가 있으면 관련 내용을 모두 찾은 뒤 삭제한다. AI 장애 등으로 범위를 확정하지 못하면 **삭제를 보류하고 아직 삭제하지 않았다고 알린다.** 기능을 끈 동안 남은 미처리 기록은 원문 범위를 다시 확인하고 정리 동의를 받아야 한다. 정리 중·실패 중에는 낡은 장기기억을 답변에 넣지 않는다.
- 한 사용자 발화에서 이야기 A를 지우면 구분된 A 부분만 지우고 B 부분과 근거 위치를 보존한다. 다만 A를 재사용한 **말벗 답변은 전체를 비울 수 있어**, 그 답변에 함께 들어 있던 B 설명도 사라질 수 있다.
- 삭제는 현재 애플리케이션 DB의 원문·연결된 이야기·요약·사실 기억에 적용한다. 디스크 잔여 영역, 별도 백업과 이미 외부 AI에 전송한 정보까지 지웠다고 보장하지 않는다.
- 기존 사실 기억과 별도 대화 요약 경로는 유지된다. 이야기 정정은 현재 이야기와 이후 조회에 반영하지만, 모든 과거 발언을 새 사실로 덮어쓰지는 않는다.

가상 대화의 실제 AI 호출로 새 세션 기억 조회, 결정 변경과 이유, 두 이야기 분리, 삭제 후 다른 원문 보존을 확인했다.
동의 철회·사용자 격리·재시작·중복 처리·잘못된 근거·진행 중 정책 변경은 자동 검사로 확인한다. 음성 장치 준비 검사는 녹음이나 실제 청취 검증과 구분한다.
속도·비용 보장 수치는 아직 정하지 않았다.

### 8.8 일반 서버에서 쓰는 방법 — 구현한 범위

이제 `/v1/agent/respond`와 `/v1/text/turns`도 이야기 기억을 사용한다. 기존 대화 API를 바꾸지 않고, **별도 동의 후 새로 완료한 대화**부터 정리한다. 서버를 다시 시작해도 DB에 남은 작업과 기억을 이어간다. 서버 생성이나 `--check`만으로 외부 AI를 호출하지 않는다.

서버는 `MALBUT_AGENT_USER_ID`로 정한 한 사용자를 담당하고, 기억 관리에는 비어 있지 않은 `MALBUT_AGENT_AUTH_TOKEN`이 필요하다. 요청으로 다른 사용자 ID를 지정할 수 없다. 여러 사용자에게 하나의 토큰을 나눠 주는 방식은 사용자별 인증이 아니다.

저장소 루트에서, 기존 OpenAI 환경과 인증 토큰을 준비한 뒤 실행한다. 아래 DB는 체험 DB와 별개인 예시이며, 같은 기억을 쓰려면 의도한 DB와 사용자 ID를 함께 맞춘다.

```sh
PYTHONPATH=malbut_agent_server python -m malbut_agent_server.cli \
  --env-file .env --provider openai --database .runtime/agent-server.sqlite3
```

기억 API는 모두 `POST /v1/stories/이름`, JSON 본문, `Authorization: Bearer 토큰`을 사용한다.

| 이름 | 본문 예시와 역할 |
| --- | --- |
| `status` | `{}` — 동의·처리 상태와 현재 `policy.revision` 확인 |
| `enable` | `{"consent":true,"external_consent":true,"expected_revision":0}` — 안내받은 보관·다음 대화 활용·외부 AI 처리에 동의. `0`은 status에서 읽은 실제 revision으로 대체 |
| `list` | `{"limit":20,"offset":0}` — 이야기 ID와 현재 상황 확인 |
| `evidence` | `{"story_id":"목록의 ID"}` — 연결된 정확한 원문 부분 확인 |
| `sync` | `{"timeout_seconds":5,"retry_failed":true}` — 최대 5초 기다리고 기술적 실패 재시도. 아직 처리 중이면 `202` |
| `delete` | `{"story_id":"목록의 ID"}` — 이야기와 관련 원문·파생 기억 삭제 |
| `disable` | `{"expected_revision":1}` — status에서 읽은 revision으로 저장·재사용 중지, 기존 기억은 보관 |
| `history-preview` | `{}` — 과거 기록의 개수·기간과 일회용 동의 토큰 발급 |

첫 상태 조회 예시다. 토큰은 환경에 미리 준비하며 코드나 Git에 넣지 않는다.

```sh
curl -sS http://127.0.0.1:8765/v1/stories/status \
  -H "Authorization: Bearer $MALBUT_AGENT_AUTH_TOKEN" \
  -H 'Content-Type: application/json' -d '{}'
```

과거 기록은 `history-preview`에서 보여준 범위를 확인한 뒤 `enable`에 `include_history:true`와 발급된 `preview_token`을 추가해 별도로 동의한다. 토큰은 해당 사용자·버전에만 쓰이고 5분 뒤 만료된다. 원문 목록을 클라이언트가 만들어 보내는 방식은 허용하지 않는다. 동의 화면은 이 API를 사용하는 클라이언트에서 제공해야 한다.

오래된 동의 요청은 `409 story_changed`로 거절한다. 이야기 삭제 범위가 아직 정리되지 않았으면 `409 story_not_settled`로 보류하고 `sync` 후 재시도한다. 꺼둔 상태의 미처리 기록에는 `history_review_required`가 올 수 있으므로 범위를 다시 확인하고 별도 동의를 받아야 한다. 동의나 삭제 상태가 바뀐 뒤 예전 답변을 재전송하거나 뒤늦게 음성으로 읽으려 하면 차단한다. 이 검사에 필요한 출처는 DB에 저장해 재시작 후에도 검사한다.

`/v1/conversations/delete`로 대화 자체를 지우면 그 원문에 의존한 이야기 요약·개인 사실 기억과 연결된 말벗 답변도 정리한다. 여러 대화가 섞인 이야기 요약은 안전하게 통째로 제거할 수 있지만 다른 대화의 사용자 원문은 남긴다. 대화 초기화·종료는 완료 원문과 기억을 보존한다. 기존 개인 사실 기억의 삭제·정정으로 제외된 원문도 이야기 기억에서 재사용하지 않는다.

서버의 이야기 관리 명령은 위 API로 호출한다. 콘솔의 “전시 이야기 잊어줘” 같은 자연어 관리 해석이 일반 서버에도 그대로 추가된 것은 아니다. 기존 개인 사실 기억 중단과 이야기 기억 중단은 별도 동의 범위이며, 응답에서도 그 범위를 구분한다.

목록·원문 조회는 페이지별 항목 수와 응답 크기를 제한한다. 현재 저장 계층은 해당 사용자 목록을 먼저 읽으므로 매우 많은 기록에 대한 DB 수준 페이지 조회는 후속 개선이다. 기억은 로봇 실행 허가를 만들지 않으며 기존 인증·현재 실행 확인 경계를 그대로 따른다.

## 9. 아직 남은 세부 결정

- 다른 표현의 검색 품질, 이야기를 합치거나 나누는 기준과 사용자 편집 방식.
- 현재 작은 묶음·대기시간·입력 한도를 실제 대화량에 맞춰 조정할 기준.
- 정리 실패 중에도 외부 AI 없이 지울 수 있는 범위, 말벗 답변의 일부만 지우는 방법.
- 다중 사용자 인증과 클라이언트 동의 화면, 실제 ROS 장치 검증, 백업·저장 매체·외부 제공자 삭제 정책.
- 사용자가 대화하지 않을 때 먼저 말을 거는 기능은 이번 범위와 별도로 정한다.
