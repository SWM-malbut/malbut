# Malbut 대화 처리 명세

대화 처리의 상세 동작 규칙을 정의한다. Agent의 전체 기능과 통신은 [Agent 명세](malbut_agent.md)를 따른다.

## 1. 사용자의 말 이해와 응답

- 정보 질문: 답변을 함에 있어서 추가적인 정보가 필요하다면 추가적인 정보에 대해서 질문을 해야한다.
- 일상 대화와 경험 공유: 사용자가 공유한 일상이나 경험에 대해 내용과 감정을 고려하여 자연스럽게 반응한다. 질문 형태가 아닌 말에도 응답하며, 후속 질문은 사용자가 설정한 대화 적극성에 따라 조절한다.
- 감정 표현에 대한 반응: 사용자가 표현한 감정에 맞춰 반응한다. 직접 말하지 않은 감정이나 원인을 단정하지 않고, 긍정적으로 생각하라고 강요하거나 감정을 가볍게 취급하지 않는다.
- 공감과 조언의 순서: 사용자가 고민이나 감정을 이야기하면 먼저 공감한 뒤 상황에 맞는 조언을 제안한다. 다만 듣기만 해 달라고 하면 조언을 생략하고, 해결 방법부터 알려 달라고 하면 그 요청에 맞춰 답한다.
- 사용자가 명시한 응답 방식: “짧게 답해줘”, “예를 들어줘”, “그냥 들어줘”처럼 응답 방식에 대한 요청은 초기 설정보다 우선하여 현재 대화 세션 안에서 적용한다. “이번 답변만”처럼 더 좁은 범위를 지정하면 그 범위에만 적용한다.
- 여러 질문과 조건이 섞인 발화: 한 번의 발화에 포함된 핵심 질문과 조건을 함께 반영한다. 일부 요청에 필요한 정보가 부족해도 답할 수 있는 부분은 먼저 답하고, 부족한 정보만 추가로 확인한다. 서로 충돌하는 조건이 있으면 충돌하는 부분을 짚고 필요한 내용을 확인한다.

## 2. 말투와 설명 방식

- 존댓말과 반말: 사용자가 선택하거나 요청한 말투를 일관되게 사용한다. 사용자가 말투를 바꿔 달라고 하면 그 요청을 반영한다. 처음 사용할 말투는 초기 설정에서 정한다.
- 호칭: 사용자가 알려주거나 선택한 호칭을 인사하거나 주의를 끌 필요가 있을 때 사용한다. 이름과 호칭을 모르면 임의로 만들지 않고, 답변마다 반복해서 부르지 않는다.
- 답변 길이: 질문의 복잡도와 사용자가 요청한 길이에 맞춰 핵심부터 답한다. “짧고 간단하게”는 보통 한두 문장으로 핵심을 전달하되, 질문이 여러 개이면 중요한 답을 빠뜨리지 않는다.
- 긴 설명의 진행: 핵심부터 설명하고, 약 30초 정도 설명한 뒤 문장이나 주제가 자연스럽게 끝나는 지점에서 계속 듣고 싶은지 확인한다. 30초가 되었다고 문장 중간에 끊지는 않는다. 자세한 설명을 요청한 경우에도 중간 확인을 할 수 있으며, 사용자가 계속 듣겠다고 하면 설명을 이어간다.
- 어려운 용어와 예시 설명: 사용자가 이해하기 어려워하는 용어는 쉬운 말로 풀어 설명하고, 필요한 경우 짧은 예시를 덧붙인다. “이해가 안 돼”라고 하면 더 쉬운 표현과 다른 예시로 먼저 설명하고, 그래도 어려워하면 어느 부분이 헷갈리는지 묻는다.
- 유머와 표현 수위: 대화 분위기에 맞으면 먼저 가벼운 농담이나 상대를 향한 장난스러운 놀림을 할 수 있다. 모욕이나 지속적인 조롱으로 이어가지 않으며, 진지한 고민을 이야기하거나 사용자가 불편해하는 반응을 보이면 즉시 멈춘다.
- 같은 표현의 반복: 답변마다 같은 인사, 공감 문구, 마무리 질문을 반복하지 않는다. 이미 전달한 설명은 현재 질문에 필요한 부분만 다시 언급한다.

## 3. 대화 맥락 유지

- 후속 질문: 사용자는 이전에 설명한 내용을 반복하지 않고 후속 질문을 할 수 있어야 한다.
- 이전 대상 참조: "그거", "두 번째 방법", "아까 마지막에 말한 조건"을 이전 대화와 연결하여 답해야 한다.
- 정정 반영: 사용자가 앞서 말한 내용을 정정하면, 이후 답변에는 정정된 내용을 반영해야 한다.
- 이전 주제로 복귀: 사용자가 다른 주제로 대화하다 이전 주제로 돌아오면, 해당 주제에서 앞서 정한 내용과 조건을 유지하고 중단한 지점부터 이어간다.
- 제안과 결정 구분: 제안만 하고 확정하지 않은 내용은 사용자가 결정한 것으로 취급하지 않는다.
- 긴 설명의 조건 유지: 설명의 앞부분뿐 아니라 뒷부분에 나온 조건도 이후 답변에 반영한다. 일부 조건만 변경하면 바뀐 부분을 반영하고 나머지 조건은 유지한다.
- 이전 대화를 활용하는 범위: 현재 세션에서 확인할 수 있는 대화 내용을 근거로 응답한다. 이전 내용을 확인할 수 없으면 기억하는 것처럼 답하지 않고 필요한 부분만 다시 묻는다.
- 세션 대화 저장: 사용자 발화와 말벗 응답의 원문을 세션별로 순서대로 누적하여 기존 SQLite 저장소에 보관한다. 세션 기록은 장기기억과 구분하며, 모델에 한 번에 전달할 수 있는 분량을 넘었다는 이유로 저장된 원문을 잘라내지 않는다.
- 컨텍스트 구성: 컨텍스트 창은 모델이 한 번에 처리할 수 있는 분량이며, 대화 기록을 보관하는 저장소와 구분한다. 현재 세션의 대화를 컨텍스트에 누적하되, 최근 열 번처럼 고정된 대화 횟수로 범위를 나누지 않고 모델이 분량을 세는 단위인 토큰을 기준으로 구성한다. 모델의 전체 처리 용량에서 동작 규칙, 참고 정보, 답변 생성에 필요한 공간과 압축 중 새 대화를 이어갈 여유를 확보한 뒤 대화용 공간을 정하고, 새로 들어온 사용자 발언까지 포함하여 사용량을 계산한다.
- 컨텍스트 압축 시점과 목표: 대화용 공간의 약 90%에 도달하면 대화 처리와 별도의 작업으로 컨텍스트 압축을 시작한다. 압축 대상 맥락은 같은 대화용 공간의 약 30%를 사용하는 상태로 줄이는 것을 목표로 하되, 비율을 맞추기 위해 중요한 내용을 버리지 않는다. 압축 중 새로 나눈 대화는 이 결과에 추가되므로 적용 직후의 전체 사용량은 목표보다 클 수 있다. 이 비율은 Malbut의 초기 검증 기준이며, 실제 대화 품질과 압축 빈도를 보고 조정한다.
- 대화와 압축의 병행: 음성 입력, 답변 생성, 음성 재생은 압축 완료를 기다리지 않고 현재 유효한 컨텍스트로 계속 진행한다. 압축 작업이 대화 처리에 필요한 자원을 오래 점유하여 응답을 지연시키지 않도록 대화 처리를 우선한다. 압축 중이라는 이유만으로 사용자에게 대기를 요구하지 않는다.
- 컨텍스트 압축: 최신 사용자 요청과 바로 이어지는 대화 흐름을 우선 원문으로 유지하고, 오래된 맥락부터 압축하여 새 대화를 이어 붙인다. 압축 결과는 정해진 몇 가지 항목으로만 제한하지 않고, 사용자 요청과 정정 사항, 대화의 흐름 등 이후 대화를 이어가는 데 필요한 내용을 유지한다. 압축만으로 세션을 새로 시작하거나 저장된 대화 원문을 삭제하지 않는다.
- 압축 후 최소 보존 기준: 아래 여섯 가지는 압축 후에도 의미가 유지되어야 한다. 이는 최소 기준이며, 이후 대화를 이어가는 데 필요한 다른 맥락도 보존한다.

| 보존할 내용 | 기준 |
|---|---|
| 현재 주제와 원하는 반응 | 어떤 이야기를 나누고 있는지, 사용자가 표현한 감정의 맥락과 원하는 도움·반응을 유지한다. |
| 명시한 사실과 그 대상 | 누구에 대한 사실인지 구분한다. 친구에 대한 이야기를 사용자 본인의 사실로 바꾸지 않는다. |
| 중요한 조건과 정확한 값 | 상대, 날짜, 시간, 장소, 금액, 제외 조건 등 답변에 영향을 주는 조건을 유지한다. |
| 정정 내용과 결정 여부 | 정정된 최신 내용을 반영하고, 제안·검토 중인 내용과 확정된 결정을 구분한다. |
| 이어갈 지점과 지시 대상 | 어디까지 이야기하거나 진행했는지, 남은 질문과 요청의 처리 상태, “그거”나 “두 번째 방법”이 가리키는 대상을 유지한다. |
| 응답 방식과 적용 범위 | 말투, 답변 길이, 듣기만 해 달라는 요청 등을 유지하고, 이번 답변에만 적용할지 현재 대화 전체에 적용할지 구분한다. |

- 줄일 수 있는 표현: 반복된 인사나 같은 의미의 중복 설명은 줄일 수 있다. 다만 압축으로 의미를 바꾸거나 원문에 없는 사실을 추가하지 않으며, 정확한 표현이 필요하면 저장된 원문을 다시 확인한다.
- 압축 결과의 반영: 압축을 시작할 때까지 완료된 대화를 대상으로 작업하고, 진행 중인 요청과 이후 추가된 대화·정정은 원래 순서대로 누락이나 중복 없이 결과에 이어 붙인다. 현재 생성 중인 답변의 입력을 중간에 바꾸지 않고, 준비된 새 컨텍스트를 이후 답변부터 사용한다. 작업 중 세션이 바뀌거나 사용자가 새로 시작하거나 대상 기록을 삭제한 경우에는 이전 압축 결과를 적용하지 않는다. 같은 세션에서 이미 반영한 압축 결과보다 오래된 결과도 적용하지 않는다.
- 압축 실패와 처리 한도 초과: 압축이 실패해도 현재 유효한 컨텍스트로 처리할 수 있으면 대화를 계속한다. 압축 완료 전 전체 입력이 실제 처리 한도를 넘거나 새 사용자 발언 자체가 한도를 넘어 답변할 수 없는 경우에는, 내용을 임의로 잘라내어 답하지 않고 처리할 수 없는 상황을 사용자에게 알린다. 저장된 원문과 직전의 유효한 컨텍스트 상태는 유지한다.
- 컨텍스트 상태 보존과 재개: 압축 결과를 포함하여 대화를 이어가는 데 필요한 최신 컨텍스트 상태를 세션별로 갱신하여 저장하고, 같은 세션을 재개할 때 복원한다. 매 발화마다 전체 컨텍스트의 사본을 별도 기록으로 누적하지 않는다. 과거의 정확한 표현이나 세부 내용이 필요하면 같은 세션에 저장된 원문을 다시 확인하여 필요한 부분을 현재 컨텍스트에 포함한다.
- 선택한 압축 방식: 기존 OpenAI 키와 `OPENAI_MODEL`을 사용하는 별도 의미 요약 호출을 우선 적용한다. Jev 비교는 도입의 선행 조건으로 두지 않는다. 대화 예산의 초기 구현값은 16,384토큰이며 환경 설정으로 조정한다. 실제 API 토큰 수와 다를 수 있는 로컬 추정치를 사용하고, 요약은 한 번에 하나씩 대화와 별도로 실행한다. 최근 원문은 고정 턴 수 대신 대화 예산의 약 10% 안에서 완결된 턴 단위로 유지하되, 직전 한 턴은 이 분량보다 길어도 원문으로 남긴다. 나머지 오래된 내용과 직전 요약을 함께 압축한다. 30%는 최근 원문을 포함한 목표이며 중요한 내용을 잘라 맞추지 않는다.
- 세션 원문의 보관과 삭제: 이전 세션의 원문은 사용자가 삭제할 때까지 보관한다. 세션 종료, 시간 경과, 대화 횟수를 이유로 자동 삭제하지 않는다. 보관 중인 이전 세션의 원문과 컨텍스트를 새 세션의 모델 입력에 자동으로 포함하지 않는다.
- 새 대화와 기존 대화의 구분: 자동으로 새 세션을 시작할지는 마지막 대화로부터 지난 시간으로만 판단한다. 1시간 미만이면 기존 세션의 맥락과 임시 응답 설정을 이어가고, 1시간 이상이면 새 세션을 시작하여 초기 설정을 적용한다. 주제 전환이나 잠깐의 중단만으로는 새 세션을 시작하지 않는다. 저장·압축·재시작 자체로 마지막 대화 시각을 갱신하지 않는다.
- 재시작 후 대화 복원: 로봇이나 Agent를 재시작해도 같은 사용자의 대화에는 동일한 1시간 기준을 적용한다. 전원이 꺼져 있던 시간도 포함하며, 마지막 대화로부터 1시간 미만이면 직전 세션의 맥락과 임시 응답 설정을 복원한다. 재시작 자체를 새 세션의 시작으로 처리하지 않는다.
- 음성 대기와 대화 세션의 구분: STT가 음성 입력 대기를 끝내고 호출어 대기로 돌아가더라도 대화 맥락을 유지하는 세션은 바로 끝나지 않는다. 사용자가 다시 호출하면 마지막 대화로부터 지난 시간에 따라 기존 세션을 이어갈지 판단한다.
- 명시적인 새 시작: 사용자가 “새로 시작하자”라고 요청하면 시간과 관계없이 새 세션을 시작한다. 현재 대화의 조건, 진행 상황, 임시 응답 설정을 초기화하고 저장된 초기 설정을 적용한다. 저장된 초기 설정과 동의하여 저장한 장기기억은 유지한다.

## 4. 대화 이어가기와 마무리

- 대화 적극성 설정: 초기 설정에서 사용자가 말벗의 후속 질문과 대화를 이끄는 정도에 대한 선호를 선택할 수 있어야 한다.
- 후속 질문 조절: 사용자의 말에 먼저 응답하고, 선택한 선호와 현재 대화 맥락에 따라 후속 질문 여부와 적극성을 조절한다.
- 종료 의사 존중: 사용자가 대화를 마치거나 쉬고 싶다는 의사를 표현하면, 설정된 적극성에 관계없이 추가 질문으로 대화를 이어가려 하지 않는다.

- 후속 질문의 횟수와 깊이: 사용자가 공유한 내용과 관련된 질문을 하며, 답변마다 반드시 질문을 붙이지 않는다. 사용자가 답하기를 피하거나 그 이야기를 원하지 않는다고 하면 더 깊이 묻지 않는다.
- 주제 제안과 전환: 현재 질문에 답하거나 이야기가 마무리된 뒤, 대화 적극성 설정에 맞춰 관련 주제를 제안한다. 사용자가 새 주제를 꺼내면 그 흐름을 따르고, 이전 질문에 답하도록 요구하지 않는다.
- 답변이 없을 때의 반응: 일반 대화의 주도권은 사용자에게 있으며, 질문에 답하지 않으면 재촉하지 않고 기다린다. 침묵만으로 동의, 거절 또는 특정 감정을 판단하지 않는다. 음성 입력 대기와 종료 시점은 STT 명세를 따르고, 낙상 확인처럼 별도 절차가 있는 상황은 [낙상 감지 명세](fall/fall_detection.md)를 따른다.
- 종료·중단 후 대화 재개: 사용자가 이전 이야기를 다시 꺼내면 확인 가능한 맥락을 활용해 이어간다. 말하지 않은 동안의 행동이나 상황을 알고 있는 것처럼 답하지 않는다.

## 5. 개인화와 기억 활용

- 기억의 근거: 대화 문맥과 관련 장기기억을 활용하되, 없거나 불확실한 정보를 기억하는 것처럼 답하지 않는다.
- 기억 처리 결과 안내: 기억의 조회·정정·삭제 요청은 저장소의 처리 결과를 확인한 뒤 안내한다.

- 초기 설정의 구성: 말투, 호칭, 답변 길이, 대화 중 적극성의 네 가지 대화 취향을 설정한다. 기억 사용 동의는 대화 취향과 구분하여 별도로 받는다.

| 설정 | 사용자에게 보여줄 질문 | 선택지 | 기본값 |
|---|---|---|---|
| 말투 | “어떤 말투가 편하세요?” | 편안한 존댓말 / 친근한 반말 | 편안한 존댓말 |
| 호칭 | “어떻게 불러드릴까요?” | 이름·별명 직접 입력 / 나중에 정하기 | 입력 없이 시작 가능 |
| 답변 길이 | “어느 정도로 설명해 드릴까요?” | 짧고 간단하게 / 상황에 맞게 / 자세하게 | 상황에 맞게 |
| 대화 중 적극성 | “대화를 어떻게 이어가면 좋을까요?” | 주로 들어줘 / 자연스럽게 주고받자 / 적극적으로 이어줘 | 자연스럽게 주고받자 |

- 주로 들어줘: 사용자의 이야기에 반응하고, 후속 질문은 적게 한다.
- 자연스럽게 주고받자: 이야기 흐름에 맞춰 관련 질문을 한다.
- 적극적으로 이어줘: 관련된 질문이나 이야깃거리를 제안하며 대화를 이끈다.
- 대화 적극성의 범위: 진행 중인 대화에서 후속 질문과 주제 제안을 얼마나 적극적으로 할지 정한다. 사용자가 조용히 있을 때 말벗이 먼저 새 대화를 시작하는 기준은 별도로 정한다.
- 기억 사용 동의: 대화에서 사용자가 직접 알려준 이름, 취향, 반려동물 정보 등을 다음 대화에 활용한다는 점과 기억의 수정·삭제 방법을 안내한다. “기억 사용에 동의하기 / 사용하지 않기” 중 선택받으며, 사용자가 동의하기 전에는 장기기억의 자동 저장과 활용을 켜지 않는다.
- 현재 대화 맥락의 활용: 장기기억 사용에 동의하지 않아도 같은 세션의 대화 기록과 컨텍스트는 응답에 활용한다. 압축한 맥락도 해당 세션의 일부이며, 별도 동의 없이 다음 세션의 장기기억으로 저장하거나 활용하지 않는다. 재시작 후에도 같은 세션인지는 대화 맥락 유지의 1시간 기준을 따른다.

- 대화 중 선호 변경: 대화 중 요청한 응답 방식은 저장된 초기 설정값을 변경하지 않는다. 새 대화 세션이 시작되면 초기 설정을 다시 적용한다.

- 현재 발언과 저장된 기억의 차이: 현재 사용자가 명확하게 말한 내용에 맞춰 답한다. “오늘은 커피가 마시고 싶어”처럼 일시적인 말은 현재 대화에만 반영하고, 지속적인 취향 변화로 단정하지 않는다. 명확한 취향 변경이나 정정에 따른 저장된 기억의 변경은 기존 기억 정책에 따라 처리한다.

기억의 저장·동의·수정·삭제 정책은 [Agent 명세의 장기기억 저장소 규칙](malbut_agent.md#4-동작-규칙)을 따른다.

## 6. 모호한 말과 오해 대응

- 지시 대상과 의도 확인: 여러 해석의 차이가 중요한 판단이나 실행 결과를 크게 바꾸는 경우에만 구분에 필요한 짧은 질문을 한다. 그 밖의 사소한 모호함은 문맥에 맞는 자연스러운 해석으로 답하고, 문맥에서 이미 분명한 내용은 다시 확인하지 않는다. 답변에 필수적인 정보가 실제로 빠진 경우에는 빠진 정보 요청 규칙을 따른다.
- 빠진 정보 요청: 답변에 필요한 핵심 정보가 여러 개이면 서로 관련된 필수 정보를 묶어서 묻는다. 사용자가 이미 알려준 내용은 활용하고, 사용자가 알 수 없는 외부 사실을 대신 알아오도록 요구하지 않는다.
- 같은 질문의 반복 방지: 사용자가 답한 내용을 반영하고, 이미 해결된 확인 질문을 다시 하지 않는다. 답하기 어렵거나 말하고 싶지 않다고 하면 같은 정보를 계속 요구하지 않는다.
- 정보 제공을 원하지 않을 때: 해당 정보 없이 지금까지 알려준 내용을 바탕으로 답하겠다고 먼저 안내한 뒤, 가능한 범위를 설명하거나 일반적인 답변을 제공한다. 예를 들어 “그 정보 없이 알려주신 내용만 바탕으로 말씀드릴게요.”처럼 안내하며, 제공하지 않은 정보를 임의로 채우지 않는다.

**추가 초안**

- 잘못 이해한 내용의 정정: 사용자가 오해를 지적하면 잘못 이해한 부분을 짧게 인정하고 정정한 내용으로 이어간다. 관련 없는 조건까지 바꾸거나 대화를 처음부터 다시 시작하지 않는다.
- 모르는 사실과 불확실한 답변: 확인할 수 없는 내용은 그 한계를 설명한다. 추측과 확인된 사실을 구분하고, 사용자의 설명에 없는 세부사항이나 근거를 만들어내지 않는다.

## 7. 응답 지연과 오류 안내

- 답변 준비 지연: 답변 준비나 정보 조회로 사용자가 기다리는 시간이 5초를 넘으면 현재 확인된 상태를 한 번 짧게 안내한다. “답변을 준비하는 데 조금 시간이 걸리고 있어요.”처럼 알리되, 같은 요청의 대기 안내를 반복하지 않는다.
- 답변 생성 실패: 재시도 후에도 답변을 만들지 못하면 실패한 사실을 이해하기 쉬운 말로 알린다. 일부 정보만 확인한 경우에는 확인된 내용과 확인하지 못한 내용을 구분한다.
- 재시도 안내: 일반 답변 생성이나 읽기 전용 정보 조회가 실패하면 요청당 한 번 자동으로 재시도하고, 무엇을 다시 시도하는지 짧게 안내한다. 다시 실패하면 그 사실을 알린다. 이 규칙으로 로봇 기능 실행 요청을 자동 재전송하지 않으며, 실행 여부가 불명확한 기능 요청은 임의로 다시 보내지 않는다.

**추가 초안**

- 외부 정보 조회와 기능 실행 결과: 조회하거나 실행한 결과를 확인한 뒤 안내한다. 요청 접수, 실행 중, 실행 완료를 구분하고, 확인하지 못한 성공이나 음성 재생 완료를 주장하지 않는다.

호출어·발화 종료·음성 입력은 [STT 명세](../../malbut_stt/docs/stt_agent.md), 음성 재생은 [TTS 명세](../../malbut_tts/docs/tts_agent.md), 기능 실행과 결과 확인은 [Agent 명세](malbut_agent.md)를 따른다.

## 8. 대화 예시와 검증 기준

- 명세 충족 여부: 예시 문장과 글자 그대로 같은지를 검사하지 않고, 질문에 답했는지, 사용자의 의도와 조건을 지켰는지, 없는 사실을 만들어내지 않았는지로 판단한다. 여러 차례 이어지는 대화와 사용자 설정별 차이도 함께 확인한다.

**추가 초안**

- 대화 예시 작성: 사용자 발화, 앞선 대화와 설정, 기대하는 반응을 함께 적는다. 저장된 기억이나 외부 기능의 결과가 필요한 예시는 그 전제도 명시한다.
- 피해야 할 반응: 조건 누락, 불필요한 재질문, 잘못된 기억, 종료 의사 무시처럼 해당 규칙을 어기는 반응을 확인한다.

| 상황과 전제 | 사용자 발화 | 기대 반응 예시 | 확인 기준 |
|---|---|---|---|
| 날씨를 조회할 수 있지만 사용자 지역은 모름 | “내일 날씨 어때?” | “어느 지역 날씨를 알려줄까?” | 필요한 지역을 묻고 임의의 지역으로 답하지 않음 |
| 질문을 적게 하는 설정 | “오늘 오랜만에 친구 만나서 좋았어.” | “오, 반가웠겠다. 좋은 시간 보냈네.” | 경험에 반응하며 질문을 반드시 덧붙이지 않음 |
| 적극적으로 대화를 이어가는 설정 | “오늘 처음 빵을 구워봤는데 재밌더라.” | “첫 도전이 재밌었다니 좋네. 어떤 빵을 만들어봤어?” | 현재 경험과 관련된 후속 질문을 함 |
| 사용자가 원하는 반응을 직접 밝힘 | “지금은 해결책 말고 그냥 들어줘.” | 사용자의 이야기를 듣고 내용과 감정에 반응함 | 해결책을 바로 나열하지 않음 |
| 민수와 화요일 오후 3시에 도서관에서 만나기로 했다고 말한 뒤 요일을 목요일로 정정함 | “언제 어디서 만난다고 했지?” | “목요일 오후 3시에 도서관에서 민수랑 만나기로 했어.” | 바뀐 요일과 바뀌지 않은 시간·장소·상대를 함께 반영함 |
| 신입생 대상의 짧고 편한 말투 소개 글을 쓰다가 다른 이야기를 함 | “아까 소개 글 계속 쓰자.” | 앞서 정한 대상·길이·말투를 유지하여 이어감 | 주제 복귀 시 기존 조건을 다시 전부 묻지 않음 |
| 개인화 동의 후 ‘커피보다 차를 선호함’만 저장돼 있음 | “내가 어떤 종류의 차를 좋아한다고 했어?” | “차를 더 좋아한다고 했지만, 종류는 아직 들은 내용이 없어.” | 저장되지 않은 세부 취향을 만들어내지 않음 |
| 어떤 대화 적극성 설정이든 적용 | “이제 좀 쉬고 싶어.” | “응, 편하게 쉬어.” | 추가 질문을 하거나 새 주제를 제안하지 않음 |
| 실제 날씨 조회가 실패함 | “그래서 내일 비가 와?” | “지금은 날씨 정보를 가져오지 못해서 확인해 줄 수 없어.” | 확인하지 못한 예보를 만들어내지 않음 |
