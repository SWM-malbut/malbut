# 기억 처리 실측 — A·B·C 각 10회

**C(답변 후 별도 기억 추출)의 답변 준비가 가장 빨랐지만, 기억 완료는 늦었고
관측된 비용은 A의 약 3.6배였다. 저장만 미루는 B의 후처리 구간은 약 2ms로
짧아, 이번 결과에서는 구조를 바꿀 만큼의 속도 이득을 확인하지 못했다.**

## 실행과 비교 기준

- 갱신한 `~/.zshrc`의 기존 키를 실험 프로세스에서만 읽었다. 키 원문은 저장·출력하지 않았다.
- 모델 접근 확인: `GET /v1/models/gpt-5.6-luna` → HTTP 200.
- 모델: 모든 호출 `gpt-5.6-luna`, reasoning `none`, 최대 출력 500토큰.
- 본시험: 각 방식 10회, 총 30회. 반려동물 4회·취향 3회·인사 3회씩 동일 배정.
- 준비 시험 3회까지 총 33개 시험, 실제 Responses API 44호출. 재시도·모델 전환 없음.
- 44개 응답 모두 `completed`. 출력 JSON 잘림과 reasoning 토큰 사용 없음.
- 같은 원래 사례·반복의 A/B/C가 모두 성공한 **9묶음**으로 시간을 비교했다.
  B 취향 실패가 포함된 2번째 묶음은 A/C도 함께 시간 집계에서 제외했다.
- 비용은 실패를 포함한 **각 방식 본시험 10회 전체**의 사용량으로 계산했다.

| 방식 | 처리 순서 | 성공/시도 | 비교 표본 | 답변 중앙값 | 기억 완료 중앙값 | 본시험 비용 |
|---|---|---:|---:|---:|---:|---:|
| A | 답변·후보 생성 → 저장 → 답변 준비 | 10/10 | 9 | 2.055초 | 2.055초 | $0.00142818 |
| B | 답변·후보 생성 → 답변 준비 → 저장 | 9/10 | 9 | 2.819초 | 2.820초 | $0.00142650 |
| C | 답변 준비 → 별도 기억 추출 → 저장 | 10/10 | 9 | 1.681초 | 3.106초 | $0.00515160 |

두 시간 모두 요청 처리 시작점을 기준으로 한다. 답변은 JSON 직렬화 완료까지이며,
HTTP 전달·TTS 합성·스피커 재생 시간은 포함하지 않는다. 기억 완료는 검증·기억 저장·
대화 완료 트랜잭션까지다. DB 준비는 측정 전이며 각 시험은 독립적인 SQLite를 사용한다.

## 실제로 관측한 차이

- C의 답변 중앙값은 A보다 **0.374초, 약 18.2% 짧았다.**
  기억 완료 중앙값은 A보다 약 1.051초 늦었다.
- B에서 답변 준비 후 검증·저장·대화 확정까지 걸린 시간의 중앙값은 **2.120ms**다.
  worker 시작 비용도 포함하므로 순수 SQLite 쓰기 시간과 동일하지 않다.
- B가 A보다 느린 중앙값을 보였지만, A/B는 같은 모델·프롬프트·후보 생성 계약을
  사용한다. 이 작은 표본의 API·생성 시간 변동을 후처리 자체의 비용으로 단정하지 않는다.
- C의 답변 뒤 기억 완료까지 걸린 시간은 중앙값 **1.296초**다. 이 사이 새 발화가
  들어오거나 기억을 정정·삭제하는 운영 상황은 별도의 전달·작업 관리 설계가 필요하다.

| 방식 | 답변 평균 | 답변 최솟값~최댓값 |
|---|---:|---:|
| A | 2.273초 | 1.523~4.719초 |
| B | 3.445초 | 1.667~6.452초 |
| C | 1.645초 | 1.222~1.935초 |

사례별 답변 중앙값도 차이가 있다. 모두 같은 성공 묶음만 집계했다.

| 사례 | 방식별 표본 수 | A | B | C |
|---|---:|---:|---:|---:|
| 반려동물 이름 | 4 | 2.384초 | 4.052초 | 1.486초 |
| 커피 선호 | 2 | 1.992초 | 3.846초 | 1.826초 |
| 일반 인사 | 3 | 1.529초 | 2.223초 | 1.681초 |

일반 인사에서는 C가 A보다 빠르지 않았다. 적은 사례와 반복으로 얻은 결과이며,
모든 대화에서 같은 개선율을 보장하거나 통계적으로 확정된 우열을 주장하지 않는다.

## 실패한 1건

입력은 `나는 커피를 좋아해.`였다. B의 모델이 `attribute=likes`에 맞는 값
`커피` 대신 `value=커피를 좋아해`를 생성했다. 기존 원문 검증은 이를 거절했고
기억은 저장되지 않았다. 저장 실패를 성공으로 안내한 것은 아니다.

- 먼저 준비된 답변: `알겠어요. 커피를 좋아하시는군요.`
- 검증 후 판단: 원문에서 대상·의미를 확인하지 못했다는 재질문.
- 기록: `postcommit_decision_changed`, `unexpected_stored_facts`.

이 1건을 성공 시간 집계에서 제외했고 전체 시도 비용에는 포함했다. A/B의 추론
계약이 같으므로 B 구조가 본질적으로 덜 정확하다는 근거로 사용하지 않는다.
**후처리 검증에서 새 질문이 필요해질 수 있으므로, 답변 후 오류·질문을 전달하는
정책 없이 운영 경로를 바꾸면 안 된다는 구체적인 사례**다.

33개 시험 DB를 별도로 읽어 JSON과 저장 사실·사용자·요청·원문 연결이 일치함을
확인했다. 답변에서 거짓 저장 완료 주장은 발견하지 못했다. 이는 이 고정 사례의
검증이며 일반적인 한국어 모델 성능을 의미하지 않는다.

## 토큰과 비용

| 본시험 | 모델 호출 | 입력 토큰 | 그중 캐시 입력 | 출력 토큰 | 추정 비용 |
|---|---:|---:|---:|---:|---:|
| A 10회 | 10 | 17,154 | 16,919 | 869 | $0.00142818 |
| B 10회 | 10 | 17,154 | 16,915 | 867 | $0.00142650 |
| C 10회 | 20 | 19,518 | 0 | 1,040 | $0.00515160 |

준비 호출까지 포함한 **44회 전체는 입력 59,211토큰(캐시 35,547 포함), 출력
3,128토큰이며 추정 비용은 $0.00919734**, 약 0.92센트다. 모든 호출의 usage를
수신했고 실패 응답을 빼서 비용을 낮춰 보이지 않았다.

계산식은 `(비캐시 입력 × $0.20 + 캐시 입력 × $0.02 + 출력 × $1.20) / 1,000,000`이다.
[GPT-5.6 Luna 공식 요금](https://developers.openai.com/api/docs/models/gpt-5.6-luna)의
기본 텍스트 요금에 따른 추정이며 청구서 확인 결과는 아니다.

**A/B 결합 프롬프트에는 캐시가 많이 적용됐지만 C의 두 호출에는 적용되지 않았다.**
따라서 약 3.6배의 비용 차이는 이번 프롬프트·캐시 조건의 관측치다. C는 모델 호출이
두 배이지만, 비용 비율이 항상 두 배 또는 3.6배라고 일반화할 수 없다.

## 적용 판단과 재현 자료

**실측 검토 후 사용자 선택은 A로 확정했다.** 답변·기억 후보를 같은 추론에서
생성하고, 검증·저장과 대화 기록 확정 후 응답하는 기존 운영 경로를 유지한다.
비교용 B/C와 원시 측정 자료는 보존한다.

저비용·단순한 처리를 우선하는 현재 기준에서는 **A 유지**를 권한다.
더 빠른 첫 답변이 중요하면 C를 검토할 근거는 생겼다. B는 후처리로 옮길 작업의
시간이 짧아 이번 목적의 개선안으로 우선 선택할 근거가 부족하다.

운영 서버는 변경하지 않았다. 이번 B/C는 JSON 준비 후 기존 완료 트랜잭션을
실행하는 실험이며, 영속적인 응답 선전달·백그라운드 작업 복구까지 구현한 결과가 아니다.
