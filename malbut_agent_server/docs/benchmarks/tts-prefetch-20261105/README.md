# 실제 로봇 선합성 비교 — 2026-11-05

기억 검증과 모델·말하기 속도를 유지하고 첫 구간 선합성만 비교했다.
조건별 9회에서 입력부터 첫 출력 오디오까지 평균 6.573초 → 5.891초,
최종 답변 발행 이후의 대기는 1.501초 → 0.519초였다.
전체 CPU 사용률은 입력부터 재생 완료까지 평균 75.0% → 75.6%였다.
종료 시 Agent와 Piper의 선합성을 모두 켠 상태로 재생·저장을 다시 확인했다.

## 조건과 측정 경계

- 기준 코드: `affb0ed`. 실제 운영 로봇의 Agent → Manager → Piper 경로와
  실제 OpenAI API를 사용했다. 앞서 적용한 API 계측·입력 캐시는 두 조건에서 유지했다.
- 모델 `gpt-5.6-luna`, reasoning `low`, 기본 KSS Piper, CPU 6스레드,
  말하기 속도 1.0, 스피커 60%를 유지했다. GPU·STT 설정은 수정하지 않았다.
- 같은 문장을 `/malbut/speech/transcript`에 자동 입력했다. 시작점은
  전사 완료 이후의 입력 발행이다. STT·말끝 판단 시간은 포함하지 않는다.
- `playing` 상태 수신 시각과 스피커의 PulseAudio sink monitor를 함께 관찰했다.
  첫 출력 오디오는 16kHz mono PCM의 10ms 구간에서 RMS > 40, peak > 120
  (int16 기준)이 3구간 연속 검출된 첫 구간의 수신 시각이다.
  녹음 스트림의 목표 지연은 20ms다. 이는 출력 오디오 검출이며 물리 스피커의
  음향 도달 시각을 별도 마이크로 측정한 값은 아니다.
- CPU는 로봇 `/proc/stat`, Agent·TTS `/proc/PID/stat`을 200ms 간격으로
  관찰했다. 각 경계에 가장 가까운 샘플을 사용해 구간별 CPU 시간을 계산했다.
  평균 CPU 비율은 관찰 구간 길이로 가중했다. 프로세스 100%는 한 코어이며
  로봇은 6코어, 장치 전체 CPU 비율은 여섯 코어를 합친 0~100%다.
  최고치는 200ms 구간의 최고 평균으로 더 짧은 순간의 peak를 뜻하지 않는다.
- 비교 순서는 **꺼짐 6회 → 켜짐 6회 → 켜짐 3회 → 꺼짐 3회**였다.
  각 배치 앞 준비 질문 1회씩은 집계에서 제외했다. 마지막 켜짐 복원 확인 1회도
  비교에서 제외했다. 총 23회 응답 중 성능 비교는 18회다.
- 처음 꺼짐에서는 Agent·TTS 모두 비활성, 마지막 꺼짐에서는 Agent의 준비
  발행을 비활성화했다. 마지막 꺼짐 동안 TTS는 준비 요청을 받지 않았고 재사용도
  없었다. 현재 운영 DB·대화 이력은 유지했고 배치 사이에 초기화하지 않았다.

| --- | --- |

**전체 대기의 개선률은 안정적으로 확정할 수 없다.** 첫 6회씩의 비교에서는
6.189초 → 6.290초로 전체 대기가 줄지 않았다. 이때도 답변 발행 후 대기는
1.592초 → 0.516초로 줄었다. 순서를 바꿔 추가한 3회에서는 API와 Agent 처리
시간도 달라졌으며, 짧은 인사의 전체 대기는 합산 결과에서도 늘었다.

이력·답변·서버 대기·배경 부하가 완전히 같지 않다. 평균 입력은 꺼짐
13,372토큰, 켜짐 13,883토큰이었고, 답변 길이는 각각 평균 73.2자와 72.3자였다.
API 시도는 모두 한 번이었다. 따라서 선합성의 재사용과 후반 대기 감소는
확인했지만 10.4% 전체 단축을 향후 대화의 보장 수치로 사용하지 않는다.
API 이전·이후 Agent 처리의 변동은 별도 조사 대상이다.

## 검증과 최종 운영 상태

- 18/18 비교 응답이 한 번씩 발행되고 재생 완료·DB 저장 완료됐다.
  비교·준비·복원 확인을 포함한 23회 모두 최종 답변 발행 후 출력 오디오가 검출됐다.
- 첫 구간은 미리 합성할 뿐 최종 구조·정책·기억 검증을 통과해야 재생한다.
  기억 변경/삭제 차단, 선합성 취소·내용 불일치 회귀 시험이 통과했다.
- 관련 단위·메모리·스트림·Piper·speech launch 시험: 212 passed.
  실제 ROS 메시지 및 launch 시험: 140 passed. 추가한 Agent 설정 파일 시험:
  2 passed. 시험 묶음 간 겹치는 항목이 있어 총합으로 합산하지 않는다.
  처음의 환경 설정 실패는 ROS overlay와 최신 메시지 빌드 후 해소했다.
- 최종 `speech_prefetch_enabled=true`, `piper_prefetch_enabled=true`,
  Piper 6스레드·1.0배속을 ROS 파라미터로 확인했다. 모델·reasoning·볼륨도 유지됐다.
  pending 턴은 0개, 배포 소스 해시는 후보와 일치했다.
- Agent 시작 전용 ROS 파라미터와 로봇별 `~/.config/malbut/agent.yaml`
  적용을 추가했다. 현재 실행의 파라미터 파일과 이후 launch 설정 모두 켜짐으로
  저장했다. Piper는 기존 `~/.config/malbut/tts.yaml`에 플래그만 추가했다.
- Agent만 기존 소유자의 자동 재시작으로 교체했다. 기존 TTS는 자동 재시작이
  없어 같은 명령·환경으로 교체했고, 현재 Bringup 소유자의 PID·시작 시각을
  감시하는 별도 프로세스 아래 실행했다. Bringup이 종료되면 교체 TTS도 종료한다.
  다음 Bringup 실행에서는 원래 launch가 저장된 TTS 설정을 읽는다.
  STT 재시작이나 에코 보정은 수행하지 않았고 기존 STT supervisor가 유지됐다.
