# 24장 모음 이미지 구분 강화 실측

> 비용 정정: 아래 최초 계산에는 GPT-5.6 기본 캐시 쓰기 요금이 누락됐다.
> 실제 응답의 쓰기 5,175 / 6,553토큰에 기본 30분 쓰기 $0.25/백만을 반영하면
> 기존 **$0.00727155 (10.907325원)**, 구분 강화 **$0.00651925 (9.778875원)**다.
> 아래 표는 당시 기록이며 최신 비교는 `methods_comparison_20261021.md`를 따른다.
> [쓰기 과금 기준](https://developers.openai.com/api/docs/guides/prompt-caching#monitor-cache-performance).

같은 Gazebo 사진 24장을 `gpt-5.6-luna`로 각 구성에서 1회씩 분석했다.
사진 간 혼동과 칸 밖 좌표는 줄었으나, 물체 명칭 인식 개선은 제한적이었다.
정밀한 물체 위치 기억 품질이 확보됐다고 볼 수 없다.

## 입력과 변경

두 실험은 동일한 원본 JPEG 24장, 순서, 메타데이터, 모델, high 입력,
최대 출력 12,000토큰, 이미지 1개·API 호출 1회 조건이다.
기존 실제 Gazebo 순찰의 저장 사진을 사용했으며 이번에 새 주행을 실행하지 않았다.
기존 키를 사용했고 키·원본 이미지·개인 환경 로그는 저장소에 포함하지 않았다.

| 구분 | 기존 | 구분 강화 |
|---|---|---|
| 배치 | 4열×6행, 가로 간격 없음 | 4열×6행, 16px 간격·4px 테두리 |
| 식별 | 작은 사진 번호·시각 | 큰 번호·행/열·구역 코드·시각 |
| 칸 범위 표 | 픽셀 좌표 | 픽셀 및 답변과 같은 0~1000 정규화 좌표 |
| 응답 스키마 | 사진 ID가 내용 뒤 | 사진 ID가 내용 앞 |
| 지시문 | 사진별 관찰 | 독립 카드 확인·순서대로 관찰 강조 |
| 전체 이미지 | 1280×1608 | 1392×1744 |
| 실제 사진 표시 | 320×200 | 320×200 |

사진 픽셀 크기를 유지하면서 장면 사이 간격을 추가했다. 코드의 일반 사진 영역은
320×224이며 이 원본의 비율에 맞춰 320×200으로 들어간다.
2,420개의 32px 패치로 기본 모델 high 예산 2,500패치 이내다.
표시·지시문·메타데이터를 함께 변경했으므로 특정 변경 하나의 효과로 단정할 수 없다.

## 동일 대조 기준의 결과

6종의 선정된 물체가 사진에 등장하는 35건을 원본과 시각 대조했다.
대조 목록 및 이름 매칭 규칙은 기존 실행과 동일하다. 이는 전체 물체 정밀도·재현율이나
독립적인 정식 벤치마크가 아니며 이름 점수에는 bbox 정확도를 포함하지 않는다.

| 항목 | 기존 | 구분 강화 |
|---|---:|---:|
| 정확한 명칭 인식 | 18/35 (51.4%) | 20/35 (57.1%) |
| 대략적 명칭까지 인정 | 20/35 (57.1%) | 20/35 (57.1%) |
| 기존 오기록 11항목 중 재발 | 11/11 | 1/11 |
| 칸을 벗어난 bbox / 전체 물체 | 52/112 | 0/91 |
| 저장된 관찰 / API 호출 | 24건 / 1회 | 24건 / 1회 |
| 입력 토큰 | 5,178 | 6,556 |
| 출력 토큰 | 4,981 | 4,067 |
| 총 토큰 | 10,159 | 10,623 |
| 분석 비용 USD | $0.0070128 | $0.0061916 |
| $1=1,500원 환산 | 10.5192원 | 9.2874원 |

[공식 Standard 단가](https://developers.openai.com/api/docs/pricing)의
입력 $0.20/백만·출력 $1.20/백만을 응답 usage에 적용했다.
두 실행 모두 캐시 입력 0. 세금·후속 질문 비용 제외다.
입력은 늘었지만 출력이 짧아져 이 단일 실행에서는 비용이 약 11.7% 줄었다.
항상 더 저렴해진다는 의미는 아니며, 각 구성 1회라 변동성을 평가하지 않았다.

| 종류 | 선정 등장 | 기존 명칭 인식 | 구분 강화 명칭 인식 |
|---|---:|---:|---:|
| 파란 운동 공 | 10 | 9 | 9 |
| 바벨·원판 | 8 | 1 | 1 |
| 하늘색 휴지통 | 7 | 1 | 3 |
| 냉장고 | 6 | 3 | 3 |
| 침대 | 2 | 2 | 2 |
| 에어컨 | 2 | 2 | 2 |

기존의 휴지통 2건은 ‘하늘색 통’이라는 대략적 표현이었고 개선 응답에서는
‘휴지통’으로 기록했다. 바벨 범주는 동일하게 바벨·덤벨·원판·역기 표현을 인정한다.

## 남은 오류와 검증 범위

- 기존 오기록 11항목 중 F03의 실제로 없는 공은 여전히 기록된다.
  1/11은 그 고정한 오류 목록의 재발 수이며 모든 오류의 수가 아니다.
- F02의 작은 공, 작은 휴지통, 멀거나 가려진 냉장고는 여전히 놓친다.
- 칸 내부 bbox는 실제 물체와 맞는 위치라는 보장이 아니다. 가구 분류 오류도 남는다.
- 원본은 깊이·구역 기능 이전에 촬영한 v1 자료다. 모든 물체 구역은 `unknown`이고
  실제 구역 정확도는 이번 평가 대상이 아니다.
- 사진별 관찰 24건 저장, SQLite 무결성, 완료 후 재호출 방지를 확인했다.
  `ready`는 처리 완료이며 내용의 정답 보장이 아니다.
- 추가 유료 호출로 좋은 응답을 고르거나, 모델 출력에 정답을 보정하지 않았다.

## 관련 사례

- [IG-VLM (2024)](https://arxiv.org/html/2403.18406v1): 영상에서 6개 프레임을 골라
  3×2 이미지 격자로 합친 뒤 VLM에 전달한다. 연구의 해당 프레임 수 비교에서는
  6개가 가장 좋았고, 공간 세부 정보와 프레임 수의 절충을 설명한다. 영상 질문 응답
  연구이며 24장의 사진별 물체 위치 저장을 검증한 결과는 아니다.
- [Set-of-Mark (2023)](https://arxiv.org/abs/2310.11441): SAM/SEEM으로 구역을 나누고
  번호·상자·마스크를 표시해 VLM이 대상을 참조하도록 한다. 이번에는 사진 카드 식별에
  유사한 원칙을 적용했으며 SoM의 물체 분할 기법 자체를 구현한 것은 아니다.
- [OpenAI 영상 이해 예제 (2025, 보관된 예제)](https://developers.openai.com/cookbook/examples/gpt_with_vision_for_video_understanding):
  추출한 여러 프레임을 각각의 `input_image` 항목으로 한 요청에 넣는다.
  현재 API의 다중 이미지 입력은 [Vision 문서](https://developers.openai.com/api/docs/guides/images-vision)에도 명시돼 있다.

다음 비교 후보는 6장 모음 4개 또는 개별 이미지 24개를 한 요청으로 보내는 것이다.
호출 1회를 유지할 수 있으나 이미지 토큰이 늘 수 있으며, 이 대안의 정확도는 아직
이번 데이터로 검증하지 않았다.

## 재현 기록

로컬 검증 폴더의 `comparison.json`에는 양쪽의 usage와 평가 결과,
`experiment.json`에는 동일 입력 확인 및 분석 모듈 해시를 기록했다.
`vision-calls.json`은 인증 헤더와 이미지 Base64를 제외한 실제 응답이며,
`patrol_mosaic_snapshot.py`와 `prompt.txt`는 유료 실행 당시 분석 코드와 지시문이다.
이 자료는 로컬에 남기며, 저장소에는 이 검증 요약만 포함한다.
