# Speech overlap progress — experiments 2026-10-30, publication 2026-10-31

로봇 발화 중 끼어들기와 잡음 구분을 개선한 후속 작업의 보존본이다.
**전체 목표는 미완료이며, 정상 서비스에 채택한 변경은 첫 음량 감소를 늦추는
100ms 후보 조건뿐이다.** 공간 처리 후보 C37–C39를 운영에 적용하지 않았다.
관련 작업: [SWM25-220](https://sanggeunji0117.atlassian.net/browse/SWM25-220).
이전 [runtime19 기록](../speech_overlap_20261029/README.md)과 결과를 합산하지 않는다.

## 저장소 코드 변경

- `dialogue_pipeline.py`: Reachy 최초 duck을 양성 후보 5×20ms 뒤 허용한다.
  같은 재생의 duck 갱신, 기존 발화 확정과 2초 ASR 선행 음성은 유지한다.
  현재 채택한 interim 재생과 같은 요청의 최종 opener가 충돌하는 경우도 수정한다.
- `echo/vad.py`, `silero_stream.py`: 20ms 무음 tick에서도 마지막으로 완성된
  512샘플 Silero 창에 신호가 있으면 그 창의 판정을 보존한다. 완전한 0 창은 거부한다.
- `incremental.py`: 같은 전체 문장을 새로 디코딩했는데 native 끝 시간만 후퇴한 경우,
  이전의 유효한 범위를 제한적으로 참조한다. 기존 0.8초 제한을 늘리거나 이전 문장을
  현재 decode 대신 반환하지 않는다. 문자 오류 자체를 복구하는 변경은 아니다.
- 모델, 상주 모델 수, ROS 메시지·서비스 규격을 변경하지 않았다.

## 실기기 관측

Mac–로봇 30cm 이내, Mac 출력 100%, 로봇 출력 80%의 배치다. 아래 사람 녹음
시험은 알려진 한국어 녹음을 Mac 실제 스피커로 재생했다. 다른 위치에 일반화하지 않는다.

|조건·버전|결과|해석|
|---|---|---|
|100ms guard, 격리 로봇 단독|3/3 자연 종료; duck·STOP·전사 0|운영 적용 전|
|100ms guard, 적용 후 정상 서비스|3/3 자연 종료; duck·STOP·전사 0|20회 반복 기준 미완료|
|100ms guard, 사람 녹음 겹침|실제 재생 확인 1회에서 중단·전사 0|운영의 겹침 문제는 남음|
|C37, 사람 녹음 겹침|5/5 중단, 5/5 최종 전사, 4/5 전체 일치, 5/5 첫 단어 보존|미채택 후보, 같은 문장 5회|
|C36, 로봇 단독|20/20 자연 종료; duck·STOP·전사 0|C38의 새 대조를 대신하지 않음|
|C38, paired 준비|사람 음원·로봇 이야기 재생 전 준비 실패|유효 겹침 0회|
|C38, 직접 TTS timing|로봇 단독 대조 시작 약 5.77초 뒤 중단; 사람 재생 0회·전사 0회|대조 실패, 감지 소리 정체 미확정|

정답은 “특히 중소형 빌딩은 개인투자자의 전폭적인 지지를 받고 있다.”이다.
C37의 1회는 “빌딩”을 “피팅”으로 인식했다. 전체 일치는 공백·문장부호를 제외한
비교다. [정답·전사 CSV](evidence/human-transcripts.csv), [집계 JSON](evidence/summary.json)에
개별 표본과 제외 이유를 남겼다. **4/5는 전체 목표의 80% 완성을 의미하지 않는다.**

실제 음향 시작부터 스피커 출력 종료까지 p95 800ms를 검증하지 못했다.
C37의 재생 요청→ROS 중단 이벤트 1.56–2.64초는 그 음향 지연과 다르다.
최신 실패 시험은 41파일/21,585,141바이트를 별도 로컬 보관하고 해시를 확인했다.
종료 당시 마이크 복원 오류 없음, 정상 서비스 active, 시험 서비스 inactive 기록이
있다. 이후 SSH 재확인은 시간 초과되어 현재 실시간 상태를 보증하지 않는다.

## 자원

Whisper Small 한 개와 Piper 3스레드를 유지하며 STT/TTS 합산 약 3GB 예산을 따른다.
C37 실제 겹침 구간의 음성 프로세스 합산 최대 추정은 2,359,694,336바이트,
관측 Swap은 0이다. 모든 부하에서의 최대 메모리나 상한 보장은 아니다.

- 진단을 끈 유휴 60초 한 쌍: 선택한 음성 필수 프로세스 CPU 합계가 C35 공간 처리
  후보에서 7.86→9.77%, **+1.91%p**였다. 같은 구간의 전체 시스템 busy CPU는
  13.64→17.13%, **+3.49%p**였다. 둘 다 6개 CPU 전체 용량 기준이고 전체 시스템에는
  다른 프로세스도 포함된다. +1%p 목표 미달이며 유휴·발화 60초×3회는 미완료다.
- 브리지 배치 계산의 별도 로봇 실험: 같은 60초 저장 입력, AB/BA/AB 세 쌍에서
  순수 계산 CPU 평균 1.694→1.226초, **27.63% 감소**, 출력 동일.
  전체 서비스 CPU 감소율이 아니며 이 최적화는 C39 로컬 후보에만 준비했다.

## 실험 소스 재구성

`runtime39.patch`는 이전에 공개한 runtime19의 135개 조합 코드와 8개 실행 파일로
만든 **143개 파일 기준 트리**에서, C39의 **179개 텍스트 소스·설정·검사 파일**로
가는 패치다. 전체 후보 manifest의 234개 중 나머지 55개 외부 자산은 Git에 없다.
`snapshot-map.json`에 기준·결과 파일 해시와 제외 자산 해시가 있다.

원본 C39 전체 manifest SHA-256은
`bd116e0a1438fe529c89ebe642e00120a53aaec476f928cff6c71efd548948dc`다.
이는 별도 로컬 원본의 식별값이다. 공개 포장의 `manifest.json` 해시와 구분한다.
`runtime37-to-runtime38.diff`, `runtime38-to-runtime39.diff`는 각각 opener 수정과
브리지 배치 계산의 작은 변경을 보여준다. 실행 코드 두 파일의 C38→C39 변경은
`raw_spatial_ring_bridge.py`와 `spatial_filter.py`에 한정된다.

이전 checkpoint는 canonical `echo/vad.py`, `incremental.py`가 달라져도 그대로
재구성되도록 기존 원본 두 파일을 추가 overlay로 보관했다. 135개 코드 해시와
runtime19 동작은 유지하며 포장만 15+120에서 17+118로 바뀌었다.

```sh
python3 tools/speech_overlap_20261030/check_checkpoint.py
python3 -m pytest -q tools/speech_overlap_20261030/tests
```

검증기는 임시 트리를 만들고 소스·집계·패치 결과 해시를 확인한 뒤 삭제한다.
로봇·네트워크·모델·마이크·스피커를 사용하지 않는다. 실제 설치나 음향 재현 명령이 아니다.

`native_bridge/`에는 순수 계산 비교의 runner와 원본/후보 소스를 보존했다.
그 `protocol.json`이 식별하는 `raw8.pcm`과 `weights.npy`는 별도 로컬 원본이 필요하다.
`quiet_guard/`의 채택·복원 도구 역시 당시 로봇용 보존 소스이며 자동 실행하지 않는다.
실제 재실행 전에 설치 경로·서비스 소유권·atomic 마이크 설정 교체와 복원 조건을
확인해야 한다. 정상 릴리스 이름은 `quiet-duck-guard-20261030`, 이전 이름은
`interaction-20261028`이다. `adopt.py rollback`은 자신이 만든 unit의 무변경 여부를
확인한 뒤 이전 릴리스를 복원한다. 로봇 접속과 실행은 이 오프라인 검증에 포함되지 않는다.

## 별도 보존 자료와 남은 검증

원음·Mac 녹음·ASR PCM·배열·DB·전체 로그·모델·ADB 바이너리·환경 파일·인증 자료는

이 Git 체크포인트만으로 동일 음향 시험을 바로 재현할 수 있다는 뜻은 아니다.

남은 검증은 최신 단독 대조 중단 원인 분리, 같은 후보의 잡음·겹침 통과,
짧은 명령·정정·화제 전환·후속 대화, 실제 음향 지연, 전체 CPU·메모리 반복 측정이다.
로컬 코드 검사, 로봇 순수 계산, 물리 음향 결과, 운영 적용을 서로 다른 근거로 취급한다.
