# 실로봇 LAN 테스트 페이지

같은 Wi-Fi의 Mac 브라우저에서 저장 지도를 선택하고 Bringup을 시작·종료하는
작은 테스트 도구다. 실시간 지도·로봇 위치, 원본·사람 인식 영상, 상태를 확인하고
AutoSLAM·사람 추적·순찰을 요청하며, 저장 지도의 구역(Zone)을 편집한다.
페이지를 열거나 서버를 실행하는 것만으로는 로봇을 움직이지 않는다.

## 실행

빌드된 실기기 적용본 기준이다. 기존 Bringup·SLAM·Nav2가 중복 실행되지 않도록
정리한 뒤 로봇에서 웹 패널을 한 번 실행한다:

```zsh
source ~/ros2_ws/install/setup.zsh
source ~/ros2_ws/install/malbut_test/local_setup.zsh
ros2 run malbut_bringup robot_web_panel
```

로봇의 IP를 `hostname -I`로 확인하고 Mac에서 `http://<로봇-IP>:8766`을 연다.
터미널에 출력된 `Access token`을 페이지에 입력한다. 토큰은 실행할 때마다 바뀌며,
URL·브라우저 영구 저장소에 넣지 않는다. 8766 포트가 이미 사용 중이면
`--ros-args -p port:=8767`로 다른 포트를 지정한다.

## 웹에서 사용하는 순서

1. **지도 만들기 모드** → Bringup이 지도 없이(SLAM) 켜지고 준비 완료를 확인.
2. 새 지도 이름 입력 → **자동 지도 만들기 시작**. 이 요청부터 탐색한다.
3. 성공 결과·저장 완료 확인. Bringup은 끄지 않는다.
4. 저장 지도 선택 → **선택한 지도로 주행**. 재시작 없이 저장 지도·AMCL로 바뀌고
   위치 보정이 로봇 위치를 찾는다. 저장 위치가 맞지 않으면 제자리에서 한 바퀴 돈다.
5. **위치 추정** 줄과 지도 위 로봇 위치를 확인한 뒤 사람 추적·순찰을 요청한다.

Bringup이 꺼져 있으면 두 버튼이 해당 상태로 Bringup을 켜고, 켜져 있으면 관리자의
`/malbut/localization/*` 서비스로 위치 추정만 바꾼다. 이동 미션이 남아 있으면 전환이
거부되므로 먼저 취소한다. 표시되는 모드와 **위치 추정** 메시지는 관리자가 보고하는
실제 위치 추정 상태다. 위치를 찾는 동안(최대 약 1분)은 방향 버튼 조작도 거부된다.

프로세스가 켜졌어도 ROS 준비가 끝나지 않았으면 **준비 대기**로 표시한다.
아래 준비 대기 사유에서 센서·TF·위치 추정·Action 서버 중 무엇이 아직 준비되지
않았는지 확인한다. Bringup이 오류로 종료되면 **Bringup 오류 로그**도 표시한다.
AutoSLAM은 지도 만들기 중에만, 사람 추적·순찰은 저장 지도 선택 후에만 관리자가
받는다. 그 밖에는 관리자가 사유와 함께 거부한다.

저장 지도 목록은 연결할 때와
AutoSLAM 종료 후 갱신하며 **지도 목록 새로고침**으로도 읽을 수 있다.
기본 저장·조회 폴더는 `~/.ros/malbut/maps`이고 ROS parameter로 변경한다:

```zsh
ros2 run malbut_bringup robot_web_panel --ros-args \
  -p map_directory:="$HOME/.ros/malbut/maps"
```

YOLO·OSNet 런타임·모델의 최초 준비는 [Bringup 안내](README.md#로봇에서-처음-준비)를
따른다. 파일이 없으면 시작 사전 검사에서 누락 경로와 준비 명령을 알려준다.
웹에서 시작한 프로세스의 로그 경로도 상태에 표시한다. 자동 설치는 하지 않는다.

이미 켠 Bringup에 `web_panel:=true`로 포함한 패널은 영상·지도·미션 요청만
제공하며 Bringup 시작·종료는 비활성화한다. 지도 전환은 관리자 서비스로 가능하다.
단독 패널과 같은 포트로 중복 실행하지 않는다.

## 동작과 경계

- 단독 패널은 정해진 `robot.launch.py`만 시작·종료한다(선택한 지도는 초기 상태만 정한다).
  임의 launch·셸 명령 실행이나 `/cmd_vel` 직접 발행은 제공하지 않는다.
- 실시간 2D 지도는 `/global_costmap/costmap`(장애물·팽창 비용 포함),
  로봇 위치·방향은 TF에서 읽는다. 지도 원점의 회전을 반영하며 새 이미지와
  좌표 정보가 모두 준비됐을 때 함께 교체한다. 수신 지연·실패 중에는 마지막
  지도를 유지하고 상태 문구로 알린다. 저장하는 지도 원본은 기존 `/map`이다.
- 지도 클릭은 이동이나 위치 초기화를 하지 않는다. 저장 지도로 바꾸면 관리자가 위치
  보정을 요청한다. 이 지도의 마지막 위치(없으면 AutoSLAM이 저장 시점에 기록한 위치)가
  LiDAR와 맞으면 그대로 쓰고, 맞지 않거나 없으면 제자리 회전과 AMCL 전역 탐색으로
  찾는다. 결과가 실제와 다르거나 찾지 못하면 RViz의 **2D Pose Estimate**로 지정한다.
- 구역(Zone): 저장 지도로 주행 중일 때만 편집한다. **구역 그리기** 후 지도에서
  드래그해 사각형을 만들고, 구역을 눌러 선택·삭제한 뒤 **주행에 적용**을 누른다.
  서버는 `<지도이름>.zones.geojson`만 다시 쓰고(로봇 명령 아님), `zone_filter`가 1초
  안에 Nav2 costmap에 반영한다. 반영 상태는 구역 줄의 **Nav2 반영**에 표시된다.
  진입 금지는 0.2m 여유를 더해 통과 불가, 우회 권장은 높은 비용으로 가능하면 피한다.
- 사람 추적·순찰: `/malbut/mission/execute`를 통해 요청한다.
- 수동 조작: 관리자가 준비되면 방향 버튼이 켜진다. 누르면 `/cmd_vel_teleop`로
  150ms마다 0.15m/s·0.45rad/s 명령을 보내고 놓으면 0을 보낸다. 첫 입력에서
  `manual_control`이 `manual_drive`를 요청해 진행 중인 이동 미션을 멈추고, 5초 동안
  조작이 없으면 끝낸다. 서버는 0.5초 동안 반복이 없으면 0을 한 번 보낸다.
- AutoSLAM: 관리자가 있으면 같은 경로로 요청하고, 관리자가 없으면 `/autoslam`에
  직접 요청한다. 직접 실행한 AutoSLAM이 끝나기 전에는 이 패널의 다른 시작을 거부한다.
- Action 서버가 없으면 기다리며 HTTP를 막지 않고 요청 실패를 표시한다.
- 원본은 `/depth_cam/rgb0/image_raw`, 사람 인식은
  `/perception/person/debug_image/compressed`를 본다. 인식 영상은 해당 노드에서
  `publish_debug_image`가 활성화되어 있어야 한다. 토픽 이름은 ROS parameter
  `rgb_topic`, `debug_topic`으로 바꿀 수 있다.
  웹으로 켠 Bringup은 인식 영상을 활성화한다.
- 이미지 콜백은 최신 프레임만 보관한다. 브라우저가 보는 동안 최대 약 5Hz로
  JPEG를 요청하며, 같은 프레임의 인코딩 결과를 공유한다. 원본 영상 인코딩은
  OpenCV로 처리하며 rqt_image_view 또는 cv_bridge를 사용하지 않는다.
- 상태는 `/malbut/state`, `/tracking/person/status`와 실제 Action 결과를 표시한다.

## 취소와 안전

시작·Bringup 종료 버튼은 확인 창을 거친다. 두 종료 동작의 범위는 다르다.

- **이 웹 패널의 요청 모두 취소**: 이 웹 서버 프로세스가 보낸 Goal만 취소한다.
  다른 CLI·웹 서버가 보낸 Goal은 이 버튼의 취소 대상이 아니다.
- **Bringup 종료**: 이 패널이 켠 스택의 활성 미션을 취소하고 종료를 확인한 뒤
  소유한 Bringup을 끈다. **그 스택에 CLI 등 다른 클라이언트가 보낸 미션도
  중지될 수 있다.** 미션 종료가 확인되지 않으면 사유를 표시하고 Bringup을 유지한다.

관리자는 같은 BASE 자원의 새 요청으로 기존 미션을 선점할 수 있다.

**브라우저를 닫거나 Wi-Fi 연결이 끊겨도 미션은 멈추지 않는다.** 예외로 웹 방향 버튼
명령은 0.5초 안에 정지하고, 수동 조작 자체도 5초 뒤 끝난다. 취소 버튼 또한
하드웨어 비상 정지가 아니다. `CANCELING`은 요청 중이며 최종 `CANCELED` 등 결과와
실제 정지를 확인해야 한다. 웹 서버 종료 시에도 Goal 취소와 소유한 Bringup
정리를 시도하지만 실제 정지를 보장하지 않는다. 통신·서버 문제는 로그를 확인한다.

인터넷에 노출하거나 공유기 포트 포워딩을 하지 않는다. 인증 토큰을 요구하고
다른 웹사이트에서의 POST를 차단하지만, HTTP이므로 전송 암호화는 제공하지 않는다.
신뢰하는 로컬 네트워크에서만 사용한다. 로봇 내부에서만 볼 때는
`--ros-args -p host:=127.0.0.1`을 사용한다.
