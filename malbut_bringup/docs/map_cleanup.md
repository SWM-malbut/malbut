# 저장 지도 정리

웹 **지도 → 지도 관리 → 지도 정리**에서 저장 지도를 선택한다. 소유자만 사용할 수 있고,
로봇 연결이 필요하다. 열기·선택·수정본 저장은 사용 중인 지도나 로봇 위치를 바꾸지 않는다.

- 사각형 또는 다각형으로 사라진 장애물을 선택한다. 초록색 칸만 빈 공간으로 바뀌며
  회색 미확인 칸은 보존한다. 확대·축소·회전·지도 이동, 전후 비교, 실행 취소·다시 실행을 제공한다.
- **수정본 저장** 후 **주행에 적용**을 별도로 누른다. 적용은 런타임이 준비되고 이동·수동 조작·
  지도 생성이 없을 때만 가능하다. 기존 위치 추정 복구 과정에서 제자리 회전이 발생할 수 있다.
- **원본으로 복원**은 최초 편집 전 장애물 정보를 새 수정본으로 저장한다. 방 이름·구역을 지우지
  않으며 주행에 적용하려면 별도로 적용한다. 연결이 끊겨도 열린 화면의 선택 내용은 유지한다.
- 첫 버전은 `trinary` 지도를 지원한다. 실제 LiDAR 장애물과 진입 금지 구역은 계속 적용된다.

## 저장과 복구

지도 이름과 루트 YAML 경로는 유지한다. `.map-edits/<지도.yaml>/versions/`에 수정본 YAML·PGM을
보관하고 `state.json`이 원본·최신 저장본·적용본을 구분한다. 저장만 한 수정본은 재시작해도
자동 적용되지 않는다. 적용 시 루트 YAML의 `image` 참조가 해당 버전의 이미지로 바뀐다.
지도 파일을 백업하거나 옮길 때 `.map-edits`도 함께 보관해야 한다.

`applying.json`에는 적용 전 YAML과 방·구역·표시 방향·위치 파일을 기록한다. 파일 변경이나
위치 추정이 실패하면 복원하고 이전 주행 지도를 다시 불러온다. 프로세스가 중단되면 다음
지도 조회·지도 공급 시작 시 복원한다. 복구가 확인되지 않으면 런타임은 준비 완료를 보고하지 않는다.
방·구역 변경과 삭제는 지도별 파일 잠금으로 직렬화한다. 지도 원본이 외부에서 바뀌면 이전 편집
요청은 거부하고, 다시 열 때 새 원본을 기준으로 시작한다. 이전 버전 파일은 보관한다.

## 연결과 배포

`nav2.map_edit = "v1"`을 보고하는 로봇에서 버튼을 표시한다. `map_edit_open`, `map_edit_save`,
`map_edit_restore`, `map_edit_apply`는 기존 소유자 명령 큐를 사용한다. 이미지는 명령 결과에
넣지 않고 장치의 `/api/device/v1/robot/saved-maps` 업로드와 소유자의
`/api/devices/<장치>/robot/saved-maps?map=<지도.yaml>` 조회로 전달한다.
적용은 `/malbut/localization/apply_map_edit` (`nav2_msgs/srv/LoadMap`)가 로봇에서 생성한 적용
요청 파일을 받아 실행한다. 이 명령의 완료는 파일 저장뿐 아니라 위치 추정 복구 완료까지 의미한다.

웹 배포 전에 `npm run db:migrate`로 `0027_robot_map_edits`를 적용한다. 웹·Bringup 원본의
변경을 `malbut_test` 배포 복사본에도 반영한다. 기존 지도는 별도 일괄 변환 없이 읽는다.

## 검증

`test_map_edit.py`, `test_cloud_sync.py`, `test_runtime_control.py`에서 편집·충돌·복구와
명령 완료 시점을 확인한다. 웹의 `robot-map-edits.test.mjs`는 좌표 변환·화면의 수정 칸·계약·
DB 격리·권한을 검증한다.

ROS 환경과 원본 패키지의 `PYTHONPATH`를 준비한 뒤 다음을 실행하면 하드웨어 없이
Nav2 map server와 planner만 DDS domain 188 / localhost에서 띄운다.

```bash
MALBUT_MAP_EDIT_NAV2_TEST=1 python3 -m pytest \
  malbut_bringup/test/test_map_edit_navigation_ros.py -q
```

임시 장애물이 있는 통로에서 저장만으로 경로가 바뀌지 않고 적용 후에는 경로가 열리는지,
센서 장애물과 keepout mask가 계속 경로를 막는지 확인한다.
