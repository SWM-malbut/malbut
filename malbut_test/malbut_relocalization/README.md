# 위치 보정

저장 지도 위에서 AMCL 위치 추정을 맞추는 `/relocalize` Action 서버다.
저장된 위치나 지정한 위치를 `/initialpose`로 보내고, AMCL이 그 위치에서 새 추정을
낸 것까지 확인한다. 저장 위치가 라이다와 맞지 않거나 `method=GLOBAL_SEARCH`(2)면
AMCL 전역 위치 탐색과 Nav2 Spin을 사용한다. 위치는 AMCL만 추정하며,
벽 정렬·위치 모호성·연속 측정의 안정성을 확인한 뒤 성공으로 판정한다. 탐색은 최대 30초다.

## 인터페이스

| 항목 | 내용 |
| --- | --- |
| Action | `/relocalize` (`malbut_interfaces/action/Relocalize`) |
| `method=AUTO`(0) | 저장 AMCL 위치·AutoSLAM `<지도>.pose.yaml` 확인, 없거나 맞지 않으면 전역 탐색 |
| `method=GIVEN_POSE`(1) | Goal의 `initial_pose`(map 좌표) |
| 결과 | `success`, `failure_reason`, `message`, AMCL 추정 `pose`, `match_ratio` |
| 피드백 | `WAITING`(지도 선택·AMCL 활성 대기) → `APPLYING` |

선택 지도는 Bringup 공통 실행기의 `/malbut/localization/state`에서 읽는다.
지도·AMCL·스캔을 사용할 수 없으면 `timeout_s`(기본 30초) 뒤 실패한다.
0.5rad/s 제한에서 한 바퀴에 최소 12.6초가 필요하다. 탐색 이후 필터 복원과 최종 확인에
각각 최대 5초를 별도로 사용한다. 회전 취소 완료는 실제 종료까지 기다린다.
한 번에 하나의 Goal만 받는다. 관리자는 지도/비지도 모드로 이 기능을 제한하지 않는다.
스캔·TF 연결은 유지하고, Action 종료 때 사용한 스캔 상태만 비운다.
실행 중 구독 객체를 삭제하지 않는다.
AMCL pose 수신과 마지막 위치 저장은 유휴 상태에서도 유지한다.

전역 탐색에는 알려진 빈칸이 필요하다. 전부 미확인인 기본 지도나 전부 점유된 지도에서는
AMCL 전역 탐색 서비스를 호출하지 않고 이유를 반환한다. `GIVEN_POSE`로 위치를 직접
지정하는 기능과 다른 센서 기반 기능은 유지한다.

## 사용처

- **Bringup 공통 실행기**: 저장 지도로 바꿀 때 `AUTO`를 요청하고, 결과를
  `/malbut/localization/state`의 `message`로 알린다. Bringup의
  `restore_pose:=false`면 요청하지 않는다.
- **다른 클라이언트**: `relocalize` 기능(Capability Manifest)으로
  `/malbut/mission/execute`에 요청한다. AMCL을 먼저 활성화하되, 이 Action이
  만들 초기 위치를 준비 단계에서 미리 요구하지 않는다.

```bash
ros2 action send_goal /malbut/mission/execute malbut_interfaces/action/ExecuteMission \
  "{capability_id: relocalize, arguments_yaml: '{method: 0}'}"
```

## 위치 보정 중 파티클 증량

기존 AMCL의 파티클 범위를 Action 실행 중에만 기본 2000~8000개로 변경한다.
새 AMCL 노드를 실행하지 않는다. 변경 전에 기존 범위를 읽고 성공·실패·취소 후 복원한다.
Humble AMCL은 범위를 바꾸면 필터를 초기화하므로, 같은 지도의 마지막 위치로 시작하고
복원할 때도 이동량을 반영한 AMCL의 마지막 위치와 공분산을 전달한다.
AUTO의 저장 위치 초기화에는 최소 표준편차 15cm·0.25rad를 주고, 새 측정으로 최대 4회
주변 수렴을 시도한다. 결과를 복원할 때는 AMCL이 계산한 공분산을 유지한다.

`match_ratio`는 지도 장애물에서 0.10m 이내인 유효 라이다 점의 **원시 비율**이다.
확률이나 위치 오차가 아니며, 환경 차이를 제외한 비율로 바꾸어 보고하지 않는다.
기본 `match_ratio_min=0.95`에 더해 다음 검사를 모두 수행한다.

- 유효 점 80개 이상, 8개 방향 중 6개 이상에서 벽을 관측해야 한다.
- 최대 20%를 제외한 벽의 RMS 잔차가 5.5cm 이내이고, 남은 점의 95%가 10cm 이내여야 한다.
- 주변 ±5cm·±0.05rad 후보가 잔차를 1cm 넘게 개선하면 위치 오차로 판정한다.
  ±20cm·±0.15rad를 구별할 수 없는 복도 등은 모호한 위치로 거부한다.
- 지도 전역의 위치·방향 후보와도 비교한다. 다른 위치가 비슷하게 맞으면 환경 변화로
  단정하지 않고 `ambiguous_global_pose`로 거부한다. 후보는 검증에만 쓰고 초기 위치로 보내지 않는다.
- 복원한 AMCL에서 시간표시가 새로운 측정 3회가 연속 통과해야 한다. odom으로 설명되지
  않는 5cm·0.05rad 이상의 추정 변화가 있으면 안정된 것으로 보지 않는다.

원시 비율이 95% 미만이어도 위 검사를 통과한 제한적 지도 차이는 `limited_map_difference`로
구분한다. 이는 이동 물체·열린 문·지도 왜곡의 **가능성**을 뜻하며 물체의 종류를 확정하지 않는다.
회전 중에는 odom으로 AMCL 추정치를 스캔 시각까지 이동시켜 비교한다. 시각이 없거나
추정치보다 오래된 스캔, 해당 시각의 odom TF가 없으면 성공으로 판정하지 않는다.
파티클 복원 중의 이동량도 반영하고 복원한 최종 필터를 검사한다.

시간 초과는 `failure_reason=timeout`, 정렬·모호성·안정성 검사 실패는 `low_match`로
Action을 중단한다. `GIVEN_POSE`에도 같은 검사를 적용한다. 취소는 `CANCELED`,
그 밖의 오류는 `failure_reason=error`로 반환한다. 실패·취소 후의 추정값은 마지막 저장 위치를
덮어쓰지 않는다. 성공한 보정이나 운영자가 새로 지정한 `/initialpose` 이후 저장을 재개한다.

Manager는 실패 결과를 Agent에 전달한다. 음성 안내는 `failure_reason`을 기준으로
일치율 부족과 시간 초과를 구분하며, 내부 진단 문자열을 그대로 읽지 않는다.

## 위치 기억

AMCL이 활성인 동안 새 `/amcl_pose`를 **5초마다**
`~/.ros/malbut/localization/last_pose.yaml`에 저장한다(`save_period_s`, `pose_file`).
기록에는 지도 YAML·이미지 내용의 SHA-256을 함께 저장하므로, 같은 이름이라도 지도가
바뀌면 예전 위치를 쓰지 않는다. 사용자가 RViz **2D Pose Estimate**로 위치를 바꾸면
그 이전에 계산된 추정은 저장하지 않는다.

복원은 초기 추정일 뿐이다. 전원이 꺼진 동안 로봇을 옮겼다면 복원 위치가 틀리므로,
지도 위 위치가 실제와 맞는지 확인하고 필요하면 RViz로 다시 지정한다.

## 검증 요약 (2026-10-26)

- 위치 보정 단위·ROS 통합 검사 82개, 적용본 검사 10개 통과.
- 시뮬레이션에서 실제 AMCL로 전역 보정 후 왕복: 보정 위치 오차 4.4cm, 주행 중 최대 5.5cm, 충돌 없음.
- 대칭 위치는 원시 일치율 92%여도 거부하고 주행 명령을 내보내지 않음.
- 시뮬레이션의 폭 60cm 통로·서로 다른 두 방에서 전역 보정 후 전체 순찰: 관측률 100%, 사진 10장,
  출발점 복귀 12.4cm, 주행 중 최대 위치 오차 6.8cm, 충돌·금지구역 침범 없음.
  외부 영상 재분석은 시뮬레이션에서 응답이 없어 시간 초과했으며 주행 검증과 구분함.
- 실제 로봇 적용 후 위치 보정 성공: 원시 일치율 85.3%, 8방향 벽 지지와 연속 측정·전역 모호성 검사 통과.
- 실제 순찰: 접근 가능한 부엌·안방·거실 진입, 관측률 99.0%, 출발점 거리 10.6cm로 복귀 후 정지.
  창고는 운영자가 문 닫힘/물건 막힘을 확인해 제외했으며 이격거리는 유지함.
  복귀 후 정지 스캔 3회도 저장 위치와 정렬·전역 모호성 검사를 통과함.
  복귀 거리는 AMCL 기준이며 외부 계측으로 확인한 실제 위치 오차는 아님.
