이 문서는 구현과 실험 결과를 기록한다. 기능 명세 `stt_agent.md`를 대체하거나 변경하지 않는다. 실험은 2026-09-13 22:14 KST에 시작했고, 2026-09-14 00:00 KST에 결과·검증을 마무리했다.

## 결론과 적용 범위

현재 CPU 경로를 유지하면서 Apple Silicon 노트북에서 MLX로 같은 multilingual Whisper small 계열을 시험할 수 있도록 추가했다. MLX는 낭독 전사에서 빠르지만 별도 검증의 짧은 합성 명령에서는 외국어 출력과 반복 등 품질 회귀가 있었다. CPU를 기본으로 유지하고 MLX는 비교 시험용으로 둔다. 모델 공유, 연속 발화 종료 처리, 빈 전사 뒤 대화 유지도 실제 구현에 반영했다.

실제 마이크 녹음·스피커 재생·로봇 구동·외부 STT 추론 API 호출은 하지 않았다. 공개 음성과 파일로 생성한 합성 음성을 로컬에서 인식했다. 공개 모델·패키지·데이터 다운로드는 준비 단계에서 사용했다. 실험 ASR 프로세스에는 연결 차단을 적용했다. 여기서 로컬이라는 범위는 STT다. 별도 Agent를 OpenAI provider로 연결하면 대상 판단·답변에는 그 Agent의 API가 쓰일 수 있다. 이번 노트북 CLI에는 Agent가 연결되어 있지 않다.

노트북의 파일 재생 결과는 사용자의 육성, 원거리 마이크, 로봇 모터음, TTS 자기 음성 제거 성능을 입증하지 않는다. ROS 검증도 가짜 오디오와 실제 ROS 통신의 조합이며 로봇 실기 검증은 아니다.

최종 검증 전 2026-09-13 14:11:43 UTC에 모델·언어 규칙·구현을 동결했다. 최초 계획의 단일 후보 비교를, 결과 확인 전에 CPU 기본 경로와 MLX 선택 경로를 모두 보고하는 비교로 확장했다. 최종 검증 실행 전에 추가한 것은 마이크에서 기존 파이프라인을 여는 `smoke --dialogue` 진입점이다. 해당 평가 스크립트는 이 진입점을 import하지 않는다. 이 예외는 `freeze_entrypoint_exception.json`에 기록했다. 평가 뒤 cold worker 실행에서 별도의 MLX 초기화 오류를 발견했으며, 아래에 동결 버전의 점수와 초기화 수정 검증을 구분한다. 모델 가중치·디코딩 옵션·종료 규칙을 최종 검증 결과에 맞춰 조정하지 않았다.

CER는 NFC 적용 후 공백과 Unicode 문장부호를 제외한 정답 문자 편집 거리 / 정답 문자 수이다. 숫자 표기 차이를 자동으로 의미 동등 처리하지 않는다. 정확 일치와 수량·부정·취소 등의 의미 오류를 별도로 확인한다. 긴 낭독과 짧은 명령의 점수는 합쳐서 하나의 정확도로 제시하지 않는다.

## 개발 단계에서 확인한 개선과 기각한 설정

새 프로세스에서 모델 로드 실험을 각각 3회 실행했다. 호출어와 일반 발화가 모델을 공유할 때 CPU int8 경로의 모델 로드 중앙값은 0.697 → 0.438초, 동일 음성을 일반 전사·호출어 경로에서 각각 한 번 처리한 뒤 프로세스 최대 RSS 중앙값은 1,271 → 926 MiB였다. 약 345 MiB 감소는 이 측정 경로의 결과이며 모든 실행에서의 최대 메모리 보장은 아니다.

FLEURS 개발 16개에서 CPU int8의 CER는 44/711 = 6.19%, 전사 중앙값은 0.935초였다. MLX는 같은 CER 44/711, 중앙값 0.240초였다. CPU float32는 43/711, 0.723초였지만 다른 합성 자료에서 최대 8.019초와 수량 오류가 관측되어 기본값으로 채택하지 않았다. MLX 개발 실행의 RSS는 약 858 MiB였지만 allocator 최대 사용량은 약 1,385 MiB였다. 통합 메모리에서 두 값은 겹칠 수 있어 합산하거나 RSS만으로 전체 메모리 절감을 주장하지 않는다.

beam 3/5는 작은 개발 점수 차이에 비해 느렸고, temperature=0 고정은 호출어에서 반복 문자를 길게 생성하는 실패가 있어 채택하지 않았다. 호출어 힌트 3종 × int8/float32 비교는 57개 개발 자료에서 모두 TP=8, FN=0, FP=1, TN=48로 같았다. `제이컵`이 `제이크`로 인식되는 문제를 해결하지 못해 기존 힌트를 유지했다.

1.5초 시점의 후보 PCM과 3초 시점 PCM을 그대로 다르게 넣으면, 같은 발화도 끝부분 무음 길이에 따라 전사가 달라졌다. 후보를 ASR에 넣을 때만 기존 3초 종료와 같은 길이가 되도록 zero padding을 추가했다. 실제 녹음·관측 무음 시간·타이머는 바꾸지 않는다. 실환경의 배경 소음이 zero padding과 같다는 보장은 없다.

이후 개발 시퀀스 6개에서 완결 발화의 CPU 확정 지연은 약 2.21–2.31초, MLX는 약 1.66–1.69초였다. 미완결은 두 경로 모두 약 3.01초를 기다렸다. MLX는 이 중 한 질문을 여전히 잘못 전사했다. 빠른 확정은 단어 정확도 개선과 구분한다.

## 실제 구현 변경

- 호출어와 일반 발화가 같은 로컬 모델 경로 또는 같은 실파일을 가리키면 모델 한 개를 공유한다. 일반 문장에는 로봇 이름 힌트를 넣지 않는다.
- 명령 발화의 무음 1.5초에 후보 인식을 시작하고, 완결 규칙에 맞으면 확정한다. 불명확하면 3초까지 기다린다. 전사가 늦으면 실제 확정도 늦어져 1.5초 응답을 보장하지 않는다.
- 후보 인식 중에도 오디오를 계속 받고, 발화가 이어지면 이전 revision의 후보를 폐기한다. 바뀌지 않은 후보는 3초 시점에서 재사용한다.
- 오래된 작업의 결과가 새 발화의 busy 상태를 해제하지 않도록 소유 관계를 수정했다. 전사 오류·빈 결과는 Agent에 전달하지 않고 다음 발화를 받을 수 있도록 대화 상태를 유지한다.
- 정확히 0인 PCM은 추론 없이 빈 결과를 반환한다. 작은 신호를 임의의 볼륨 기준으로 버리는 필터는 추가하지 않았다.
- MLX는 별도 노트북 환경에서 명시적으로 선택한다. 기존 ROS CPU 기본값은 유지한다. 모델 파일을 먼저 확인하며 로컬 경로가 없으면 자동 원격 추론으로 전환하지 않는다.
- `smoke --dialogue`와 `tools/replay_local.py`로 동일 연속 파이프라인을 직접 시험할 수 있다. CLI는 TTS 재생 완료 이벤트를 받지 않아 TTS 완료 후 5초 무음 종료는 시험하지 못한다.

### 동결한 설정으로 별도 자료를 한 번씩 평가

2026-09-13 14:19:35–14:28:05 UTC에 12개 직렬 작업을 완료했다. 다른 담당자가 평가 당시의 원본 manifest, 순서, PCM·모델·소스 hash를 확인하고 CER·정확 일치·호출어 결정을 다시 계산했으며 불일치 0건이었다. 다음 시간은 모델 로드와 워밍업을 제외한 전사 중앙값이다.

| 입력과 지표 | 작업 시작 전 CPU | 개선한 CPU 기본 경로 | MLX 선택 경로 |
|---|---:|---:|---:|
| FLEURS 16개 CER | 47/683 = 6.88% | 47/683 = 6.88% | 45/683 = 6.59% |
| FLEURS 정확 일치 | 3/16 | 3/16 | 2/16 |
| FLEURS 전사 중앙값 / p95 | 0.849 / 0.980초 | 0.871 / 1.057초 | 0.240 / 0.306초 |
| 짧은 합성 일반 문장 20개 CER | 73/201 = 36.32% | 69/201 = 34.33% | 101/201 = 50.25% |
| 같은 20개 정확 일치 | 2/20 | 3/20 | 2/20 |
| 같은 20개 전사 중앙값 / p95 | 0.681 / 2.774초 | 0.705 / 2.765초 | 0.144 / 4.854초 |

p95는 nearest-rank 방식이다. 16개/20개의 한 번 관측으로 통계적 개선을 주장하지 않는다. CPU의 일반 비영 PCM 디코딩 설정은 전후 동일하고 fallback sampling의 seed가 고정되지 않아 짧은 합성 문장의 작은 점수 차이를 구현의 정확도 향상으로 해석할 수 없다.

일반 문장용 힌트 없는 경로에 호출어 등까지 넣은 전체 합성 음성 32개도 버리지 않았다. CER는 baseline 105/306=34.31%, CPU 108/306=35.29%, MLX 600/306=196.08%였다. MLX의 단독 이름 반복 출력이 이 수치를 크게 높였다. 삽입 문자가 많으면 CER는 100%를 넘을 수 있다. 이 진단은 실제 호출어 힌트 경로의 점수와 구분한다.

특히 다음 실패는 남아 있다. 이는 기준 문자열과 출력 비교이며 청취자가 음성의 자연스러움을 평가한 결과는 아니다.

- `방금 예약은 철회해 줘.` → 세 경로 모두 `방금 예약은 철회했어`: 요청이 완료 사실처럼 바뀐다.
- `상자 일곱 개를 세어 줘.` → CPU는 `잠자 일곱 캐루세요`, MLX는 `nicht`: CPU도 전체 의도가 보존되지 않으며 MLX는 수량도 사라진다.
- `거리는 일 점 오 미터야.` → CPU는 `그 린은 일찬모 미터야`, MLX는 `그 일crowd 모집사야!`: 수치가 보존되지 않는다.
- `문이 닫혀 있다면 그 앞에서 기다려 주세요.` → 세 경로 모두 앞 조건절을 생략하고 `그 앞에서 기다려주세요.`를 출력한다.

### 호출어와 비음성

별도 호출어 힌트를 사용하는 실제 recognizer 경로는 세 설정 모두 단독 호출어 4/4 검출, 비호출어 입력 33개에서 오탐 0/33이었다.

이 33개는 일반 문장/시퀀스 26개, 문장 내 이름 2개, 비음성 5개다. 문장 내 이름을 받지 않는 결과는 기존 전체 구문 matcher 동작이며 호출어와 명령을 한 문장으로 말하는 기능을 입증하지 않는다. 비음성 5개에 일반 문장 경로는 모두 빈 결과를 냈다. 호출어 힌트 경로는 baseline 4/5, CPU·MLX 각각 2/5에서 비어 있지 않은 텍스트를 냈지만 이름 힌트 문장 등이라 matcher가 거절했다. 비어 있지 않은 전사와 호출어 오탐을 혼동하지 않는다.

| 정상 완료·고유 UID의 최종 결과 1개씩 | 6/6 | 6/6 | 6/6 |
| 전사 정확 일치 | 2/6 | 2/6 | 1/6 |
| 문자 오류 / 정답 문자 | 21/70 | 21/70 | 32/70 |
| 마지막 VAD부터 최종 결과 중앙값 / p95 | 3.717 / 5.309초 | 2.602 / 3.008초 | 2.333 / 3.509초 |

각 결과는 마지막 원본 음성 조각 뒤에 확정됐고 중복 확정·overflow·busy로 버린 발화·ASR 오류가 없었다. 완결로 준비한 5개 중 조기 확정은 요청·조건·부정 꼬리의 3개였고, 자기정정과 짧은 응답 `네.`는 현재 보수적인 어미 규칙에서 3초 fallback을 유지했다. 조건절·정정 시퀀스가 여러 발화로 잘리지 않았다는 처리 증거이며 모든 절의 의미가 전사에 남았다는 뜻은 아니다. 위 조건절 누락과 다른 단어 오류를 성공으로 바꾸어 세지 않았다. MLX의 미완결 시퀀스는 빠른 중앙값에도 불구하고 3.509초가 걸렸다.

### 연속 실행 및 최종 회귀 검증

CPU에서는 실제 로컬 모델과 VAD를 사용해 “제이크야” 한 번 → “창문을 열어 줘.” → “저녁은 언제 먹을까?”를 파일로 실시간 재생했다. 호출어 검출 1회, 서로 다른 발화 ID의 전사 2개가 나왔고 두 문장은 공백·문장부호를 제외하면 정확했다. 이 WAV는 개발용 합성 음성을 이어 붙인 것이며 마이크나 스피커를 열지 않았다.

CPU 연속 실행은 대화가 이미 활성화된 상태에서 서로 다른 Yuna 개발 문장 6개를 같은 순서로 20회 반복했다. 원본 음성 조각 사이에 4초 무음을 넣은 653.415초 WAV이고 실행기가 끝에 4초 무음을 추가한다. 모든 입력을 처리해 120개 결과와 120개 고유 발화 ID를 얻었으며, 전사 오류·빈 전사·overflow·busy로 버린 발화·중복이 없고 두 worker가 정상 종료했다. 전사도 120/120 normalized exact, CER 0/980이었다. 서로 다른 120문장의 정확도나 실제 사용자 정확도 100%를 뜻하지 않는다.

CPU의 마지막 VAD 처리부터 결과까지 중앙값은 2.205초, p95는 3.009초였다. 처음 30개와 마지막 30개의 중앙값은 각각 2.205초와 2.201초다. 프로세스 최대 RSS 관측치는 중간부터 약 970 MiB로 유지됐다. high-water RSS만으로 메모리 누수가 없다고 증명할 수는 없다.

초기화 수정 후 MLX에도 동일한 653.415초 입력을 한 번 적용해 정상 완료했다. 독립 감사에서 두 경로의 원본 PCM·120개 조각·119개 무음 구간·progress journal와 최종 inference 120행이 모두 일치했다.

| 6문장 × 20회 연속 실행 | CPU int8 | MLX FP16 |
|---|---:|---:|
| 최종 결과 / 고유 발화 ID | 120 / 120 | 120 / 120 |
| 정규화 정확 일치 / CER | 120/120 / 0/980 | 120/120 / 0/980 |
| ASR 오류·overflow·discard·빈 전사·중복 | 모두 0 | 모두 0 |
| 전사만 중앙값 / p95 | 0.688 / 0.746초 | 0.155 / 0.188초 |
| 마지막 VAD → 결과 중앙값 / p95 | 2.205 / 3.009초 | 1.667 / 3.011초 |
| 처음 30개 → 마지막 30개 결과 지연 중앙값 | 2.205 → 2.201초 | 1.665 → 1.667초 |
| 관측한 프로세스 최대 RSS | 969.8 MiB | 888.2 MiB |

두 연속 실행은 별도 ASR 워밍업 없이 시작했고 첫 추론도 통계에 포함했다. 두 실행 모두 입력을 전량 처리하고 capture/ASR worker가 정상 종료했다. 120회 반복 동안 지연이 계속 늘어나는 현상은 관측하지 않았다. 반복 문장 중 미완결 구절이 있어 p95는 약 3초다. 이 평가는 대화가 이미 활성화된 상태이며 TTS 완료 후 5초 무음 종료를 시험하지 않는다.

MLX는 별도로 관측한 allocator active 메모리가 매 추론 후 약 461.6 MiB, allocator peak는 최대 1,374.8 MiB, cache는 최대 1,002.9 MiB였다. RSS와 allocator·cache 수치가 겹칠 수 있으므로 합산하지 않는다. 메모리 측정은 관측 범위의 값이며 장시간 누수 부재를 보장하지 않는다. 원본과 독립 검산은 `soak/FINAL_SOAK_AUDIT.md` 및 `.json`에 있다.

최종 초기화 수정과 연속 대화 CLI를 포함한 로컬 STT 전체 테스트는 **414 passed, 2 skipped**였다. 2개 skip은 macOS 환경에 ROS 2가 없기 때문이며, 별도의 ROS 컨테이너에서 신규 서비스 통신 4개와 기존 통신 회귀 33개가 통과했다. 이 ROS 검사 이후 변경은 노트북 CLI와 선택 MLX 초기화이며 ROS 노드·인터페이스는 그대로다.

`malbut_interfaces`, `malbut_agent_server`, `malbut_stt`, `malbut_tts`, `malbut_system_manager` 5개 패키지 빌드를 통과했다. 마지막 CLI·초기화 수정 이후 STT를 컨테이너에 다시 설치했고 설치된 Python 파일 해시가 소스와 일치했다. 최종 실행 코드·테스트·패키지 설정 220개 파일은 검토한 해시와 일치한다.

ROS는 `ROS_DOMAIN_ID=180`, `ROS_LOCALHOST_ONLY=1`의 별도 임시 작업 공간을 사용했다. 원래 테스트가 다른 domain으로 바꾸는 경우 검증 전용 pytest plugin으로 180을 유지했으며 원본 테스트 정책을 수정하지 않았다. 가짜 오디오를 사용했고 외부 추론 API나 로봇 동작은 실행하지 않았다.

flake8의 신규 진단은 0건이다. 원래 있던 9건 때문에 raw exit는 1이므로 전체 스타일 검사가 깨끗하게 통과했다고 표현하지 않는다. `git diff --check`는 통과했다. 상세 명령·JUnit·빌드·설치·스타일 비교·최종 소스 해시는 `validation/final-summary.json` 및 그 참조 파일에 남겼다.

사용자 소유 명세 `stt_agent.md`의 SHA-256은 실험 전후 모두 `7a158263566ab331d80152f64c316f8cfbae57d295293eeb0b9314925f5b51ce`로 동일하다. 기존에 수정 중이던 다른 작업을 초기화하지 않았고 commit/push를 수행하지 않았다.

### MLX의 첫 worker 실행 오류

동결 버전의 MLX 평가에는 메인 스레드의 워밍업이 있었지만, 실제 CLI처럼 워밍업 없이 worker에서 첫 전사를 하니 `RuntimeError: There is no Stream(gpu, 1) in current thread.`가 발생했다. 최초 호출어 시퀀스는 오류 3회, 호출어 검출·전사 모두 0건이었다. 파일 입력 처리가 완료됐다는 harness 상태만 보고 성공으로 처리하지 않았다. 원본 실패 결과를 `wake_sequence/mlx-result.json`에 보존했다.

MLX loader는 model parameters를 평가하지만 별도 내부 상수의 lazy 계산 그래프는 남아 있었다. 생성 스레드와 다른 스레드에서 이 그래프를 처음 평가하면서 오류가 났다. 같은 18,240샘플 PCM의 별도 프로세스 비교에서 생성 스레드의 `mx.eval(loaded.state)`로 전체 상태를 평가하면 추가 음성 워밍업 없이 `제이크야.` 전사가 성공했다. 이 추가 준비 단계는 해당 진단에서 약 0.0047초였다.

초기화에 `mx.eval(loaded.state)`를 추가한 후 새 프로세스의 첫 worker 전사가 약 0.245초에 성공했다. 실제 `replay_local.py --wake` 진입점도 호출어 1회와 고유 발화 ID의 후속 문장 2개를 정상 처리했고 두 문장 모두 normalized exact였다. 검사한 두 실행에서 네트워크 연결 시도는 0회였다. 초기화·smoke·replay의 관련 테스트 107개가 통과했으며, 새 회귀 테스트에서 수정 줄을 제거하면 같은 thread 오류가 재현되는 것도 확인했다. 최종 초기화 수정 및 source hash는 `final_runtime_freeze.json`에 기록했다.

이 초기화 경계의 수정 검증은 새로운 holdout 정확도 평가가 아니다. 위 MLX 점수는 메인 스레드 워밍업을 거친 동결 버전의 결과이며, 외국어·반복 출력 같은 인식 품질 문제는 이 수정으로 해결했다고 주장하지 않는다.

## 제한과 다음 사용자 시험

Whisper의 잘못된 전사가 문장처럼 자연스럽게 끝나면 종료 판정도 영향을 받는다. 어미 규칙은 의미를 이해하는 분류기가 아니다. 중요한 수량·부정·고유명사 오류가 남아 있어 자연스러운 문자열만 보고 인식 성공으로 처리하면 안 된다.

단독 호출어 소수 샘플과 짧은 합성 잡음은 장시간 오탐률을 입증하지 않는다. 실제 사용자의 가까운/먼 거리 발화, 작은 목소리, 생활 소음, TTS 재생 중 끼어들기는 사용자 입회 시험으로 남는다. Jetson 성능도 이 Mac 측정으로 추정해 확정하지 않는다.

실행 명령과 MLX 환경 구성은 [STT README](../README.md)의 로컬 연속 대화 항목에 둔다. 첫 육성 시험은 README의 모델·장치 인자를 포함한 `--local --dialogue --manual`로 인식 자체를 확인하고, 이어 `--manual`을 빼고 호출어부터 확인할 수 있다.

## 자료 위치와 기술 출처

- `candidate_freeze.json`, `freeze_entrypoint_exception.json`, `final_runtime_freeze.json`: 동결 설정, 진입점·초기화 수정 예외.
- `evaluation/FLEURS_PROVENANCE.md`, `evaluation/generated_fixtures/manifest.json`: 데이터 출처, 정답, PCM 해시.

- `heldout_results/`, `HELDOUT_AUDIT.md`, `HELDOUT_AUDIT.json`: 최종 검증 전사와 독립 재채점.
- `wake_sequence/`, `soak/`: 실제 모델 호출어→후속 발화 및 연속 실행 증거.
- `validation/`: 테스트·ROS 빌드·스타일 기존 진단 비교·소스 hash 감사.
- [faster-whisper 공식 저장소](https://github.com/SYSTRAN/faster-whisper): lazy segment 소비와 런타임 사용.
- [CTranslate2 성능 안내](https://opennmt.net/CTranslate2/performance.html): CPU 연산·스레드 설정.
- [MLX Whisper 공식 예제](https://github.com/ml-explore/mlx-examples/tree/main/whisper): 로컬 모델 경로와 Apple GPU 경로.

MLX 모델 준비 당시 upstream Whisper와 MLX examples의 MIT 라이선스를 확인했다. 선택한 MLX Community 모델 카드에는 별도 license metadata가 없어 변환물의 독립 라이선스 선언으로 간주하지 않았다. 고정 revision, 가중치 SHA-256, 확인한 원문은 실험 루트의 `MLX_PREPARATION.md`에 보존했다.
