# 실행부 좌표 형식·연속 영상 추적 연결 검증

작성: 2026-09-28 / SWM25-193 후속 로컬 작업

## 변경 범위

1. Gemma 주기적 확인의 Cloud 출력 형식을 평가한 native_boxes_v4로 변경했다.
   0~1000 정수 yxyx를 검사한 뒤 기존 내부 0~1 xyxy로 바꾼다.
   과거 평가 프로필·재생 함수 기본값은 유지하며, 지시문 일치 테스트를 추가했다.
2. Cloud 발견 이벤트에서 로컬 추적을 자동 시작하고, 실제 받은 RGB와 같은 시각의
   Pose를 사건 연결 코어에 전달한다. 연결 함수를 수동 호출하는 시험만으로 끝내지 않았다.
3. SAM2.1 tiny GPU 추적은 별도 프로세스로 분리했다. 원본 JPEG의 파일 저장,
   미래 프레임 선입력, Pose ID/답변 전달, CPU 자동 전환은 하지 않는다.
4. 실시간 추적은 선택 설정이며 기본 OFF다. 주기 확인·사건 확인 모델은 모두
   `gemma4:31b`를 유지한다. 기존 5초/12장, Cloud 20초, 연결 만료 정책은 변경하지 않았다.

구조·설정·실패 처리: [실행 문서](fall_runtime.md),
[사건 연결 조건](fall_deferred_association.md).

각 테스트 묶음에는 중복되는 검사가 있으므로 숫자를 합산하지 않는다.

ROS 검사는 `ROS_LOCALHOST_ONLY=1`과 별도 domain/UUID 토픽을 사용했다.
실제 로봇 주행·음성 재생·보호자 알림은 실행하지 않았다.

새 자동 추적 ROS 검사에서는 실제 공급자 코드의 HTTP 경계만 시험 응답으로 바꾸었다.
native 박스 응답 → 사건/질문 이벤트 → 런타임의 자동 추적 시작 → 같은 시각 Pose →
기존 사건 연결 → SQLite 이력을 확인했다. 해당 사람의 기존 질문 ID가 유지됐고,
연결 때문에 세 번째 Cloud 호출이 생기지 않았다. 다른 사람·카메라 OFF·추적기 오류에서는
연결하지 않고 원래 장면 질문을 유지했다. 이 검사의 추적 박스는 시험 값이다.

단위 검사에는 취소 직전/프로세스 생성 중 취소, 시드 영상 퇴거, 프레임 간격 초과,
마스크 소실, 모호한 사람 박스, RGB/Pose 콜백 순서, 저장 실패 전파,
기본 OFF와 잘못된 설정 거부도 포함했다.

### GPU 확인 범위

RTX 3070에서 저장된 SYN059 RGB 20장을 받은 순서로 한 장씩 전달했다.
모델/소스 해시가 고정된 SAM2.1 tiny를 사용했으며, 모든 출력 박스가
이전 incremental GPU 실험의 같은 입력·시드 결과와 일치했다.

- 모델 시작과 첫 이미지 결과까지: 1.937초.
- 이후 이미지: 0.060~0.071초/장.
- 같은 이벤트 루프의 10ms 확인 작업에서 최대 간격: 약 0.012초.
- 종료 시 자식 프로세스 회수 확인.

이는 새 프로세스/메모리 입력 방식의 일치·비차단 확인이다.
박스 정답 라벨을 새로 채점한 정확도나, 실제 ROS 카메라와 GPU를 함께 실행한 지연,
Jetson 성능, 가림/교차 상황에서의 사람 식별 성공률을 입증하지 않는다.
초기 모델 로딩을 포함한 한 번의 PC 측정이므로 운영 보장값으로 쓰지 않는다.

## 미완료와 환경 문제

홈캠 launch 검사 실패는 `homecam_media_agent`가 ament 패키지 인덱스에 없어
구성 파일을 찾지 못한 것이다. C++ 미디어 노드나 실제 카메라를 설치·실행한 상태가 아니다.
실물/설치 환경에서 이 검사부터 다시 해야 한다. 최초 시도에서 ROS Python 경로 누락으로
수집하지 못한 검사도 있었으며, 경로를 갖춘 뒤 위 ROS 59개를 다시 실행했다.

현재 PC에서 아래 **기본 경로**의 파일은 없었다. 다른 위치의 평가용 키를 지우거나,
해당 키가 없다고 판정한 것은 아니다. 키 내용은 읽지 않았다.

- `/etc/malbut/fall_runtime.json`
- `/etc/malbut/ollama-cloud.key`
- `~/.cache/malbut_perception/yolo26s-pose.onnx`
- `~/.cache/malbut_fall_pose/runtime/bin/python`

등록된 로봇 ID·실행 계정·실기기 접속 대상을 확인한 뒤 설정과 경로를 준비해야 한다.
키 값은 Git/Jira/채팅이 아니라 보호된 파일에 두며, 내용 전달을 요청하지 않는다.
이번 실행에서 Cloud API 호출·비용 발생·실제 영상 전송은 없었다.
