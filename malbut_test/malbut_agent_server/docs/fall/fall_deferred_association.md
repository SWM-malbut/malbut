# Cloud 발견을 나중의 Pose 관측에 연결하기

## 구현 범위

Cloud의 개별 `CloudDiscovery`를 연속 영상 추적으로 유지하다가 같은 대상의 사용 가능한 Pose가 확인되면, 기존 사람 사건에 영상 근거를 붙인다. 대상 사건이 없으면 사람별 사건을 만든다. 단순히 실패 유형을 기록하던 단계와 달리 실제 `incident_id`, 영상 판단, 질문 전달, SQLite 이력이 바뀐다.

장면 확인 사건(`subject_key=None`)에는 여러 사람이 섞일 수 있다. 따라서 장면 사건 자체를 사람 사건으로 합치거나, 장면에서 받은 답변을 사람의 답변으로 복사하지 않는다. 원래 사건·질문·도움 요청과 개별 발견 기록을 남기고, 연결 기록에 출발 사건과 목적 사건을 함께 보관한다. 장면 질문의 자동 취소/사건 정리는 이번 범위에 포함하지 않았다.

## 입력 경계

- `CloudFallMonitor.begin_discovery_tracking(discovery_id)`로 로컬 추적 세션을 시작한다.
- 추적기는 해당 발견의 가장 이른 Cloud 박스와 정확한 촬영 시각의 RGB로 시작해야 한다.
- `ingest_discovery_track(session_id, observed_at=..., box=...)`에 실제 추적 결과를 넣는다. 관측 실패는 `box=None`이다.
- 호출자가 Pose ID나 `verified=True`를 지정하는 인터페이스가 아니다. 모니터가 같은 촬영 시각의 Pose 관측과 연속성 토큰을 조회해 대상을 결정한다.
- 신뢰하는 로컬 영상 추적기 전용 경계다. Cloud 응답/대화 Agent/새 ROS 명령으로 노출하지 않았으며, 실제 RGB에서 추적한 결과인지 확인할 책임은 추적 어댑터에도 있다. 좌표의 기하 관계만으로 신원을 보증하지 않는다.

## 연결 조건과 차단

개발 실험 조건은 IoU 0.60 이상, 두 번째 후보와 차이 0.15 이상, 같은 Pose ID·연속성 토큰이 최소 3회/0.5초 이상 유지되는 것이다. 약한 박스도 경쟁 후보에 포함한다. 프레임 간격은 최대 0.5초이며, 영상 박스의 큰 점프·면적 급변·마스크 소실이 있으면 해당 시드의 추적은 끊긴 것으로 처리한다. 다시 나타난 사람을 같은 발견으로 임의 재지정하지 않는다.

- 실제 받은 RGB와 같은 시각의 Pose만 사용한다. 가까운 프레임의 박스를 복사하지 않는다.
- 확정 시점에는 최신 Pose와 토큰이 같고 관측이 신선해야 한다. 과거 중간 프레임에서 잠깐 일치했다는 이유만으로 현재 사건에 붙이지 않는다.
- 같은 Cloud 응답의 서로 다른 발견 둘이 하나의 Pose 대상을 차지하면 두 번째 연결을 막는다.
- 기존 사건의 대상 토큰이 다르거나, 해당 사건이 종료됐거나 Cloud 분석 중이면 붙이지 않는다.
- 출발 사건의 종료·revision 변경, 실행 조건 변경, 카메라 OFF, 무효 Pose 입력도 검사한다.
- 메모리에는 이미지 없이 최대 256개 발견 메타데이터를 접수 후 60초간 보관한다. 카메라/감지 OFF에서는 비운다. 기존 RGB 버퍼 보관 제한은 늘리지 않았다.

## 실제 사건 반영

연결이 확인되면 해당 발견의 긍정 영상 근거와 `cloud_crosscheck` 출처를 사람 사건에 추가한다. 정상 종료 근거는 초기화하고, 연결만으로 사건을 정상 종료하지 않는다.

이미 진행 중인 해당 사람의 질문 ID와 도움 요청은 유지한다. 이전의 부정적 답변으로 새 의심 상황을 끝내지 않도록 필요한 경우 revision과 질문을 갱신하되, 이전 이력은 DB에 남는다. 다른 사람 또는 장면 전체에 대한 답변은 옮기지 않는다.

완료된 Cloud 영상 구간이 아직 시작하지 않은 Pose 사건의 첫 분석을 포함하면 기존 결과를 사용하고 대기 중인 첫 호출을 해제한다. 이때 분석 근거 1회로 기록하며 재확인 횟수는 늘리지 않는다. 더 새로운 Pose 근거나 이미 요청된 재확인은 지우지 않는다. 이미 연결된 세션을 반복 전달해도 사건·질문·재확인 횟수는 바뀌지 않는다.

`cloud_discovery_linked`는 로컬 이력/이벤트다. 출발 사건 ID·revision, 대상 토큰, 시드/확정 시각, 관측 수를 기록한다. 원본 발견을 덮어쓰지 않고 링크 이력을 추가한다. 사건 변경과 연결 이력은 SQLite 한 트랜잭션으로 저장한 후 메모리/외부 이벤트에 공개한다. 저장 실패 시 롤백하고 감지를 중단한다. 기존 서버 전송 계약에 새 사건 이벤트 종류를 추가하지 않았다.

## 실시간 실행 연결과 남은 확인

이 코어는 저장된 SAM/Pose 결과로 재생 검증했다. 2026-09-28에는 ROS가 받은 RGB에서 별도 SAM GPU 프로세스를 실행하고 이 경계로 결과를 넣는 선택 어댑터를 연결했다. 기본은 OFF이며, 명시적인 모델·Python 설정이 있을 때만 사용한다. 이전의 느린 CPU 실행으로 자동 전환하지 않는다. 설정과 자원 상한은 [실행부 후속 연결](fall_runtime.md#2026-09-28-실행부-후속-연결)에 적었다.

PC ROS 테스트는 Cloud 발견 이벤트 이후 수동으로 추적 함수를 부르지 않고, 런타임이 자동으로 추적을 시작해 받은 Pose와 연결하는지 확인한다. 이때 영상·Pose·Cloud 답변·추적 박스는 시험 값이다. 별도로 RTX 3070에서 저장된 SYN059 RGB 20장으로 실제 GPU 어댑터를 실행해 이전 추적 박스와 일치하는지 확인했다. 실물 카메라와 실제 Cloud를 함께 사용한 정확도·지연 검증은 아니다.

완전 가림 후 재등장, 사람 교차, 잘못된 Cloud 시드, 장시간 다인 추적에서 안전한 연결을 보장한다는 뜻은 아니다.
