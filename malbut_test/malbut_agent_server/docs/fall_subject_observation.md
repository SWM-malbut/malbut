# 대상 관측과 사건 영상 연결

2026-09-19 구현. 질문·답변 연동은 이번 범위에서 제외했다.
실제 Agent 답변이 없으면 정상 자동 종결도 하지 않는다.

## 처리 순서

1. 기존 Pose 감지기가 사람별 자세·추적 상태를 관측한다.
2. 새 관측을 `clear` / `suspected` / `unknown`으로 구분한다. 낙상 확정·회복 판정은 아니다.
3. RGB와 관측의 원본 촬영 시각을 맞춘다. 같은 이미지의 콜백 수신 시간이 달라도 같은 시각으로 연결한다.
4. 사건 영상의 모든 샘플에 같은 대상의 유효한 관측이 있으면 프레임별 박스를 Cloud에 전달한다.
5. 정상 결과 두 건·같은 대상의 새 관측·유효한 Agent 답변·이력 조건을 모두 만족해야 정상 종결한다.

## 새 관측 기준

추가 모델은 없다. 기존 `FallCandidateConfig`의 값을 사용한 보수적인 실험 기준이다.
**실물 검증이 끝난 의료적 안전 기준이 아니다.** 기존 낙상 후보 생성 조건은 바꾸지 않았다.

| 상태 | 관측 |
|---|---|
| `clear` | strong·tracked 상태, 유효한 어깨·골반·발 관절, 세워진 상체와 신체 축, 정지한 로봇에서 기존 `rearm_upright_sec` 동안 연속 관측. 새 자세 급변·낮은 자세·활성 후보 없음 |
| `suspected` | 낮은 자세, 급격한 자세 변화 또는 아직 유지 중인 후보 |
| `unknown` | 관절 부족, 약한 검출, 추적 불확실·끊김, 로봇 이동, 관측 시간 부족 등 |

현재 기본 실험값은 몸통·신체 축 35도 이내, 2초 연속 관측, 최소 3샘플,
프레임 공백 0.5초 이하이다. strong은 기존 Pose 설정을 따른다.
이는 정상 근거 생성에만 쓰며, 의심 후보 검출의 낮은 신뢰도 문턱을 높이는 변경이 아니다.
누워서 쉬는 사람은 이 규칙으로 `clear`가 되지 않을 수 있다. 놓친 낙상을 해제하는 것보다
미해결로 남겨 추가 판단을 받도록 한 제한이다.

## 대상 연결

- `/homecam/fall_candidates`의 기존 출력에 `subjectCheckVersion: 1`, `subjectCheckMaxGapSec`와
  사람별 `box`, `associationUsable`, `subjectCheck`를 추가했다. 새 토픽은 필요하지 않다.
- 관절과 추적 상태가 유효한 관측만 연결한다. ID가 있다는 이유만으로 연결을 인정하지 않는다.
- 약한 검출·추적 누락·모호한 대응·시각 공백·카메라 전환·OFF 이후에는 연속 연결을 새로 시작한다.
- 선택한 RGB의 정확한 촬영 시각과 박스가 맞아야 한다. 과거 박스를 복사하거나 중간 위치를 추정하지 않는다.
- Cloud에는 프레임별 정규화 좌표 `[left, top, right, bottom]`만 추가한다.
  추적 ID·사건 ID·연속 연결 토큰은 보내지 않는다. 이미지 크기·비율도 바꾸지 않는다.
- 박스가 사람을 빗나가거나 여러 사람을 포함하면 `unobservable`로 답하도록 지시한다.
  프롬프트만으로 잘못된 박스를 완전히 방지할 수는 없으므로 다인 실영상 검증은 남아 있다.
- 대상 연결이 없는 Cloud 정상 결과는 자동 관측 생성의 종결 근거로 쓰지 않는다.
  두 정상 요청부터 현재 관측까지 같은 대상 연결이 유지되어야 한다.
- 정상 관측 뒤 추적이 끊기면 옆 사람의 정상 관측으로 대신하지 않는다.

## 주기적 Cloud 발견 → 대상 연결

사건 영상은 이미 대상이 정해져 있다. 주기적 확인은 장면 전체를 보므로,
Cloud가 의심한 사람이 누구인지 먼저 연결해야 한다. 이 역방향 연결도 구현했다.

1. Cloud 요청 직전에 선택된 RGB 시각별 Pose 박스와 추적 연속성 정보를 복사해 둔다.
2. Cloud는 장면 판정과 함께 의심한 사람별 `findings`를 반환한다.
3. 같은 샘플 시각의 Cloud 박스와 Pose 박스를 비교한다. 현재 위치로 과거 영상을 비교하지 않는다.
4. 최소 2개 프레임이 같은 대상·같은 추적 구간과 맞고 현재까지 추적이 이어졌을 때만 연결한다.
5. 기존 사건이 있으면 같은 사건에 합친다. 없으면 사건 하나와 질문 요청 하나를 만든다.
   이미 받은 Cloud 결과를 사용하므로 같은 내용을 확인하려고 즉시 Cloud를 다시 호출하지 않는다.
6. 위치 누락·YOLO 미검출·여러 사람 중 연결 불가·추적 끊김은 **대상 미확인 의심**으로 남긴다.
   다른 사람에게 질문하거나 정상으로 처리하지 않는다.

박스 IoU 0.60 이상, 두 후보의 IoU 차이 0.15 이상을 요구한다. 약한 검출도 겹치는
경쟁 후보로 확인한다. **이 숫자는 보수적으로 시작하기 위한 실험값이며 실영상 검증 전이다.**
ID가 같아도 추적이 끊겼으면 이전 사건의 대상이라고 인정하지 않는다.
Cloud 응답 대기 중 사건이 새로 생기거나 바뀌거나 종결된 경우도 미확인으로 남긴다.

### Cloud 출력

주기적 요청(`purpose=crosscheck`)에만 다음 출력이 추가된다.
사건 확인 요청은 기존 `assessment`, `explanation` 형식을 유지한다.

```json
{
  "assessment": "suspected_fall",
  "explanation": "바닥에 옆으로 누워 있으며 내려오는 과정은 보이지 않음",
  "findings": [{
    "assessment": "suspected_fall",
    "kind": "already_down",
    "regions": [
      {"frame_index": 0, "box": [0.1, 0.4, 0.7, 0.9]},
      {"frame_index": 1, "box": [0.1, 0.4, 0.7, 0.9]}
    ]
  }]
}
```

- `findings`: 최대 8명. 사람별 `observed_fall` 또는 `suspected_fall`만 허용한다.
- `kind`: `motion_seen`(과정 보임), `already_down`(이후만 보임), `unknown`(구분 불가).
  `observed_fall`에는 `motion_seen`이 필요하다. 이후만 보였다는 이유로 낙상을 확정하지 않는다.
- `frame_index`: 요청한 이미지 배열의 0부터 시작하는 번호. 원본 영상 프레임 번호가 아니다.
- `box`: 0~1 좌표 `[left, top, right, bottom]`. 사람의 보이는 부분만 표시한다.
- `regions`: 시간순 최대 4개. 위치가 불확실하면 빈 배열을 허용한다. 1개만 오면 연결하지 않는다.
- 위치가 틀린 형식이거나 범위를 벗어나도 유효한 장면의 낙상 의심까지 버리지는 않는다.
  대상 위치를 전부 폐기하고 `invalid_locations`로 미확인 기록을 남긴다.
- 이전 두 필드 응답도 수용한다. 의심 결과에 위치가 없으면 미확인이다.
- 장면의 정상 판정은 특정 사람의 정상 확인·사건 종결 근거로 쓰지 않는다.

### 저장과 전달

- 모든 발견은 `cloud_discovery` 이벤트로 전달하고 SQLite `cloud_discoveries`에 기록한다.
  `association_status`는 `matched` 또는 `unidentified`이다.
- 기록에는 요청·발견 ID, 이미지 시각, 위치, 판정, 연결 여부와 이유만 남긴다.
  RGB·음성·모델 설명 원문·API 키는 저장하지 않는다.
- 연결된 발견은 기존 사건 저널/업로드 경로에도 반영된다. 같은 대상의 중복 출력은
  새 사건이나 질문을 추가하지 않는다. 재확인 횟수도 초기화하지 않는다.
- 미확인 발견은 로컬 기록과 Manager 전달 이벤트까지만 구현했다.
  웹 사건으로 꾸며 올리거나 보호자에게 실제 알림을 보내지는 않는다.
  재시작 후 `SqliteFallJournal.discoveries(after_sequence=0, limit=100)`으로 순서대로 읽을 수 있다.
  다른 요청의 미확인 발견끼리는 같은 사람인지 알 수 없어 자동 병합하지 않는다.
- 저장 실패 시 감지를 중지하고 오류를 낸다. 저장되지 않은 발견을 처리 완료로 내보내지 않는다.

## 구현하지 않은 것

- Manager/Agent의 실제 질문 재생·응답 수집·해석: 담당 팀 연동 필요. 가짜 답변을 만들지 않는다.
- 미확인 발견의 웹 목록·보호자 알림·후속 대상 지정과 사건 연결.
- 실제 보호자 푸시 수신·Jetson 동시 부하·실물 추적 정확도 검증.

## 검증

시험용 관측과 Cloud 응답으로 프레임 시각 일치, 두 사람 분리, 대상 소실,
추적 연속성 단절, 입력 오류, 메모리 상한, Cloud 메타데이터의 ID 제외를 시험했다.
실제 Pose 특징 계산으로 안정된 기립 자세·낮은 자세·관절 부족·움직이는 로봇·시간 공백을 시험했다.
실제 Agent 없이 종결되지 않는 경우도 포함했다. 새 정확도·미탐률을 측정한 것은 아니다.
이전에 평가한 Cloud 프롬프트와 대상 박스가 추가된 프롬프트의 점수를 동일시하지 않는다.
주기적 확인의 위치 출력 프롬프트도 새 버전이다. 출력 예산은 512→2048 토큰으로 늘렸지만
응답 제한 20초는 그대로다. 새 출력의 정확도·지연·소요 토큰은 실호출로 다시 측정해야 한다.

커밋 전 회귀 테스트: Agent 1078개 통과·12개 건너뜀(기존 ROS 통신 테스트 두 파일 제외),
홈캠 감지기 201개 통과, 홈캠 관련 966개 통과, 웹 103개 통과.
Cloud 실호출·질문 재생·실제 푸시 발송·실물 로봇 검증은 실행하지 않았다.

같은 날 주기적 발견 연결 추가 후 Agent 회귀 테스트: **1112개 통과·12개 건너뜀**.
동일한 ROS 통신 테스트 두 파일은 제외했다. 신규 34개 테스트는 위치 출력 파싱,
다인·중복 발견, YOLO 미검출, 추적 단절·ID 재사용, 응답 대기 중 대상 이동·사건 변경,
동의 철회, 미확인 기록의 재시작 복원·저장 실패, 정상 오종결 방지를 확인한다.
